> **ಸತ್ಯದ ಮೂಲ:** `src/lib/guardrails/`
> **ಕೊನೆಯ ನವೀಕರಣ:** 2026-08-29 — v3.8.51 (Video Bridge ಪ್ರತಿಲೇಖದ ಮೂಲವನ್ನು ಕರೆಮಾಡುವವರು ಘೋಷಿಸುತ್ತಾರೆ,
> ಸರ್ವರ್ ಇನ್ನೂ ಅದನ್ನು ಪರಿಶೀಲಿಸುವುದಿಲ್ಲ — #11661 ಪ್ರಕಾರ ಸ್ಪಷ್ಟಪಡಿಸಲಾಗಿದೆ)

Guardrails, OmniRoute ಮತ್ತು ಅಪ್ಸ್ಟ್ರೀಮ್ ಪೂರೈಕೆದಾರರ ನಡುವಿನ ಗಡಿಯಲ್ಲಿ ಸುರಕ್ಷತೆ,
ನೀತಿ ಮತ್ತು ವಿಷಯ ರೂಪಾಂತರಗಳನ್ನು ಜಾರಿಗೊಳಿಸುತ್ತವೆ. ಪ್ರತಿಯೊಂದು guardrail ವಿನಂತಿಯ
ಪೇಲೋಡ್ಗಳನ್ನು (`preCall`) ಮತ್ತು ಅಪ್ಸ್ಟ್ರೀಮ್ ಪ್ರತಿಕ್ರಿಯೆಗಳನ್ನು (`postCall`)
ಪರಿಶೀಲಿಸಬಹುದು (ಮತ್ತು ಐಚ್ಛಿಕವಾಗಿ ತಿರಸ್ಕರಿಸಬಹುದು, ರೂಪಾಂತರಿಸಬಹುದು ಅಥವಾ ಟಿಪ್ಪಣಿ ಸೇರಿಸಬಹುದು).

ಈ ವ್ಯವಸ್ಥೆಯು **fail-open** ಆಗಿದೆ: ಕಾರ್ಯಗತಗೊಳ್ಳುವಾಗ guardrail ದೋಷವನ್ನು ಎಸೆದರೆ,
registry ಆ ದೋಷವನ್ನು ದಾಖಲಿಸಿ, ವಿನಂತಿಯನ್ನು ವಿಫಲಗೊಳಿಸುವ ಬದಲು ಮುಂದಿನ guardrail
ಜೊತೆಗೆ ಮುಂದುವರಿಯುತ್ತದೆ. ನಿರ್ಬಂಧಿಸುವುದು ಸ್ಪಷ್ಟ ನಿರ್ಧಾರವಾಗಿದೆ (`block: true`),
ಎಂದಿಗೂ ಆಕಸ್ಮಿಕವಲ್ಲ.

## ನಿರ್ಮಿತ ಗಾರ್ಡ್‌ರೈಲ್ಸ್

ರಿಜಿಸ್ಟ್ರಿ ಆಮ್ಲಜನಕದಲ್ಲಿ ಆರು ಗಾರ್ಡ್‌ರೈಲ್ಸ್ ಅನ್ನು ಆದ್ಯತೆಯ ಕ್ರಮದಲ್ಲಿ ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಲೋಡ್ ಮಾಡುತ್ತದೆ (ನೋಡಿ `registry.ts` → `registerDefaultGuardrails()`):

| ಆದ್ಯತೆ | ಹೆಸರು               | ಹಂತ(ಗಳು)       | ಫೈಲ್                  |
| ------ | ------------------- | -------------- | --------------------- |
| `5`    | `vision-bridge`     | `preCall`      | `visionBridge.ts`     |
| `6`    | `audio-bridge`      | `preCall`      | `audioBridge.ts`      |
| `7`    | `video-bridge`      | `preCall`      | `videoBridge.ts`      |
| `10`   | `pii-masker`        | `pre` + `post` | `piiMasker.ts`        |
| `20`   | `prompt-injection`  | `preCall`      | `promptInjection.ts`  |
| `95`   | `credential-masker` | `pre` + `post` | `credentialMasker.ts` |

ಕೀಳ್ಮಟ್ಟದ ಆದ್ಯತೆ ಸಂಖ್ಯೆಗಳು **ಮೊದಲು** ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತವೆ.

### ದೃಷ್ಟಿ ಬ್ರಿಡ್ಜ್ (`visionBridge.ts`) — ಮೋಡಾಲಿಟಿ ಬ್ರಿಡ್ಜ್ PR-1

**ಅದೃಷ್ಟಿ ಮಾದರಿಗಳಿಗೆ** ಉದ್ದೇಶಿತ ಚಿತ್ರ-ಬೇರುವುದು ವಿನಂತಿಗಳನ್ನು ಅಡ್ಡಗಟ್ಟುತ್ತದೆ ಮತ್ತು ಸಂಪೂರ್ಣ ವಿನಂತಿಯನ್ನು ದೃಷ್ಟಿ-ಸಾಧ್ಯ ಮಾದರಿಯ ಕಡೆಗೆ ಪುನರ್‌ರೇಖೆಗೊಳಿಸುತ್ತದೆ ಅಥವಾ ಮೇಲ್ಮಟ್ಟದ ಕರೆಗೂ ಮುನ್ನ ಕಾನ್ಫಿಗರ್‌ ಮಾಡಬಹುದಾದ ದೃಷ್ಟಿ ಮಾದರಿಯ ಮೂಲಕ ಉತ್ಪಾದಿತ ಪಠ್ಯ ವಿವರಣೆಗಳೊಂದಿಗೆ ಚಿತ್ರ ಭಾಗಗಳನ್ನು ಬದಲಾಯಿಸುತ್ತದೆ. ಇದು ಪಠ್ಯ-ಮಾತ್ರದ ಒದಗಿಸುವವರಿಗೆ ಬಹುಮೋಡಲ್ ಪೇಲೋಡ್‌ಗಳನ್ನು ಪಾರದರ್ಶಕವಾಗಿ ನಿರ್ವಹಿಸಲು ಅನುಮತಿಸುತ್ತದೆ.

ಹರಿವು:

1. ಗುರಿ ಮಾದರಿ ಈಗಾಗಲೇ ದೃಷ್ಟಿಯನ್ನು ಬೆಂಬಲಿಸುತ್ತಿದ್ದರೆ (ಬಲವಾಗಿ-ಬ್ರಿಡ್ಜ್ ಪಟ್ಟಿಯಲ್ಲಿ `isVisionBridgeForcedModel` ಕಾಣಿಸುವುದಿಲ್ಲ) ಬಿಟ್ಟು ಹೋಗಿ.
2. `extractImageParts(messages)` ಮೂಲಕ ಚಿತ್ರ ಭಾಗಗಳನ್ನು ತೆಗೆದುಹಾಕಿ (`visionBridgeHelpers.ts`), ಇದು **ಊಟದ ಮಾಧ್ಯಮ ಪತ್ತೆಗಾರ** `detectMediaParts()` ಗೆ ನಿಯೋಜಿಸುತ್ತದೆ `open-sse/utils/mediaParts.ts` — ಕಾಂಬೋ ಹೊಂದಾಣಿಕೆ ಫಿಲ್ಟರ್‌ೊಂದಿಗೆ ಹಂಚಿಕೊಳ್ಳುವ ಏಕೀಕೃತ ಮೂಲ ಸತ್ಯ. ತೆಗೆದುಹಾಕುವುದು `replaceImageParts` ಪುನಃ ಸೇರಿಸಲು ಸಾಧ್ಯವಾಗುವ ಶ್ರೇಣಿಯ ಮೇಲ್ಮಟ್ಟದ ಭಾಗಗಳಿಗೆ ಅನುಮತಿಸಲಾಗಿದೆ (ತೆಗೆಯುವುದು↔ಬದಲಾಯಿಸುವುದು ಒಪ್ಪಂದ): OpenAI `image_url`, Anthropic base64 `source.type:"base64"`, Anthropic URL `source.type:"url"`, ಮತ್ತು Responses API `input_image`. ನೆಟ್ಟಗೆ ಹಿಟ್‌ಗಳು ಮತ್ತು ಸೂಚಕ-ಮಾತ್ರದ ಶ್ರೇಣಿಗಳು ಕಾಂಬೋ-ಫಿಲ್ಟರ್ ವಸ್ತು ಮತ್ತು ಎಂದಿಗೂ ತೆಗೆದುಹಾಕಲಾಗುವುದಿಲ್ಲ. ಯಾವುದೂ ಕಂಡುಬಂದಿಲ್ಲದಿದ್ದರೆ ಬಿಟ್ಟು ಹೋಗಿ.
3. `resolveVisionBridgeRuntimeSettings()` ಮೂಲಕ ಕಾರ್ಯಾಚರಣೆ ಕಾನ್ಫಿಗ್ ಅನ್ನು ಪರಿಹರಿಸಿ (`src/shared/constants/modalityBridgeDefaults.ts`): ಹೊಸ `modalityBridge*` ಸೆಟಿಂಗ್ ಕೀಗಳು ಗೆಲ್ಲುತ್ತವೆ; ಪುರಾತನ `visionBridge*` ಕೀಗಳು **ಒಂದು-ಚಕ್ರದ ಹಿಂತಿರುಗುವಿಕೆ** (ಹಿಂತಿರುಗುವ ಕಿಟಕಿ). ಬ್ರಿಡ್ಜ್ ಅಸಕ್ರಿಯವಾಗಿರುವಾಗ ಯಾವುದೇ ಮಾಧ್ಯಮ ಪಥದ ಮುನ್ನ ಬಿಟ್ಟು ಹೋಗಿ.
4. ಮೋಡ್ ಆಯ್ಕೆಯು (`modalityBridgeVisionMode`, ಕೆಳಗಿನ ಪಟ್ಟಿಯನ್ನು ನೋಡಿ) ಪುನರ್‌ರೇಖೆ ವಿರುದ್ಧ ವಿವರಣೆ ನಿರ್ಧಾರ ಮಾಡುತ್ತದೆ. ಪುನರ್‌ರೇಖೆ `modifiedPayload` ಅನ್ನು ಮಾತ್ರ `model` ಬದಲಾಯಿತಾದಂತೆ, ಜೊತೆಗೆ ಮೆಟಾ `{ rerouted, fromModel, toModel, imagesKept }` ಅನ್ನು ಹಿಂತಿರುಗಿಸುತ್ತದೆ.
5. ವಿವರಣೆ ಮಾರ್ಗ: `maxImages` ನಲ್ಲಿ ಚಿತ್ರಗಳನ್ನು ಮಿತಿಗೊಳಿಸಿ, ಕಾರ್ಯ-ಜ್ಞಾನ ಪಠ್ಯವನ್ನು ರೂಪಿಸಿ, ವಿವರಣೆ ಕಾಶ್ ಅನ್ನು ಪರಿಗಣಿಸಿ, ದೃಷ್ಟಿ ಮಾದರಿಯನ್ನು **ಸಮಾನಾಂತರದಲ್ಲಿ** ಕರೆ ಮಾಡಿ (`Promise.allSettled`), ಮತ್ತು `[Image N]: <description>` ಪಠ್ಯ ಭಾಗಗಳನ್ನು ಅವರ ಸ್ಥಳದಲ್ಲಿ ಸೇರಿಸಿ. ವಿಫಲವಾದ ವಿವರಣೆ `null` ಅನ್ನು ನೀಡುತ್ತದೆ ಮತ್ತು ಮೂಲ ಚಿತ್ರ ಭಾಗವು **ಕಾಪಾಡಲಾಗುತ್ತದೆ** (#4012) — ಪ್ರತಿಯೊಂದು ವಿವರಣೆ ವಿಫಲವಾದಾಗ ಕಾಂಬೋ ವಿವರಣೆ ಮಾರ್ಗದಲ್ಲಿ ಹೊರತುಪಡಿಸಿ, ದೃಷ್ಟಿ-ಸಾಧ್ಯ ಒದಗಿಸುವಿಕೆಯನ್ನು ಸಂಪರ್ಕಿಸಿದಾಗ `(unavailable — no vision-capable provider connected)` ಸ್ಟಬ್ ಅನ್ನು ಪಡೆಯುತ್ತದೆ (#8430).
6. `modifiedPayload` + ಮೆಟಾ (`imagesProcessed`, `descriptions`, `processingTimeMs`, `visionModel`) ಅನ್ನು ಹಿಂತಿರುಗಿಸಿ.

#### ಮೋಡ್ ಆಯ್ಕೆಯು (`modalityBridgeVisionMode`)

| ಮೋಡ್       | ಡೀಫಾಲ್ಟ್ | ವರ್ತನೆ                                                                                                                                                                                                                                                                               |
| ---------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `auto`     | ✔        | ಪುರಾತನ ಹ್ಯೂರಿಸ್ಟಿಕ್, ಅಚಲ (#6640/#7204): ನಾನ್-ಕಾಂಬೋ/`auto/` ಮಾದರಿಗಳು ಉತ್ತಮ ದೃಷ್ಟಿ ಮಾದರಿಯ ಕಡೆಗೆ ಪುನರ್‌ರೇಖೆಗೊಳ್ಳುತ್ತವೆ, ಮೂಲ ಮಾದರಿಯು ಬಳಸಬಹುದಾದ ಪ್ರಮಾಣಪತ್ರಗಳನ್ನು ಹೊಂದಿದ್ದರೆ (ಆಗ ವಿವರಣೆ); ಕಾಂಬೋ ಗುರಿಗಳು ಯಾವಾಗಲೂ ವಿವರಣೆ ಮಾಡುತ್ತವೆ.                                                          |
| `describe` |          | ಯಾವಾಗಲೂ ವಿವರಣೆ — ಪುನರ್‌ರೇಖೆ ಬ್ಲಾಕ್ ಸಂಪೂರ್ಣವಾಗಿ ಬಿಟ್ಟು ಹೋಗುತ್ತದೆ; ಬಳಕೆದಾರನ ಆಯ್ಕೆಯಾದ ಮಾದರಿ ಯಾವಾಗಲೂ ಉತ್ತರಿಸುತ್ತದೆ.                                                                                                                                                                      |
| `reroute`  |          | ಬಲವಾಗಿ ಪುನರ್‌ರೇಖೆ: ಕೀಪ್-ಕ್ರೆಡೆನ್ಷಿಯಲ್-ಮಾಡೆಲ್ ಗಾರ್ಡ್ ಅನ್ನು ಬದ್ಧಪಡಿಸಲಾಗಿದೆ. ಪುನರ್‌ರೇಖೆ-**ಗುರಿ** ಕ್ರೆಡೆನ್ಷಿಯಲ್ ಗಾರ್ಡ್ ಇನ್ನೂ ಅನ್ವಯಿಸುತ್ತದೆ — ಬಳಸಬಹುದಾದ ದೃಷ್ಟಿ ಗುರಿ ಇಲ್ಲದಾಗ, ವಿನಂತಿ ವಿವರಣೆಗೆ ಬಿದ್ದುಹೋಗುತ್ತದೆ, ಆದ್ದರಿಂದ ಕಚ್ಚಾ ಚಿತ್ರಗಳು ಪಠ್ಯ-ಮಾತ್ರದ ಬೆನ್ನುಹತ್ತುವಿಕೆಗೆ ತಲುಪುವುದಿಲ್ಲ (#8430). |

ಬಲವಾದ ಮೋಡ್‌ಗಳು **ಆಟೋ ಹ್ಯೂರಿಸ್ಟಿಕ್ ಕಾರ್ಯನಿರ್ವಹಿಸುವ ಮೊದಲು** ಶಾರ್ಟ್-ಸರ್ಕ್ಯೂಟ್ ಮಾಡುತ್ತವೆ; `auto` ವರ್ತನೆ pre-PR-1 ಗಾರ್ಡ್‌ರೈಲ್‌ಗಳಿಗೆ ಬೈಟ್-ಒಪ್ಪಂದವಾಗಿದೆ.

#### API-ಕೀ ವ್ಯಾಪ್ತಿ (`visionBridgeKeyScope.ts`)

ಕೋಲರ್‌ನ API ಕೀ `allowedConnections`, ಕ್ವೋಟಾ ಪೂಲ್‌ಗಳನ್ನು (`allowedQuotas`) ಅಥವಾ ಮಾದರಿಗಳನ್ನು (`allowedModels` / `blockedModels` / `modelAccessMode: "restricted"` / `disableNonPublicModels`) ನಿರ್ಬಂಧಿಸಿದಾಗ, ಬ್ರಿಡ್ಜ್ ಕೀ ಬಳಸಬಹುದಾದ ಪುನರ್‌ರೇಖೆ ಮತ್ತು ವಿವರಣೆ ಮಾದರಿಗಳನ್ನು ಮಾತ್ರ ಆಯ್ಕೆ ಮಾಡುತ್ತದೆ, ಕೀ ಬಳಸಬಹುದಾದ ಸಂಪರ್ಕಗಳಲ್ಲಿ. ನಂತರ ವಿವರಣೆ ಕರೆ ಯಾವಾಗಲೂ `x-omniroute-self-loop-key-id` ಹೆಡರ್‌ನೊಂದಿಗೆ ಓಮ್ನಿರೌಟ್ ಸ್ವಯಂ-ಚಕ್ರದ ಮೂಲಕ ಹೋಗುತ್ತದೆ, ಆದ್ದರಿಂದ ಸ್ವೀಕರಿಸುವ ಚಾಟ್ ವಿನಂತಿಯು ಆ ಕೀದಿನ ಸಂಪರ್ಕ ಮತ್ತು ಮಾದರಿ ನೀತಿಯನ್ನು ಮತ್ತೆ ಬಲಪಡಿಸುತ್ತದೆ. `enforceApiKeyPolicy()` ಆ ಹೆಡರ್ ಅನ್ನು ಸ್ವಯಂ-ಚಕ್ರದ ಬೆರರ್‌ನೊಂದಿಗೆ ಮಾತ್ರ ಗೌರವಿಸುತ್ತದೆ, ಆದ್ದರಿಂದ ಇದು ಪ್ರವೇಶವನ್ನು ಕೀಳ್ಮಟ್ಟಗೊಳಿಸಲು ಮಾತ್ರ ಸಾಧ್ಯ, ಮತ್ತು ಪರಿಹರಿಸುವುದಿಲ್ಲದ ಐಡಿ ನಿರಾಕರಿಸಲಾಗುತ್ತದೆ.

ಕೀಗಾಗಿ ಯಾವುದೇ ದೃಷ್ಟಿ ಮಾದರಿ ಅನುಮತಿಸಲಾಗದಿದ್ದರೆ, ವಿವರಣೆ ಮಾರ್ಗವು ಬದ್ಧವಾಗುತ್ತದೆ ಮತ್ತು ವಿನಂತಿ ಬದಲಾಯಿಸಲಾಗದೆ ಹಾರುತ್ತದೆ, ಅಸಾಧಾರಣ ಗಾರ್ಡ್‌ರೈಲ್‌ನಂತೆ ಅದೇ ವಿಫಲ-ಓಪನ್ ವರ್ತನೆ (ಮೆಟಾ `{ skipped: true, reason: "no_permitted_vision_model" }`). ಕೀ ಇಲ್ಲದ ವಿನಂತಿಗಳು ಮತ್ತು ಈ ನಿರ್ಬಂಧಗಳಿಲ್ಲದ ಕೀಗಳು ಹಿಂದಿನಂತೆ ಮಾತ್ರ ವರ್ತಿಸುತ್ತವೆ.

#### ಕಾರ್ಯ-ಜ್ಞಾನ ವಿವರಣೆ ಪಠ್ಯ (`modalityBridgeVisionTaskAware`)

ಡೀಫಾಲ್ಟ್ **ಸತ್ಯ**. `composeVisionPrompt()` (`visionBridgeHelpers.ts`) ಕೊನೆಯ ಬಳಕೆದಾರ ಸಂದೇಶದ (500 ಅಕ್ಷರಗಳಿಗೆ ಕಡಿತಗೊಳಿಸಲಾಗಿದೆ) ಪಠ್ಯವನ್ನು ಮೂಲ ವಿವರಣೆ ಪ್ರಾಂಪ್ಟ್‌ಗೆ ಸೇರಿಸುತ್ತದೆ, ಬಳಕೆದಾರನು ವಾಸ್ತವವಾಗಿ ಕೇಳಿದುದಕ್ಕೆ ವಿವರಣೆಯನ್ನು ತಿರುಗಿಸುತ್ತದೆ (codex-vision-proxy ಮಾದರಿ) ಮತ್ತು ದೃಶ್ಯ ಮಾದರಿಯನ್ನು ದೃಶ್ಯಮಾನವಾದ ಪಠ್ಯವನ್ನು ವರ್ಗಾಯಿಸಲು ಕೇಳುತ್ತದೆ. ಧ್ವಜವನ್ನು ಆಫ್ ಮಾಡಿದಾಗ — ಅಥವಾ ಯಾವುದೇ ಬಳಕೆದಾರ ಪಠ್ಯವಿಲ್ಲ — ಮೂಲ ಪ್ರಾಂಪ್ಟ್ ಬದಲಾಯಿಸಲಾಗದೆ ಬಳಸಲಾಗುತ್ತದೆ.

ವಿವರಣೆ ಸ್ವಯಂ-ಚಕ್ರದ ತನ್ನ OpenAI-ಅನುಕೂಲವಾದ ವಿನಂತಿ (`callVisionModelSingle()` `visionBridgeHelpers.ts` ನಲ್ಲಿ) ಯಾವಾಗಲೂ `image_url.detail: "high"` ಅನ್ನು ಕೇಳುತ್ತದೆ — ಯಾವುದೇ ಗ್ರಾಹಕ ಸಂಕೇತದ ಮೇಲೆ ನಿರ್ಬಂಧವಿಲ್ಲದೆ, ಪ್ರತಿಯೊಬ್ಬ ಕರೆಗಾರ/ಪ್ರದಾತನಿಗಾಗಿ. ಕಡಿಮೆ-ವಿವರ ಮಾದರಿಯು OCR ಶುದ್ಧತೆಯನ್ನು ಹಾಳು ಮಾಡುತ್ತದೆ, ಈ ಪ್ರಾಂಪ್ಟ್ ಕೇಳುವ ಪಠ್ಯ-ವರ್ಗಾಯನ ಕಾರ್ಯಕ್ಕಾಗಿ, ಆದ್ದರಿಂದ ವಿವರಣೆ ಕರೆ ಸ್ವಯಂ-ಚಕ್ರವು ಮೂಲ ಪ್ರವೇಶ ವಿನಂತಿಯು ಬಳಸಿದ ವಿವರ ಮಟ್ಟವನ್ನು ಪರಿಗಣಿಸದೆ ಯಾವಾಗಲೂ ಹೆಚ್ಚಿನ ವಿವರವನ್ನು ಕೇಳುತ್ತದೆ. ಇದು ಒಳಗಿನ ವಿವರಣೆ ವಿನಂತಿಯ ಶರೀರವನ್ನು ಮಾತ್ರ ಪರಿಣಾಮ ಬೀರುತ್ತದೆ; ಇದು OmniRoute ಕರೆಗಾರನ ತಮ್ಮ `image_url.detail` ಅನ್ನು ಪ್ರಾಥಮಿಕ ವಿನಂತಿಯಲ್ಲಿ ಹೇಗೆ ಮುಂದುವರಿಸುತ್ತದೆ ಎಂಬುದನ್ನು ಬದಲಾಯಿಸುವುದಿಲ್ಲ — ಆ ಡೀಫಾಲ್ಟ್ ಪ್ರತ್ಯೇಕವಾಗಿ ಅನ್ವಯಿಸಲಾಗುತ್ತದೆ, ಮತ್ತು ಕೇವಲ ಪತ್ತೆಹಚ್ಚಿದ OpenCode ಗ್ರಾಹಕರಿಗಾಗಿ, `defaultImageDetail()` (`open-sse/handlers/chatCore/upstreamBody.ts` ನಲ್ಲಿ). ವಿವರಣೆ ಸ್ವಯಂ-ಚಕ್ರದ Anthropic ವೈರ್-ಫಾರ್ಮಾಟ್ ಶಾಖೆಗೆ ಯಾವುದೇ `detail` ಕ್ಷೇತ್ರವಿಲ್ಲ ಮತ್ತು ಎರಡೂ ಡೀಫಾಲ್ಟ್‌ಗಳಿಂದ ಪ್ರಭಾವಿತವಾಗುವುದಿಲ್ಲ.

#### ವಿವರಣೆ ಔಟ್‌ಪುಟ್ ಕ್ಯಾಪ್ (`modalityBridgeVisionMaxChars`)

| ಕೀ                             | ಡೀಫಾಲ್ಟ್ | ಶ್ರೇಣಿಯು           |
| ------------------------------ | -------- | ------------------ |
| `modalityBridgeVisionMaxChars` | `0`      | `0` ಅಥವಾ 100–50000 |

`0` (ಡೀಫಾಲ್ಟ್) ಅಂದರೆ **ಯಾವುದೇ ಕ್ಯಾಪ್ ಇಲ್ಲ** — `callVisionModel()` ಮೂಲಕ ಹಿಂತಿರುಗಿಸಿದ ವಿವರಣೆ ಬದಲಾಯಿಸಲಾಗದೆ ಹಾರುತ್ತದೆ, ಹಳೆಯ ವರ್ತನೆಯನ್ನು ಉಳಿಸುತ್ತದೆ. 100–50000 ಶ್ರೇಣಿಯಲ್ಲಿನ ಯಾವುದೇ ಮೌಲ್ಯವು ವಿವರಣೆಯನ್ನು `…` ಉಪಸರ್ಗದೊಂದಿಗೆ ಕಡಿತಗೊಳಿಸುತ್ತದೆ, ನಂತರ `[Image N]: <description>` ಎಂದು ಪುನಃ ಸೇರಿಸಲಾಗುತ್ತದೆ (`VisionBridgeGuardrail.preCall()` `src/lib/guardrails/visionBridge.ts` ನಲ್ಲಿ). ಈ ವಿವರ-ಭಾರಿತ OCR ಕಾರ್ಯಗಳಿಗೆ ಹೆಚ್ಚಿಸಲು, ಅಲ್ಲಿ ಹಿಂತಿರುಗುವ ಮಾದರಿಯು ಸಂಪೂರ್ಣ ವರ್ಗಾಯನವನ್ನು ಅಗತ್ಯವಿದೆ; ಚಾಟ್ ಮಾಡುವ ದೃಶ್ಯ ಮಾದರಿಗಳಲ್ಲಿ ಟೋಕನ್ ಬಳಕೆಯನ್ನು ನಿರ್ಬಂಧಿಸಲು ಕಡಿಮೆ ಮಾಡಿ. ಡ್ಯಾಶ್‌ಬೋರ್ಡ್ ಕ್ಷೇತ್ರವು Vision ಟ್ಯಾಬ್‌ನ ಉನ್ನತ ಪ್ಯಾನಲ್‌ನಲ್ಲಿ ಇದೆ (`modality-bridge-max-chars` `ModalityBridgeVisionTab.tsx` ನಲ್ಲಿ) ಮತ್ತು 1 ಮತ್ತು 99 ನಡುವಿನ ಯಾವುದೇ ಮೌಲ್ಯವನ್ನು 100 ನೆಲಕ್ಕೆ ತಲುಪಿಸುತ್ತದೆ, ಆದರೆ ಸ್ಪಷ್ಟ `0` ಅನ್ನು ಅಸ್ಪಷ್ಟವಾಗಿಡುತ್ತದೆ — `0` ತನ್ನದೇ ಆದ ಮಾನ್ಯ Zod ಮೌಲ್ಯವಾಗಿದೆ (`z.union([z.literal(0), z.number().int().min(100).max(50000)])`), ಕೇವಲ "ಸೆಟ್ನಿಲ್ಲದ" ಡೀಫಾಲ್ಟ್ ಅಲ್ಲ.

#### ವಿವರಣೆ ಕ್ಯಾಶೆ (`modalityBridge/bridgeCache.ts`)

ವಿವರಣೆ ಔಟ್‌ಪುಟ್‌ಗಳಿಗೆ ಮೆಮೊರಿ LRU + TTL ಕ್ಯಾಶೆ, ಹಂಚಿದ ಪ್ರಕ್ರಿಯೆ-ವಿಸ್ತಾರ. ಕೀ = `sha256(imageRef + composedPrompt + configuredBridgeModel)` ಉದ್ದ-ಪೂರ್ವಕ ಫ್ರೇಮಿಂಗ್ (ಯಾವುದೇ ಕ್ಷೇತ್ರ-ಸೀಮಿತ ಸಂಘರ್ಷಗಳಿಲ್ಲ). ಮಾದರಿ ಘಟಕವು **ಕೋನ್ಫಿಗರ್ ಮಾಡಿದ** ಬ್ರಿಡ್ಜ್ ಮಾದರಿಯಾಗಿದೆ, ವಾಸ್ತವವಾಗಿ ಉತ್ತರಿಸಿದ ಮಾದರಿ ಅಲ್ಲ — `callVisionModel` ಆಂತರಿಕವಾಗಿ ಹಿಂತಿರುಗಬಹುದು, ಮತ್ತು ಪ್ರಯತ್ನ ಪ್ರತಿ ಕೀ ಹಾಕುವುದು ಕ್ಯಾಶೆ ಅನ್ನು ತುಂಡು ಮಾಡುತ್ತದೆ. ವಿಫಲವಾದ ವಿವರಣೆಗಳನ್ನು ಎಂದಿಗೂ ಕ್ಯಾಶೆ ಮಾಡಲಾಗುವುದಿಲ್ಲ. ಸೆಟ್ಟಿಂಗ್‌ಗಳು:

| ಕೀ                              | ಡೀಫಾಲ್ಟ್ | ಶ್ರೇಣಿಯು |
| ------------------------------- | -------- | -------- |
| `modalityBridgeCacheEnabled`    | `true`   | —        |
| `modalityBridgeCacheTtlMinutes` | `60`     | 1–1440   |
| `modalityBridgeCacheMaxEntries` | `200`    | 10–5000  |

#### ದೂರದ ಚಿತ್ರ ಸಾಮಾನ್ಯೀಕರಣ (ಸ್ವಯಂ-ಚಕ್ರ ವಿವರಣೆ/base64 ಪಡೆಯುವುದು)

ಬ್ರಿಡ್ಜ್ **ದೂರದ** ಚಿತ್ರವನ್ನು ಸ್ವಯಂ-ಕೋಲಾಹಲವಾಗಿ ಪಡೆಯುವಾಗ — Anthropic ವಿವರಣೆ ಸ್ವಯಂ-ಕೋಲಾಹಲ ಮತ್ತು ಕ್ಲೋಡ್-ವೈರ್-ಫಾರ್ಮಾಟ್ base64 ಪರಿವರ್ತನೆ (`ensureBase64ImagesForClaudeWire`), ಎರಡೂ `fetchRemoteImageAsDataUri()` ಮೂಲಕ `visionBridgeHelpers.ts` ನಲ್ಲಿ — ಫಲಿತಾಂಶ ಡೇಟಾ URI ಅನ್ನು `normalizeDataUri()` ಮೂಲಕ ಹಾರುತ್ತದೆ (`open-sse/utils/imageNormalize.ts`) ದೃಶ್ಯ-ಮಾದರಿ ವಿನಂತಿಯಲ್ಲಿ ಅಳವಡಿಸುವ ಮೊದಲು. ಅತಿದೊಡ್ಡ ಚಿತ್ರಗಳನ್ನು **2048px ಉದ್ದದ ಅಂಚಿಗೆ** ಕಡಿತಗೊಳಿಸಲಾಗುತ್ತದೆ (OpenAI/Anthropic ಈಗಾಗಲೇ ಸರ್ವರ್-ಪಕ್ಷದಲ್ಲಿ ಅನ್ವಯಿಸುತ್ತಿರುವ ಪುನರ್-ಗಾತ್ರದ ಕ್ಯಾಪ್ ಅನ್ನು ಹೊಂದಿಸುತ್ತದೆ), ಇದು ಅಪ್ಲೋಡ್ ಬೈಟ್ಸ್/ವಿಲಂಬವನ್ನು ಕಡಿಮೆ ಮಾಡುತ್ತದೆ, ಆದರೆ ದೃಶ್ಯ ಮಾದರಿ ಏನನ್ನು ನೋಡುತ್ತದೆ ಎಂಬುದನ್ನು ಬದಲಾಯಿಸುವುದಿಲ್ಲ. ಪುನರ್-ಗಾತ್ರವು `sharp` ಅನ್ನು ಬಳಸುತ್ತದೆ, ಡೈನಾಮಿಕ್ ಇಂಪೋರ್ಟ್ ಮೂಲಕ ಲೋಡ್ ಮಾಡಲಾಗಿದೆ: ಅದರ ಸ್ವದೇಶಿ ಬೈನರಿ ಲೋಡ್ ಮಾಡಲು ವಿಫಲವಾದ ವೇದಿಕೆಯ ಮೇಲೆ, `normalizeDataUri()` **ಊರೆಯುವುದಿಲ್ಲ** — ಇದು ಮೂಲ ಬೈಟ್ಸ್‌ನ್ನು ಪಾಸ್‌ಥ್ರೂಗೆ ಹಿಂತಿರುಗುತ್ತದೆ, ಆದ್ದರಿಂದ ವಿವರಣೆ/base64-ಪರಿವರ್ತನೆ ಮಾರ್ಗವು ಯಾವಾಗಲೂ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತದೆ. ಚಿತ್ರವಲ್ಲದ ಬೈಟ್ಸ್ (ಅನುವಾದಿಸಲು ಸಾಧ್ಯವಾದ ಚಿತ್ರವನ್ನು ಹಿಂತಿರುಗಿಸದ ಪಡೆಯುವುದು) ಕೂಡ ಬದಲಾಯಿಸಲಾಗದೆ ಪಾಸ್‌ಥ್ರೂಗೆ ಹಿಂತಿರುಗುತ್ತವೆ. ಈ ಸಾಮಾನ್ಯೀಕರಣವು ಬ್ರಿಡ್ಜ್ ತನ್ನ ಸ್ವಯಂ-ಕೋಲಾಹಲಕ್ಕಾಗಿ ಪಡೆಯುವ ಚಿತ್ರಗಳಿಗೆ ಮಾತ್ರ ವ್ಯಾಪ್ತಿಯಲ್ಲಿದೆ — ಇದು ಕರೆಗಾರನ ಕಚ್ಚಾ ಪಾಸ್‌ಥ್ರೂ ಪೇಲೋಡ್‌ಗೆ ಅನ್ವಯಿಸಲಾಗುವುದಿಲ್ಲ, ಆಯ್ಕೆ-ಮಾತ್ರ ಪರಿವರ್ತನೆಯ ತತ್ವವನ್ನು ಅನುಸರಿಸುತ್ತದೆ (ಹಾರ್ಡ್ ನಿಯಮ #20).

#### ಸೆಟ್ಟಿಂಗ್‌ಗಳ ಶ್ರೇಣೀಬದ್ಧತೆ + ವಲಯಾಂತರ

ಹೊಸ `modalityBridge*` ಕೀಗಳನ್ನು `updateSettingsSchema` ನಲ್ಲಿ Zod-ಮಾನ್ಯಗೊಳಿಸಲಾಗಿದೆ (`src/shared/validation/settingsSchemas.ts`): `modalityBridgeVisionEnabled`, `modalityBridgeVisionMode`, `modalityBridgeVisionModel`, `modalityBridgeVisionTaskAware`, `modalityBridgeVisionPrompt`, `modalityBridgeVisionTimeout`, `modalityBridgeVisionMaxImages`, `modalityBridgeVisionMaxChars`, `modalityBridgeCache*` ತ್ರಿಕೋನ ಮತ್ತು `modalityBridgeAudio*` ಗುಂಪು Audio Bridge ಮೂಲಕ ಬಳಸಲಾಗುತ್ತದೆ. ವಲಯಾಂತರ `141_modality_bridge_settings.sql` ಹಳೆಯ `visionBridge*` ಮೌಲ್ಯಗಳನ್ನು ಹೊಂದಿರುವ ಹೊಸ ಕೀಗಳಿಗೆ ನಕಲಿಸುತ್ತದೆ (ಐಡೆಂಪೊಟೆಂಟ್, ಎಂದಿಗೂ ಕಾರ್ಯನಿರ್ವಹಿಸುವ `modalityBridge*` ಮೌಲ್ಯವನ್ನು ಮೀರಿಸುವುದಿಲ್ಲ); ಹಳೆಯ ಕೀಗಳನ್ನು ಓದುವ ಹಿಂತಿರುಗುವಿಕೆಗಾಗಿ ಒಬ್ಬ ಬಿಡುಗಡೆ ಚಕ್ರಕ್ಕಾಗಿ ಒಪ್ಪಿಗೆಯಾದಂತೆ ಉಳಿಯುತ್ತವೆ.

#### ಪಾರದರ್ಶಕತೆಯ ಹೆಡರ್ + ಅಂಕಿಅಂಕಿಗಳು

ವಿವರಣೆ-ಪರಿವರ್ತಿತ ಪ್ರತಿಸ್ಪಂದನೆಗಳು `x-omniroute-modality-bridge: image->text;model=<visionModel>;parts=<n>` ಅನ್ನು ಹೊಂದಿಸುತ್ತವೆ (ಇದು `modalityBridge/bridgeStats.ts` ನಲ್ಲಿ `buildModalityBridgeHeader()` ಮೂಲಕ ನಿರ್ಮಿಸಲಾಗಿದೆ, `src/sse/handlers/chatHelpers.ts` ನಲ್ಲಿ `withModalityBridgeHeader()` ಮೂಲಕ ಮುದ್ರಿತವಾಗಿದೆ). ಪುನರ್-ಮಾರ್ಗದ ವಿನಂತಿಗಳಿಗೆ **ಯಾವುದೇ** ಹೆಡರ್ ಇಲ್ಲ — ಪೇಲೋಡ್ ಬದಲಾಯಿಸಲಾಗಿಲ್ಲ ಮತ್ತು ಮಾದರಿ ಬದಲಾವಣೆ ಪ್ರತಿಸ್ಪಂದನೆಯ ಶರೀರದ `model` ಕ್ಷೇತ್ರದಲ್ಲಿ ಈಗಾಗಲೇ ದೃಶ್ಯಮಾನವಾಗಿದೆ.

`GET /api/modality-bridge/stats` (ನಿರ್ವಹಣಾ ಪ್ರಮಾಣೀಕರಣ, `GET /api/settings` ಗೆ ಸಮಾನ ಶ್ರೇಣಿಯ) `vision`, `audio`, ಮತ್ತು `video` ಗೆ ಸಂಬಂಧಿಸಿದ ಮೆಮೊರಿ‌ನಲ್ಲಿ ಪ್ರತಿ-ಮೋಡಾಲಿಟಿ ಕೌಂಟರ್‌ಗಳನ್ನು ಹಿಂತಿರುಗಿಸುತ್ತದೆ `{ attempts, successes, bridged, cacheHits, failures, totalLatencyMs, latencySamples, averageLatencyMs, lastUsedAt }`. `averageLatencyMs` ತನ್ನ ಹಂಚಿಕೆದಾರನಾಗಿ `latencySamples` ಅನ್ನು ಬಳಸುತ್ತದೆ, ಎಲ್ಲಾ ಪ್ರಯತ್ನಗಳನ್ನು ಅಲ್ಲ; ಸಮಯವಿಲ್ಲದ ಕಾರ್ಯವು ಶೂನ್ಯ-ಮಿಲಿಸೆಕೆಂಡು ಮಾದರಿಯನ್ನು ತಯಾರಿಸುವುದಿಲ್ಲ. ಯಶಸ್ವಿ ಪರಿವರ್ತನೆಗಳಿಗೆ `bridged` ಹಿಂದಿನ-ಸಂಗತವಾದ ಪರ್ಯಾಯವಾಗಿ ಉಳಿಯುತ್ತದೆ; ವಿಫಲ ಪ್ರಯತ್ನಗಳು ಇದನ್ನು ಹೆಚ್ಚಿಸುತ್ತಿಲ್ಲ. ಕೌಂಟರ್‌ಗಳನ್ನು ಪ್ರಕ್ರಿಯೆ ಪುನಾರಂಭದ ಮೇಲೆ ವಿನ್ಯಾಸದಂತೆ ಪುನಃ ಸೆಟಪ್ ಮಾಡಲಾಗುತ್ತದೆ (ಟೆಲೆಮೆಟ್ರಿ, ಲೆಕ್ಕಹಾಕುವುದು ಅಲ್ಲ).

#### ಡ್ಯಾಶ್‌ಬೋರ್ಡ್ ಕಾನ್ಫಿಗರೇಶನ್

ನಿರ್ದಿಷ್ಟ ಡ್ಯಾಶ್‌ಬೋರ್ಡ್ ಪುಟವು `/dashboard/settings/modality-bridge` ಆಗಿದೆ. ಇದರ URL-ವಿಳಾಸಿತ `Vision`, `Audio`, ಮತ್ತು `Video` ಟ್ಯಾಬ್‌ಗಳು `tab` ಮೌಲ್ಯವನ್ನು ಬದಲಾಯಿಸುವಾಗ ಕ್ವೇರಿ ಪ್ಯಾರಾಮೀಟರ್‌ಗಳನ್ನು ಉಳಿಸುತ್ತವೆ. Vision ಟ್ಯಾಬ್ ಸಕ್ರಿಯತೆ, ಮೋಡ್, ಮಾದರಿ ಆಯ್ಕೆ (ಸ್ವಾಯತ್ತ ಡೀಫಾಲ್ಟ್ ಅನ್ನು ಒಳಗೊಂಡಂತೆ), ಕಾರ್ಯ-ಜ್ಞಾನ ಪ್ರಾಂಪ್ಟಿಂಗ್, ಉನ್ನತ ಟೈಮ್‌ಔಟ್/ಚಿತ್ರ/ವಿವರಣೆ-ಅಗಲ/ಕ್ಯಾಶೆ ಮಿತಿಗಳು, ಕಾರ್ಯಾಚರಣೆ ಕೌಂಟರ್‌ಗಳು, ಮತ್ತು ರಕ್ಷಿತ ಮಾದರಿ ವಿನಂತಿಯನ್ನು ಬಹಿರಂಗಪಡಿಸುತ್ತದೆ. Audio ಟ್ಯಾಬ್ ಸಹ ಜೀವಂತವಾಗಿದೆ: ಇದು ಸಕ್ರಿಯತೆ, STT-ಮಾತ್ರ ಮಾದರಿ ಆಯ್ಕೆಯನ್ನು Auto, ಟೈಮ್‌ಔಟ್/ಗರಿಷ್ಠ-ಕ್ಲಿಪ್ ಮಿತಿಗಳು, ಆಡಿಯೋ ಕೌಂಟರ್‌ಗಳು, ಮತ್ತು `input_audio` ಮಾದರಿ ಪರೀಕ್ಷೆಯನ್ನು ಬಹಿರಂಗಪಡಿಸುತ್ತದೆ. Video ಟ್ಯಾಬ್ ಕಾರ್ಯಾತ್ಮಕವಾಗಿದೆ: ಇದು FFmpeg/ffprobe ಕಾರ್ಯಾಚರಣೆ ಸ್ಥಿತಿಯನ್ನು ವರದಿ ಮಾಡುತ್ತದೆ — ನಾಲ್ಕು ಸ್ಪಷ್ಟ UI ಸ್ಥಿತಿಗಳಲ್ಲಿ ಒಂದಾಗಿದೆ (`unknown` ಪ್ರೋಬ್ ಹಾರುವಾಗ ಅಥವಾ ಪೂರ್ಣಗೊಳ್ಳಲು ಸಾಧ್ಯವಾಗದಾಗ, `restricted` ಲೂಪ್‌ಬ್ಯಾಕ್ ಡ್ಯಾಶ್‌ಬೋರ್ಡ್ ಹೋಸ್ಟ್‌ನಲ್ಲಿ ಪ್ರೋಬ್ ಕ್ಲೈಂಟ್-ಪಕ್ಷದಲ್ಲಿ ಬಿಟ್ಟುಹೋಗುತ್ತದೆ, `unavailable` ಪ್ರೋಬ್ ಮಾಡಿದ ನಂತರ ಮತ್ತು ಖಚಿತವಾಗಿ ಕಳೆದುಹೋಗುತ್ತದೆ, ಅಥವಾ `available` FFmpeg/ffprobe ಆವೃತ್ತಿಗಳೊಂದಿಗೆ) — ಸಕ್ರಿಯ/ಮೋಡ್/ಫ್ರೇಮ್/ವಿಡಿಯೋ/ಟೈಮ್‌ಔಟ್ ಮಿತಿಗಳನ್ನು ಉಳಿಸುತ್ತದೆ, ಮಾದರಿ ಆಯ್ಕೆಯನ್ನು ದೃಷ್ಟಿ-ಸಾಧ್ಯ ಮಾದರಿಗಳಿಗೆ ಶೋಧಿಸುತ್ತದೆ, ಮತ್ತು ವಿಡಿಯೋ ಕೌಂಟರ್‌ಗಳನ್ನು ಬಹಿರಂಗಪಡಿಸುತ್ತದೆ.

AI ಸೆಟಿಂಗ್‌ಗಳ ಅಡಿಯಲ್ಲಿ ಹಳೆಯ Vision Bridge ಕಾರ್ಡ್ ಹೊಸ ಪುಟಕ್ಕೆ ಹೊಂದಾಣಿಕೆಯ ಲಿಂಕ್ ಆಗಿದೆ; ಇದು ಫಾರ್ಮ್‌ನ ಎರಡನೇ ನಕಲೆಯನ್ನು ಹೊಂದಿಲ್ಲ. ಮೀಡಿಯಾ ಪೂರಕಗಳು ಇಮೇಜ್-ಟು-ಟೆಕ್ಸ್ಟ್ ಮತ್ತು ಸ್ಪೀಚ್-ಟು-ಟೆಕ್ಸ್ಟ್ ಕಾರ್ಯವಿಧಾನಗಳನ್ನು ಸಂಬಂಧಿತ ಮೋಡಾಲಿಟಿ ಬ್ರಿಡ್ಜ್ ಟ್ಯಾಬ್‌ಗಳಿಗೆ ಲಿಂಕ್ ಮಾಡುತ್ತದೆ, ಹಳೆಯ ಸ್ಪೀಚ್-ಟು-ಟೆಕ್ಸ್ಟ್ ಆಟದ ಮೈದಾನವನ್ನು ತೆಗೆದು ಹಾಕದೆ.

**ಸೆಲ್ಫ್-ಲೂಪ್ ಪ್ರವೇಶ ಬಾಯ್‌ಪಾಸ್:** ವಿವರಣೆ ಕರೆ OmniRoute ನ ಸ್ವಂತ `/v1` ಸೆಲ್ಫ್-ಲೂಪ್ (ಅನಿಯಮಿತ ಪೂರಕ ಮಾದರಿ) ಮೂಲಕ ಮಾರ್ಗದರ್ಶನ ಮಾಡಿದಾಗ, ಉಪ-ವಿನಂತಿ `x-omniroute-admission-bypass: internal` ಅನ್ನು ಕಳುಹಿಸುತ್ತದೆ ಮತ್ತು ಪರಿಹರಿಸಲಾದ ಸೆಲ್ಫ್-ಲೂಪ್ ಪ್ರಮಾಣಪತ್ರದೊಂದಿಗೆ ಪ್ರಮಾಣೀಕೃತವಾಗುತ್ತದೆ — ಸ್ಥಳೀಯ `sk_omniroute` ಸ್ಥಳೀಯ ಮೋಡ್‌ನಲ್ಲಿ, ಅಥವಾ ಕಾರ್ಯನಿರ್ವಹಕ-ಕೋಷ್ಟಕ `OMNIROUTE_API_KEY` / `ROUTER_API_KEY` env ಕೀ (#1350) ಆದ್ದರಿಂದ `REQUIRE_API_KEY=true` ನಿಯೋಜನೆಗಳು ಇನ್ನೂ ವಿವರಣೆ ಕರೆ ನಡೆಸಬಹುದು. ಈ ಬಾಯ್‌ಪಾಸ್ ಮಾತ್ರ ಆ ನಿಖರ ಪ್ರಮಾಣಪತ್ರಗಳಿಗೆ ಗೌರವಿಸಲಾಗುತ್ತದೆ, ಆದ್ದರಿಂದ ಹೊರಗಿನ ಕ್ಲೈಂಟ್‌ಗಳು ಪ್ರವೇಶವನ್ನು ಬಿಟ್ಟುಹೋಗಲು ಹೆಡರ್ ಅನ್ನು ಬಳಸಲು ಸಾಧ್ಯವಿಲ್ಲ.

ಹಳೆಯ ಡೀಫಾಲ್ಟ್‌ಗಳು `src/shared/constants/visionBridgeDefaults.ts` ನಲ್ಲಿ ಇವೆ; ಹೊಸ ಮೋಡ್/ಕಾರ್ಯ-ಜ್ಞಾನ/ಕ್ಯಾಶೆ ಡೀಫಾಲ್ಟ್‌ಗಳು ಮತ್ತು ಸೆಟಿಂಗ್‌ಗಳ ಪರಿಹಾರಕಾರರು `src/shared/constants/modalityBridgeDefaults.ts` ನಲ್ಲಿ ಇವೆ. ಗಾರ್ಡ್‌ರೇಲ್ `deps` ನಿರ್ಮಾಪಕ ಆಯ್ಕೆಯನ್ನು ಬಹಿರಂಗಪಡಿಸುತ್ತದೆ, ಆದ್ದರಿಂದ ಪರೀಕ್ಷೆಗಳು ನಕಲಿ `getSettings` ಮತ್ತು `callVisionModel` ಕಾರ್ಯಗತಗೊಳಣೆಗಳನ್ನು ಸೇರಿಸಬಹುದು.

### ಆಡಿಯೋ ಬ್ರಿಡ್ಜ್ (`audioBridge.ts`) — ಮೋಡಾಲಿಟಿ ಬ್ರಿಡ್ಜ್ PR-3

ಆಡಿಯೋ ಹೊಂದಿರುವ ಚಾಟ್ ವಿನಂತಿಗಳನ್ನು ಗುರಿಯ ಕಡೆಗೆ ತಲುಪುವ ಮೊದಲು ಅಡ್ಡಗೋಚಿಸುತ್ತವೆ, ಅದು ಆಡಿಯೋ ಇನ್ಪುಟ್ ಅನ್ನು ಸ್ವೀಕರಿಸಲು ತಿಳಿದಿಲ್ಲ. ಇದು ಚಾಟ್ ವಿನಂತಿಯನ್ನು ಪುನರ್‌ಮಾರ್ಗದರ್ಶನ ಮಾಡುವುದಿಲ್ಲ: ಆಡಿಯೋ ಭಾಗಗಳನ್ನು ಇತ್ತೀಚಿನ OpenAI-ಅನುಕೂಲ multipart ಎಂಡ್ಪಾಯಿಂಟ್ ಮೂಲಕ ಲಿಖಿತಗೊಳಿಸಲಾಗುತ್ತದೆ ಮತ್ತು ಆಯ್ಕೆಯ ಚಾಟ್ ಮಾದರಿ ಪಠ್ಯ ಲಿಖಿತಗಳೊಂದಿಗೆ ಮುಂದುವರಿಯುತ್ತದೆ.

ಹರಿವು:

1. `getResolvedModelCapabilities()` ಮೂಲಕ `supportsAudio` ಅನ್ನು ಪರಿಹರಿಸಿ. ಸ್ಪಷ್ಟ ಪೂರಕ-ರಿಜಿಸ್ಟ್ರಿ ಮೆಟಾಡೇಟಾ ಗೆಲ್ಲುತ್ತದೆ, ನಂತರ ಸ್ಥಿರ ಮಾದರಿ ಮೆಟಾಡೇಟಾ, ನಂತರ ಸಿಂಕ್ ಮಾಡಿದ `modalities_input`. `audio` ಇಲ್ಲದ ಘೋಷಿತ ಇನ್ಪುಟ್ ಪಟ್ಟಿಯು `false` ಆಗಿದೆ; ಯಾವುದೇ ಸಾಮರ್ಥ್ಯದ ಸಾಕ್ಷ್ಯ `null` ಉಳಿಯುತ್ತದೆ. `false` ಮತ್ತು `null` ಎರಡೂ ಸಂರಕ್ಷಣಾತ್ಮಕ ಬ್ರಿಡ್ಜ್ ಅನ್ನು ಸಕ್ರಿಯಗೊಳಿಸುತ್ತವೆ, ಆದರೆ `true` ಇದನ್ನು ಬಾಯ್‌ಪಾಸ್ ಮಾಡುತ್ತದೆ.
2. `modalityBridgeAudio*` ಸೆಟಿಂಗ್‌ಗಳನ್ನು ಪರಿಹರಿಸಿ ಮತ್ತು ಹಂಚಬಹುದಾದ ಶ್ರೇಣಿಯ ಆಡಿಯೋ ಭಾಗಗಳನ್ನು ಪ್ರತಿಯೊಂದು ಸಂದೇಶದಿಂದ `detectMediaParts()` ಶೇರ್ ಡಿಟೆಕ್ಟರ್ ಮೂಲಕ ತೆಗೆದುಕೊಳ್ಳಿ. ಬೆಂಬಲಿತ ವೈರ್ ಶೇಪ್ಗಳು OpenAI `input_audio`, `audio_url`, ಮತ್ತು `source.media_type: "audio/*"` ಆಗಿವೆ. ಮಾರ್ಗದರ್ಶನಕ್ಕಾಗಿ ನೆಟ್ಟೆ ಆಡಿಯೋವನ್ನು ಗುರುತಿಸಲಾಗುತ್ತದೆ ಆದರೆ ಸ್ಪ್ಲೈಸ್ ಮಾರ್ಗದಿಂದ ತೆಗೆದು ಹಾಕಲಾಗುವುದಿಲ್ಲ. ಕೆಲಸವು `modalityBridgeAudioMaxClips` ಮೂಲಕ ಮಿತಿಯಲ್ಲಿದೆ; ನಂತರದ ಭಾಗಗಳು ಅಚಲವಾಗಿರುತ್ತವೆ.
3. ಕಾನ್ಫಿಗರ್ ಮಾಡಿದ `provider/model` ಅನ್ನು ಗೌರವಿಸಿ, ಅಥವಾ `selectAudioBridgeModel()` ಅನ್ನು `AUDIO_TRANSCRIPTION_PROVIDERS` ಅನ್ನು ಸ್ಥಿರ ಕ್ಯಾಟಲಾಗ್ ಕ್ರಮದಲ್ಲಿ ನಡೆಯಲು ಬಿಡಿ ಮತ್ತು ಬಳಸಬಹುದಾದ ಸಕ್ರಿಯ ಪೂರಕ ಪ್ರಮಾಣಪತ್ರವನ್ನು ಹೊಂದಿರುವ ಮೊದಲ ಮಾದರಿಯನ್ನು ಆಯ್ಕೆ ಮಾಡಿ.
4. `callAudioTranscription()` base64/data-URI ಆಡಿಯೋವನ್ನು multipart `file` ಗೆ ಪರಿವರ್ತಿಸುತ್ತದೆ, ಅಥವಾ ಸಾರ್ವಜನಿಕ-ಮಾತ್ರ ಹೊರಗಿನ ಗಾರ್ಡ್ ಮೂಲಕ DNS ಪಿನ್ನಿಂಗ್ ಮತ್ತು 25 MB ಮಿತಿಯೊಂದಿಗೆ ದೂರದ `audio_url` ಅನ್ನು ಡೌನ್‌ಲೋಡ್ ಮಾಡುತ್ತದೆ. ನಂತರ ಇದು ಫೈಲ್ ಮತ್ತು ಆಯ್ಕೆಯ ಮಾದರಿಯನ್ನು ಸ್ಥಳೀಯ `/v1/audio/transcriptions` ಸೆಲ್ಫ್-ಲೂಪ್ ಗೆ POST ಮಾಡುತ್ತದೆ, `resolveSelfLoopBearer()` ಮೂಲಕ ಪ್ರಮಾಣೀಕೃತವಾಗಿದೆ. ಇತ್ತೀಚಿನ ಲಿಖಿತ ಮಾರ್ಗವು ಸಾಮಾನ್ಯ ಪ್ರಮಾಣಪತ್ರ ಹುಡುಕಾಟ, ಶೀತಲ/ರೇಟ್-ಮಿತಿಯ ನಿರ್ವಹಣೆ, ಮತ್ತು ಪೂರಕ ವಿತರಣೆಯನ್ನು ನಿರ್ವಹಿಸುತ್ತದೆ.
5. ಯಶಸ್ವಿ ಕರೆಗಳು ತಮ್ಮ ಭಾಗಗಳನ್ನು `[Audio N]: <transcript>` ಮೂಲಕ ಬದಲಾಯಿಸುತ್ತವೆ. ಕರೆಗಳು `Promise.allSettled` ಮೂಲಕ ನಡೆಯುತ್ತವೆ: ವೈಯಕ್ತಿಕ ವಿಫಲತೆ ಮೂಲ ಆಡಿಯೋ ಭಾಗವನ್ನು ಉಳಿಸುತ್ತದೆ (#4012 ಒಪ್ಪಂದ). ಪ್ರತಿಯೊಂದು ಕರೆ ವಿಫಲವಾದರೆ ಮತ್ತು ಗುರಿಯು `supportsAudio === false` ಎಂದು ತೋರಿತಾದರೆ, ಭಾಗಗಳು `[Audio N]: (unavailable — no STT provider connected)` (#8430 ಒಪ್ಪಂದ) ಆಗುತ್ತವೆ. ಅಜ್ಞಾತ ಗುರಿಯು (`null`) ಎಲ್ಲಾ-ವಿಫಲ ಫಲಿತಾಂಶವು ಅಚಲವಾಗಿರುತ್ತದೆ. ಬಳಸಬಹುದಾದ STT ಪ್ರಮಾಣಪತ್ರವಿಲ್ಲದ ದೃಷ್ಟಿ-ಮಾತ್ರ ಗುರಿಯು ನೆಟ್ವರ್ಕ್ ಕರೆ ನೀಡದೆ ಅದೇ ಸ್ಪಷ್ಟ ಸ್ಟಬ್ ಅನ್ನು ಪಡೆಯುತ್ತದೆ.

ಯಶಸ್ವಿ ಲಿಖಿತಗಳು ಪ್ರಕ್ರಿಯೆ-ವಿಸ್ತಾರವಾದ ಮೋಡಾಲಿಟಿ ಬ್ರಿಡ್ಜ್ LRU/TTL ಕ್ಯಾಶ್ ಅನ್ನು ಬಳಸುತ್ತವೆ. ಕೀ ಆಡಿಯೋ ಉಲ್ಲೇಖ, ಸ್ಥಿರ `audio-transcription` ಕಾರ್ಯಚರಣೆ ಲೇಬಲ್, ಮತ್ತು ಆಯ್ಕೆಯ STT ಮಾದರಿಯನ್ನು ಸಂಯೋಜಿಸುತ್ತದೆ; ವಿಫಲತೆಗಳನ್ನು ಎಂದಿಗೂ ಕ್ಯಾಶ್ ಮಾಡಲಾಗುವುದಿಲ್ಲ. ಆಡಿಯೋ ಪ್ರಯತ್ನಗಳು ಹಂಚಿದ `bridged`, `cacheHits`, `failures`, ಮತ್ತು `lastUsedAt` ಕೌಂಟರ್‌ಗಳನ್ನು ನವೀಕರಿಸುತ್ತವೆ. ಪರಿವರ್ತಿತ ಪ್ರತಿಸ್ಪಂದನೆಗಳು `x-omniroute-modality-bridge: audio->text;model=<sttModel>;parts=<n>` ಅನ್ನು ಹೊಂದಿಸುತ್ತವೆ; ಅಚಲ ವಿನಂತಿಗಳು ಆಡಿಯೋ ಬ್ರಿಡ್ಜ್ ವಿಭಾಗವನ್ನು ಪಡೆಯುವುದಿಲ್ಲ.

ಕಾರ್ಯಾಚರಣೆ ಸೆಟಿಂಗ್‌ಗಳು DB-ಆಧಾರಿತ ಮತ್ತು Zod-ಮಾನ್ಯಿತವಾಗಿವೆ:

| ಕೀ                            | ಡೀಫಾಲ್ಟ್ | ಶ್ರೇಣೀಬದ್ಧತೆ     |
| ----------------------------- | -------- | ---------------- |
| `modalityBridgeAudioEnabled`  | `true`   | —                |
| `modalityBridgeAudioModel`    | `""`     | Auto ಅಥವಾ STT ID |
| `modalityBridgeAudioTimeout`  | `60000`  | 1000–300000      |
| `modalityBridgeAudioMaxClips` | `3`      | 1–10             |

ಹಂಚಿದ ಕ್ಯಾಶ್ ಅನ್ನು `modalityBridgeCacheEnabled`,
`modalityBridgeCacheTtlMinutes`, ಮತ್ತು `modalityBridgeCacheMaxEntries` ಮೂಲಕ ನಿಯಂತ್ರಿಸಲಾಗುತ್ತದೆ.

### ವೀಡಿಯೋ ಬ್ರಿಡ್ಜ್ (`videoBridge.ts`, `videoBridgePipeline.ts`)

ಗೋಚಿಯಲ್ಲಿನ ಗುರಿಯು ತಿಳಿದ ಸ್ಥಳೀಯ ವೀಡಿಯೋ ಬೆಂಬಲವಿಲ್ಲದ ಮೊದಲು ಚಾಟ್ ಸಂಪೂರ್ಣತೆ `messages` ಮತ್ತು ಪ್ರತಿಕ್ರಿಯೆಗಳ
API `input` ನಲ್ಲಿ ಶ್ರೇಣೀಬದ್ಧ ವೀಡಿಯೋ ಭಾಗಗಳನ್ನು ಅಡ್ಡಗೋಚಿಸುತ್ತವೆ.
ಮಟ್ಟದ ರೂಪಗಳು `input_video`, `video_url`, `video_source`, HTTPS URLs,
ಮತ್ತು `data:video/*;base64,...` ಡೇಟಾ URI ಗಳಾಗಿವೆ. ಪ್ಲೇನ್ ಫೈಲ್ ಹೆಸರುಗಳನ್ನು ಪಠ್ಯದಲ್ಲಿ ವೀಡಿಯೋ ಎಂದು ಪರಿಗಣಿಸಲಾಗುವುದಿಲ್ಲ.

`VideoBridgeGuardrail.preCall` (`videoBridge.ts`) ವಿನಂತಿ ಪಥವನ್ನು, ಸಾಮರ್ಥ್ಯ/ನೀತಿ ಪರಿಶೀಲನೆಯನ್ನು, ಪ್ರತಿ ವಿನಂತಿಯ ಒಟ್ಟುಗೂಡಿಸುವಿಕೆ, ಮತ್ತು ಪ್ರತಿಕ್ರಿಯೆ ಪೇಲೋಡ್ ಅನ್ನು ಹೊಂದಿದೆ.
ಪ್ರತಿ ವೀಡಿಯೋ ಕೆಲಸ — ಸಂಪಾದನೆ, ಸಂಪೂರ್ಣ-ಫಲಿತಾಂಶ ಕ್ಯಾಶ್, ಫ್ರೇಮ್ ಕ್ರಮವನ್ನು ವಿವರಿಸುವುದು (ಯಾವುದೇ ಕರೆ ಮಾಡಿದ ವ್ಯಕ್ತಿಯ ಘೋಷಿತ ಆಡಿಯೋ ಪಠ್ಯವನ್ನು ವಿಲೀನಗೊಳಿಸುತ್ತದೆ), ಮತ್ತು ಪ್ರತಿ ಪ್ರಯತ್ನದ ಮೆಟ್ರಿಕ್/ಬಂದ್/ಶುದ್ಧೀಕರಣ — `processVideoPart` ನಲ್ಲಿ ಮರೆಮಾಚಲಾಗಿದೆ
`videoBridgePipeline.ts` ನಲ್ಲಿ, `preCall` ನ ಲೂಪ್ನಲ್ಲಿ ಪ್ರತಿ ವೀಡಿಯೋ ಭಾಗಕ್ಕೆ ಒಮ್ಮೆ ಕರೆ ಮಾಡಲಾಗುತ್ತದೆ.
ಆ ಮೋಡ್ಯೂಲ್ ಸ್ಪಷ್ಟ ಪೋರ್ಟ್ ಗಡಿಗಳನ್ನು `VideoMediaBrokerPort` ಅನ್ನು
(ಬೈಟ್‌ಗಳನ್ನು ಪಡೆಯುವುದು ಮತ್ತು ಮಾದರಿಯ ಫ್ರೇಮ್‌ಗಳನ್ನು ತೆಗೆದುಹಾಕುವುದು), `VideoAudioTranscriptionPort`
(ಕರೆ ಮಾಡಿದ ವ್ಯಕ್ತಿಯ ಘೋಷಿತ ಆಡಿಯೋ ಪಠ್ಯವನ್ನು ಮಾದರಿಯ ಶೀರ್ಷಿಕೆಗಳೊಂದಿಗೆ ವಿಲೀನಗೊಳಿಸುವುದು), ಮತ್ತು
`VideoDrilldownPort` (ಹಳೆಯ ಕಚ್ಚಾ-ಸ್ಟೋರ್ ರೂಪ). ಉತ್ಪಾದನಾ STT ಮತ್ತು ಫ್ರೇಮ್ ನಿರ್ವಹಣೆ
`createVideoSttAdapter` ಮತ್ತು `createVideoDrilldownAdapter` ಮೂಲಕ ವಿವರಿಸುವ ಪೋರ್ಟ್ ಅನ್ನು ಸಿದ್ಧಪಡಿಸುತ್ತವೆ; ನಂತರದವು ಹಂಚಿದ ಓಪಾಕ್-ಹ್ಯಾಂಡಲ್ ಜೀವನಚರ್ಯೆಯನ್ನು ಬಳಸುತ್ತದೆ.

ಸಾರ್ವಜನಿಕ `/v1` ವಿನಂತಿ ಮಾರ್ಗವು ಎಂದಿಗೂ ಉಪಪ್ರಕ್ರಿಯೆಯನ್ನು ಆಮದು ಅಥವಾ ಕರೆ ಮಾಡುವುದಿಲ್ಲ. ದೂರದ ವೀಡಿಯೋಗಳನ್ನು 50 MiB ಗಡಿಯಲ್ಲಿ ಡೌನ್‌ಲೋಡ್ ಮಾಡಲಾಗುತ್ತದೆ; ಇನ್‌ಲೈನ್ ಬೇಸ್64 ವೀಡಿಯೋಗಳಿಗೆ
50 MiB ನ ಸಾರ್ವಜನಿಕ JSON ವಿನಂತಿ ಪ್ರವೇಶ ಮಿತಿಯ ಒಳಗೆ ಉಳಿಯಲು 36 MiB ಡಿಕೋಡ್ ಮಾಡಿದ ಪ್ರತಿ ವೀಡಿಯೋ ಗಡಿಯನ್ನು ಹೊಂದಿದೆ. ವೀಡಿಯೋಗಳ ಉದ್ದ ಮತ್ತು ಡಿಕೋಡ್-ಗಾತ್ರದ ಅಂದಾಜುಗಳನ್ನು ಹಂಚುವ ಮೊದಲು ಪರಿಶೀಲಿಸಲಾಗುತ್ತದೆ. ಪ್ರಾಥಮಿಕ ದೂರದ URL ಮತ್ತು ಪ್ರತಿಯೊಂದು ಪುನರ್ದಿಕ್ಕೆಗೆ HTTPS ಅಗತ್ಯವಿದೆ, ಈಗಾಗಲೇ ಇರುವ
ಸಾರ್ವಜನಿಕ-ಮಾತ್ರದ ಔಟ್‌ಬೌಂಡ್ ಗಾರ್ಡ್ ಅನ್ನು DNS ಪಿನ್ನಿಂಗ್ ಬಳಸುತ್ತದೆ. ನಂತರ ಬೈಟ್‌ಗಳು ಖಚಿತವಾದ ಆಂತರಿಕ
`POST /api/modality-bridge/video/extract` ಬ್ರೋಕರ್ ಗಡಿಯನ್ನು ದಾಟುತ್ತವೆ. ಆ ಮಾರ್ಗವು `LOCAL_ONLY` ಮತ್ತು `SPAWN_CAPABLE` ಎರಡೂ ಆಗಿದ್ದು, ಪ್ರತಿ-ಪ್ರಕ್ರಿಯೆಯ ಪ್ರಮಾಣಿತ,
ನಂಬಿಕೆ-ಲೂಬ್ಯಾಕ್ ವಿನಂತಿಯನ್ನು ಮಾತ್ರ ಒಪ್ಪಿಸುತ್ತದೆ, ಮತ್ತು URL, ಫೈಲ್‌ಸಿಸ್ಟಮ್ ಪಥ, ಕಾರ್ಯನಿರ್ವಹಣಾ, ಅಥವಾ ಆರ್ಗ್ಯುಮೆಂಟ್ ಪಟ್ಟಿಯನ್ನು ಎಂದಿಗೂ ಒಪ್ಪುವುದಿಲ್ಲ. API ಶರೀರ-ಗಾತ್ರ ಪೈಪ್‌ಲೈನ್ ಮತ್ತು ಹ್ಯಾಂಡ್ಲರ್‌ನ ಹಂತ ಹಂತದ ಶರೀರ
ಊರೆಯುವಿಕೆ ಸ್ವಾಯತ್ತವಾಗಿ 50 MiB ಬ್ರೋಕರ್ ಇನ್ಪುಟ್ ಗಡಿಯನ್ನು ಬಲಪಡಿಸುತ್ತವೆ. ಇದರ ಗಡಿತಾಲಿಕೆಯಲ್ಲಿ ಒಂದೇ ಸಮಯದಲ್ಲಿ ಒಂದು ನಿರ್ವಹಣೆ ನಡೆಯುತ್ತದೆ, ನಾಲ್ಕು ಬಾಕಿ ಕೆಲಸಗಳನ್ನು ಅನುಮತಿಸುತ್ತದೆ, ಮತ್ತು ಬಾಕಿ ಇನ್ಪುಟ್ ಅನ್ನು 100 MiB ಗೆ ಗಡಿಬಿಡಿಸುತ್ತದೆ.

ಬ್ರೋಕರ್ ಒಳಗೆ, `ffprobe` ಖಾಸಗಿ ಸ್ಥಳೀಯ ಫೈಲ್ ಅನ್ನು ಓದುತ್ತದೆ; ನಿರ್ಧಾರಿತ ರೂಪ
ಅನುವಾದ ಪಟ್ಟಿಯಿಂದ ಪ್ಲೇಲಿಸ್ಟ್ ಮತ್ತು ಮ್ಯಾನಿಫೆಸ್ಟ್ ರೂಪಗಳನ್ನು ಹೊರತುಪಡಿಸುತ್ತದೆ. ಅನುಮತಿತ MOV-ಕುಟುಂಬದ
ಕಂಟೈನರ್‌ಗಳಿಗೆ, ಹೊರಗಿನ MOV ಡೇಟಾ ಉಲ್ಲೇಖಗಳು ಡೀಫಾಲ್ಟ್‌ನಲ್ಲಿ ನಿಷ್ಕ್ರಿಯವಾಗಿರುತ್ತವೆ, ಮತ್ತು ನಿರ್ಧಾರಿತ ಆಜ್ಞೆ ಅವುಗಳಿಗೆ ಸೇರಲು ಆಯ್ಕೆ ಮಾಡುತ್ತಿಲ್ಲ. `ffprobe` ಮತ್ತು `ffmpeg` ಎರಡೂ
`file`-ಮಾತ್ರದ ಪ್ರೋಟೋಕಾಲ್ ಶ್ವೇತಪಟ್ಟಿಯನ್ನು ಬಳಸುತ್ತವೆ, ಒಂದು ಥ್ರೆಡ್, ನಿರ್ಧಾರಿತ ಆರ್ಗ್ಯುಮೆಂಟ್ ಶ್ರೇಣಿಗಳು, ಶೆಲ್ ಇಲ್ಲ, ಮತ್ತು `PATH` ನಿಂದ ಪರಿಹಾರಗೊಂಡ ಕಾರ್ಯನಿರ್ವಹಣಾ. ಅಟ್ಯಾಚ್ಡ್-ಚಿತ್ರ ಕವರ್ನಲ್ಲಿ ಹರಿಯುವಿಕೆಗಳನ್ನು ಆಡಲು ಸಾಧ್ಯವಿಲ್ಲ. ಎಲ್ಲಾ ಆಡಲು ಸಾಧ್ಯವಾದ ಹರಿಯುವಿಕೆಗಳು ಗಡಿಗಳನ್ನು ಪೂರೈಸಬೇಕು, ಮತ್ತು ನಿರ್ಧಾರಿತ ಡೀಫಾಲ್ಟ್ ಹರಿಯುವಿಕೆ ಕಡಿಮೆ ಸೂಚ್ಯಂಕದ ಬದಲಾವಣೆಗಿಂತ ಮುಂಚೆ ಆದ್ಯತೆಯನ್ನು ಹೊಂದಿದೆ. ವೀಡಿಯೋಗಳು 600 ಸೆಕೆಂಡುಗಳು, 8,192 ಪಿಕ್ಸೆಲ್ ಪ್ರತಿ ಆಯಾಮ, ಮತ್ತು 33,554,432 ಮೂಲ ಪಿಕ್ಸೆಲ್‌ಗಳಿಗೆ ಮಿತಿಯಲ್ಲಿವೆ. FFmpeg 1–16 ಮಧ್ಯದ JPEG ಫ್ರೇಮ್‌ಗಳನ್ನು ಮಾದರೀಕರಿಸುತ್ತದೆ, ದೀರ್ಘ ಅಂಚನ್ನು 1,024 ಪಿಕ್ಸೆಲ್‌ಗಳಿಗೆ ಕಡಿಮೆ ಮಾಡುತ್ತದೆ, ಸಣ್ಣ ಇನ್ಪುಟ್‌ಗಳನ್ನು ಅಪ್‌ಸ್ಕೇಲ್ ಮಾಡದೆ, ಮತ್ತು URL ಅನ್ನು ಎಂದಿಗೂ ಸ್ವೀಕರಿಸುತ್ತಿಲ್ಲ. ಮಾದರೀಕರಣವು ಡೀಫಾಲ್ಟ್‌ನಲ್ಲಿ `uniform` ಆಗಿದೆ. ಆಯ್ಕೆಯಾದ
`scene_aware` ಮತ್ತು ಪ್ರಯೋಗಾತ್ಮಕ `segment_aware` ನೀತಿಗಳು ಈಗಾಗಲೇ ಪರಿಶೀಲಿತ ಸ್ಥಳೀಯ ಹರಿಯುವಿಕೆಯ ಮೇಲೆ ಒಂದು ಹೆಚ್ಚುವರಿ ನಿರ್ಧಾರಿತ FFmpeg ಪಾಸ್ ಅನ್ನು ನಿರ್ವಹಿಸುತ್ತವೆ, ಗಡಿತಾದ `showinfo` ದೃಶ್ಯದ ಟೈಮ್‌ಸ್ಟ್ಯಾಂಪ್‌ಗಳನ್ನು ಆಯ್ಕೆ ಮಾಡುತ್ತವೆ, ಮತ್ತು ನಿರ್ಧಾರಿತವಾಗಿ ಡಿಟೆಕ್ಟರ್ ವಿಫಲವಾದಾಗ, ಟೈಮ್‌ಔಟ್, ತಪ್ಪಾದ ಔಟ್‌ಪುಟ್, ಅಥವಾ ಖಾಲಿ ಅಭ್ಯರ್ಥಿ ಸೆಟ್‌ಗೆ ಒಂದೇ ಸಮಾನ ಮಾದರಿಯ ಮಧ್ಯದ ಬಿಂದುಗಳಿಗೆ ಹಿಂತಿರುಗುತ್ತವೆ. ಸೆಗ್ಮೆಂಟ್-ಜಾಗAware ಮೋಡ್ ಪರಿಶೀಲಿತ ದೃಶ್ಯದ ಅಂತರಗಳಿಗೆ ಅನುಪಾತವಾಗಿ ಮಧ್ಯದ ಮಾದರಿಗಳನ್ನು ಹಂಚಿಸುತ್ತದೆ; ಸೆಗ್ಮೆಂಟ್-ಜಾಗAware ಸಾಕ್ಷ್ಯ ಮತ್ತು ಹಿಂತಿರುಗುವ ವರ್ತನೆ ಕೆಳಗೆ ವಿವರಿಸಲಾಗಿದೆ. ಕಠಿಣ 16-ಫ್ರೇಮ್ ಗಡಿ
ಪ್ರತಿ ನೀತಿಯಲ್ಲಿ ಆಯ್ಕೆ ಮಾಡಿದ ನಂತರ ಅನ್ವಯಿಸಲಾಗುತ್ತದೆ. ದೃಶ್ಯ-ಜಾಗAware ವಿನಂತಿಯು ಕೇವಲ ಒಂದು-ಫ್ರೇಮ್ ಬಜೆಟ್ ಹೊಂದಿದಾಗ, ಇದು ಸಕ್ರಿಯ ಸಂಪೂರ್ಣ-ವೀಡಿಯೋ ಅಥವಾ ಫೋಕಸ್
ಕಿಟಕಿಯ ಸಮಾನಾಂತರವನ್ನು ಬಳಸುತ್ತದೆ ಮತ್ತು `policyEffective: uniform` ಅನ್ನು ವರದಿ ಮಾಡುತ್ತದೆ: ಒಬ್ಬ ಆಯ್ಕೆ ಮಾಡಿದ ದೃಶ್ಯ ಫ್ರೇಮ್ ಎರಡೂ ಕಾಲಿಕ ಕೊನ್ಗಳನ್ನು ಉಳಿಯಲು ಸಾಧ್ಯವಿಲ್ಲ. ಕರೆ ಮಾಡಿದ ವ್ಯಕ್ತಿಯು ಆಯ್ಕೆಯಾದ ಫೋಕಸ್ ಕಿಟಕಿ (`start`/`end` ಸೆಕೆಂಡುಗಳು) ಒದಗಿಸಬಹುದು; ಗಡಿಗಳು ಮಾಧ್ಯಮದ ಅವಧಿಗೆ ಕ್ಲ್ಯಾಂಪ್ ಮಾಡಲಾಗುತ್ತದೆ, ಹಿಂತಿರುಗಿದ ಅಥವಾ ನಿರಂತರ ಕಿಟಕಿಗಳನ್ನು ನಿರಾಕರಿಸಲಾಗುತ್ತದೆ, ಮತ್ತು ಎಲ್ಲಾ ಮಾದರೀಕರಣ ನೀತಿಗಳನ್ನು ಮಾತ್ರ ಸಾಮಾನ್ಯಗೊಳಿಸಿದ ಅಂತರದಲ್ಲಿ ನಿರ್ವಹಿಸಲಾಗುತ್ತದೆ. ಫಲಿತಾಂಶದ ಕಿಟಕಿ ಮಾದರೀಕರಣ ಮೆಟಾಡೇಟಾ ಮತ್ತು ಅಪ್ರಮಾಣಿತ ವಿವರಣಾ ಪ್ರೀಫಿಕ್ಸ್‌ನಲ್ಲಿ ಸೇರಿಸಲಾಗುತ್ತದೆ, ಆದ್ದರಿಂದ ಹಿಂಬಾಲಿಸುವ ಮಾದರಿಗಳು ಸಂಪೂರ್ಣ ಕಾಲಾವಧಿಯಿಂದ ಫೋಕಸ್ ಮಾಡಿದ ಉಲ್ಲೇಖವನ್ನು ವಿಭಜಿತ ಮಾಡಬಹುದು.

ಅರ್ಥಪೂರ್ಣ ಶೀರ್ಷಿಕೆ ಫೋಕಸ್ ಒಂದು ಪ್ರತ್ಯೇಕ, ನಿರ್ಧಿಷ್ಟ ಸೆಟಿಂಗ್. ಡೀಫಾಲ್ಟ್ `full`
ವಿಶ್ಲೇಷಣಾ ಮೋಡ್ ಈಗಾಗಲೇ ಇರುವ ಫ್ರೇಮ್ ಪ್ರಾಂಪ್ಟ್ ಅನ್ನು ಉಳಿಸುತ್ತದೆ ಮತ್ತು ಶೀರ್ಷಿಕೆ ಮಾದರಿಯೊಂದಿಗೆ ವಿನಂತಿ ಪಠ್ಯವನ್ನು ಎಂದಿಗೂ ಮುಂದುವರಿಸುತ್ತಿಲ್ಲ. `focused` ಮೋಡ್‌ನಲ್ಲಿ, ಬ್ರಿಡ್ಜ್ ಕೇವಲ ಇತ್ತೀಚಿನ
ಖಾಲಿ ಅಲ್ಲದ ಬಳಕೆದಾರ-ರಚಿತ `text`/`input_text` ಅನ್ನು ಒಂದೇ ಚಾಟ್ ಅಥವಾ ಪ್ರತಿಕ್ರಿಯೆಗಳ
ಕಂಟೈನರ್‌ನಿಂದ ಓದುತ್ತದೆ, ಅದನ್ನು NFC ಗೆ ಸಾಮಾನ್ಯಗೊಳಿಸುತ್ತದೆ, ನಿಯಂತ್ರಣ ಅಕ್ಷರಗಳನ್ನು ಮತ್ತು ಖಾಲಿ ಸ್ಥಳವನ್ನು ಕುಗ್ಗಿಸುತ್ತದೆ, ಮತ್ತು 500 Unicode ಕೋಡ್ ಪಾಯಿಂಟ್‌ಗಳಿಗೆ ಮಿತಿಯಲ್ಲಿದೆ. ಖಾಲಿ ಫಲಿತಾಂಶವು ಖಚಿತವಾದ `full` ಪ್ರಾಂಪ್ಟ್ ಗೆ ಹಿಂತಿರುಗುತ್ತದೆ. ಬಳಸಬಹುದಾದ ಸೂಚನೆ JSON ರೂಪದಲ್ಲಿ ವಿಶೇಷವಾಗಿ ಅಪ್ರಮಾಣಿತ-ಬಳಕೆದಾರ-ಸಂದರ್ಭದ ಬ್ಲಾಕ್‌ನಲ್ಲಿ ಸರಣೀಬದ್ಧವಾಗುತ್ತದೆ ಮತ್ತು observable ವಿವರಗಳನ್ನು ಮಾತ್ರ ಆದ್ಯತೆಯನ್ನು ನೀಡಬಹುದು; ಇದು ಮಾಧ್ಯಮದಲ್ಲಿ ದೃಶ್ಯ ಅಥವಾ ಶ್ರವಣೀಯವಾಗಿ ಕಾಣುವ ಸೂಚನೆಗಳನ್ನು ಅನುಸರಿಸಲು ಪ್ರತ್ಯೇಕ ಎಚ್ಚರಿಕೆಯನ್ನು ಮೀರಿಸಲು ಸಾಧ್ಯವಿಲ್ಲ. ಪಠ್ಯ ಫೋಕಸ್ ಎಂದಿಗೂ `start`/`end` ಅನ್ನು ಊಹಿಸುವುದಿಲ್ಲ ಅಥವಾ ಕಾಲಿಕ ಮಾದರಿಕರ್ತೆಯನ್ನು ಬದಲಾಯಿಸುವುದಿಲ್ಲ.

#### FU-07 ರಚನಾತ್ಮಕ ಸೆಗ್ಮೆಂಟ್ ಸಾಕ್ಷ್ಯ

`segment_aware` ಈಗಾಗಲೇ ಮಾನ್ಯತೆಯಾದ ಸ್ಥಳೀಯ ವೀಡಿಯೋ ಸ್ಟ್ರೀಮ್ ಮೇಲೆ ಒಂದು ನಿರ್ಬಂಧಿತ ಪೂರ್ವ-ವಿಶ್ಲೇಷಣಾ ಪಾಸ್ ಅನ್ನು ಬಳಸುತ್ತದೆ. ಸ್ಥಿರ ಫಿಲ್ಟರ್ ಶ್ರೇಣಿಯು ಮೊದಲಿಗೆ ಅತಿದೊಡ್ಡ 320 ಪಿಕ್ಸೆಲ್ ಅಗಲಕ್ಕೆ ಪ್ರಮಾಣಿತಗೊಳಿಸುತ್ತದೆ, ದೃಶ್ಯ ಬದಲಾವಣೆಗಳನ್ನು ಮತ್ತು ಹಿಮ್ಮೆಟ್ಟಿದ ಅಂತರಗಳನ್ನು ಗುರುತಿಸುತ್ತದೆ, ನಂತರ ಮೃದುವಾದ, ಸರಾಸರಿ ಲ್ಯೂಮಾ, ಮತ್ತು ಸ್ಥಳೀಯ/ಕಾಲಿಕ ಮಾಹಿತಿಗಾಗಿ ಪ್ರತಿ ಸೆಕೆಂಡಿಗೆ 1 ಫ್ರೇಮ್ ಅನ್ನು ಮಾದರೀಕರಿಸುತ್ತದೆ. ಈ ಪಾಸ್ 600 ರಚನಾತ್ಮಕ ಮಾದರಿಗಳಿಗೆ, ಒಂದು FFmpeg/filter ಥ್ರೆಡ್, ಒಂದೇ `file`-ಮಾತ್ರ ಪ್ರೋಟೋಕಾಲ್ ಮತ್ತು ಕಂಟೈನರ್ ಅನುಮತಿಗಳೊಂದಿಗೆ, 1 MiB ಪ್ರಕ್ರಿಯೆ-ಔಟ್‌ಪುಟ್ ಬೌಂಡ್, ಮತ್ತು ಬ್ರೋಕರ್‌ನ ಹಂಚಿದ ಅಬಾರ್ಟ್/ಡೆಡ್‌ಲೈನ್‌ನಲ್ಲಿ ಅತಿದೊಡ್ಡ 30 ಸೆಕೆಂಡುಗಳ ಒಳಗೆ ನಿರ್ಬಂಧಿತವಾಗಿದೆ. ಇದು ಕೇಳುವಿಕೆಯಿಂದ ಆದೇಶ, ಫಿಲ್ಟರ್, ಮಾರ್ಗ ಅಥವಾ URL ಅನ್ನು ಎಂದಿಗೂ ಒಪ್ಪುವುದಿಲ್ಲ.

ರಚನಾತ್ಮಕ ಮೌಲ್ಯಗಳು ನಿರ್ಧಾರಾತ್ಮಕ ಮಾದರೀಕರಣದ ಸಾಕ್ಷ್ಯವಾಗಿವೆ, ಅರ್ಥಾತ್ಮಕ ವೀಡಿಯೋ ಅರ್ಥಮಾಡಿಕೊಳ್ಳುವಿಕೆ ಅಲ್ಲ. ಇವು ವಿಷಯಗಳು, ಕ್ರಿಯೆಗಳು, ಶೀರ್ಷಿಕೆಗಳು, ಭಾಷಣ ಅಥವಾ ಬಳಕೆದಾರ ಉದ್ದೇಶವನ್ನು ಊಹಿಸುವುದಿಲ್ಲ. ದೃಶ್ಯ ಮತ್ತು ಹಿಮ್ಮೆಟ್ಟಿದ ಗಡಿಯುಗಳು ವಿಭಾಗಗಳನ್ನು ರೂಪಿಸುತ್ತವೆ; ಹಿಮ್ಮೆಟ್ಟಿದ ಆವರಣ, ಮೃದುವಾದ, ಎಕ್ಸ್‌ಪೋಸರ್, ಸ್ಥಳೀಯ ವಿವರ ಮತ್ತು ಕಾಲಿಕ ಬದಲಾವಣೆಗಳು ಮಾತ್ರ ಈಗಾಗಲೇ ಇರುವ 1–16 ಫ್ರೇಮ್ ಬಜೆಟ್ ಹೇಗೆ ಹಂಚಿಕೊಳ್ಳಲಾಗುತ್ತದೆ ಎಂಬುದನ್ನು ಪ್ರಭಾವಿತ ಮಾಡುತ್ತವೆ. ಸಂಪೂರ್ಣವಾಗಿ ಹಿಮ್ಮೆಟ್ಟಿದ ವಿಭಾಗವು ಒಂದು ಫ್ರೇಮ್‌ನಲ್ಲಿ ಮಿತಿಯಲ್ಲಿದೆ, ಆದರೆ ಹಿಮ್ಮೆಟ್ಟದ ವಿಭಾಗಗಳು ಉಳಿದ ಬಜೆಟ್‌ಗಾಗಿ ಸ್ಪರ್ಧಿಸುತ್ತವೆ. ಗಡಿಗಳು ಫ್ರೇಮ್‌ಗಳನ್ನು ಮೀರಿಸಿದಾಗ, ಸಮಾನ ಕಾಲರೇಖೆ ಆವರಣವನ್ನು ಉಳಿಸಲಾಗಿದೆ, ಆದ್ದರಿಂದ ತ್ವರಿತ ಮುಂಚಿನ ಕಟ್‌ಗಳು ದೀರ್ಘ ಹಿಂಬಾಲಿಸುವ ವಿಭಾಗವನ್ನು ಮರೆಮಾಚಲು ಸಾಧ್ಯವಿಲ್ಲ. ಹಿಮ್ಮೆಟ್ಟಿದ ಗಡಿಯ 1-ಸೆಕೆಂಡು ವಿಶ್ಲೇಷಣಾ ನಿರ್ಧಾರದಲ್ಲಿ ದೃಶ್ಯ ಗಡಿಗಳು ಒಗ್ಗೂಡಿಸುತ್ತವೆ.

ಕಳೆದುಹೋಗಿರುವ ಫಿಲ್ಟರ್‌ಗಳು, ತಪ್ಪಾದ/ಖಾಲಿ ಸಾಕ್ಷ್ಯ, ಡಿಟೆಕ್ಟರ್ ದೋಷ, ಅಥವಾ ನಿರ್ಬಂಧಿತ ಪೂರ್ವ-ವಿಶ್ಲೇಷಣಾ ಟೈಮ್‌ಔಟ್ ನಿಖರ ಸಮಾನ ಮಧ್ಯದ ನೀತಿಗೆ ತೆರೆಯುತ್ತದೆ. ಕರೆ ಮಾಡುವವರ ಅಬಾರ್ಟ್ ಅಥವಾ ಬ್ರೋಕರ್ ಡೆಡ್‌ಲೈನ್ ತೆರೆಯುವುದಿಲ್ಲ: ಇದು ಹಾರುವ ಉಪಪ್ರಕ್ರಿಯೆಯನ್ನು ಕೊನೆಗೊಳಿಸುತ್ತದೆ, ನಂತರದ ಫ್ರೇಮ್ ನಿರ್ಗಮನೆಗೆ ತಡೆಯುತ್ತದೆ, ಮತ್ತು ಖಾಸಗಿ ತಾತ್ಕಾಲಿಕ ಮರವನ್ನು `finally` ನಲ್ಲಿ ತೆಗೆದುಹಾಕುತ್ತದೆ.

`scripts/perf/video-bridge-fu07-eval.ts` ನಂತರದ ಡೆಡ್ಯೂಪ್ ಶೀರ್ಷಿಕೆ-ಕೋಲ್ ಉಳಿತಾಯ, ಘನ-ಚಲನ ಬಜೆಟ್ ಹಂಚಿಕೆ, ಮೃದುವಾದ/ಎಕ್ಸ್‌ಪೋಸರ್/SI-TI ಸಾಕ್ಷ್ಯ, ದೀರ್ಘ ತುದಿಯೊಂದಿಗೆ ತ್ವರಿತ ಕಟ್‌ಗಳು, ಮತ್ತು ಹಂತ ಹಂಚಿಕೆ ತಪ್ಪು ಸಕಾರಾತ್ಮಕಗಳನ್ನು ಉತ್ಪಾದಿಸುತ್ತದೆ. ಇದು ಪೂರ್ವ-ವಿಶ್ಲೇಷಣಾ ಗೋಡೆ ಸಮಯವನ್ನು ದಾಖಲಿಸುತ್ತದೆ ಮತ್ತು, `/usr/bin/time` ಲಭ್ಯವಿರುವಾಗ, ಮಕ್ಕಳ CPU ಮತ್ತು ಶ್ರೇಷ್ಟ RSS ಅನ್ನು ದಾಖಲಿಸುತ್ತದೆ. ಇದರ ಗುಣಮಟ್ಟದ ಪರಿಶೀಲನೆಗಳು ರಚನಾತ್ಮಕ ಓರಾಕಲ್‌ಗಳಾಗಿವೆ ಮಾತ್ರ. ವಾಸ್ತವ ಶೀರ್ಷಿಕೆ-ಮಾದರಿಯ ಗುಣಮಟ್ಟ `HOLD` ನಲ್ಲಿ ಉಳಿಯುತ್ತದೆ ಏಕೆಂದರೆ ಈ ಹಾರ್ನೆಸ್‌ಗೆ ಯಾವುದೇ ಅಧಿಕೃತ ಅಂತಿಮ ಬಿಂದುವು ಅಥವಾ ಹಿಮ್ಮೆಟ್ಟಿದ ನ್ಯಾಯಾಧೀಶವಿಲ್ಲ. ಹಣಕಾಸಿನ ಉಳಿತಾಯಗಳು `HOLD` ನಲ್ಲಿ ಉಳಿಯುತ್ತವೆ, ಏಕೆಂದರೆ `--caption-cost-per-call-usd` ಸ್ಪಷ್ಟ ಧನಾತ್ಮಕ ಪ್ರತಿ-ಕೋಲ್ ಅಂದಾಜು ಒದಗಿಸುತ್ತಿಲ್ಲ; ಸ್ಕ್ರಿಪ್ಟ್ ಯಾವಾಗಲೂ ಯಾವುದೇ ಫಲಿತಾಂಶವನ್ನು ತಯಾರಿಸುತ್ತಿಲ್ಲ.

ಪ್ರತಿ ಫ್ರೇಮ್ 4 MiB ಗೆ ಮಿತಿಯಲ್ಲಿದೆ, ಎಲ್ಲಾ ಕಚ್ಚಾ ಫ್ರೇಮ್‌ಗಳನ್ನು ಒಟ್ಟಿಗೆ 23 MiB ಗೆ, ಮತ್ತು ಸರಣೀಬದ್ಧ ಬ್ರೋಕರ್ ಪ್ರತಿಕ್ರಿಯೆಯನ್ನು 32 MiB ಗೆ ಮಿತಿಯಲ್ಲಿದೆ. ಖಾಸಗಿ ತಾತ್ಕಾಲಿಕ ಡೈರೆಕ್ಟರಿ `finally` ನಲ್ಲಿ ತೆಗೆದುಹಾಕಲಾಗುತ್ತದೆ. OmniRoute FFmpeg ಅನ್ನು ಒಟ್ಟುಗೂಡಿಸುವುದಿಲ್ಲ ಮತ್ತು ಕಸ್ಟಮ್ ಕಾರ್ಯನಿರ್ವಹಣಾ ಮಾರ್ಗವನ್ನು ಒಪ್ಪುವುದಿಲ್ಲ. ಶೀರ್ಷಿಕೆ ನೀಡುವ ಮೊದಲು, ಬ್ರಿಡ್ಜ್ ಸಂರಕ್ಷಣಾತ್ಮಕ ದೃಶ್ಯ ಡೆಡ್ಯೂಪ್ಲಿಕೇಶನ್ ಪಾಸ್ ಅನ್ನು ಅನ್ವಯಿಸುತ್ತದೆ: ಪ್ರತಿ JPEG ಅನ್ನು 16×16 ಗ್ರೇಸ್ಕೇಲ್ ಬಫರ್ ಗೆ ಕಡಿಮೆ ಮಾಡಲಾಗುತ್ತದೆ ಮತ್ತು ಇದು ಕೇವಲ ಕೊನೆಯ ಫ್ರೇಮ್ ಅನ್ನು ಉಳಿಯುತ್ತದೆ. ಒಂದು ಫ್ರೇಮ್‌ಗಿಂತ ಹೆಚ್ಚು ಶೀರ್ಷಿಕೆ ಬಜೆಟ್ ಅನ್ನು ಕೇಳಿದಾಗ, ನಿರ್ಗಮನೆ ಆ ಬಜೆಟ್‌ಗಿಂತ ಎರಡು ಪಟ್ಟು ಹೆಚ್ಚು ನಿರ್ಬಂಧಿತ ಅಭ್ಯರ್ಥಿಗಳ ಪೂಲ್ ಅನ್ನು ಒದಗಿಸುತ್ತದೆ ಮತ್ತು 16 ಫ್ರೇಮ್‌ಗಿಂತ ಹೆಚ್ಚು ಎಂದಿಗೂ ಇಲ್ಲ. ಡೆಡ್ಯೂಪ್ಲಿಕೇಶನ್ ನಂತರ ಮಾತ್ರ ಕೇಳಿದ ಮಿತಿಯನ್ನು ಅನ್ವಯಿಸಲಾಗುತ್ತದೆ, ಮೊದಲ ಮತ್ತು ಅಂತಿಮ ಆಯ್ಕೆಯಾದ ಅಭ್ಯರ್ಥಿಗಳನ್ನು ಬಜೆಟ್ ಕನಿಷ್ಠ ಎರಡು ಇದ್ದಾಗ ಅಂತಿಮ ತೂಕದಲ್ಲಿ ಉಳಿಸಲಾಗುತ್ತದೆ. ಆವೃತ್ತಿಯ `grayscale-16x16-mean-cells-v2` ನೀತಿ ಸರಾಸರಿ ಲ್ಯೂಮಾ ಡೆಲ್ಟಾ ಮತ್ತು ನಾರ್ಮಲೈಜ್ಡ್ ಡೆಲ್ಟಾ ಕನಿಷ್ಠ 0.05 ಇರುವ ಥಂಬ್ನೇಲ್ ಸೆಲ್‌ಗಳ ಅನುಪಾತದ ದೊಡ್ಡದನ್ನು ಬಳಸುತ್ತದೆ. ಪುನರಾವೃತ್ತದ ತೀವ್ರತೆ ನಿರ್ಧಾರಾತ್ಮಕ 0.04, ನಿರ್ಧಾರಾತ್ಮಕತೆಯನ್ನು ಆಯ್ಕೆ ಮಾಡಲಾಗಿದೆ, ಆದರೆ ಕಾರ್ಯನಿರ್ವಹಣಾ ಸೆಟಿಂಗ್ ಎಂದು ಬಹಿರಂಗಪಡಿಸಲಾಗಿಲ್ಲ. ಈ ದ್ವಿತೀಯ ಉನ್ನತ-ಕಾಂಟ್ರಾಸ್ಟ್ ಸಂಕೇತವು ಸಣ್ಣ ಚಲನ ಮತ್ತು ದೃಶ್ಯ-ಪಠ್ಯ ಬದಲಾವಣೆಗಳನ್ನು ಉಳಿಸುತ್ತದೆ, ಏಕೆಂದರೆ ಸರಾಸರಿ ಮಾತ್ರ ಹೋಲಿಸುವುದು ಮರೆಮಾಚಬಹುದು. ಹೋಲಿಸುವ ಅಥವಾ ಡಿಕೋಡರ್ ದೋಷಗಳು ತೆರೆಯುತ್ತವೆ ಮತ್ತು ಆವರಣವನ್ನು ಉಳಿಸುತ್ತವೆ. ಔಟ್‌ಪುಟ್ ಮೆಟಾಡೇಟಾ ನಿರ್ಗಮಿತ ಅಭ್ಯರ್ಥಿಗಳನ್ನು, ಯಶಸ್ವಿಯಾಗಿ ಬಳಸಿದ ಫ್ರೇಮ್‌ಗಳನ್ನು, ಮತ್ತು ದೃಶ್ಯ ಪುನರಾವೃತ್ತಗಳನ್ನು ಬೇರೆಯಾಗಿ ವಿಭಜಿಸುತ್ತದೆ.

ನಿಖರವಾಗಿ ಗುರುತಿಸಲಾದ ವೀಡಿಯೋ ಭಾಗವು ಟೈಮ್‌ಸ್ಟ್ಯಾಂಪ್ ಮಾಡಿದ ಸಂಪರ್ಕ ಶೀಟ್ನನ್ನು ಕೇಳಬಹುದು. ಬ್ರಿಡ್ಜ್ ಅತಿದೊಡ್ಡ 4-ಕೋಷ್ಟಕ, 16-ಫ್ರೇಮ್ JPEG ಗ್ರಿಡ್ ಅನ್ನು ನಿರ್ಮಿಸುತ್ತದೆ. ಪ್ರತಿ 512-ಪಿಕ್ಸೆಲ್ ಸೆಲ್ ತನ್ನ ಮೂಲ ಟೈಮ್‌ಸ್ಟ್ಯಾಂಪ್ ಅನ್ನು ಉನ್ನತ-ಕಾಂಟ್ರಾಸ್ಟ್ ಕೆಳಗಿನ ಬ್ಯಾಂಡ್‌ನಲ್ಲಿ ಬೆರೆಯುತ್ತದೆ, ಆದರೆ ಅದೇ ಟೈಮ್‌ಸ್ಟ್ಯಾಂಪ್‌ಗಳನ್ನು ಹಿಂಬಾಲಿಸುವ ಸಂಬಂಧ ಮತ್ತು ಪರಿಶೀಲನೆಗಾಗಿ ಪಠ್ಯ ಮೆಟಾಡೇಟಾದಲ್ಲಿ ಉಳಿಯುತ್ತವೆ. ಸಂಪೂರ್ಣ JPEG 32 MiB ಗೆ ಮಿತಿಯಲ್ಲಿದೆ. `sharp` ಗ್ರಿಡ್ ಅನ್ನು ಡಿಕೋಡ್ ಅಥವಾ ರಚಿಸಲು ಸಾಧ್ಯವಾಗದಿದ್ದರೆ, ಬ್ರಿಡ್ಜ್ ವೈಯಕ್ತಿಕ JPEG ಫ್ರೇಮ್‌ಗಳಿಗೆ ಹಿಂತಿರುಗುತ್ತದೆ; ಕ್ಲೈಂಟ್ ಅಬಾರ್ಟ್ ಶೀಟ್ ಕಾರ್ಯಾಚರಣೆಯ ಮೂಲಕ ಇನ್ನೂ ಹರಡುತ್ತದೆ.

ಪ್ರೋಮೋಶನ್ ಸಾಕ್ಷ್ಯವು ಸಿಂಥಟಿಕ್ ಸಂಯೋಜನೆಯ ಮೈಕ್ರೋಬೆಂಚ್ಮಾರ್ಕ್‌ಗಳಿಂದ ಉಲ್ಲೇಖಿತವಾಗಿ ಪ್ರತ್ಯೇಕವಾಗಿದೆ. `scripts/perf/video-bridge-contact-sheet-eval.ts` ವಾಸ್ತವ OpenAI-ಅನುಕೂಲ ದೃಶ್ಯ ಮಾದರಿಗಳಿಗೆ A/B ಹಾರ್ನೆಸ್ ಅನ್ನು ಪರಿಕಲ್ಪಿಸುತ್ತದೆ. ಇದು ಒದಗಿಸುವವರ ವರದಿ ಮಾಡಿದ ಟೋಕನ್‌ಗಳನ್ನು, ಅಂತ್ಯ-ತುದಿ ಗೋಡೆ ವಿಳಂಬವನ್ನು (ಶೀಟ್ ಸಂಯೋಜನೆಯು ಒಳಗೊಂಡಂತೆ), ಮಾದರಿ-ಕೋಲ್ ಸಂಖ್ಯೆಯನ್ನು, ಮತ್ತು ಮ್ಯಾನಿಫೆಸ್ಟ್-ನಿರ್ಧಾರಿತ ವಾಸ್ತವವನ್ನು ಅಳೆಯುತ್ತದೆ. ಕಚ್ಚಾ ಮಾದರಿ ಪ್ರತಿಕ್ರಿಯೆಗಳನ್ನು ವರದಿಗೆ ಬರೆಯಲಾಗುವುದಿಲ್ಲ; ಕೇವಲ SHA-256 ಡಿಜೆಸ್ಟ್‌ಗಳು ಮತ್ತು ಹೊಂದಿಸಿದ ವಾಸ್ತವ IDಗಳನ್ನು ಉಳಿಸಲಾಗುತ್ತದೆ. ಈ ಹಾರ್ನೆಸ್ ಯಾವುದೇ ನೆಟ್‌ವರ್ಕ್ ಅಥವಾ ಪೇಡ್ ಮಾದರಿ ಕರೆ ಮಾಡುವುದಿಲ್ಲ, ಏಕೆಂದರೆ `--execute-real` ಅನ್ನು ಒದಗಿಸಲಾಗುತ್ತದೆ ಮತ್ತು `--model`, `OMNIROUTE_BASE_URL`, ಮತ್ತು `OMNIROUTE_API_KEY` ಅನ್ನು ಕಾನ್ಫಿಗರ್ ಮಾಡಲಾಗಿದೆ. ಆ ಸ್ಪಷ್ಟ ವಾಸ್ತವ ಓಡಾಟವಿಲ್ಲದೆ, ಇದರ ಯಂತ್ರ-ಓದನೀಯ ತೀರ್ಪು `HOLD` ನಲ್ಲಿ ಉಳಿಯುತ್ತದೆ; ಸಿಂಥಟಿಕ್ ಪೇಲೋಡ್/ಕೋಲ್-ಗಣನೆ ಅಳೆಯುವಿಕೆ ಮಾತ್ರ ಪ್ರೋಮೋಶನ್ ಸಾಕ್ಷ್ಯವಲ್ಲ.

ಪರಿಸರ `scripts/perf/video-bridge-promotion-eval.ts` FU-07 ಅಥವಾ FU-09 ವೀಕ್ಷಣೆಗಳನ್ನು ಬಳಸುತ್ತದೆ. ಪ್ರೋಮೋಶನ್ ಪ್ರವೇಶವು ಎಲ್ಲಾ ಎಂಟು ಸಿಂಥಟಿಕ್ ದೃಶ್ಯ ಪರಿಕಲ್ಪನೆಗಳ ಪ್ರಕಾರಗಳನ್ನು ಮತ್ತು ಶುದ್ಧವಾದ ವಾಸ್ತವ ಕ್ಲಿಪ್ ಅನ್ನು, ಪ್ರತಿ ಪಾತ್ರ ಮತ್ತು ಪ್ರಕರಣಕ್ಕೆ ಕನಿಷ್ಠ ಮೂರು ಅಳೆಯಲ್ಪಟ್ಟ ಪುನರಾವೃತ್ತಗಳನ್ನು, ಎಲ್ಲಾ ಹತ್ತು ಘೋಷಿತ ಮೆಟ್ರಿಕ್‌ಗಳನ್ನು, ಹಿಮ್ಮೆಟ್ಟಿದ ಮಾಧ್ಯಮ/ಪ್ರಾಂಪ್ಟ್/ನಿರೀಕ್ಷಿತ-ವಾಸ್ತವ/ಸೆಟಿಂಗ್‌ಗಳ ಡಿಜೆಸ್ಟ್‌ಗಳನ್ನು, ವಿಶಿಷ್ಟ ವೀಕ್ಷಣೆ IDಗಳನ್ನು ಮತ್ತು ಪರಿಶೀಲಿತ ಬೀಜಿತ A/B ಕ್ರಮವನ್ನು ಅಗತ್ಯವಿದೆ. ಕಾರ್ಯಾಚರಣೆಯ ರಸೀದಿಯು ಕಾರ್ಪಸ್ ಡಿಜೆಸ್ಟ್, ನಿಖರ ಅಭ್ಯರ್ಥಿ SHA ಮತ್ತು ಮಾದರಿ ಪರಿಷ್ಕರಣೆಗಳನ್ನು ಬಂಧಿಸುತ್ತದೆ. ಕಳೆದುಹೋಗಿರುವ ಅಥವಾ ಅಮಾನ್ಯ ಅಳೆಯುವಿಕೆಗಳು `HOLD` ನಲ್ಲಿ ಉಳಿಯುತ್ತವೆ, 30 ಸೆಕೆಂಡುಗಳ ಮೇಲೆ CPU, 512 MiB ಗೆ ಮೀರಿದ ಶ್ರೇಷ್ಟ RSS ಅಥವಾ 30 ಸೆಕೆಂಡುಗಳ ಮೇಲೆ ಪೂರ್ವ-ವಿಶ್ಲೇಷಣೆ ಒಳಗೊಂಡಂತೆ. ಇವು ಸಾಕ್ಷ್ಯ-ಪ್ರವೇಶ ಮಿತಿಗಳು, ಹೊಸ ಕಾರ್ಯನಿರ್ವಹಣಾ RSS ಜಾರಿಗೆ ಖಾತರಿಯಲ್ಲ.

FU-07 ಕನಿಷ್ಠ 98% ಗುಣಮಟ್ಟದ ಉಳಿವನ್ನು ಮತ್ತು p95 ವಿಳಂಬವನ್ನು ಮೂಲದ 1.2x ಕ್ಕಿಂತ ಹೆಚ್ಚು ಇಲ್ಲದಂತೆ ಅಗತ್ಯವಿದೆ, ಜೊತೆಗೆ ಸಮಾನ ಅರ್ಥದ ಶೀರ್ಷಿಕೆ ಕರೆಗಳಲ್ಲಿ 0.05 ಶ್ರೇಣೀಬದ್ಧವಾದ ಅರ್ಥದ ಪುನಃಕೋಷ್ಟಕ ಸುಧಾರಣೆಯು ಅಥವಾ ಕನಿಷ್ಠ 10% ಕಡಿಮೆ ಶ್ರೇಣೀಬದ್ಧ ಶೀರ್ಷಿಕೆ ಕರೆಗಳ ಅಗತ್ಯವಿದೆ. FU-09 ಕನಿಷ್ಠ 0.85 ಗುಣಮಟ್ಟ, 95% ಉಳಿವು, 20% p95 ವಿಳಂಬ ಕಡಿತ ಮತ್ತು 10% ಟೋಕನ್ ಕಡಿತವನ್ನು ಅಗತ್ಯವಿದೆ. ಕ್ರಿಟಿಕಲ್-ಫ್ಯಾಕ್ ನಷ್ಟ, ಇಂಜೆಕ್ಷನ್ ಅನುಕೂಲತೆ ಅಥವಾ ಕಳೆದುಹೋಗಿರುವ ಬಳಕೆ ಉತ್ತೇಜನವನ್ನು ತಡೆಯುತ್ತದೆ. ಒಂದು ಕಾರ್ಯಾಚರಣೆ ಯಾವುದನ್ನೂ ಉತ್ತೇಜಿಸಲು ಸಾಧ್ಯವಿಲ್ಲ: `--previous-report` ಒಂದೇ ನೀತಿ/ಮಾದರಿ ಪರಿಷ್ಕರಣೆ/ಅಭ್ಯರ್ಥಿ/ಕೋಶದ ಎರಡು ವಿಭಿನ್ನ, ಅತಿವ್ಯಾಪ್ತಿಯಿಲ್ಲದ, ಕ್ರಮಬದ್ಧವಾಗಿ ಅರ್ಹ ಕಾರ್ಯಾಚರಣೆಗಳನ್ನು ದೃಢೀಕರಿಸುತ್ತದೆ. ಒಂದು ಮಾದರಿ ಪ್ರಯೋಗವು ಸಂಪರ್ಕ-ಶೀಟ್ ಪ್ರಯೋಗವನ್ನು ದೃಢೀಕರಿಸಲು ಸಾಧ್ಯವಿಲ್ಲ.

ಕಲೆಕ್ಟರ್‌ಗಳು ಪ್ರತಿಕ್ರಿಯೆಗಳನ್ನು ಮೆಮೊರಿಯಲ್ಲಿ ಅಂಕಿತಗೊಳಿಸಬೇಕು ಮತ್ತು `responseDigest` ಜೊತೆಗೆ ಮೆಟ್ರಿಕ್‌ಗಳು ಮತ್ತು ವೀಕ್ಷಣೆ ಬಾಂಧವ್ಯಗಳನ್ನು ಉಳಿಸಬೇಕು, ಪ್ರತಿಕ್ರಿಯೆ ಪಠ್ಯವನ್ನು ಎಂದಿಗೂ ಉಳಿಸಬಾರದು. ಗ್ರಾಹಕ ಹಳೆಯ ಕಚ್ಚಾ ವೀಕ್ಷಣೆಗಳನ್ನು ಓದುತ್ತದೆ ಆದರೆ ಆ ಪಠ್ಯವನ್ನು ತನ್ನ ವರದಿಗಳಲ್ಲಿ ಕಾಪಿ ಮಾಡುವುದಿಲ್ಲ. ಪ್ರತಿಯೊಂದು ವೀಕ್ಷಣೆಗೆ `responseDigest` ಅಥವಾ `rawResponseText` ನಿಖರವಾಗಿ ಒಪ್ಪಿಗೆಯಾಗಿದೆ. ಆವೃತ್ತಿಯ ಅನುಮತಿತ ಪಟ್ಟಿಯು ಖಾಲಿಯಲ್ಲಿದೆ ಮತ್ತು ಬದಲಾಯಿಸಲಾಗದ `hold` ಡೀಫಾಲ್ಟ್ ಅನ್ನು ಹೊಂದಿದೆ. ಅರ್ಹ ಪ್ರವೇಶವು ಅದರ ಸಾಕ್ಷ್ಯ ಉಲ್ಲೇಖ, ನೀತಿ, ಮಾದರಿ ಪರಿಷ್ಕರಣೆ, ನಿಖರವಾದ ಅಭ್ಯರ್ಥಿ SHA, ಮ್ಯಾನಿಫೆಸ್ಟ್ ಡೈಜೆಸ್ಟ್ ಮತ್ತು ಎರಡು ವಿಭಿನ್ನ ಓಟ IDಗಳನ್ನು ಅಗತ್ಯವಿದೆ; ಸಂಘರ್ಷಿತ ಸಂದರ್ಭಗಳನ್ನು ನಿರಾಕರಿಸಲಾಗುತ್ತದೆ. ಈ ಮೆಟಾಡೇಟಾ ಒಂದು ಆಡಿಟ್ ಒಪ್ಪಂದವಾಗಿದೆ, ಉಲ್ಲೇಖಿತ ಫೈಲ್ ನಿಜವಾದ ಅಳೆಯುವಿಕೆಗಳನ್ನು ಒಳಗೊಂಡಿದೆ ಎಂಬುದಕ್ಕೆ ಸಾಕ್ಷಿಯಲ್ಲ. ಯಾವುದೇ ಪ್ರವೇಶವನ್ನು ಸೇರಿಸುವ ಮೊದಲು ವಾಸ್ತವಿಕ ರಸೀದಿಗಳನ್ನು ಪರಿಶೀಲಿಸಿ. ನಿರ್ವಹಣಾ ಅಂಕಿಅಂಶಗಳ ಅಂತಿಮ ಬಿಂದುವು ಮತ್ತು ವಿಡಿಯೋ ಡ್ಯಾಶ್‌ಬೋರ್ಡ್ ಸಂರಕ್ಷಣಾತ್ಮಕ ತಯಾರಿಕೆಯನ್ನು ಬಹಿರಂಗಪಡಿಸುತ್ತವೆ. ಕಾನ್ಫಿಗರ್ ಮಾಡಿದ ಮಾದರಿ ಉಪನಾಮವು ಮಾತ್ರ ಅದರ ಪರಿಷ್ಕರಣೆಯನ್ನು ಅಥವಾ ಓಡುತ್ತಿರುವ ಅಭ್ಯರ್ಥಿ SHA ಅನ್ನು ಸ್ಥಾಪಿಸುವುದಿಲ್ಲ, ಆದ್ದರಿಂದ ಪ್ರಸ್ತುತ ಡ್ಯಾಶ್‌ಬೋರ್ಡ್ `HOLD` ಅನ್ನು ವರದಿ ಮಾಡುತ್ತದೆ, ಬೇರೆಯ ಕಾರ್ಯಾಚರಣೆ ಸಂದರ್ಭದಿಂದ ಅರ್ಹತೆಯನ್ನು ಪುನಃ ಬಳಸುವುದಿಲ್ಲ. ಸ್ಪಷ್ಟ ಪ್ರಯೋಗಾತ್ಮಕ ಆಯ್ಕೆ ಉತ್ತೇಜನದಿಂದ ಪ್ರತ್ಯೇಕವಾಗಿರುತ್ತದೆ; ಯಾವುದೇ ಡೀಫಾಲ್ಟ್ ಸ್ವಯಂವಾಗಿ ಬದಲಾಯಿಸಲಾಗುವುದಿಲ್ಲ.

ಕೋಲರ್‌ಗಳು ಈಗಾಗಲೇ ಹೊಂದಿರುವ ಅಂಕಿತ ಪಠ್ಯವನ್ನು ಬೆಂಬಲಿತ ವಿಡಿಯೋ ಭಾಗಕ್ಕೆ ಆಯ್ಕೆಯಾದ `transcript.cues` ಅರೆವನ್ನು ಜೋಡಿಸಬಹುದು. ಪ್ರತಿಯೊಂದು ಸೂಚಕವು `text`, ಪರೀಕ್ಷಿತ ಅವಧಿಯ ಒಳಗೆ ನಿರ್ಧಿಷ್ಟ `start`/`end` ಅಂತರವನ್ನು ಮತ್ತು ಶ್ರೇಣೀಬದ್ಧ `source` (`client`, `embedded`, ಅಥವಾ `audio-bridge`) ಅನ್ನು ಹೊಂದಿರಬೇಕು; `confidence` ಡೀಫಾಲ್ಟ್ `1` ಆಗಿದ್ದು `0` ಮತ್ತು `1` ನಡುವಿನಲ್ಲಿರಬೇಕು. ನಿಖರವಾದ ನಕಲಿ ಸೂಚಕಗಳನ್ನು ಒಗ್ಗಡಿಸಲಾಗುತ್ತದೆ. OmniRoute ಈ ಮೆಟಾಡೇಟಾದಿಂದ ವರ್ಣನೆಯನ್ನು ಪ್ರಾರಂಭಿಸುತ್ತಿಲ್ಲ: ದೃಢೀಕರಿಸಿದ ಸೂಚಕಗಳನ್ನು ಮೂಲ, ವಿಶ್ವಾಸ ಮತ್ತು ಅಂತರದೊಂದಿಗೆ ವಿವರಿಸಿದ ಫಲಿತಾಂಶದಲ್ಲಿ ನಕಲಿಸಲಾಗುತ್ತದೆ ಮತ್ತು ಫ್ರೇಮ್ ಶೀರ್ಷಿಕೆಗಳೊಂದಿಗೆ ಅಸಂಬದ್ಧ ವೀಕ್ಷಣೆಗಳಂತೆ ಪ್ರದರ್ಶಿಸಲಾಗುತ್ತದೆ. ಅಮಾನ್ಯ, ವ್ಯಾಪ್ತಿಯ ಹೊರಗಿನ, ಅಥವಾ ಮೂಲವಿಲ್ಲದ ಪಠ್ಯವನ್ನು ಶೀರ್ಷಿಕೆ ಹರಿವಿನಲ್ಲಿ ಮಿಶ್ರಿತಗೊಳಿಸುವ ಬದಲು ನಿರಾಕರಿಸಲಾಗುತ್ತದೆ. ಎರಡೂ ವಿನಂತಿ-ಶರೀರದ ವರ್ಣನ ಚಾನೆಲ್‌ಗಳು ಒದಗಿಸಿದ ಮೂಲವನ್ನು `client` ಗೆ ಸಾಮಾನ್ಯೀಕರಿಸುತ್ತವೆ, ಸ್ವಯಂ-ಅಭಿಪ್ರಾಯಿತ `embedded` ಅಥವಾ `audio-bridge` ಲೇಬಲ್‌ಗಳನ್ನು ಒಳಗೊಂಡಂತೆ. ವಿಶ್ವಾಸಾರ್ಹ ಲೇಬಲ್‌ಗಳನ್ನು ಕೇಂದ್ರೀಯ `trustedSource` ಆರ್ಗ್ಯುಮೆಂಟ್ ಮೂಲಕ ಮಾತ್ರ ಸರ್ವರ್-ಮಾಲಿಕದ ಅಡಾಪ್ಟರ್ ನಿಯೋಜಿಸಬಹುದು; ವಿನಂತಿ JSON ಕ್ಷೇತ್ರವು ಆ ಆರ್ಗ್ಯುಮೆಂಟ್‌ಗೆ ತಲುಪಲು ಸಾಧ್ಯವಿಲ್ಲ. ವರ್ಣನ ಪಠ್ಯವು ವಿಶ್ವಾಸಾರ್ಹ ಮಾಧ್ಯಮ-ಆಧಾರಿತ ವಿಷಯವಾಗಿದ್ದು, ಅದರ ಮೂಲವನ್ನು ಪರಿಗಣಿಸುವುದಿಲ್ಲ ಮತ್ತು ಎಂದಿಗೂ ಅಧಿಕಾರವನ್ನು ನಿರ್ಧರಿಸಬಾರದು.

ಒಂದು ಉನ್ನತ ಕೋಲರ್ ಅದೇ ವಿಡಿಯೋಕ್ಕಾಗಿ `audioTranscript` ಟ್ರಾಕ್ ಅನ್ನು ಒದಗಿಸಬಹುದು; ಇದು ಕ್ಲೈಂಟ್-ಒದಗಿಸಿದ ಪಠ್ಯವಾಗಿ ಪರಿಗಣಿಸಲಾಗುತ್ತದೆ, ಸರ್ವರ್ ವರ್ಣನೆಯ ಸಾಕ್ಷಿಯಲ್ಲ. ಫ್ಯೂಷನ್ ಸೀಮ್ ದೃಶ್ಯ ಮತ್ತು ಧ್ವನಿ ವೀಕ್ಷಣೆಗಳನ್ನು ಒಂದೇ ಸಮಯದ ಮಿತಿಯ ಅಡಿಯಲ್ಲಿ ಮತ್ತು ನಿಲ್ಲಿಸುವ ಸಂಕೇತದ ಅಡಿಯಲ್ಲಿ ನಡೆಸುತ್ತದೆ, ಅವುಗಳನ್ನು ಸಾಮಾನ್ಯ ಕಾಲರೇಖೆಯ ಮೇಲೆ ಆಜ್ಞಾಪಿಸುತ್ತದೆ, ನಿಖರವಾದ ನಕಲಿಗಳನ್ನು ಒಗ್ಗಡಿಸುತ್ತದೆ ಮತ್ತು ಒಂದೇ ಬದಿಯು ಯಶಸ್ವಿಯಾಗುವಾಗ ಭಾಗಶಃ ಫಲಿತಾಂಶವನ್ನು ವರದಿ ಮಾಡುತ್ತದೆ. ಅಮಾನ್ಯ `audioTranscript` ಆ ಭಾಗಶಃ ಫಲಿತಾಂಶಕ್ಕೆ ಕುಸಿತಗೊಳ್ಳುತ್ತದೆ — ದೃಶ್ಯ ವಿವರಣೆ ಉಳಿಯುತ್ತದೆ ಮತ್ತು ಧ್ವನಿ ಶಾಖೆ ಶುದ್ಧೀಕೃತ ವಿಫಲ ಕೋಡ್ ಅನ್ನು ದಾಖಲಿಸುತ್ತದೆ — ಸಂಪೂರ್ಣ ವಿಡಿಯೋವನ್ನು ವಿಫಲಗೊಳಿಸುವ ಬದಲು. ಪ್ರತಿ ಶಾಖೆಯ ಲಭ್ಯತೆ, ಭಾಗಶಃ ಧ್ವಜ ಮತ್ತು ಶುದ್ಧೀಕೃತ ವಿಫಲ ಕೋಡ್‌ಗಳನ್ನು ವಿವರಿಸಿದ ಫಲಿತಾಂಶದಲ್ಲಿ, ಗಾರ್ಡ್‌ರೇಲ್ ಮೆಟಾಡೇಟಾದಲ್ಲಿ (`audioFusionRuns`/`audioFusionPartials`/`audioFusionFailureCodes`), ಫಲಿತಾಂಶ-ಕ್ಯಾಶ್ ಮೆಟಾಡೇಟಾದಲ್ಲಿ ಮತ್ತು ಬ್ರಿಡ್ಜ್ ಫ್ಯೂಷನ್ ಕೌಂಟರ್‌ಗಳಲ್ಲಿ ಉಳಿಸಲಾಗುತ್ತದೆ. ಡೀಫಾಲ್ಟ್ ವಿಡಿಯೋ ಬ್ರಿಡ್ಜ್ ಮಾರ್ಗವು ಭಾಷಣ-ಟು-ಪಠ್ಯವನ್ನು ಉಲ್ಲೇಖಿಸುವುದಿಲ್ಲ ಅಥವಾ ಎರಡನೇ ಮಾಧ್ಯಮ ನಕಲನ್ನು ಡೌನ್‌ಲೋಡ್ ಮಾಡುವುದಿಲ್ಲ; ಆ ಸ್ಪಷ್ಟ ಟ್ರಾಕ್ ಇಲ್ಲದಿದ್ದರೆ, ಇದು ವಿಡಿಯೋ-ಮಾತ್ರವಾಗಿರುತ್ತದೆ.

**ವರ್ಣನ ಉಳಿವು (#12150 P1).** ಇದು ಸ್ವಯಂ-ಆಪ್ಟ್-ಇನ್ ಆಗಿರುವ ವಿಡಿಯೋ ಬ್ರಿಡ್ಜ್ ವರ್ಣನ ಸೂಚಕವನ್ನು ನಿರ್ವಹಿಸುವಾಗ ಸ್ವಯಂ-ಆಟೋಮ್ಯಾಟಿಕ್ ಆಗಿ ಅನ್ವಯಿಸುತ್ತದೆ — ಪ್ರತ್ಯೇಕ ಉಳಿವಿನ ಧ್ವಜವಿಲ್ಲ. ಒಂದು ವಿನಂತಿ ಯಾವುದೇ ವರ್ಣನ ಸೂಚಕವನ್ನು (ಕೋಲರ್-ಘೋಷಿತ `transcript` ಅಥವಾ ಫ್ಯೂಸ್ ಮಾಡಿದ `audioTranscript`) ನಿರ್ವಹಿಸಿದಾಗ, ಗಾರ್ಡ್‌ರೇಲ್ ಅದನ್ನು `videoBridgeObserved` ಎಂದು ಗುರುತಿಸುತ್ತದೆ ಮತ್ತು ವಿಡಿಯೋ ವಿವರಣೆಯ ಒಂದು ಸಂಪಾದಿತ ಛಾಯೆ ಉತ್ಪಾದಿಸುತ್ತದೆ — ಪ್ರತಿಯೊಂದು ಸೂಚಕದ ಉಚಿತ-ಪಠ್ಯದ ಶರೀರವನ್ನು `[redacted-video-transcript]` ಮೂಲಕ ಬದಲಾಯಿಸಲಾಗುತ್ತದೆ, ಶ್ರೇಣೀಬದ್ಧ ಸೂಚಕ ಕ್ಷೇತ್ರವನ್ನು ಸ್ಟ್ರಿಂಗ್ ಅನ್ನು ಅಸೆಂಬಲ್ ಮಾಡುವ ಮೊದಲು ಬದಲಾಯಿಸುವ ಮೂಲಕ ನಿರ್ಮಿಸಲಾಗಿದೆ (ಹರಿಯುವ ಪಠ್ಯವನ್ನು ಪಾರ್ಸಿಂಗ್ ಮಾಡುವ ಮೂಲಕ ಎಂದಿಗೂ ಅಲ್ಲ, ಆದ್ದರಿಂದ ಯಾವುದೇ ಸೂಚಕ ವಿಷಯ — ಶತ್ರು ಅಥವಾ ಸಾಮಾನ್ಯ, `]` ಅನ್ನು ಒಳಗೊಂಡ ಶರೀರಗಳನ್ನು ಒಳಗೊಂಡಂತೆ ` [inaudible]`/`[music]` — ಉಳಿಯಲು ಸಾಧ್ಯವಿಲ್ಲ). ಉಳಿಯುವ ಕಾಲ್-ಲಾಗ್ ವಿನಂತಿ ಶರೀರವು ಪ್ರತಿಯೊಂದು ವಿಡಿಯೋ-ಆಧಾರಿತ ಪಠ್ಯ ಭಾಗವನ್ನು ಆ ಸಂಪಾದಿತ ಛಾಯೆಗಾಗಿ ಬದಲಾಯಿಸುತ್ತದೆ, ವಿಷಯ ಸಮಾನಾಂತರದಿಂದ ಹೊಂದಿಸಲಾಗಿದೆ; `fullText` ಆಂಕರ್ ಪೂರ್ಣಗೊಂಡ ಪೂರ್ವ-ಕಾಲ್ ಗಾರ್ಡ್‌ರೇಲ್ ಪೇಲೋಡ್‌ನಿಂದ ಪುನಃ ಓದಲಾಗುತ್ತದೆ, ಆದ್ದರಿಂದ ನಂತರದ ಶ್ರೇಣೀಬದ್ಧ ಗಾರ್ಡ್‌ರೇಲ್‌ಗಳು (PII ಮತ್ತು ಕ್ರೆಡೆನ್ಷಿಯಲ್ ಮಾಸ್ಕರ್‌ಗಳು, ಆದ್ಯತೆ 10/95) ವಿವರಣಾ ಪಠ್ಯವನ್ನು ಸ್ಥಳದಲ್ಲಿ ಪುನರ್-ಲೇಖನ ಮಾಡಿದಾಗ ಮತ್ತು ಸಿಸ್ಟಮ್-ಪ್ರಾಂಪ್ಟ್/ಹ್ಯಾಂಡಾಫ್/ಮೆಮೊರಿ ಇಂಜೆಕ್ಷನ್ ಸಂದೇಶ ಶ್ರೇಣಿಯನ್ನು ಪುನರ್-ಆಕೃತಗೊಳಿಸುತ್ತಿರುವಾಗ, ಹೊಂದಾಣಿಕೆ ಇನ್ನೂ ಯಶಸ್ವಿಯಾಗುತ್ತದೆ. ಮಾದರಿಯತ್ತ ಮೇಲ್ಮಟ್ಟಕ್ಕೆ ಕಳುಹಿಸಲಾದ ಶರೀರವು ಬದಲಾಯಿತಿಲ್ಲ. ಒಂದು ವೀಕ್ಷಿತ ವಿನಂತಿಯು ಯಾವುದೇ ಶಾಶ್ವತ ಮೆಮೊರಿಯನ್ನು ಕೂಡ ತುಂಬಿಸುವುದಿಲ್ಲ (ವಿನಂತಿ ಮತ್ತು ಪ್ರತಿಕ್ರಿಯೆ-ಆಧಾರಿತ ನಿರ್ವಹಣೆಯನ್ನು ಬಿಟ್ಟು), ಆದ್ದರಿಂದ ಮಾದರಿಯ ಸ್ವಂತ ಪ್ರತಿಕ್ರಿಯೆ ಮೆಮೊರಿಯಲ್ಲಿಯೇ ವರ್ಣನ ಪಠ್ಯವನ್ನು ಪ್ರತಿಬಿಂಬಿಸಲು ಸಾಧ್ಯವಿಲ್ಲ.

**ಕಚ್ಚಾ ವಿಡಿಯೋ ಕ್ಷೇತ್ರಗಳು (#12430).** ಬ್ರಿಡ್ಜ್ ಸಕ್ರಿಯಗೊಂಡಾಗ ಮತ್ತು ಸ್ಥಳೀಯ ವಿಡಿಯೋ ಬೆಂಬಲವನ್ನು ತಿಳಿಯದಾಗ ಅಥವಾ ಇಲ್ಲದಾಗ, ವ್ಯಾಖ್ಯಾನಿತ `transcript`/`audioTranscript` ಕ್ಷೇತ್ರಗಳು `videoBridgeObserved` ಅನ್ನು ಸಕ್ರಿಯಗೊಳಿಸುತ್ತವೆ, ವಿವರಣೆ ವಿಫಲವಾದಾಗ ಅಥವಾ `maxVideos` ಮಿತಿಯ ನಂತರವೂ. `null` ಮತ್ತು ಖಾಲಿ ಶ್ರೇಣಿಗಳು ಎಣಿಸುತ್ತವೆ; ಇಲ್ಲದ ಕ್ಷೇತ್ರಗಳು ಮತ್ತು ಅನ್-ವಿಡಿಯೋ ಮೆಟಾಡೇಟಾ ಎಣಿಸುವುದಿಲ್ಲ. ಉಳಿಯುವ ನಕಲುಗಳು ಈ ಕ್ಷೇತ್ರಗಳನ್ನು ಸಂಪಾದಿಸುತ್ತವೆ ಅಥವಾ ವಿನಂತಿಯನ್ನು ಬಿಟ್ಟುಹೋಗುತ್ತವೆ, ಮತ್ತು ಕ್ಯಾಶ್/ಮೆಮೊರಿ ಬypass ಮಾಡಲಾಗುತ್ತದೆ.

ಈ ಹಿನ್ನೋಟ ಮಾರ್ಗಗಳಲ್ಲಿ, ಮಾನ್ಯ ಕರೆದಾರರ ಸೂಚನೆಗಳು ಅಸಾಮಾನ್ಯ ಒದಗಿಸುವವರ ಕ್ಷೇತ್ರಗಳ ಬದಲು ಬೆಂಬಲಿತ `text`/`input_text` ಭಾಗಗಳಾಗುತ್ತವೆ. ಎರಡೂ ವಿನಂತಿ-ಸೂಚಿಸಲಾದ ಪಠ್ಯಗಳು ಅಸಂಬದ್ಧ `client` ವೀಕ್ಷಣೆಗಳಾಗಿವೆ, ವಿಡಿಯೋವನ್ನು ವಿವರಿಸಲಾಗಿಲ್ಲ ಮತ್ತು ಸಮಯಚಿಹ್ನೆಗಳನ್ನು ಮಾಧ್ಯಮದ ವಿರುದ್ಧ ಪರಿಶೀಲಿಸಲಾಗಿಲ್ಲ ಎಂಬ ಸ್ಪಷ್ಟ ಎಚ್ಚರಿಕೆ ಇದೆ. ಇತ್ತೀಚಿನ 256-ಸೂಚನೆ/64-KiB ಒಟ್ಟು ಮತ್ತು ಪ್ರತಿ-ಸೂಚನೆ ಬಜೆಟ್‌ಗಳು ಎರಡೂ ಪಠ್ಯಗಳ ಮೇಲೆ ಅನ್ವಯಿಸುತ್ತವೆ; ಸಮಯಚಿಹ್ನೆಗಳು ಬ್ರೋಕರ್‌ನ 600-ಸೆಕೆಂಡು ಮಿತಿಯಲ್ಲಿಯೇ ಇರಬೇಕು ಮತ್ತು ಯಾವುದೇ ಒದಗಿಸಲಾದ ಕೇಂದ್ರೀಕೃತ ಕಿಟಕಿಯಲ್ಲಿಯೇ ಇರಬೇಕು. ಅಮಾನ್ಯ ಪಠ್ಯಗಳನ್ನು ತಿರಸ್ಕಾರ ಮಾಡಲಾಗುತ್ತದೆ, ಅಸಾಮಾನ್ಯ ಪಠ್ಯವಾಗಿ ಮುಂದುವರಿಸಲಾಗುವುದಿಲ್ಲ; ಅವರ ಸಂಯೋಜಿತ ಬಜೆಟ್ ಮೀರಿದರೆ ಮಾನ್ಯ ಸಹೋದರವನ್ನು ಬಳಸಬಹುದು. ಶೂನ್ಯ/ಖಾಲಿ ಕ್ಷೇತ್ರಗಳು ಯಾವುದೇ ಪಠ್ಯವನ್ನು ಸೇರಿಸುತ್ತವೆ. ಈ ಹಿನ್ನೋಟದಿಂದ ಯಾವುದೇ ಮಾಧ್ಯಮವನ್ನು ಪಡೆಯುವುದು ಅಥವಾ ವರ್ಣನೆಯನ್ನು ಸೇರಿಸಲಾಗುವುದಿಲ್ಲ. ವರ್ಣನೆಯನ್ನು ವಿಸ್ತರಿಸುವ ಕ್ಷೇತ್ರಗಳನ್ನು ಹಿನ್ನೋಟ ವಿಡಿಯೋ ಕೇರಿಯರ್ ಮತ್ತು ಅದರ `video_url`/`source` ವಸ್ತುಗಳಿಂದ ತೆಗೆದುಹಾಕಲಾಗುತ್ತದೆ. OpenAI ವೈರ್ ಅನುಮತಿಸು ಕಠಿಣವಾಗಿರುತ್ತದೆ; ಅಜ್ಞಾತ-ಸ್ಥಳೀಯ ವಿಡಿಯೋ ಕೇರಿಯರ್‌ಗಳು ಲಭ್ಯವಿರುತ್ತವೆ ಮತ್ತು ತಿಳಿದ ಪಠ್ಯ-ಮಾತ್ರ ಗುರಿಗಳು ಸುರಕ್ಷಿತ ಗುರುತಿಗಳನ್ನು ಕಾಯ್ದಿರಿಸುತ್ತವೆ. ರಚಿತ ಅಳವಡಿಕೆ ನೆರಳು ಸೇರಿಸಲಾದ ವರ್ಣನೆಯ ಪಠ್ಯವನ್ನು ರಕ್ಷಿಸುತ್ತದೆ, ಆದರೆ ಮೂಲ ಕರೆದಾರ-ಸ್ವಾಮ್ಯದ ವಿನಂತಿ ಬದಲಾಯಿಸಲಾಗುವುದಿಲ್ಲ. ಸ್ಥಳೀಯ ಬೆಂಬಲಿತ ಗುರಿಗಳು ಮತ್ತು ನಿಷ್ಕ್ರಿಯ ಸೇತುವೆಗಳು ತಮ್ಮ ಇತ್ತೀಚಿನ ಬypass ವರ್ತನೆಯನ್ನು ಕಾಯ್ದಿರಿಸುತ್ತವೆ.

ಹೆಚ್ಚುವರಿ ಉಳಿಸಲಾದ ನಕಲುಗಳು ಒಂದೇ ವೀಕ್ಷಿತ-ವಿನಂತಿ ಸಂಕೇತವನ್ನು ಬಳಸುತ್ತವೆ. ಕಚ್ಚಾ ಪೂರ್ವ-ಗೋಚಿ ಕ್ಲೈಂಟ್-ವಿನಂತಿ ಸ್ನಾಪ್‌ಶಾಟ್, ಮೆಮೊರಿ‌ನಲ್ಲಿ ಬಾಕಿ ಇರುವ ವಿನಂತಿ, ಮತ್ತು ಮುಂಚಿನ ತಿರಸ್ಕೃತ-ವಿನಂತಿ ಲಾಗ್ ರಚನಾತ್ಮಕವಾಗಿ ವಿಡಿಯೋ ಭಾಗಗಳಲ್ಲಿ ವರ್ಣನಾ ಕ್ಷೇತ್ರಗಳನ್ನು ಬದಲಾಯಿಸುತ್ತವೆ; ಪೈಪ್‌ಲೈನ್ ಹಂತಗಳು ಮತ್ತು ಸಂದರ್ಭ ಹಸ್ತಾಂತರದಿಂದ ಸಂಶ್ಲೇಷಿತ ಶ್ರೇಣೀಬದ್ಧ ಪ್ರಾಂಪ್ಟ್‌ಗಳನ್ನು ಉಳಿಸಲಾದ-ವಿನಂತಿ-ಶರೀರದ ತೋಳದಲ್ಲಿ ಅಳವಡಿಸಲಾಗುತ್ತದೆ. ಉಳಿಸಲಾದ `video_content_removed` ಗುರುತಿನ ಚಿಹ್ನೆ `previous_response_id` ಮುಂದುವರಿಯುವಿಕೆಯನ್ನು ಮುಚ್ಚುತ್ತದೆ, ಬದಲಾಗಿ ಉದ್ದೇಶಿತವಾಗಿ ತಿರಸ್ಕಾರ ಮಾಡಲಾದ ಪಠ್ಯವನ್ನು ಪುನರ್‌ರಚಿಸಲು. ವೀಕ್ಷಿತ ವಿನಂತಿಯು ಲಾಗ್ ಮಾಡುವ ಮೊದಲು ಅದರ ಪ್ರತಿ-ಭಾಗದ ಅಳವಡಿಕೆ ನೆರಳನ್ನು ಕಳೆದುಕೊಳ್ಳುವಾಗ, ಅಥವಾ ನಂತರದ ವಿನಂತಿ ಪರಿವರ್ತನೆಗಳ ನಂತರ ಹಲವಾರು ವಿಡಿಯೋ ನೆರಳಗಳಲ್ಲಿ ಒಂದೇ ಒಂದೇ ಹೊಂದಾಣಿಕೆಯಾಗದಾಗ, ಉಳಿಸಲಾದ ವಿನಂತಿ ಶರೀರವನ್ನು ಸಂಪೂರ್ಣವಾಗಿ ಬಿಟ್ಟುಹೋಗುತ್ತದೆ, ಭಾಗಶಃ ಅಳವಡಿಸಲಾದ ವರ್ಣನೆಯನ್ನು ಉಳಿಸುವ ಬದಲು.

ವೀಕ್ಷಿತ ವಿನಂತಿಯು, ಮಾದರಿ ಪ್ರತಿಕ್ರಿಯೆ ಯಾವುದೇ ಭಾಗವನ್ನು ವರ್ಣನೆಯಿಂದ ಉಲ್ಲೇಖಿಸಬಹುದು, ರಚಿತ ಸೂಚನೆ ಗಡಿಯನ್ನು ಇಲ್ಲದೆ. ಇದರ ಉಳಿಸಲಾದ ಕರೆ-ಲಾಗ್ `responseBody` ಆದ್ದರಿಂದ ಒಂದು ತಿರಸ್ಕಾರ ಗುರುತಿನಿಂದ ಬದಲಾಯಿಸಲಾಗುತ್ತದೆ; ವಿವರವಾದ ಪೈಪ್‌ಲೈನ್ ಕಲ್ಪನೆ (ಯಾವುದೇ ಮೇಲ್ಮಟ್ಟ/ಕ್ಲೈಂಟ್ ಶರೀರಗಳು ಮತ್ತು ಸ್ಟ್ರೀಮ್ ತುಂಡುಗಳನ್ನು ಒಳಗೊಂಡಿರಬಹುದು) ಉಳಿಸಲಾಗುವುದಿಲ್ಲ. ಅರ್ಥಶಾಸ್ತ್ರ, ಐಡಂಪೊಟೆನ್ಸಿ, ಮತ್ತು ಯೋಚನೆಯ ಪುನರಾವೃತ್ತ ಕ್ಯಾಶ್‌ಗಳು ಆ ವಿನಂತಿಯ ಓದು ಮತ್ತು ಬರೆಯುವಿಕೆಯನ್ನು ಬypass ಮಾಡುತ್ತವೆ. ಒದಗಿಸುವವರ ವಿನಂತಿ ಮತ್ತು ಕ್ಲೈಂಟ್-ದೃಶ್ಯ ಪ್ರತಿಕ್ರಿಯೆ ಬದಲಾಯಿಸಲಾಗುವುದಿಲ್ಲ. ವಿವರವಾದ ಕಲ್ಪನೆಯು ಬಿಟ್ಟುಹೋಗುವಾಗ ತಾತ್ಕಾಲಿಕ ಬಫರ್‌ನಿಂದ ಮುಂಚಿನ ಕೀಪಾಲಿವ್ ಬೈಟ್ಗಳನ್ನು ಹೀರುವುದಿಲ್ಲ. ಕಿರೋನ ಅಸಮರ್ಥಿತ ಇವೆಂಟ್‌ಸ್ಟ್ರೀಮ್ ಎಚ್ಚರಿಕೆ payload ಬೈಟ್ ಸಂಖ್ಯೆಯನ್ನು ಮಾತ್ರ ವರದಿ ಮಾಡುತ್ತದೆ, ಅದರ ವಿಷಯ ಅಥವಾ JSON ಪಾರ್ಸರ್‌ನ ಕಚ್ಚಾ ದೋಷವನ್ನು ಎಂದಿಗೂ ಅಲ್ಲ.

ಈದು ಪ್ರತಿ ಸಂಬಂಧವಿಲ್ಲದ ಒದಗಿಸುವವರ/ಪ್ಲಗಿನ್ ನಿರೀಕ್ಷಣೆಯನ್ನು ಪರಿಶೀಲಿಸಲಾಗಿದೆ ಎಂದು ಹೇಳುವುದಿಲ್ಲ; ವ್ಯಾಪಕವಾಗಿ ಉಳಿಸಲಾದ-ತೋಳವನ್ನು #11658 ನಲ್ಲಿ ಟ್ರ್ಯಾಕ್ ಮಾಡಲಾಗಿದೆ.

ಆಂತರಿಕ `/api/modality-bridge/video/drilldown` ಜೀವನಚರಿತ್ರೆ ಪ್ರತ್ಯೇಕ, ಲೂಪ್ಬಾಕ್/ಟೋಕನ್-ಅಥೆಂಟಿಕೇಟೆಡ್ ಕ್ಯಾಶ್ ಉಪಭೂಮಿಯಾಗಿದೆ. ಪ್ರತಿಯೊಂದು ಕಾರ್ಯಾಚರಣೆಯು ಕಾನೋನಿಕಲ್ ಓಪಾಕ್ ಪ್ರಿನ್ಸಿಪಲ್ ID ಅನ್ನು ಅಗತ್ಯವಿದೆ. ಉತ್ಪಾದನಾ ಕರೆದಾರವನ್ನು ಸಕ್ರಿಯಗೊಳಿಸುವ ಮೊದಲು, ಅದು ಪ್ರಮಾಣೀಕೃತ ಟೆನಂಟ್‌ನಿಂದ ಆ ID ಅನ್ನು ಪಡೆಯಬೇಕು ಮತ್ತು ಕ್ಲೈಂಟ್-ಚಯನಿತ ಮೌಲ್ಯವನ್ನು ಎಂದಿಗೂ ಮುಂದುವರಿಯಬಾರದು. ಕ್ಯಾಶ್ ಕೀಗಳು ಆ ಪ್ರಿನ್ಸಿಪಲ್ ಅನ್ನು ಕಾನೋನಿಕಲ್ ಸೆಷನ್ ಮತ್ತು ವಿಡಿಯೋ-ಉಲ್ಲೇಖ IDಗಳಿಗೆ ಬಂಧಿಸುತ್ತವೆ, ಕೇವಲ ಅವರ SHA-256-ನಿಂದ ಪಡೆದ ಕೀಗಳನ್ನು ಸಂಗ್ರಹಿಸುತ್ತವೆ, ಮತ್ತು ಓದು ಮತ್ತು ಅಳವಡಿಕೆಯನ್ನು ಒಂದೇ ಪ್ರಿನ್ಸಿಪಲ್‌ಗೆ ವ್ಯಾಪಿಸುತ್ತವೆ. ಕ್ಯಾಶ್ ಪ್ರತಿ ಎಂಟ್ರಿಗೆ 16 ಪಡೆದ JPEG ಫ್ರೇಮ್‌ಗಳನ್ನು ಹೆಚ್ಚು ಸಂಗ್ರಹಿಸುತ್ತದೆ, ಹತ್ತು ನಿಮಿಷಗಳ ನಂತರ ಅವುಗಳನ್ನು ಮುಗಿಸುತ್ತದೆ, ಮತ್ತು ನಿರ್ದಿಷ್ಟ ಸೆಷನ್ ಅಳವಡಿಕೆಗೆ ಅಥವಾ ಬounded `start`/`end` ಓದುಗಳಿಗೆ ಬೆಂಬಲಿಸುತ್ತದೆ.

ಪ್ರತಿ ಪ್ರಿನ್ಸಿಪಲ್ 16 ಎಂಟ್ರಿಗಳು ಮತ್ತು 64 MiB ಕಾನೋನಿಕಲ್ JPEG ಡೇಟಾಗೆ ಮಿತಿಯಲ್ಲಿದೆ. ಆ ಮಿತಿಗಳು ಜಾಗತಿಕ 64-ಎಂಟ್ರಿ/256 MiB ಮಿತಿಯಿಂದ ಸ್ವಾಯತ್ತವಾಗಿವೆ: ಪ್ರಿನ್ಸಿಪಲ್ ಕೋಟಾ ಒತ್ತಣೆ ಕೇವಲ ಆ ಪ್ರಿನ್ಸಿಪಲ್‌ನ ಕಡಿಮೆ-ಇತ್ತೀಚಿನ-ಬಳಸಿದ ಎಂಟ್ರಿಗಳನ್ನು ಹೊರಗೊಮ್ಮಲು ಮಾಡುತ್ತದೆ, ಜಾಗತಿಕ LRU ತಿರಸ್ಕಾರ ಪರಿಗಣನೆಯ ಮೊದಲು. ಮುಗಿದ ಎಂಟ್ರಿಗಳನ್ನು ಕ್ಯಾಶ್ ಚಟುವಟಿಕೆಯಲ್ಲಿ ಪ್ರಿನ್ಸಿಪಲ್ ಮತ್ತು ಜಾಗತಿಕ ಲೆಕ್ಕಾಚಾರದಿಂದ ತೆಗೆದುಹಾಕಲಾಗುತ್ತದೆ, ಆದರೆ ರದ್ದುಗೊಳಿಸುವಿಕೆ ಮತ್ತು ಪ್ರಮಾಣೀಕರಣ ವಿಫಲವಾದಾಗ ಭಾಗಶಃ ಬದಲಾವಣೆಗಳನ್ನು ಬದ್ಧಗೊಳಿಸುವುದಿಲ್ಲ.

ಕ್ಯಾಶ್ ಅಕಾನೋನಿಕಲ್ ಬೇಸ್64, ಹೆಚ್ಚುವರಿ ಪ್ಯಾಡಿಂಗ್, ಅಜ್ಞಾತ-JPEG ಮಾಧ್ಯಮ, ಅಸಮರ್ಥಿತ ಅಥವಾ ಕತ್ತರಿಸಿದ JPEGಗಳನ್ನು ತಿರಸ್ಕಾರ ಮಾಡುತ್ತದೆ, ಮತ್ತು ಬounded ಸಂಪೂರ್ಣ-ಚಿತ್ರ `sharp` ಡಿಕೋಡ್ ಮಾಡುವಾಗ ಎಚ್ಚರಿಕೆ ನೀಡುವ JPEGಗಳನ್ನು ತಿರಸ್ಕಾರ ಮಾಡುತ್ತದೆ. ಇದು ಪ್ರತಿಯೊಂದು ಅಂಗೀಕರಿಸಲಾದ ಚಿತ್ರವನ್ನು ಕಾನೋನಿಕಲ್ JPEG ಆಗಿ ಪುನಃ-ಕೋಡ್ ಮಾಡುತ್ತದೆ, ಡಿಕೋಡ್ ಮಾಡಿದ ಬೈಟ್ಸ್‌ನಿಂದ ಅಗಲ ಮತ್ತು ಎತ್ತರವನ್ನು ಪಡೆಯುತ್ತದೆ, ಕರೆದಾರರ ಕ್ಷೇತ್ರಗಳನ್ನು ನಂಬುವುದಿಲ್ಲ, ಮತ್ತು ಯಾವುದೇ ಹಿಂಬಾಲಿಸುವ ಪೋಲಿಗ್ಲಾಟ್ ಬೈಟ್ಸ್ ಅನ್ನು ಉಳಿಸುವ ಬದಲು ತಿರಸ್ಕಾರ ಮಾಡುತ್ತದೆ. ಕೇವಲ ಬounded ಕಾನೋನಿಕಲ್ ಸಂಕೋಚಿತ ಬಫರ್ ಎರಡೂ ಕೋಟಾಗೆ ಚಾರ್ಜ್ ಮಾಡಲಾಗುತ್ತದೆ. JSON ವೈರ್ ಮಿತಿಯು 32 MiB ಡಿಕೋಡ್-ಇನ್ಪುಟ್ ಮಿತಿಯಿಗಾಗಿ ಬೇಸ್64 ಓವರಹೆಡ್ ಅನ್ನು ಒಳಗೊಂಡಿದೆ. ಪ್ರತಿಯೊಂದು
ಉಳಿಸಲಾದ ವ್ಯಾಖ್ಯಾನವು ಅದರ ಪ್ರಮಾಣೀಕೃತ JPEG ಸ್ವರೂಪ/ನಿರ್ಧಾರ, ಮಾದರೀಕರಣ ನೀತಿ, ವ್ಯಾಖ್ಯಾನ ಆವೃತ್ತಿ, ಸೃಷ್ಟಿ ಸಮಯ, ಸರ್ವರ್-ಗಣಿತ ವಿಷಯ ಹ್ಯಾಶ್, ಮತ್ತು ಹ್ಯಾಶ್ ಮಾಡಿದ ಪೋಷಕ ಉಲ್ಲೇಖವನ್ನು ದಾಖಲಿಸುತ್ತದೆ, ಜೊತೆಗೆ ವಿಶ್ವಾಸಾರ್ಹ ಕರೆದಾರನ ಪೋಷಕ-ವಿಷಯ ಹ್ಯಾಶ್ ಅನ್ನು ಸೇರಿಸುತ್ತದೆ. ಅಸಿಂಕ್ರೋನಸ್ ಡಿಕೋಡ್/ಹ್ಯಾಶ್ ಹಂತಗಳ ನಡುವೆ ರದ್ದುಗೊಳಿಸುವಿಕೆ ಪರಿಶೀಲಿಸಲಾಗುತ್ತದೆ, ಅಣು ಕ್ಯಾಶ್ ಬದ್ಧಗೊಳಿಸುವ ಮೊದಲು.

ಉತ್ಪಾದನಾ ಉತ್ಪಾದಕವು ಯಶಸ್ವಿ ದೃಶ್ಯ ವಿಶ್ಲೇಷಣೆಯ ನಂತರ ಮಾತ್ರ ಈಗಾಗಲೇ-ಪಡೆಯಲ್ಪಟ್ಟ ಬ್ರೋಕರ್ ಫ್ರೇಮ್‌ಗಳನ್ನು ಪುನಃ ಬಳಸುತ್ತದೆ, ಎರಡನೇ ವಿಡಿಯೋ ಡೌನ್‌ಲೋಡ್/ಹರಿಯುವಿಕೆ ಇಲ್ಲ. ಇದು ಕಾರ್ಯಾಚರಣಾ `modalityBridgeVideoDrilldownEnabled=true`, ಕಠಿಣ ಪ್ರತಿ-ಭಾಗ `drilldown: true`, ಮತ್ತು ಪ್ರಮಾಣೀಕೃತ API-ಕೀ ದಾಖಲೆ ID ಅನ್ನು ಅಗತ್ಯವಿದೆ. ಕ್ಲೈಂಟ್-ಘೋಷಿತ ಪ್ರಿನ್ಸಿಪಲ್/ಸೆಷನ್ ಮೌಲ್ಯಗಳು ಎಂದಿಗೂ ಸ್ವಾಮ್ಯವನ್ನು ಸ್ಥಾಪಿಸುತ್ತವೆ. ಈ ಮೂರು ಶರತ್ತುಗಳಿಲ್ಲದೆ, ಇದು ಹ್ಯಾಶ್, ಪುನರ್-ಗಾತ್ರ ಅಥವಾ ಹೆಚ್ಚುವರಿ ಫ್ರೇಮ್‌ಗಳನ್ನು ಉಳಿಸುವುದಿಲ್ಲ. ಉಳಿಸುವ ವಿಫಲವು ಬಳಸಬಹುದಾದ ದೃಶ್ಯ ಪ್ರತಿಕ್ರಿಯೆಯನ್ನು ಕಾಯ್ದಿರಿಸುತ್ತದೆ. ಒಪ್ಪಿಗೆಯಾದ ವಿನಂತಿಗಳು ಸಂಪೂರ್ಣ-ವಿಡಿಯೋ ಫಲಿತಾಂಶ ಕ್ಯಾಶ್ ಅನ್ನು ಬypass ಮಾಡುತ್ತವೆ, ಆದ್ದರಿಂದ ಕ್ಯಾಶ್ ಮಾಡಿದ ಫಲಿತಾಂಶಗಳು ಎಂದಿಗೂ ಪುನರಾವೃತ್ತ ಕೈಗಾರಿಕೆಗಳನ್ನು ಹೊಂದಿಲ್ಲ.

ಯಶಸ್ವಿ JSON ಮತ್ತು SSE ಪ್ರತಿಕ್ರಿಯೆಗಳು ಗರಿಷ್ಠವಾಗಿ ನಾಲ್ಕು ಅಸ್ಪಷ್ಟ ಹ್ಯಾಂಡಲ್‌ಗಳನ್ನು ಬೌಂಡೆಡ್ `x-omniroute-video-drilldown` ಹೆಡರ್‌ನಲ್ಲಿ ಬಹಿರಂಗಪಡಿಸುತ್ತವೆ. ಅನುಮತಿತ ಬ್ರೌಸರ್ ಮೂಲಗಳು ಆ ಹೆಡರ್ ಅನ್ನು CORS ಮೂಲ ನೀತಿಯನ್ನು ವಿಸ್ತಾರಗೊಳಿಸದೆ ಓದಬಹುದು. ಹೊಸ ಹ್ಯಾಂಡಲ್‌ಗಳು `v1.<32-byte random base64url token>` ಅನ್ನು ಬಳಸುತ್ತವೆ, ಮತ್ತು ರಿಜಿಸ್ಟ್ರಿ ಕೇವಲ ಅವರ SHA-256 ಹ್ಯಾಶ್‌ಗಳನ್ನು ಉಳಿಸುತ್ತದೆ. ಓದುಗರ/ಹೆಡರ್ ಪಾರ್ಸರ್ ಹಳೆಯ 64-ಹೆಕ್ಸ್ ಟೋಕನ್‌ಗಳನ್ನು ಸಹ ಒಪ್ಪಿಸುತ್ತದೆ. ಪ್ರಮಾಣಿತ ಸಾರ್ವಜನಿಕ ಗ್ರಾಹಕವು `GET /api/v1/video-bridge/drilldown?handle=...` ಆಗಿದ್ದು, `modalityBridgeVideoDrilldownRemoteEnabled=true` ಮೂಲಕ ಸ್ವಾಯತ್ತವಾಗಿ ನಿರ್ಬಂಧಿತವಾಗಿದೆ. ಸ್ಪಷ್ಟವಾಗಿ ಉಳಿಸಲಾಗದ ಸುಳ್ಳು ಪ್ರವೇಶವನ್ನು ಹಿಂಪಡೆಯುತ್ತದೆ, ಹಳೆಯ `OMNIROUTE_VIDEO_BRIDGE_DRILLDOWN_REMOTE_ENABLED` env ಬಾಕಿ ಸಕ್ರಿಯವಾಗಿದ್ದರೂ ಸಹ. ಉತ್ಪಾದನಾ ಉಳಿವಿಗೆ ಹೋಲಿಸುವ ಹಳೆಯ `OMNIROUTE_VIDEO_BRIDGE_DRILLDOWN_ENABLED` ಬಾಕಿ ಇದೆ. ಎರಡೂ ಬಾಕಿಗಳು ಡೀಫಾಲ್ಟ್ ಆಫ್ ಆಗಿವೆ.

ಗ್ರಾಹಕವು ಪ್ರಮಾಣಿತ ಕೀದಿಂದ ಸ್ವಾಮ್ಯವನ್ನು ಪಡೆಯುತ್ತದೆ, ಕೀ ನೀತಿಯನ್ನು ಅನ್ವಯಿಸುತ್ತದೆ ಮತ್ತು ಅಜ್ಞಾತ, ಅವಧಿ ಮುಗಿದ ಮತ್ತು ಇನ್ನೊಂದು ಕೀ ಹ್ಯಾಂಡಲ್‌ಗಳಿಗೆ ಒಂದೇ 404 ಅನ್ನು ಹಿಂತಿರುಗಿಸುತ್ತದೆ. ಇದು `variant=preview|standard|detail` (ಗರಿಷ್ಠ JPEG ಆಯಾಮ 320/640/1280, ಎಂದಿಗೂ ಅಪ್‌ಸ್ಕೇಲ್ ಆಗುವುದಿಲ್ಲ), `limit=1..8` (ಅಥವಾ ಹಳೆಯ `frames` ಪರ್ಯಾಯ, ಎಂದಿಗೂ ಎರಡೂ ಅಲ್ಲ), ಶೂನ್ಯ ಆಧಾರಿತ `page`, ಮತ್ತು ಐಚ್ಛಿಕ `start`/`end` ಫೋಕಸ್ ಸೆಕೆಂಡುಗಳನ್ನು ಒಪ್ಪಿಸುತ್ತದೆ. ಪುನರಾವೃತ್ತ ಕ್ವೇರಿ ಕೀಗಳು ಮತ್ತು ಹಿಂತಿರುಗಿದ ಫೋಕಸ್ ಕಿಟಕಿಗಳು ನಿರಾಕರಿಸಲಾಗುತ್ತವೆ. ಪ್ರತಿಯೊಂದು ಹಿಂತಿರುಗಿದ ಪರ್ಯಾಯವು ಅದರ ವಾಸ್ತವ ವಿಷಯ ಮತ್ತು ವಾಸ್ತವ ಪರಿಹಾರ ಮೆಟಾಡೇಟಾದ ಹ್ಯಾಶ್ ಅನ್ನು ಹೊಂದಿದೆ, ಉಳಿಸಲಾದ ಮೂಲಕ್ಕೆ ಸಂಪರ್ಕಿಸಲಾಗಿದೆ. ಪರ್ಯಾಯಗಳನ್ನು ಓದುವಾಗ ಉತ್ಪಾದಿಸಲಾಗುತ್ತದೆ, ಹೆಚ್ಚುವರಿ ಉಳಿಸಲಾದ ನಕಲುಗಳಂತೆ ಸಂಗ್ರಹಿಸಲಾಗುವುದಿಲ್ಲ. JSON ಪ್ರತಿಕ್ರಿಯೆ, Base64/envelope ಅನ್ನು ಒಳಗೊಂಡಂತೆ, 32 MiB ಗೆ ಮಿತಿಯಾಗಿದೆ; ದೊಡ್ಡ ಪುಟವು 413 ಅನ್ನು ಹಿಂತಿರುಗಿಸುತ್ತದೆ ಮತ್ತು ಕ್ಲೈಂಟ್ ಕಡಿಮೆ ಫ್ರೇಮ್‌ಗಳನ್ನು ಕೇಳಬೇಕು. ಓದುಗಳು ಪ್ರತಿಯೊಂದು ಪುನರ್‌ಗೊಳಿಸುವಿಕೆಯ ಸುತ್ತಲೂ ರದ್ದುಪಡಿಸುವಿಕೆಯನ್ನು ಪರಿಶೀಲಿಸುತ್ತವೆ ಮತ್ತು ಹ್ಯಾಂಡಲ್ ಮಾನ್ಯತೆಯನ್ನು ಹಿಂತಿರುಗಿಸುವ ಮೊದಲು ಪುನಃ ಪರಿಶೀಲಿಸುತ್ತವೆ. ಮಾಲೀಕರಿಂದ `DELETE` ಐಡೆಂಪೊಟೆಂಟ್ ಆಗಿದೆ; ಅಳಿಸುವಿಕೆ ಅಥವಾ TTL ಅವಧಿಯ ಮುಗಿಯುವುದು ಉಳಿಸಲಾದ ಮೂಲ ಮತ್ತು ಬಳಕೆ ಲೆಕ್ಕವನ್ನು ಬಿಡುಗಡೆ ಮಾಡುತ್ತದೆ.

ಹಂಚಿದ ಅಂಗಸಾಧನವು ಪ್ರಕ್ರಿಯೆ-ಸ್ಥಳೀಯವಾಗಿದೆ: ಹ್ಯಾಂಡಲ್‌ಗಳು ಪುನಾರಂಭದ ಮೇಲೆ ಮುಗಿಯುತ್ತವೆ ಮತ್ತು ಸ್ವಾಯತ್ತ ಓಮ್ನಿರೌಟ್ ಪ್ರಕ್ರಿಯೆಗಳ ನಡುವೆ ವರ್ಗಾಯಿಸಲಾಗುವುದಿಲ್ಲ. ನಿರ್ವಹಣಾ ಅಂಕಿಅಂಶಗಳು ಪರಿಣಾಮಕಾರಿ ಉಳಿವು/ದೂರದ ನೀತಿಯನ್ನು ಮತ್ತು ಒಟ್ಟಾರೆ ಉಳಿಸಲಾದ ಎಂಟ್ರಿಗಳು/ಬೈಟ್ಸ್ ಅನ್ನು ಮಾತ್ರ ಬಹಿರಂಗಪಡಿಸುತ್ತವೆ, ಎಂದಿಗೂ ಮಾಧ್ಯಮ, ಉಲ್ಲೇಖಗಳು, ಪ್ರಧಾನ IDಗಳು ಅಥವಾ ಹ್ಯಾಂಡಲ್‌ಗಳು ಅಲ್ಲ. ವಿಡಿಯೋ ಸೆಟಿಂಗ್‌ಗಳ ಪ್ಯಾನೆಲ್ ಆ ಮೌಲ್ಯಗಳನ್ನು ತೋರಿಸುತ್ತದೆ ಮತ್ತು ಎರಡೂ ಒಪ್ಪಿಗೆಯ ಸ್ವಿಚ್‌ಗಳನ್ನು ಉಳಿಸಲು ಸಾಧ್ಯವಾಗುತ್ತದೆ. ಈ ಕಾರ್ಯಗತಗೊಳಿಸುವಿಕೆ ಡಾಕ್ಯುಮೆಂಟೇಶನ್ ನೇರ ನಿಯೋಜನೆ ಅಥವಾ ಪ್ರಚಾರದ ಸಾಕ್ಷ್ಯವಲ್ಲ; ವಾಸ್ತವ ಮಾದರಿಯ ಒಪ್ಪಿಗೆಯನ್ನು ಪ್ರತ್ಯೇಕವಾಗಿ ಟ್ರ್ಯಾಕ್ ಮಾಡಲಾಗುತ್ತದೆ.

ಫ್ರೇಮ್‌ಗಳನ್ನು ಸಂರಚಿತ ವಿಡಿಯೋ ಮಾದರಿಯೊಂದಿಗೆ ಕ್ರಮಬದ್ಧವಾಗಿ ಶೀರ್ಷಿಕೆಯನ್ನು ನೀಡಲಾಗುತ್ತದೆ. ಖಾಲಿ ವಿಡಿಯೋ ಓವರೈಡ್ ದೃಷ್ಟಿ ಸೆಟಿಂಗ್ ಅನ್ನು ಹಕ್ಕು ಪಡೆಯುತ್ತದೆ; ಎರಡೂ ಖಾಲಿಯಾಗಿದ್ದರೆ, ದೃಷ್ಟಿ ಸ್ವಾಯತ್ತ-ರೌಟರ್ ಪರಿಣಾಮಕಾರಿ ದೃಷ್ಟಿ-ಸಾಧ್ಯ ಮಾದರಿಯನ್ನು ಆಯ್ಕೆ ಮಾಡುತ್ತದೆ. ಯಶಸ್ವಿ ಶೀರ್ಷಿಕೆಗಳು ಮೂಲ ಭಾಗವನ್ನು ಸ್ಥಿರ `[Video description:` ಪೂರ್ವಭಾವಿಯೊಂದಿಗೆ ಬದಲಾಯಿಸುತ್ತವೆ, ಇದು ಪಠ್ಯವನ್ನು ಅಸಂಬದ್ಧ ಮಾಧ್ಯಮ-ಆಧಾರಿತ ವೀಕ್ಷಣೆಯಾಗಿ ಗುರುತಿಸುತ್ತದೆ ಮತ್ತು ಹಿಂತಿರುಗಿದ ಮಾದರಿಗಳಿಗೆ ಮಾಧ್ಯಮದಲ್ಲಿ ಕಂಡುಬರುವ ಸೂಚನೆಗಳನ್ನು ಅನುಸರಿಸಲು ಹೇಳುತ್ತದೆ. ಫ್ರೇಮ್-ಶೀರ್ಷಿಕೆ ಕ್ಯಾಶ್ ಕೀಗಳಲ್ಲಿ JPEG ಬೈಟ್ಸ್, ಪ್ರಾಂಪ್ಟ್, ಟೈಮ್‌ಸ್ಟ್ಯಾಂಪ್, ಮತ್ತು ಪರಿಣಾಮಕಾರಿ ಮಾದರಿಯು ಒಳಗೊಂಡಿದೆ; ಕೇವಲ ಯಶಸ್ವಿ ಶೀರ್ಷಿಕೆಗಳನ್ನು ಮಾತ್ರ ಕ್ಯಾಶ್ ಮಾಡಲಾಗುತ್ತದೆ. ಕ್ಯಾಶ್ ಎಂಟ್ರಿಗಳು ವಾಸ್ತವ ಯಶಸ್ವಿ ಉತ್ಪಾದಕ ಮಾದರಿಯನ್ನು ಉಳಿಸುತ್ತವೆ, ಬಾಕಿ ಮಾದರಿಯೊಂದಿಗೆ; ಬ್ರೀಜ್ `mixed` ಅನ್ನು ವರದಿ ಮಾಡುತ್ತದೆ, ಏಕೆಂದರೆ ವಿಭಿನ್ನ ಮಾದರಿಗಳಿಂದ ವಿಭಿನ್ನ ಫ್ರೇಮ್‌ಗಳನ್ನು ಉತ್ಪಾದಿಸಲಾಗಿದೆ. ಕ್ಯಾಶ್ ಹಿಟ್ ಆ ಉತ್ಪಾದಕ ಗುರುತನ್ನು ಪುನಃ ಬಳಸುತ್ತದೆ, ಅದನ್ನು ಕೇಳಿದ ಮಾರ್ಗದ ಯೋಜನೆಯಂತೆ ಪುನರ್‌ಲೇಬಲ್ ಮಾಡುವ ಬದಲು. ಸಂಪೂರ್ಣ-ವಿಡಿಯೋ ಫಲಿತಾಂಶ ಕ್ಯಾಶ್ ಪ್ರತಿಯೊಂದು ಇನ್ಪುಟ್‌ನಲ್ಲಿ ಕೀ ಮಾಡಲಾಗುತ್ತದೆ, ಅದು ಔಟ್‌ಪುಟ್ ಅನ್ನು ಬದಲಾಯಿಸುತ್ತದೆ — ಪ್ರಾಂಪ್ಟ್, ಪರಿಣಾಮಕಾರಿ ಮಾದರಿ, ಮಾದರೀಕರಣ ನೀತಿ, ಫ್ರೇಮ್ ಸಂಖ್ಯೆಯು, ಅರ್ಥಶಾಸ್ತ್ರ ವಿಶ್ಲೇಷಣಾ ಮೋಡ್, ನಾರ್ಮಲೈಜ್ಡ್ ಫೋಕಸ್ ಹಿಂಟ್ನ SHA-256 ಫಿಂಗರ್‌ಪ್ರಿಂಟ್, ಫೋಕಸ್ ಕಿಟಕಿಯು, `transcript`, `audioTranscript`, ಮತ್ತು ಸಂಪರ್ಕ-ಶೀಟ್ ಧ್ವಜ — ಆದ್ದರಿಂದ ಆ ಆಯಾಮಗಳಲ್ಲಿ ಯಾವುದಾದರೂ ಬದಲಾವಣೆ ಮಾಡಿದರೆ, ಅದು ಕ್ಯಾಶ್ ಮಿಸ್, ಎಂದಿಗೂ ಹಳೆಯ ಪುನರ್‌ಬಳಕೆ ಅಲ್ಲ. ದೃಶ್ಯ ಡಿಡುಪ್ನ ನೀತಿ ಆವೃತ್ತಿ, ತೂಕ, ಮತ್ತು ಬೌಂಡೆಡ್ ಅಭ್ಯರ್ಥಿ-ಫ್ರೇಮ್ ಸಂಖ್ಯೆಯು ಫಲಿತಾಂಶ-ಕ್ಯಾಶ್ ಕೀ ಮತ್ತು ಮೆಟಾಡೇಟಾದಲ್ಲಿ ಸ್ಪಷ್ಟವಾಗಿದೆ; ಆದ್ದರಿಂದ ನೀತಿ ಬದಲಾವಣೆ ಹಳೆಯ ಸಂಪೂರ್ಣ-ವಿಡಿಯೋ ವಿವರಣೆಯನ್ನು ಪುನರ್‌ಬಳಕೆ ಮಾಡಲಾಗುವುದಿಲ್ಲ. ಫಲಿತಾಂಶ-ಕ್ಯಾಶ್ v4 ಮೆಟಾಡೇಟಾ ಮೋಡ್ ಮತ್ತು ಫಿಂಗರ್‌ಪ್ರಿಂಟ್ ಅನ್ನು ಉಳಿಸುತ್ತದೆ, ಎಂದಿಗೂ ಕಚ್ಚಾ ಬಳಕೆದಾರ ಕಾರ್ಯವನ್ನು ಅಲ್ಲ. ಗಾರ್ಡ್‌ರೇಲ್ ಮೆಟಾಡೇಟಾ ಕೇಳಿದ ಮತ್ತು ಪರಿಣಾಮಕಾರಿ ವಿಶ್ಲೇಷಣಾ ಮೋಡ್‌ಗಳನ್ನು ವರದಿ ಮಾಡುತ್ತದೆ; ಬಳಸಬಹುದಾದ ಬಳಕೆದಾರ ಪಠ್ಯವಿಲ್ಲದ ಕೇಳಿದ `focused` ಮೋಡ್ ಪರಿಣಾಮಕಾರಿಯಾಗಿ `full` ಎಂದು ವರದಿ ಮಾಡುತ್ತದೆ.

ಗಾರ್ಡ್‌ರೇಲ್ ಪ್ರತಿಯೊಂದು ಬೆಂಬಲಿತ ವಿಡಿಯೋ ಭಾಗವನ್ನು ತೆಗೆದುಕೊಳ್ಳುತ್ತದೆ ಆದರೆ `modalityBridgeVideoMaxVideos` ಕ್ಕಿಂತ ಹೆಚ್ಚು ವಿವರಿಸುತ್ತಿಲ್ಲ. `supportsVideo === false` ಅನ್ನು ಹೊಂದಿರುವ ಗುರಿಯಿಗಾಗಿ, ವಿಫಲವಾದ ಮತ್ತು ಮಿತಿಯ ಮೀರಿಸಿದ ವಿಡಿಯೋಗಳು ಸ್ಪಷ್ಟ ಸುರಕ್ಷಿತ ಪಠ್ಯ ಗುರುತಿಸುವಿಕೆಯಾಗುತ್ತವೆ, ಆದ್ದರಿಂದ ಯಾವುದೇ ಕಚ್ಚಾ ವಿಡಿಯೋ ಉಳಿಯುವುದಿಲ್ಲ. ಸಾಮರ್ಥ್ಯ ತಿಳಿದಿಲ್ಲದಾಗ, ಆ ಭಾಗಗಳು ತಮ್ಮ ವಿಡಿಯೋ ಕ್ಯಾರಿಯರ್ ಅನ್ನು ಉಳಿಸುತ್ತವೆ; ಯಾವುದೇ ಬಾಕಿ ಪಠ್ಯ ಮೇಲ್ಕಂಡ ಬೌಂಡೆಡ್ ಪಠ್ಯ ಪರಿವರ್ತನೆಯಂತೆ ಮುಂದುವರಿಯುತ್ತದೆ. `supportsVideo === true` ಅನ್ನು ಹೊಂದಿರುವ ಗುರಿಗಳು ಬ್ರೀಜ್ ಅನ್ನು ಬypass ಮಾಡುತ್ತವೆ. ಕ್ಲೈಂಟ್ ವಿನಂತಿ ನಿಲ್ಲಿಸುವ ಸಂಕೇತವು ಡೌನ್‌ಲೋಡ್, ಬ್ರೋಕರಿಂಗ್ ಕ್ಯೂ, ಉಪಪ್ರಕ್ರಿಯೆಗಳು, ಮತ್ತು ಶೀರ್ಷಿಕೆ ಕರೆಗಳ ಮೂಲಕ ಹರಡುತ್ತದೆ; ನಿಲ್ಲಿಸುವಿಕೆಗಳು ವಿಡಿಯೋಗಳ ನಡುವಿನ ಅಂತರದಲ್ಲಿ ನಿಲ್ಲಿಸುತ್ತವೆ ಮತ್ತು ಎಂದಿಗೂ ಕಚ್ಚಾ ಮಾಧ್ಯಮಕ್ಕೆ ತೆರಳುವುದಿಲ್ಲ.

Legacy persisted Video timeout values above 120 seconds are clamped to the
broker deadline; new settings writes above that limit are rejected.
`GET /api/modality-bridge/video/runtime` requires trusted stamped loopback
locality before authentication or runtime probing, then requires management
auth. It returns only `available`, sanitized FFmpeg/ffprobe versions, and a fixed
reason when the runtime is unavailable. The internal extraction endpoint is not
a public upload API: queue saturation returns `503` plus `Retry-After`, a caller
disconnect returns `499`, and the fixed broker deadline returns `504`. Converted responses add
`video->text;model=<visionModel>;parts=<videos>` to the central
`x-omniroute-modality-bridge` header without removing Vision or Audio segments.

**ಎಲ್ಲಾ** ಹಂತಗಳಲ್ಲಿ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತದೆ.

- **`preCall`** ಪೇಲೋಡ್ ಅನ್ನು ಕ್ಲೋನ್ ಮಾಡುತ್ತದೆ, `system`, `messages`, `input`, ಮತ್ತು
  `prompt` (ಸರಳ ಸ್ಟ್ರಿಂಗ್ ಐಟಮ್‌ಗಳನ್ನು ಒಳಗೊಂಡಂತೆ) ಅನ್ನು ಸಾಗಿಸುತ್ತದೆ ಮತ್ತು `processPII()` (from
  `@/shared/utils/inputSanitizer`) ಅನ್ನು ಸ್ಟ್ರಿಂಗ್ `content`/`text` ಕ್ಷೇತ್ರಗಳಿಗೆ ಅನ್ವಯಿಸುತ್ತದೆ. `PII_REDACTION_ENABLED=true` ಆಗಿರುವಾಗ, ಪತ್ತೆಯಾದ PII ಹೊರಗಿನ
  ಪೇಲೋಡ್‌ನಲ್ಲಿ ಅಡಗಿಸಲಾಗುತ್ತದೆ. ಇದು `INPUT_SANITIZER_MODE` ಗೆ ಸ್ವಾಯತ್ತವಾಗಿದೆ (ಇದು ಕೇವಲ
  ಪ್ರಾಂಪ್ಟ್-ಇಂಜೆಕ್ಷನ್ ನೀತಿಯನ್ನು ನಿಯಂತ್ರಿಸುತ್ತದೆ). ಅಡಗಿಸುವಿಕೆ ಆಫ್ ಆಗಿರುವಾಗ, ಕರೆ ದಾಖಲೆ ಪತ್ತೆ
  ಸಂಖ್ಯೆಯನ್ನು ಪುನರ್‌ಲೇಖನ ಮಾಡದೆ ದಾಖಲಿಸುತ್ತದೆ.
- **`postCall`** ಪ್ರತಿಕ್ರಿಯೆಯನ್ನು ಡೀಪ್-ಕ್ಲೋನ್ ಮಾಡುತ್ತದೆ, `sanitizePIIResponse()` ಅನ್ನು ಕಾರ್ಯಗತಗೊಳಿಸುತ್ತದೆ ಮತ್ತು
  ಪ್ರತಿಕ್ರಿಯೆಗಳು-ಎಪಿಐ-ಆಕೃತಿಯ ಮಾಸ್ಕರ್ (`maskResponsesOutput` — `output_text` ಮತ್ತು `output[].content[].text` ಅನ್ನು ಒಳಗೊಂಡಿದೆ). ಯಾವುದೇ ಅಡಗಿಸುವಿಕೆ ಸಂಭವಿಸಿದರೆ,
  ಬದಲಾಯಿತ ಪ್ರತಿಕ್ರಿಯೆ ಮೂಲವನ್ನು ಬದಲಾಯಿಸುತ್ತದೆ.

ಗಾರ್ಡ್‌ರೇಲ್ ಎಂದಿಗೂ ಅಡ್ಡಗೋಚಿ ಮಾಡುವುದಿಲ್ಲ; ಇದು ಕೇವಲ ಟಿಪ್ಪಣಿಗಳನ್ನು ಸೇರಿಸುತ್ತದೆ (`meta.detections`,
`meta.redacted`) ಅಥವಾ ಪುನರ್‌ಲೇಖನ ಮಾಡುತ್ತದೆ.

### Prompt Injection (`promptInjection.ts`)

ಬಳಕೆದಾರ-ನೀಡಿದ ವಿಷಯದಲ್ಲಿ ಶತ್ರುಶ್ರೇಣಿಗಳನ್ನು ಪತ್ತೆಹಚ್ಚುತ್ತದೆ ಮತ್ತು
ನಿಯೋಜಿತ ನೀತಿಯನ್ನು ಕಡ್ಡಾಯಗೊಳಿಸುತ್ತದೆ. ವರ್ತನೆ ಪರಿಸರ ಚರಗಳು ಮತ್ತು ನಿರ್ಮಾಪಕ
ಆಪ್ಷನ್‌ಗಳಿಂದ ನಿರ್ಧಾರವಾಗುತ್ತದೆ:

| ಸೆಟಿಂಗ್           | ಪರಿಸರ ಚರ                                                                                               | ಡೀಫಾಲ್ಟ್ | ಪರಿಣಾಮ                                                                                                                                                                                                     |
| ----------------- | ------------------------------------------------------------------------------------------------------ | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ಸಕ್ರಿಯ            | `INPUT_SANITIZER_ENABLED`                                                                              | `true`   | `false` ಆಗಿರುವಾಗ, ಗಾರ್ಡ್‌ರೇಲ್ ಶಾರ್ಟ್-ಸರ್ಕಿಟ್ ಮಾಡುತ್ತದೆ.                                                                                                                                                    |
| ಮೋಡ್              | `INJECTION_GUARD_MODE` / `INPUT_SANITIZER_MODE`                                                        | `warn`   | ಇಂಜೆಕ್ಷನ್ ನೀತಿ: `block`, `warn`, ಅಥವಾ `log`. (`redact` ಹಿಂದಿನ-ಸಂಗತಕ್ಕಾಗಿ ಒಪ್ಪಿಗೆಯಾಗಿದೆ ಆದರೆ ಇಂಜೆಕ್ಷನ್ ಪಠ್ಯವನ್ನು **ಕತ್ತರಿಸುವುದಿಲ್ಲ**; PII ಪುನರ್‌ಲೇಖನವನ್ನು `PII_REDACTION_ENABLED` ಮೂಲಕ ನಿಯಂತ್ರಿಸಲಾಗುತ್ತದೆ.) |
| ಬ್ಲಾಕ್ ಥ್ರೆಶೋಲ್ಡ್ | `blockThreshold` ಆಯ್ಕೆಯು / `INPUT_SANITIZER_BLOCK_THRESHOLD` (ಉಪನಾಮ `INJECTION_GUARD_BLOCK_THRESHOLD`) | `high`   | ಬ್ಲಾಕ್ ಮಾಡಲು ಅಗತ್ಯವಿರುವ ಕನಿಷ್ಠ ತೀವ್ರತೆ. ಮಧ್ಯಮವು ಡೀಫಾಲ್ಟ್‌ನಲ್ಲಿ ಕೇವಲ ಗಮನಿಸುವುದಾಗಿದೆ.                                                                                                                        |

**ಮೋಡ್ ಆದ್ಯತೆ** (`getMode`): ಕರೆಗಾರ `options.mode` →
`INJECTION_GUARD_MODE` **ಡಿಬಿ ವೈಶಿಷ್ಟ್ಯ-ಫ್ಲಾಗ್ ಓವರ್ರೈಡ್** (ಡ್ಯಾಶ್‌ಬೋರ್ಡ್ → ಸೆಟಿಂಗ್‌ಗಳು →
ವೈಶಿಷ್ಟ್ಯ ಫ್ಲಾಗ್‌ಗಳು) → `INJECTION_GUARD_MODE` ಪರಿಸರ → `INPUT_SANITIZER_MODE` ಪರಿಸರ →
`warn`. ಡ್ಯಾಶ್‌ಬೋರ್ಡ್ ಓವರ್ರೈಡ್ ಆದ್ದರಿಂದ ಪರಿಸರ ಚರಗಳನ್ನು ಮೀರಿಸುತ್ತದೆ, ಆದ್ದರಿಂದ ವೈಶಿಷ್ಟ್ಯ
ಫ್ಲಾಗ್‌ಗಳು UI ನೇರವಾಗಿ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತವೆ (ಮರುಪ್ರಾರಂಭವಿಲ್ಲ). ಡಿಬಿ ಓದು ವಿಫಲ-ಸುರಕ್ಷಿತವಾಗಿದೆ:
ಅದು ದೋಷವಾಗಿದ್ದರೆ, ಗಾರ್ಡ್ ಪರಿಸರ ಆಧಾರಿತ ವರ್ತನೆಗೆ ಹಿಂತಿರುಗುತ್ತದೆ, ಮತ್ತು ಯಾವುದೇ
ಓವರ್ರೈಡ್ ಹೊಂದಿಲ್ಲದಾಗ ವರ್ತನೆ ಪರಿಸರ-ಮಾತ್ರ ಪರಿಹಾರಕ್ಕೆ ಸಮಾನವಾಗಿದೆ.

ಪತ್ತೆ ಮೂಲಗಳು:

1. `sanitizeRequest()` from `@/shared/utils/inputSanitizer` (ಪೈಪ್‌ಲೈನ್‌ನಲ್ಲಿ ಇತರ ಸ್ಥಳಗಳಲ್ಲಿ ಬಳಸುವ ಹಂಚಿಕೆ ಪತ್ತೆಗಾರ
   ಸೆಟ್).
2. ನಿರ್ಮಿತ `DEFAULT_GUARD_PATTERNS` (ಪ್ರಸ್ತುತ `system_override_inline` ಮತ್ತು
   `markdown_system_block`, ಎರಡೂ `high` ತೀವ್ರತೆ).
3. ನಿರ್ಮಾಪಕ ಆಯ್ಕೆಗಳ ಮೂಲಕ ಪಾಸಾದ ಆಯ್ಕೆಯ `customPatterns` (ಸ್ಟ್ರಿಂಗ್‌ಗಳು, regex,
   ಅಥವಾ `{ name, pattern, severity }` ದಾಖಲೆಗಳು).

`mode === "block"` **ಮತ್ತು** ಕನಿಷ್ಠ ಒಂದು ಪತ್ತೆ ತೀವ್ರತೆ
ಥ್ರೆಶೋಲ್ಡ್ ಅನ್ನು ಪೂರೈಸಿದಾಗ, `preCall` `{ block: true, message: "Request rejected:
suspicious content detected" }` ಅನ್ನು ಹಿಂತಿರುಗಿಸುತ್ತದೆ. `warn`/`log` ಮೋಡ್‌ಗಳಲ್ಲಿ ಗಾರ್ಡ್‌ರೇಲ್ ಲಾಗ್ ಮಾಡುತ್ತದೆ ಆದರೆ
ಕರೆಗೆ ಅವಕಾಶ ನೀಡುತ್ತದೆ. ಹಂಚಿಕೆ ಸಹಾಯಕ `evaluatePromptInjection()` ಅನ್ನು ಕರೆಗಾರರಿಗೆ
ಪರೀಕ್ಷಿಸಲು ಹೊರಗೊಮ್ಮಲು ಮಾಡಲಾಗಿದೆ.

**ಸ್ಕಾನ್ ಬೌಂಡ್ (v3.8.20):** ಪತ್ತೆಗಾರ ಕೇವಲ **ಮೊದಲ 16 KB** ಅನ್ನು ಪರಿಶೀಲಿಸುತ್ತದೆ
ಜೋಡಿಸಲಾದ ಪ್ರಾಂಪ್ಟ್ ಪಠ್ಯ — `MAX_INJECTION_SCAN_BYTES = 16 * 1024` (16 384 ಬೈಟ್ಸ್) in
`src/shared/utils/inputSanitizer.ts`. `detectInjection()` ಮತ್ತು
`evaluatePromptInjection()` `slice(0, MAX_INJECTION_SCAN_BYTES)` ಅನ್ನು ಕಾರ್ಯಗತಗೊಳಿಸುತ್ತವೆ
ಪ್ಯಾಟರ್ನ್ ಲೂಪ್ ಅನ್ನು ನಡೆಸುವ ಮೊದಲು. ಇಂಜೆಕ್ಷನ್ ನಿರ್ದೇಶನಗಳು ಇನ್ಪುಟ್‌ನ ಮೇಲ್ಭಾಗದಲ್ಲಿ ಇರುತ್ತವೆ, ಆದ್ದರಿಂದ ಇದು
ಬಹು-ಶತಕ KB ಪೇಲೋಡ್‌ಗಳಲ್ಲಿ regex CPU/GC ಅನ್ನು ಮಿತಿಯಲ್ಲಿಡುತ್ತದೆ, ಪತ್ತೆ ಹೀನಗೊಳಿಸುವುದಿಲ್ಲ (cf.
#3932, #4041).

### Credential Masker (`credentialMasker.ts`)

**ಎಲ್ಲಾ** ಹಂತಗಳಲ್ಲಿ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತದೆ, ಡೀಫಾಲ್ಟ್ ಶ್ರೇಣಿಯಲ್ಲಿ ಕೊನೆಯದು (ಪ್ರಾಧಾನ್ಯ `95`). ಪ್ರಸಿದ್ಧ API-ಕೀ / ಸೀಕ್ರೆಟ್-ಟೋಕನ್ ಮಾದರಿಗಳನ್ನು ಹೊರಗಿನ ಪೇಲೋಡ್ (ಸಂದೇಶ
ವಿಷಯ, ಸಾಧನ-ಕರೆ ಆರ್ಗ್ಯುಮೆಂಟ್‌ಗಳು, ಸಾಧನ ಫಲಿತಾಂಶಗಳು) **ಮತ್ತು** ಒದಗಿಸುವ ಪ್ರತಿಕ್ರಿಯೆ, ಆದ್ದರಿಂದ ಪ್ರಾಂಪ್ಟ್‌ನಲ್ಲಿ ಅಂಟಿಸಿದ ಕ್ರೆಡೆನ್ಷಿಯಲ್‌ಗಳು (ಅಥವಾ ಸಾಧನ ಫಲಿತಾಂಶದಿಂದ ಹಿಂದಿರುಗಿಸಿದ) ಮೇಲ್ಮಟ್ಟ ಒದಗಿಸುವವರಿಗೆ ಅಥವಾ ಕ್ಲೈಂಟ್‌ಗೆ ಹಂಚಿಕೆಯಾಗುವುದಿಲ್ಲ.

- **ಆಪ್ಟ್-ಇನ್ ಮಾತ್ರ**, PII ಅಳವಡಿಕೆ (ಕಠಿಣ ನಿಯಮ #20-ಅಡ್ಜೆಸೆಂಟ್) ಗೆ ಸಮಾನವಾದ ನಿಯಮ:
  `settings.credentialRedactionEnabled === true` **ಅಥವಾ**
  `CREDENTIAL_REDACTION_ENABLED=true` ಇಲ್ಲದಾಗ ನಿಷ್ಕ್ರಿಯವಾಗಿರುತ್ತದೆ. ಇದನ್ನು ಆಫ್ ಮಾಡಿದಾಗ, ಗಾರ್ಡ್‌ರೇಲ್ ನೋ-ಆಪ್ ಆಗಿರುತ್ತದೆ —
  ಇದು ಎಂದಿಗೂ ತಡೆಹಿಡಿಯುವುದಿಲ್ಲ ಮತ್ತು ಎಂದಿಗೂ ಪುನರ್‌ಲೇಖನ ಮಾಡುವುದಿಲ್ಲ.
- `redactCredentials()` ಸಂಪೂರ್ಣ ಪೇಲೋಡ್/ಪ್ರತಿಸ್ಪಂದನ ಮರವನ್ನು ನಡೆಯುತ್ತದೆ (`walkValue()`,
  ಪ್ರೋಟೋಟೈಪ್-ಪಾಲಿಷನ್-ಸೇಫ್, ಚಕ್ರ-ಸೇಫ್ `WeakSet` ಮೂಲಕ) ಮತ್ತು ಹೊಂದಾಣಿಕೆಗಳನ್ನು
  `[REDACTED:<type>]` ಪ್ಲೇಸ್‌ಹೋಲ್ಡರ್‌ೊಂದಿಗೆ ಬದಲಾಯಿಸುತ್ತದೆ, ವಾಸ್ತವವಾಗಿ ಬದಲಾಯಿಸಿದ
  ಶಾಖೆಗಳನ್ನು ಮಾತ್ರ ಕ್ಲೋನ್ ಮಾಡುತ್ತದೆ.
- `CREDENTIAL_PATTERNS` LLM ಪೂರೈಕೆದಾರ ಕೀಗಳನ್ನು (OpenAI, OpenAI-proj,
  Anthropic, Google, Hugging Face, Replicate), VCS/SaaS ಟೋಕನ್‌ಗಳನ್ನು (GitHub, Slack,
  Linear, Notion, npm, Postman, Discord), ಪಾವತಿ ಕೀಗಳನ್ನು (Stripe, Square), ಕ್ಲೌಡ್
  ಕೀಗಳನ್ನು (AWS access key, Twilio, SendGrid, Mailgun), ಖಾಸಗಿ ಕೀಗಳು / JWTಗಳು,
  ಕ್ರೆಡೆನ್ಷಿಯಲ್-ಬೇರುವ ಸಂಪರ್ಕ ಶ್ರೇಣಿಗಳನ್ನು (`mongodb://user:pass@...`, ಇತ್ಯಾದಿ), ಮತ್ತು
  ಸಾಮಾನ್ಯ `Authorization`/`x-api-key`/`api-key`/`apikey` ಹೆಡರ್-ಮೌಲ್ಯ
  ಮಾದರಿಯನ್ನು ಒಳಗೊಂಡಿದೆ. ಹೆಡರ್-ಆಕಾರದ ಕೀಗಳು (`authorization`, `x-api-key`, `api-key`,
  `apikey`) ರಚನಾತ್ಮಕವಾಗಿ ಅಳವಡಿಸಲಾಗುತ್ತದೆ (ಮೌಲ್ಯ ಮಾತ್ರ, ಯೋಜನೆ ಪೂರ್ವಭಾವಿ
  `Bearer `/`Basic ` ಉಳಿಸಲಾಗಿದೆ) ಸಾಮಾನ್ಯ ಪಠ್ಯ regex ಮೂಲಕ ಅಲ್ಲ.
- ಗಾರ್ಡ್‌ರೇಲ್ ಎಂದಿಗೂ ತಡೆಹಿಡಿಯುವುದಿಲ್ಲ; ಇದು ಕೇವಲ ಪುನರ್‌ಲೇಖನ ಮಾಡುತ್ತದೆ (`modifiedPayload` /
  `modifiedResponse`) ಮತ್ತು ಟ್ಯಾಗ್‌ಗಳನ್ನು ಸೇರಿಸುತ್ತದೆ (`meta.credentialsRedacted`, `meta.count`).

ರಿಗ್ರೆಷನ್ ಗಾರ್ಡ್: `tests/unit/credential-masker-guardrail.test.ts`.

## ಮೂಲ ಒಪ್ಪಂದ (`base.ts`)

```typescript
class BaseGuardrail {
  enabled: boolean;
  name: string;
  priority: number;

  constructor(name: string, options?: { enabled?: boolean; priority?: number });

  async preCall(payload: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;

  async postCall(response: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;
}

interface GuardrailResult<TValue = unknown> {
  block?: boolean; // true ಸರಪಳಿಯನ್ನು ತಕ್ಷಣವೇ ಸ್ಥಗಿತಗೊಳಿಸುತ್ತದೆ
  message?: string; // ನಿರ್ಬಂಧಿಸುವಾಗ ಪ್ರದರ್ಶಿಸಲಾಗುತ್ತದೆ
  meta?: Record<string, unknown> | null;
  modifiedPayload?: TValue; // ವಿನಂತಿಯನ್ನು ಮರುಬರೆಯಲು preCall ಮೂಲಕ ಹಿಂತಿರುಗಿಸಲಾಗುತ್ತದೆ
  modifiedResponse?: TValue; // ಪ್ರತಿಕ್ರಿಯೆಯನ್ನು ಮರುಬರೆಯಲು postCall ಮೂಲಕ ಹಿಂತಿರುಗಿಸಲಾಗುತ್ತದೆ
}

interface GuardrailContext {
  apiKeyInfo?: Record<string, unknown> | null;
  disabledGuardrails?: string[] | null;
  endpoint?: string | null;
  headers?: Headers | Record<string, unknown> | null;
  log?: GuardrailLog | Console | null;
  method?: string | null;
  model?: string | null;
  provider?: string | null;
  signal?: AbortSignal;
  sourceFormat?: string | null;
  stream?: boolean;
  targetFormat?: string | null;
}
```

`void`, `{}`, ಅಥವಾ `{ block: false }` ಇವುಗಳಲ್ಲಿ ಯಾವುದನ್ನಾದರೂ ಹಿಂತಿರುಗಿಸುವ ಮೂಲಕ guardrail "ಯಾವುದೇ ಬದಲಾವಣೆ ಇಲ್ಲ" ಎಂದು ಸೂಚಿಸುತ್ತದೆ. `modifiedPayload`/`modifiedResponse` ಅನ್ನು ಹಿಂತಿರುಗಿಸುವುದರಿಂದ, ನಂತರದ guardrailಗಳಿಗಾಗಿ ಸರಪಳಿಯ ಮೂಲಕ ಹರಿಯುವ ಮೌಲ್ಯವನ್ನು ಅದು ಬದಲಿಸುತ್ತದೆ.
`signal?: AbortSignal` ಕಾಲರ್ನ ಜೀವನಚಕ್ರವನ್ನು guardrailಗಳಿಗೆ ಒಯ್ಯುತ್ತದೆ. ವಿನಂತಿಯ ರದ್ದತಿಯು ಉದ್ದೇಶಪೂರ್ವಕ fail-open ಅಪವಾದವಾಗಿದೆ: media bridgeಗಳು ಕೆಲಸವನ್ನು ನಿಲ್ಲಿಸಿ cleanup ಮಾಡುತ್ತವೆ ಮತ್ತು ಅದನ್ನು ಬೆಂಬಲಿಸುವುದಿಲ್ಲ ಎಂದು ತಿಳಿದಿರುವ ಗುರಿಗೆ raw media ಅನ್ನು ಮರುಸ್ಥಾಪಿಸುವುದಿಲ್ಲ.

## ರಿಜಿಸ್ಟ್ರಿ (`registry.ts`)

singleton `guardrailRegistry` ಈ ಕೆಳಗಿನವುಗಳನ್ನು ಒದಗಿಸುತ್ತದೆ:

- `register(guardrail)` — guardrail ಅನ್ನು ಸೇರಿಸುತ್ತದೆ (ಅಥವಾ normalized name ಆಧಾರದಲ್ಲಿ ಬದಲಿಸುತ್ತದೆ) ಮತ್ತು ಏರಿಕೆ ಕ್ರಮದ `priority` ಪ್ರಕಾರ ಮರು-ವಿಂಗಡಿಸುತ್ತದೆ.
- `clear()` / `list()` — ಆಡಳಿತಾತ್ಮಕ ಸಹಾಯಕಗಳು.
- `runPreCallHooks(payload, context)` — ಸಕ್ರಿಯ guardrailಗಳ ಮೂಲಕ ಪುನರಾವರ್ತಿಸುತ್ತದೆ, `modifiedPayload` ಮೂಲಕ payload ಅನ್ನು ಮುಂದಕ್ಕೆ ಕೊಂಡೊಯ್ಯುತ್ತದೆ ಮತ್ತು ಮೊದಲ `block: true` ದೊರೆತಾಗ ನಿಲ್ಲುತ್ತದೆ.
- `runPostCallHooks(response, context)` — response ಭಾಗದಲ್ಲಿಯೂ ಇದೇ ಹರಿವನ್ನು ಅನುಸರಿಸುತ್ತದೆ.
- `resetGuardrailsForTests({ registerDefaults })` — ಸ್ಥಿತಿಯನ್ನು ತೆರವುಗೊಳಿಸುತ್ತದೆ ಮತ್ತು ಸ್ವಚ್ಛ test isolationಗಾಗಿ ಐಚ್ಛಿಕವಾಗಿ defaults ಅನ್ನು ಮರು-ನೋಂದಾಯಿಸುತ್ತದೆ.

ಎರಡೂ runnerಗಳು `{ blocked, payload|response, results, guardrail?, message? }` ಅನ್ನು ಹಿಂತಿರುಗಿಸುತ್ತವೆ, ಇಲ್ಲಿ `results` ಎಂಬುದು ಪ್ರತಿಯೊಂದು guardrailಗೆ ಸಂಬಂಧಿಸಿದ `blocked`, `skipped`, `modified`, `error`, ಮತ್ತು `meta` ಕ್ಷೇತ್ರಗಳನ್ನು ಒಳಗೊಂಡಿರುವ `GuardrailExecutionResult` recordಗಳ array ಆಗಿದ್ದು, tracingಗೆ ಉಪಯುಕ್ತವಾಗಿದೆ.

### ಪ್ರತಿ ವಿನಂತಿಗೆ Guardrailಗಳನ್ನು ನಿಷ್ಕ್ರಿಯಗೊಳಿಸುವುದು

`resolveDisabledGuardrails({ apiKeyInfo, body, headers })` ಪ್ರಸ್ತುತ ವಿನಂತಿಗಾಗಿ ಬಿಟ್ಟುಬಿಡಬೇಕಾದ guardrail ಹೆಸರುಗಳ duplicate ತೆಗೆದುಹಾಕಿದ ಪಟ್ಟಿಯನ್ನು ಒಟ್ಟುಗೂಡಿಸುತ್ತದೆ. ಮೂಲಗಳು (ಎಲ್ಲವೂ ಐಚ್ಛಿಕ, ಎಲ್ಲವನ್ನೂ ವಿಲೀನಗೊಳಿಸಲಾಗುತ್ತದೆ):

- `apiKeyInfo.disabledGuardrails`
- ವಿನಂತಿಯ bodyಯಲ್ಲಿನ `disabledGuardrails` (top-level)
- ವಿನಂತಿಯ bodyಯಲ್ಲಿನ `metadata.disabledGuardrails`
- Header `x-omniroute-disabled-guardrails` (ಅಥವಾ ಹಳೆಯ
  `x-disabled-guardrails`)

ಮೌಲ್ಯಗಳು stringಗಳ array ಆಗಿರಬಹುದು ಅಥವಾ comma-separated string ಆಗಿರಬಹುದು; ಹೆಸರುಗಳನ್ನು lowercase kebab-caseಗೆ normalize ಮಾಡಲಾಗುತ್ತದೆ (`pii_masker` → `pii-masker`). ಫಲಿತಾಂಶವನ್ನು `context.disabledGuardrails` ಮೂಲಕ registryಗೆ ರವಾನಿಸಲಾಗುತ್ತದೆ, ಅದು ಹೊಂದಿಕೆಯಾಗುವ guardrailಗಳನ್ನು ಬಿಟ್ಟುಬಿಡುತ್ತದೆ (`results` ನಲ್ಲಿ `skipped: true`).

## ಕಾರ್ಯಗತಗೊಳಿಸುವ ಕ್ರಮ

`src/sse/handlers/chat.ts` ಮತ್ತು
`open-sse/handlers/chatCore.ts` ಮೂಲಕ ಹರಿಯುವ ಪ್ರತಿ ವಿನಂತಿಗಾಗಿ:

1. `resolveDisabledGuardrails(...)` API ಕೀ, ಬಾಡಿ ಮತ್ತು ಹೆಡರ್ಗಳಿಂದ ಬಿಟ್ಟುಬಿಡುವ ಪಟ್ಟಿಯನ್ನು ರಚಿಸುತ್ತದೆ.
2. `guardrailRegistry.runPreCallHooks(body, ctx)` ಗಾರ್ಡ್ರೇಲ್ಗಳನ್ನು ಆದ್ಯತೆಯ ಆರೋಹಣ ಕ್ರಮದಲ್ಲಿ ಚಲಾಯಿಸುತ್ತದೆ:
   - ನಿಷ್ಕ್ರಿಯಗೊಳಿಸಲಾದ ಗಾರ್ಡ್ರೇಲ್ಗಳನ್ನು `skipped` ಎಂದು ದಾಖಲಿಸಲಾಗುತ್ತದೆ.
   - ಪ್ರತಿ ಗಾರ್ಡ್ರೇಲ್ನ `preCall`, `modifiedPayload` ಮೂಲಕ ಪೇಲೋಡ್ ಅನ್ನು ಮರುಬರೆಯಬಹುದು.
   - ಮೊದಲ `block: true` ಸರಪಳಿಯನ್ನು ಅಲ್ಲಿಯೇ ನಿಲ್ಲಿಸುತ್ತದೆ ಮತ್ತು ಹ್ಯಾಂಡ್ಲರ್ ಗಾರ್ಡ್ರೇಲ್ ನಿರಾಕರಣೆಯ ಪ್ರತಿಕ್ರಿಯೆಯನ್ನು ಹಿಂತಿರುಗಿಸುತ್ತದೆ.
3. (ಸಂಭಾವ್ಯವಾಗಿ ಮರುಬರೆಯಲಾದ) ಪೇಲೋಡ್ ಕಾಂಬೊ ರೂಟಿಂಗ್ ಮತ್ತು ಅಪ್ಸ್ಟ್ರೀಮ್ ಡಿಸ್ಪ್ಯಾಚ್ಗೆ ಹರಿಯುತ್ತದೆ.
4. ಪ್ರತಿಕ್ರಿಯೆಯನ್ನು ಜೋಡಿಸಿದ ನಂತರ, `guardrailRegistry.runPostCallHooks(...)` ಪ್ರತಿಕ್ರಿಯೆಯ ಮೇಲೆ ಅದೇ ಸರಪಳಿಯನ್ನು ಚಲಾಯಿಸುತ್ತದೆ. ಇಲ್ಲಿ `block: true` ಅಪ್ಸ್ಟ್ರೀಮ್ ಪ್ರತಿಕ್ರಿಯೆಯನ್ನು ಕೈಬಿಡುತ್ತದೆ.

ದೋಷ ಎಸೆಯುವ ಗಾರ್ಡ್ರೇಲ್ಗಳನ್ನು `error: <message>` ಜೊತೆಗೆ ದಾಖಲಿಸಲಾಗುತ್ತದೆ ಮತ್ತು
`logger.warn` ಮೂಲಕ ಲಾಗ್ ಮಾಡಲಾಗುತ್ತದೆ, ಆದರೆ ಸರಪಳಿ ಮುಂದುವರಿಯುತ್ತದೆ — ವಿನ್ಯಾಸದ ಪ್ರಕಾರ ದೋಷ ಸಂಭವಿಸಿದಾಗಲೂ ಅನುಮತಿಸಲಾಗುತ್ತದೆ.

## ಕಸ್ಟಮ್ ಗಾರ್ಡ್ರೈಲ್ಗಳು

```typescript
import { BaseGuardrail, guardrailRegistry } from "@/lib/guardrails";

class BudgetGuardrail extends BaseGuardrail {
  constructor() {
    super("budget", { priority: 50 });
  }

  async preCall(payload, ctx) {
    if (ctx.apiKeyInfo?.budgetExceeded) {
      return { block: true, message: "Daily budget exceeded" };
    }
    return { block: false };
  }
}

guardrailRegistry.register(new BudgetGuardrail());
```

ಹಂತಗಳು:

1. `BaseGuardrail` ಅನ್ನು ವಿಸ್ತರಿಸುವ `src/lib/guardrails/myGuardrail.ts` ಅನ್ನು ರಚಿಸಿ.
2. `preCall` ಮತ್ತು/ಅಥವಾ `postCall` ಅನ್ನು ಅನುಷ್ಠಾನಗೊಳಿಸಿ.
3. ಇಂಪೋರ್ಟ್ ಸಮಯದಲ್ಲಿಯೇ ನೋಂದಾಯಿಸಿ (`registerDefaultGuardrails` ನಿಂದ ಪುಶ್ ಮಾಡಿ) ಅಥವಾ
   ರನ್ಟೈಮ್ನಲ್ಲಿ `guardrailRegistry.register(...)` ಅನ್ನು ಕರೆ ಮಾಡಿ — ಅದೇ ಸಾಮಾನ್ಯೀಕರಿಸಿದ
   ಹೆಸರನ್ನು ಹೊಂದಿರುವ ಯಾವುದೇ ಹಿಂದಿನ ಗಾರ್ಡ್ರೈಲ್ ಅನ್ನು ರಿಜಿಸ್ಟ್ರಿ ಬದಲಿಸುತ್ತದೆ.
4. `tests/unit/` ಅಡಿಯಲ್ಲಿ ಪರೀಕ್ಷೆಗಳನ್ನು ಸೇರಿಸಿ (ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಉದಾಹರಣೆಗಳು:
   `tests/unit/guardrails-registry.test.ts`,
   `tests/unit/prompt-injection-guard.test.ts`,
   `tests/unit/guardrails/visionBridge.test.ts`).

## ಪರೀಕ್ಷೆ

ತಿಳಿದಿರುವ ಸ್ಥಿತಿಯಿಂದ ಪ್ರಾರಂಭಿಸಲು ಪರೀಕ್ಷೆಗಳ ನಡುವೆ `resetGuardrailsForTests()` ಅನ್ನು ಬಳಸಿ.
ಖಾಲಿ ರಿಜಿಸ್ಟ್ರಿಯೊಂದಿಗೆ ಪ್ರಾರಂಭಿಸಲು `{ registerDefaults: false }` ಅನ್ನು ಪಾಸ್ ಮಾಡಿ ಮತ್ತು
ಪರೀಕ್ಷೆಯಲ್ಲಿರುವ ಗಾರ್ಡ್ರೈಲ್ಗಳನ್ನು ಮಾತ್ರ ನೋಂದಾಯಿಸಿ. Vision Bridge ಡಿಪೆಂಡೆನ್ಸಿ
ಇಂಜೆಕ್ಷನ್ ಅನ್ನು ಸ್ವೀಕರಿಸುತ್ತದೆ (`deps.getSettings`, `deps.callVisionModel`); Audio Bridge,
ಸೆಟ್ಟಿಂಗ್ಗಳು, ಸಾಮರ್ಥ್ಯಗಳು, STT ಮಾದರಿ ಆಯ್ಕೆ, ಕ್ರೆಡೆನ್ಶಿಯಲ್ ಪರಿಶೀಲನೆಗಳು ಮತ್ತು
ಟ್ರಾನ್ಸ್ಕ್ರಿಪ್ಷನ್ಗಾಗಿ ಸಮಾನವಾದ ಸೀಮ್ಗಳನ್ನು ಒದಗಿಸುತ್ತದೆ. ಆದ್ದರಿಂದ ಪರೀಕ್ಷೆಗಳು DB
ಅಥವಾ ನೆಟ್ವರ್ಕ್ ಪ್ರವೇಶವಿಲ್ಲದೆಯೇ ಎರಡೂ ಫ್ಲೋಗಳನ್ನು ಪರೀಕ್ಷಿಸಬಹುದು.

## ಇಂಜೆಕ್ಷನ್-ಗಾರ್ಡ್ ರೂಟ್ ವ್ಯಾಪ್ತಿ ಮತ್ತು ರೆಡ್-ಟೀಮ್ (ಹಂತ 8 · ಬ್ಲಾಕ್ D)

ಇಂಜೆಕ್ಷನ್-ಗಾರ್ಡ್ (`createInjectionGuard` / `withInjectionGuard`) ಬಳಕೆದಾರರ
ಪ್ರಾಂಪ್ಟ್ಗಳನ್ನು ಸ್ವೀಕರಿಸುವ ಎಲ್ಲಾ ರೂಟ್ಗಳನ್ನು ಒಳಗೊಳ್ಳುತ್ತದೆ. ಇದು `INJECTION_GUARD_MODE`
ಅನ್ನು ಗೌರವಿಸುತ್ತದೆ (ಡೀಫಾಲ್ಟ್ `warn` = ಲಾಗ್ ಮಾತ್ರ; `block` = HTTP 400 `SECURITY_001` ಅನ್ನು ಹಿಂದಿರುಗಿಸುತ್ತದೆ).

| ಪ್ರಕಾರ                     | ರೂಟ್ಗಳು                                                                                                                                              | ಡೀಫಾಲ್ಟ್ ಮೋಡ್ |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ------------- |
| ಪಠ್ಯ (ಅಸ್ತಿತ್ವದಲ್ಲಿರುವುದು) | `/v1/chat/completions`, `/v1/completions`, `/v1/relay/chat/completions`                                                                              | warn          |
| ಜನರೇಟಿವ್                   | `/v1/messages`, `/v1/responses`, `/v1/images/generations`, `/v1/images/edits`, `/v1/videos/generations`, `/v1/music/generations`, `/v1/audio/speech` | warn          |
| ಡೇಟಾ                       | `/v1/embeddings`, `/v1/rerank`, `/v1/search`, `/v1/moderations`                                                                                      | warn          |

ಪಠ್ಯ ಹೊರತೆಗೆಯುವಿಕೆ (`extractMessageContents`) `messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system` ಅನ್ನು ಒಳಗೊಳ್ಳುತ್ತದೆ.

**ರೆಡ್-ಟೀಮ್ (ಪ್ರತಿ ರಾತ್ರಿ, `nightly-llm-security.yml`):** `INJECTION_GUARD_MODE=block`
ನಲ್ಲಿ ಪ್ರತಿಯೊಂದು ರೂಟ್, `OWASP-LLM` ಕಾರ್ಪಸ್ ಅನ್ನು ನಿರ್ಬಂಧಿಸುತ್ತದೆ ಎಂಬುದನ್ನು promptfoo
ಮೌಲ್ಯೀಕರಿಸುತ್ತದೆ; garak ಪ್ರೋಬ್ಗಳನ್ನು ಚಲಾಯಿಸುತ್ತದೆ (ಸೀಕ್ರೆಟ್ ಇಲ್ಲದಿದ್ದರೆ ಬಿಟ್ಟುಬಿಡುತ್ತದೆ).
ಸ್ಥಿರತೆಗಾಗಿ `moderations` ಅನ್ನು ಸೇರಿಸಲಾಗಿದೆ — ಬ್ಲಾಕ್-ಮೋಡ್ನಲ್ಲಿರುವ ಆಪರೇಟರ್ಗಳು
`resolveDisabledGuardrails` ಮೂಲಕ ಅದಕ್ಕೆ ವಿನಾಯಿತಿ ನೀಡಬಹುದು.

ಪ್ರತಿ ರಾತ್ರಿಯ ವರ್ಕ್ಫ್ಲೋ (`.github/workflows/nightly-llm-security.yml`, cron + ಮ್ಯಾನುಯಲ್
ಡಿಸ್ಪ್ಯಾಚ್) ಎರಡು ಜಾಬ್ಗಳನ್ನು ಹೊಂದಿದೆ:

- **`promptfoo-guard` (ನಿರ್ಬಂಧಿಸುವುದು)** — `INJECTION_GUARD_MODE=block` ಜೊತೆಗೆ
  `promptfoo eval -c promptfooconfig.yaml` ಅನ್ನು ಚಲಾಯಿಸುತ್ತದೆ. ಪ್ರತಿಯೊಂದು ಪ್ರತಿಕೂಲ
  ಪ್ರಕರಣವು (ಉದಾ. "ಹಿಂದಿನ ಎಲ್ಲಾ ಸೂಚನೆಗಳನ್ನು ನಿರ್ಲಕ್ಷಿಸಿ…", DAN-ಶೈಲಿಯ ಜೈಲ್ಬ್ರೇಕ್ಗಳು)
  ಪ್ರತಿಕ್ರಿಯೆಯು `error.code === "SECURITY_001"` ಅನ್ನು ಹೊಂದಿದೆ ಎಂದು ದೃಢೀಕರಿಸುತ್ತದೆ,
  ಅಂದರೆ ಗಾರ್ಡ್ ನಿಜವಾಗಿಯೂ ವಿನಂತಿಯನ್ನು ತಿರಸ್ಕರಿಸಿದೆ.
- **`garak` (ಸಲಹಾತ್ಮಕ)** — ಸ್ಥಳೀಯ OmniRoute ಇನ್ಸ್ಟನ್ಸ್
  (`http://localhost:20128/v1`) ವಿರುದ್ಧ garak `--probes promptinject,dan,leakreplay`
  ಅನ್ನು ಚಲಾಯಿಸುತ್ತದೆ. ಇದು ಪ್ರೊವೈಡರ್ ಸೀಕ್ರೆಟ್ (`PROMPTFOO_PROVIDER_KEY`) ಮೇಲೆ
  ಅವಲಂಬಿತವಾಗಿದೆ; ಸೀಕ್ರೆಟ್ ಇಲ್ಲದಿದ್ದರೆ ಸರಾಗವಾಗಿ ಬಿಟ್ಟುಬಿಡುತ್ತದೆ ಮತ್ತು `|| true`
  ಪ್ರತ್ಯಯವನ್ನು ಹೊಂದಿರುತ್ತದೆ, ಆದ್ದರಿಂದ CI ವಿಫಲಗೊಳಿಸದೆಯೇ ವರದಿ ಮಾಡುತ್ತದೆ.

ಗಾರ್ಡ್ ಹೆಲ್ಪರ್ನ (`createInjectionGuard` / `withInjectionGuard`) ವ್ಯಾಪ್ತಿಯು ಪ್ರಾಂಪ್ಟ್
ಹೊಂದಿರುವ ಪ್ರತಿಯೊಂದು `/v1` ರೂಟ್ಗೆ ವಿಸ್ತರಿಸುತ್ತದೆ; ಪ್ರಾಂಪ್ಟ್ ಪಠ್ಯವನ್ನು
`src/shared/utils/inputSanitizer.ts` ನಲ್ಲಿರುವ `extractMessageContents()` ಮೂಲಕ
`messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system` ನಿಂದ
ಪಡೆಯಲಾಗುತ್ತದೆ.
