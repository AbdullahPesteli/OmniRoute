> **உண்மையின் ஆதாரம்:** `src/lib/guardrails/`
> **கடைசியாகப் புதுப்பிக்கப்பட்டது:** 2026-08-29 — v3.8.51 (Video Bridge உரைமாற்றத்தின் மூலச்சான்று அழைப்பாளரால் அறிவிக்கப்படுகிறது,
> இன்னும் சேவையகத்தால் சரிபார்க்கப்படவில்லை — #11661-இன்படி தெளிவுபடுத்தப்பட்டது)

OmniRoute-க்கும் மேல்நிலை வழங்குநர்களுக்கும் இடையிலான எல்லையில் பாதுகாப்பு, கொள்கை மற்றும் உள்ளடக்க மாற்றங்களை Guardrails செயல்படுத்துகின்றன. ஒவ்வொரு guardrail-உம் கோரிக்கை payload-களை (`preCall`) மற்றும் மேல்நிலை பதில்களை (`postCall`) ஆய்வு செய்து, விருப்பமாக அவற்றை நிராகரிக்கவோ, மாற்றவோ அல்லது குறிப்புரையிடவோ முடியும்.

இந்த அமைப்பு **fail-open** முறையில் இயங்குகிறது: செயல்பாட்டின்போது ஒரு guardrail பிழையை எறிந்தால், registry அந்தப் பிழையைப் பதிவுசெய்துவிட்டு, கோரிக்கையைத் தோல்வியடையச் செய்வதற்குப் பதிலாக அடுத்த guardrail-உடன் தொடரும். தடுத்தல் என்பது எப்போதும் வெளிப்படையான முடிவு (`block: true`); அது ஒருபோதும் தற்செயலாக நிகழாது.

## உள்ளமைக்கப்பட்ட பாதுகாப்புகள்

பதிவேடு இறக்குமதியில் முன்னுரிமை வரிசையில் ஆட்டோ-லோடு செய்யும் ஆறு பாதுகாப்புகள்
(பார்க்கவும் `registry.ts` → `registerDefaultGuardrails()`):

| முன்னுரிமை | பெயர்               | நிலை(கள்)      | கோப்பு                |
| ---------- | ------------------- | -------------- | --------------------- |
| `5`        | `vision-bridge`     | `preCall`      | `visionBridge.ts`     |
| `6`        | `audio-bridge`      | `preCall`      | `audioBridge.ts`      |
| `7`        | `video-bridge`      | `preCall`      | `videoBridge.ts`      |
| `10`       | `pii-masker`        | `pre` + `post` | `piiMasker.ts`        |
| `20`       | `prompt-injection`  | `preCall`      | `promptInjection.ts`  |
| `95`       | `credential-masker` | `pre` + `post` | `credentialMasker.ts` |

குறைந்த முன்னுரிமை எண்கள் **முதலில்** இயங்கும்.

### பார்வை பாலம் (`visionBridge.ts`) — முறைமைக் பாலம் PR-1

**கண்ணோட்ட மாதிரிகள்** நோக்கி உள்ள படங்களை கொண்ட கோரிக்கைகளை இடைமுகம் செய்கிறது மற்றும்
முழு கோரிக்கையை ஒரு கண்ணோட்டம் செய்யக்கூடிய மாதிரிக்கு மறுசீரமைக்கிறது அல்லது படத்தின்
பகுதிகளை ஒரு கட்டமைக்கக்கூடிய கண்ணோட்ட மாதிரியால் உருவாக்கப்பட்ட உரை விளக்கங்களுடன்
மாற்றுகிறது. இது உரை மட்டுமே வழங்குநர்களுக்கு பல்முறை உள்ளடக்கங்களை தெளிவாக கையாள அனுமதிக்கிறது.

ஓட்டம்:

1. குறிக்கோள் மாதிரி ஏற்கனவே கண்ணோட்டத்தை ஆதரிக்கிறதா என்பதை தவிர்க்கவும் (அல்லது அது
   கட்டாய-பாலம் பட்டியலில் `isVisionBridgeForcedModel` தோன்றினால்).
2. `extractImageParts(messages)` மூலம் படத்தின் பகுதிகளை எடுக்கவும்
   (`visionBridgeHelpers.ts`), இது **ஒன்றிணைந்த ஊடக கண்டுபிடிப்பாளர்**
   `detectMediaParts()` க்கு委托 செய்கிறது `open-sse/utils/mediaParts.ts` — இது
   கூட்டணி பொருத்தத்திற்கான ஒரே உண்மையின் மூலமாகும்.
   எடுப்பது `replaceImageParts` மீண்டும் இணைக்கக்கூடிய வடிவங்களின் மேல் நிலை
   பகுதிகளுக்கு அனுமதிக்கப்படுகிறது (எடுக்கும்↔மாற்றும் ஒப்பந்தம்): OpenAI
   `image_url`, Anthropic base64 `source.type:"base64"`, Anthropic URL
   `source.type:"url"`, மற்றும் Responses API `input_image`. அடுக்குமட்ட hits மற்றும்
   குறியீடு மட்டுமே வடிவங்கள் கூட்டணி-பொருத்தத்திற்கான பொருள் மற்றும் எப்போதும் எடுக்கப்படாது.
   எதுவும் கிடைக்கவில்லை என்றால் தவிர்க்கவும்.
3. `resolveVisionBridgeRuntimeSettings()` மூலம் இயக்க நேர அமைப்புகளை தீர்க்கவும்
   (`src/shared/constants/modalityBridgeDefaults.ts`): புதிய `modalityBridge*`
   அமைப்புகள் வெற்றி; பழைய `visionBridge*` விசைகள் **ஒரு சுற்று
   மீள்பார்வை** (மீள்பார்வை ஜன்னல்). பாலம் முடக்கப்பட்ட போது எந்த ஊடக பயணத்திற்கு முன் தவிர்க்கவும்.
4. முறை தேர்வாளர் (`modalityBridgeVisionMode`, கீழே உள்ள அட்டவணையைப் பாருங்கள்)
   மறுசீரமைப்பு மற்றும் விவரிக்க இடையே தீர்மானிக்கிறது. மறுசீரமைப்பு `modifiedPayload` ஐ
   மட்டுமே `model` மாற்றியுடன், மேலும் மெட்டா `{ rerouted, fromModel, toModel, imagesKept }` ஐ
   திருப்புகிறது.
5. விவரிக்கும் பாதை: `maxImages` இல் படங்களை கட்டுப்படுத்தவும், பணியுடன் தொடர்புடைய
   உத்தியை உருவாக்கவும், விவரிக்கும் கச்சேனை அணுகவும், கண்ணோட்ட மாதிரியை **சமகாலமாக**
   (`Promise.allSettled`) அழைக்கவும், மற்றும் `[Image N]: <description>` உரை பகுதிகளை
   அவற்றின் இடத்தில் உள்ளடக்கவும். ஒரு தோல்வியடைந்த விவரிப்பு `null` ஐ வழங்குகிறது
   மற்றும் அசல் பட பகுதி **காத்திருக்கிறது** (#4012) — ஒட்டுமொத்த விவரிக்கும் பாதையில்
   ஒவ்வொரு விவரிப்பும் தோல்வியடைந்தால், உறுதிப்படுத்தப்பட்ட கண்ணோட்டமில்லாத மேலோட்டம்
   `(unavailable — no vision-capable provider connected)` இடைநிலை கிடைக்கிறது (#8430).
6. `modifiedPayload` + மெட்டா (`imagesProcessed`, `descriptions`,
   `processingTimeMs`, `visionModel`) ஐ திருப்பவும்.

#### முறை தேர்வாளர் (`modalityBridgeVisionMode`)

| முறை       | இயல்புநிலை | நடத்தை                                                                                                                                                                                                                                                                                  |
| ---------- | ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `auto`     | ✔          | பழைய உளவியல், பாதிக்கப்படவில்லை (#6640/#7204): non-combo/`auto/` மாதிரிகள் சிறந்த கண்ணோட்ட மாதிரிக்கு மறுசீரமைக்கின்றன, அப்போது விவரிக்கவும்; கூட்டணி குறிக்கோள்கள் எப்போதும் விவரிக்கின்றன.                                                                                            |
| `describe` |            | எப்போதும் விவரிக்கவும் — மறுசீரமைப்பு தடுப்பு முற்றிலும் தவிர்க்கப்படுகிறது; பயனர் தேர்ந்த மாதிரி எப்போதும் பதிலளிக்கிறது.                                                                                                                                                              |
| `reroute`  |            | கட்டாய மறுசீரமைப்பு: காப்பு-அங்கீகாரம் பெற்ற மாதிரி பாதுகாப்பு தவிர்க்கப்படுகிறது. மறுசீரமைப்பு-**இலக்கு** அங்கீகாரம் பாதுகாப்பு இன்னும் பொருந்துகிறது — usable vision target இல்லை என்றால், கோரிக்கை விவரிக்க செல்லும், எனவே கச்சா படங்கள் உரை மட்டுமே உள்ள பின்புறம் (#8430) அடையாது. |

கட்டாய முறை **முதலில்** ஆட்டோ உளவியலுக்கு முன் செயல்படுகிறது; `auto` நடத்தை
pre-PR-1 பாதுகாப்புக்கு பைட்-அடையாளமாக உள்ளது.

#### API-கீ வரம்பு (`visionBridgeKeyScope.ts`)

அழைப்பாளரின் API கீ `allowedConnections`, quota pools
(`allowedQuotas`) அல்லது மாதிரிகளை ( `allowedModels` / `blockedModels` /
`modelAccessMode: "restricted"` / `disableNonPublicModels`) கட்டுப்படுத்தும் போது,
பாலம் மட்டுமே மறுசீரமைப்பு மற்றும் விவரிக்கும் மாதிரிகளை தேர்ந்தெடுக்கிறது
அந்த கீ பயன்படுத்தக்கூடிய இணைப்புகளில். பின்னர் விவரிக்கும் அழைப்பு எப்போதும்
`x-omniroute-self-loop-key-id` தலைப்புடன் OmniRoute சுய-சுழற்சியில் செல்கிறது,
எனவே பெறும் உரையாடல் கோரிக்கை அந்த கீயின் இணைப்பு மற்றும் மாதிரி கொள்கையை மீண்டும்
செயல்படுத்துகிறது. `enforceApiKeyPolicy()`
அந்த தலைப்பை மட்டும் சுய-சுழற்சியின் கையொப்பத்துடன் மதிக்கிறது, எனவே இது
அணுகலைக் குறைக்க மட்டுமே முடியும், மற்றும் தீர்க்கப்படாத அடையாளம் நிராகரிக்கப்படுகிறது.

கீக்கு எந்த கண்ணோட்ட மாதிரி அனுமதிக்கப்படவில்லை என்றால், விவரிக்கும் பாதை
புறக்கணிக்கப்படுகிறது மற்றும் கோரிக்கை மாற்றமின்றி செல்லும், முடிவில் திறந்த
நடத்தை போலவே (மெட்டா `{ skipped: true, reason: "no_permitted_vision_model" }`).
கீ இல்லாத கோரிக்கைகள், மற்றும் இந்த கட்டுப்பாடுகள் இல்லாத கீகள், முன்பு போலவே
நடிக்கின்றன.

#### பணியுடன் தொடர்புடைய விவரிக்கும் உத்தி (`modalityBridgeVisionTaskAware`)

மூல **உண்மை**. `composeVisionPrompt()` (`visionBridgeHelpers.ts`) கடைசி பயனர் செய்தியின் உரையை (500 எழுத்துக்களுக்கு குறுக்கீடு செய்யப்பட்ட) அடிப்படைக் விவரிக்கான உத்தியில் சேர்க்கிறது, பயனர் உண்மையில் கேட்டதைப் பற்றிய விவரத்தை வழிநடத்துகிறது (codex-vision-proxy மாதிரி) மற்றும் காட்சி மாதிரியை காணக்கூடிய உரையை எழுத்துப்பதிவு செய்ய கேட்கிறது. கொடுக்கப்பட்ட கொள்கை அண்மையில் выключить — அல்லது பயனர் உரை இல்லாத போது — அடிப்படைக் உத்தி மாற்றமின்றி பயன்படுத்தப்படுகிறது.

விவரிக்கான சுய-சுழற்சியின் OpenAI-க்கு ஏற்புடைய கோரிக்கை (`callVisionModelSingle()` `visionBridgeHelpers.ts` இல்) எப்போதும் `image_url.detail: "high"` ஐ கோரிக்கையிடுகிறது — எந்தவொரு அழைப்பாளர்/வழங்குநருக்கும், எந்தவொரு கிளையன்ட் சிக்னலின் அடிப்படையில் அல்லாமல், கட்டாயமாக. குறைந்த விவரமான மாதிரிகள் OCR துல்லியத்தை குறைக்கின்றன, இது இந்த உத்தி கேட்கும் உரை-எழுத்துப்பதிவு பணிக்கே, எனவே விவரிக்கான அழைப்பு எப்போதும் உயர் விவரத்திற்காக கேட்கப்படுகிறது, முதன்மை உள்ளீட்டு கோரிக்கையில் எந்த விவர நிலை பயன்படுத்தப்பட்டாலும். இது உள்ளக விவரிக்கான கோரிக்கை உடலுக்கு மட்டுமே பாதிக்கிறது; OmniRoute முதன்மை கோரிக்கையில் அழைப்பாளரின் சொந்த `image_url.detail` ஐ எவ்வாறு முன்னேற்றுகிறது என்பதைக் மாற்றாது — அந்த இயல்பானது தனியாகப் பயன்படுத்தப்படுகிறது, மற்றும் கண்டறியப்பட்ட OpenCode கிளையன்ட்களுக்கு மட்டும், `defaultImageDetail()` (`open-sse/handlers/chatCore/upstreamBody.ts`) இல். விவரிக்கான சுய-சுழற்சியின் Anthropic கம்பி வடிவம் `detail` புலம் இல்லாமல் உள்ளது மற்றும் எந்தவொரு இயல்புக்கும் பாதிக்கப்படவில்லை.

#### விவரிக்கான வெளியீட்டு வரம்பு (`modalityBridgeVisionMaxChars`)

| விசை                           | இயல்பு | வரம்பு               |
| ------------------------------ | ------ | -------------------- |
| `modalityBridgeVisionMaxChars` | `0`    | `0` அல்லது 100–50000 |

`0` (இயல்பு) என்பது **எந்த வரம்பும் இல்லை** — `callVisionModel()` மூலம் திரும்பிய விவரம் மாற்றமின்றி செல்கிறது, ஏற்கனவே உள்ள நடத்தைப் பாதுகாக்கிறது. 100–50000 வரம்பில் உள்ள எந்த மதிப்பும் விவரத்தை `…` பின்னணி சேர்க்கும் முன் குறுக்கீடு செய்கிறது, பின்னர் அதை `[Image N]: <description>` ஆக இணைக்கிறது (`VisionBridgeGuardrail.preCall()` `src/lib/guardrails/visionBridge.ts` இல்). இது விவரமான OCR பணிகளுக்காக உயர்த்தவும், கீழ்த்தரமானது உரையாடல் காட்சி மாதிரிகளில் டோக்கன் பயன்பாட்டை கட்டுப்படுத்தவும். டாஷ்போர்டு புலம் Vision தாவலின் முன்னணி பாணியில் உள்ளது (`modality-bridge-max-chars` `ModalityBridgeVisionTab.tsx` இல்) மற்றும் 1 மற்றும் 99 இடையே உள்ள எந்த மதிப்பையும் 100 அடிக்குறியுடன் கட்டுப்படுத்துகிறது, மேலும் தெளிவான `0` ஐ மாற்றமின்றி விட்டுவிடுகிறது — `0` என்பது தனியாக ஒரு செல்லுபடியாகும் Zod மதிப்பு (`z.union([z.literal(0), z.number().int().min(100).max(50000)])`), வெறும் "அமைக்கப்படாத" இயல்பு அல்ல.

#### விவரிக்கான கச்சா (`modalityBridge/bridgeCache.ts`)

விவரிக்கான வெளியீடுகளுக்கான நினைவக LRU + TTL கச்சா, பகிர்ந்த செயல்முறை அளவில். விசை = `sha256(imageRef + composedPrompt + configuredBridgeModel)` நீளம்-முன்குறியீட்டு வடிவமைப்புடன் (எந்த புலம்-எல்லை மோதல்கள் இல்லை). மாதிரி கூறு என்பது **அமைக்கப்பட்ட** பாலம் மாதிரி, உண்மையில் பதிலளித்த மாதிரி அல்ல — `callVisionModel` உள்ளகமாக பின்னடைவு செய்யலாம், மற்றும் முயற்சிக்கு அடிப்படையில் விசை அமைப்பது கச்சாவை உடைக்குமாறு இருக்கும். தோல்வியடைந்த விவரங்கள் எப்போதும் கச்சாவில் சேமிக்கப்படவில்லை. அமைப்புகள்:

| விசை                            | இயல்பு | வரம்பு  |
| ------------------------------- | ------ | ------- |
| `modalityBridgeCacheEnabled`    | `true` | —       |
| `modalityBridgeCacheTtlMinutes` | `60`   | 1–1440  |
| `modalityBridgeCacheMaxEntries` | `200`  | 10–5000 |

#### தொலைக்காட்சி படத்தை சீரமைத்தல் (சுய-சுழற்சி விவரிக்கான/base64 பெறுதல்)

பாலம் **தொலைக்காட்சி** படத்தை தானாகவே பெறும் போது — Anthropic விவரிக்கான சுய-அழைப்பு மற்றும் claude-wire-format base64 மாற்றம் (`ensureBase64ImagesForClaudeWire`), இரண்டும் `fetchRemoteImageAsDataUri()` இல் `visionBridgeHelpers.ts` மூலம் — பெறப்பட்ட தரவுப் URI `normalizeDataUri()` மூலம் செல்கிறது (`open-sse/utils/imageNormalize.ts`) காட்சி-மாதிரி கோரிக்கையில் இணைக்கப்படுவதற்கு முன். மிகப்பெரிய படங்கள் **2048px நீளமான எல்லைக்கு** குறைக்கப்படுகின்றன (OpenAI/Anthropic ஏற்கனவே சர்வர் பக்கம் பயன்படுத்தும் அளவீட்டு வரம்பை ஒத்துப்போகிறது), இது பதிவேற்றம் செய்யும் பைட்டுகளை/தாமதத்தை குறைக்கிறது, காட்சி மாதிரி என்ன பார்க்கிறதைக் மாற்றாமல். மறுசீரமைப்பு `sharp` ஐப் பயன்படுத்துகிறது, இது இயக்கவியல் இறக்குமதி மூலம் ஏற்றப்படுகிறது: அதன் உள்ளூர் பைனரி ஏற்றப்படாத ஒரு தளத்தில், `normalizeDataUri()` **எப்போதும் வீழ்ச்சியடையாது** — இது முதன்மை பைட்டுகளைப் பாஸ்திரூவாகக் கொண்டு செல்லும், எனவே விவரிக்கான/base64-மாற்றம் பாதை எப்போதும் செயல்படுகிறது. படமல்லாத பைட்டுகள் (ஒரு குறியாக்கத்திற்கான படம் திரும்பவில்லை) மாற்றமின்றி செல்கின்றன. இந்த சீரமைப்பு பாலம் தனது சொந்த சுய-அழைப்பிற்காகப் பெறும் படங்களுக்கு மட்டுமே வரையறுக்கப்பட்டுள்ளது — இது அழைப்பாளரின் கச்சா பாஸ்திரூவுப் பைலுக்கு எப்போதும் பயன்படுத்தப்படுவதில்லை, தேர்வு செய்யும் மாற்றத்தின் கோட்பாட்டுடன் (Hard Rule #20).

#### அமைப்புகள் திட்டம் + மாறுதல்

புதிய `modalityBridge*` விசைகள் `updateSettingsSchema` இல் Zod-சரிபார்க்கப்பட்டுள்ளன (`src/shared/validation/settingsSchemas.ts`): `modalityBridgeVisionEnabled`, `modalityBridgeVisionMode`, `modalityBridgeVisionModel`, `modalityBridgeVisionTaskAware`, `modalityBridgeVisionPrompt`, `modalityBridgeVisionTimeout`, `modalityBridgeVisionMaxImages`, `modalityBridgeVisionMaxChars`, `modalityBridgeCache*` மூன்று, மற்றும் Audio Bridge மூலம் பயன்படுத்தப்படும் `modalityBridgeAudio*` குழு. மாறுதல் `141_modality_bridge_settings.sql` ஏற்கனவே உள்ள பாரம்பரிய `visionBridge*` மதிப்புகளை பொருந்தும் புதிய விசைகளுக்கு நகலெடுக்கிறது (இயல்பாக, எப்போதும் ஒரு இயக்குநர் அமைக்கப்பட்ட `modalityBridge*` மதிப்பை மீறாது); பாரம்பரிய விசைகள் ஒரு வெளியீட்டு சுற்றுக்கு வாசிப்பு மீள்பார்வையாக ஏற்கனவே ஏற்றுக்கொள்ளப்படுகின்றன.

#### வெளிப்படைத்தன்மை தலைப்பு + புள்ளிவிவரங்கள்

விவரிக்கான மாற்றப்பட்ட பதில்கள் `x-omniroute-modality-bridge: image->text;model=<visionModel>;parts=<n>` ஐ கொண்டுள்ளன (இது `modalityBridge/bridgeStats.ts` இல் `buildModalityBridgeHeader()` மூலம் உருவாக்கப்படுகிறது, `src/sse/handlers/chatHelpers.ts` இல் `withModalityBridgeHeader()` மூலம் முத்திரை இடப்படுகிறது). மறுவழிமாற்றப்பட்ட கோரிக்கைகள் **எந்த** தலைப்பும் பெறவில்லை — payload மாற்றமின்றி இருந்தது மற்றும் மாதிரி மாற்றம் பதிலின் உடலில் `model` புலத்தில் ஏற்கனவே தெளிவாக உள்ளது.

`GET /api/modality-bridge/stats` (மேலாண்மை அங்கீகாரம், `GET /api/settings` உடன் ஒரே நிலை) நினைவகத்தில் உள்ள ஒவ்வொரு முறைமையின் எண்ணிக்கைகளை
`{ attempts, successes, bridged, cacheHits, failures, totalLatencyMs,
latencySamples, averageLatencyMs, lastUsedAt }` `vision`, `audio`, மற்றும்
`video` க்காக திருப்புகிறது. `averageLatencyMs` அதன்
கணக்கீட்டில் `latencySamples` ஐ பயன்படுத்துகிறது, அனைத்து முயற்சிகளையும் அல்ல; நேரம் இல்லாத ஒரு செயல்பாடு பூஜ்ய மில்லிசெகண்ட்
மாதிரியை உருவாக்காது. வெற்றிகரமான மாற்றங்களுக்கு `bridged` பின்னணி-ஒத்திகை பெயராக உள்ளது; தோல்வியடைந்த முயற்சிகள் அதை
மேம்படுத்தாது.
எண்ணிக்கைகள் செயலியை மீண்டும் தொடங்கும் போது வடிவமைப்பின் அடிப்படையில் மீட்டமைக்கப்படுகின்றன
(தொலைபேசி, கணக்கீடு அல்ல).

இயல்புநிலை), பணியுடன் தொடர்புடைய உந்துதல், முன்னணி நேரம்/படம்/விளக்கம்-நீளம்/கேஷ்
வரம்புகள், இயக்க நேரம்
எண்ணிக்கைகள் மற்றும் பாதுகாக்கப்பட்ட மாதிரி கோரிக்கையை வெளிப்படுத்துகிறது. Audio தாவல் கூட உயிருடன் உள்ளது: இது
செயல்படுத்தல், STT-மட்டுமே மாதிரி தேர்வாளர், தானாகவே, நேரம்/அதிகபட்ச-கிளிப் வரம்புகள், ஒலி
எண்ணிக்கைகள் மற்றும் `input_audio` மாதிரி சோதனை. Video தாவல் செயல்படுகிறது: இது
FFmpeg/ffprobe இயக்க நிலையை அறிவிக்கிறது — நான்கு தெளிவான UI நிலைகளில் ஒன்றாக (`unknown` probe பறக்கும்போது
அல்லது முடிக்க முடியவில்லை, `restricted` ஒரு non-loopback
டாஷ்போர்ட் ஹோஸ்டில் probe கிளையன்ட் பக்கம் தவிர்க்கப்படுகிறது, `unavailable` probe செய்யப்பட்டு
உள்ளதாக உறுதிப்படுத்தப்பட்டது, அல்லது `available` FFmpeg/ffprobe பதிப்புகளுடன்) —
enable/model/frame/video/timeout வரம்புகளை நிலைநாட்டுகிறது, மாதிரி தேர்வாளரை
vision-capable மாதிரிகளுக்கே வடிகட்டுகிறது, மற்றும் வீடியோ எண்ணிக்கைகளை வெளிப்படுத்துகிறது.

AI அமைப்புகளின் கீழ் முந்தைய Vision Bridge அட்டை புதிய பக்கத்திற்கான
ஒத்திகை இணைப்பாக உள்ளது; இது வடிவத்தை மீண்டும் கொண்டிருக்கவில்லை. மீடியா வழங்குநர்கள்
Image-to-Text மற்றும் Speech-to-Text வேலைப்பாடுகளை தொடர்புடைய முறைமையின்
Bridge தாவல்களுக்கு இணைக்கின்றன, ஏற்கனவே உள்ள Speech-to-Text விளையாட்டை நீக்காமல்.

**சுய-சுழற்சி அனுமதி தவிர்ப்பு:** விவரிக்கப்படும் அழைப்பு OmniRoute இன்
சுய-சுழற்சியில் `/v1` வழியாக செல்லும்போது (சாதாரணமாக இல்லாத வழங்குநர் மாதிரி), துணை-கோரிக்கை
`x-omniroute-admission-bypass: internal` ஐ அனுப்புகிறது மற்றும் தீர்க்கப்பட்ட
சுய-சுழற்சி அங்கீகாரத்துடன் அங்கீகாரம் பெறுகிறது — உள்ளூர் `sk_omniroute` உள்ளூர் முறையில், அல்லது
ஆசிரியர்-அமைக்கப்பட்ட `OMNIROUTE_API_KEY` / `ROUTER_API_KEY` env விசை (#1350) எனவே
`REQUIRE_API_KEY=true` செயல்பாடுகள் விவரிக்கப்படும் அழைப்பை இன்னும் இயக்கலாம். இந்த தவிர்ப்பு
அந்த குறிப்பிட்ட அங்கீகாரங்களுக்கு மட்டுமே மதிக்கப்படுகிறது, எனவே வெளிப்புற கிளையன்கள்
அனுமதியை தவிர்க்க தலைப்பை பயன்படுத்த முடியாது.

பழைய இயல்புகள் `src/shared/constants/visionBridgeDefaults.ts` இல் உள்ளன; புதிய
முறை/பணி-தகவலுடன் கூடிய/கேஷ் இயல்புகள் மற்றும் அமைப்புகள் தீர்க்குபவர்
`src/shared/constants/modalityBridgeDefaults.ts` இல் உள்ளன. பாதுகாப்பு
`deps` கட்டமைப்பாளர் விருப்பத்தை வெளிப்படுத்துகிறது, எனவே சோதனைகள் போலியான
`getSettings` மற்றும் `callVisionModel` செயல்பாடுகளை ஊட்டலாம்.

### Audio Bridge (`audioBridge.ts`) — Modality Bridge PR-3

ஒலியுடன் கூடிய உரையாடல் கோரிக்கைகளை இலக்கத்திற்கு செல்லும் முன்
தடுக்கிறது, அது ஒலியினை ஏற்கிறது என்று தெரியாது. இது உரையாடல் கோரிக்கையை மீண்டும் வழிமொழியாது: ஒலி பகுதிகள்
ஓப்பன்AI-க்கு ஏற்புடைய பல்வேறு முடிவுகளை வழியாக உரை மாற்றப்படுகின்றன மற்றும்
தேர்ந்தெடுக்கப்பட்ட உரையாடல் மாதிரி உரை உரைபடுத்தலுடன் தொடர்கிறது.

போக்கு:

1. `getResolvedModelCapabilities()` மூலம் `supportsAudio` ஐ தீர்க்கவும். தெளிவான
   வழங்குநர்-பதிவு மெட்டாடேட்டா வெற்றி பெறுகிறது, பின்னர் நிலையான மாதிரி மெட்டாடேட்டா, பின்னர்
   ஒத்திசைவு `modalities_input`. `audio` இல்லாத ஒரு அறிவிக்கப்பட்ட உள்ளீட்டு பட்டியல் `false`; எந்த
   திறனை நிரூபிக்கும் ஆதாரம் `null` ஆக இருக்கும். `false` மற்றும் `null` இரண்டும்
   பாதுகாப்பான பாலத்தை செயல்படுத்துகின்றன, ஆனால் `true` அதை தவிர்க்கிறது.
2. `modalityBridgeAudio*` அமைப்புகளை தீர்க்கவும் மற்றும் ஒவ்வொரு செய்தியிலிருந்தும்
   பகிரப்பட்ட `detectMediaParts()` கண்டுபிடிப்பாளரின் மூலம் துண்டிக்கக்கூடிய மேல் நிலை
   ஒலி பகுதிகளை எடுக்கவும். ஆதரிக்கப்படும் வயர் வடிவங்கள் OpenAI `input_audio`, `audio_url`, மற்றும்
   `source.media_type: "audio/*"` ஆக உள்ளன. அடுக்குமுறை ஒலியை வழிமொழிக்க
   கண்டுபிடிக்கப்படுகிறது ஆனால் துண்டிக்கப்படும் பாதையால் நீக்கப்படாது. வேலை `modalityBridgeAudioMaxClips` மூலம்
   கட்டுப்படுத்தப்படுகிறது; பின்னணி பகுதிகள் untouched ஆக இருக்கும்.
3. ஒரு கட்டமைக்கப்பட்ட `provider/model` ஐ மதிக்கவும், அல்லது `selectAudioBridgeModel()` ஐ
   நிலையான பட்டியலில் `AUDIO_TRANSCRIPTION_PROVIDERS` ஐ நடைமுறைப்படுத்த அனுமதிக்கவும்
   மற்றும் பயன்பாட்டிற்குரிய செயல்பாட்டாளர் அங்கீகாரத்துடன் முதல் மாதிரியை தேர்ந்தெடுக்கவும்.
4. `callAudioTranscription()` base64/data-URI ஒலியை ஒரு பல்வேறு
   `file` ஆக மாற்றுகிறது, அல்லது பொதுவாக மட்டுமே வெளியே செல்லும்
   பாதுகாப்புடன் DNS pinning மற்றும் 25 MB வரம்பு மூலம் தொலைவில் உள்ள `audio_url` ஐ பதிவிறக்கம் செய்கிறது. பின்னர்
   அது கோப்பையும் தேர்ந்தெடுக்கப்பட்ட மாதிரியையும் உள்ளூர் `/v1/audio/transcriptions` சுய-சுழற்சிக்கு POST செய்கிறது,
   `resolveSelfLoopBearer()` மூலம் அங்கீகாரம் பெறுகிறது. உள்ளமைவான உரை மாற்றம்
   சாதாரண அங்கீகார தேடல், குளிர்ச்சி/விகிதம்-வரம்பு கையாளுதல் மற்றும் வழங்குநர் அனுப்புதல்
   செய்கிறது.
5. வெற்றிகரமான அழைப்புகள் `[Audio N]: <transcript>` உடன் தங்கள் பகுதிகளை மாற்றுகின்றன. அழைப்புகள்
   `Promise.allSettled` உடன் இயக்கப்படுகின்றன: தனிப்பட்ட தோல்வி அந்த முதன்மை
   ஒலி பகுதியை பாதுகாக்கிறது (#4012 ஒப்பந்தம்). ஒவ்வொரு அழைப்பும் தோல்வியடைந்தால் மற்றும் இலக்கு
   `supportsAudio === false` என நிரூபிக்கப்பட்டால், பகுதிகள்
   `[Audio N]: (unavailable — no STT provider connected)` (#8430 ஒப்பந்தம்) ஆக மாறுகின்றன. ஒரு
   தெரியாத இலக்கு (`null`) என்றால், அனைத்து தோல்வி முடிவுகள் untouched ஆக இருக்கும். ஒரு
   நிரூபிக்கப்பட்ட உரை-மட்டுமே இலக்கு எந்த பயன்பாட்டிற்குரிய STT அங்கீகாரத்தையும் பெறாமல்
   அதே தெளிவான stub ஐ பெறுகிறது, நெட்வொர்க் அழைப்பை வெளியிடாமல்.

வெற்றிகரமான உரை மாற்றங்கள் செயலியின் அளவுக்கு முறைமையின் பாலத்தின் LRU/TTL கேஷ்
பயன்படுத்துகின்றன. விசை ஒலியின் குறிப்பை, நிலையான `audio-transcription` செயல்பாட்டின்
குறிப்பை மற்றும் தேர்ந்தெடுக்கப்பட்ட STT மாதிரியை இணைக்கிறது; தோல்விகள்
எப்போதும் கேஷ் செய்யப்படாது. ஒலி முயற்சிகள் பகிரப்பட்ட `bridged`, `cacheHits`, `failures`, மற்றும் `lastUsedAt` எண்ணிக்கைகளை
புதுப்பிக்கின்றன. மாற்றிய பதில்கள்
`x-omniroute-modality-bridge: audio->text;model=<sttModel>;parts=<n>` ஐ கொண்டிருக்கின்றன; untouched
கோரிக்கைகள் Audio Bridge பகுதியை பெறவில்லை.

இயக்க நேர அமைப்புகள் DB-ஆதாரமாகவும் Zod-சரிபார்க்கப்பட்டவையாகவும் உள்ளன:

| விசை                          | இயல்பானது | வரம்பு             |
| ----------------------------- | --------- | ------------------ |
| `modalityBridgeAudioEnabled`  | `true`    | —                  |
| `modalityBridgeAudioModel`    | `""`      | Auto அல்லது STT ID |
| `modalityBridgeAudioTimeout`  | `60000`   | 1000–300000        |
| `modalityBridgeAudioMaxClips` | `3`       | 1–10               |

பகிரப்பட்ட கேஷ் `modalityBridgeCacheEnabled`,
`modalityBridgeCacheTtlMinutes`, மற்றும் `modalityBridgeCacheMaxEntries` மூலம் கட்டுப்படுத்தப்படுகிறது.

### வீடியோ பாலம் (`videoBridge.ts`, `videoBridgePipeline.ts`)

இது Chat Completions `messages` மற்றும் Responses API `input` இல் உள்ள மேல் நிலை வீடியோ பகுதிகளை ஒரு இலக்கு அழைக்கப்படுவதற்கு முன் இடைமுகம் செய்கிறது, அதில் உள்ள உள்ளூர் வீடியோ ஆதரவைப் பற்றிய தகவல் இல்லை.
ஆதரிக்கப்படும் வடிவங்கள் `input_video`, `video_url`, `video_source`, HTTPS URLs,
மற்றும் `data:video/*;base64,...` தரவுப் URI கள். உரை உள்ள சாதாரண கோப்பு பெயர்கள்
வீடியோவாகக் கருதப்படுவதில்லை.

`VideoBridgeGuardrail.preCall` (`videoBridge.ts`) கோரிக்கையின் பயணத்தை, திறன்/கொள்கை சரிபார்ப்பை, கோரிக்கைக்கு அடிப்படையிலான தொகுப்பை, மற்றும் பதிலளிக்கும் தரவுகளை உடையது.
ஒவ்வொரு வீடியோ வேலை — வாங்குதல், முழு முடிவின் கேஷ், ஒரு கட்டம்
அணுக்கத்தை விவரிக்கிறது (எது எந்த அழைப்பாளர் அறிவிக்கப்பட்ட ஆடியோ உரையை இணைக்கிறது), மற்றும் ஒவ்வொரு முயற்சிக்கும்
அளவீடுகள்/நிறுத்தம்/சுத்தம் — `processVideoPart` இன் பின்னால் மறைக்கப்பட்டுள்ளது
`videoBridgePipeline.ts` இல், `preCall` இன் சுற்றுப்பாதையில் ஒவ்வொரு வீடியோ பகுதிக்கும் ஒருமுறை அழைக்கப்படுகிறது.

`segment_aware` ஏற்கனவே சரிபார்க்கப்பட்ட உள்ளூர் வீடியோ ஸ்ட்ரீமில் ஒரு வரையறுக்கப்பட்ட முன்-அனாலிசிஸ் கடத்தலைப் பயன்படுத்துகிறது. நிலையான வடிகட்டல் சங்கிலி முதலில் அதிகபட்சமாக 320 பிக்சல்களுக்கு அளவிடுகிறது, காட்சி மாற்றங்களை மற்றும் உறைந்த இடைவெளிகளை கண்டறிகிறது, பின்னர் மங்கலான, சராசரி லூமா மற்றும் இடவியல்/கால தகவலுக்கு 1 ஃப்ரேம் ஒரு வினாடிக்கு மாதிரிகளை எடுக்கிறது. இந்த கடத்தல் 600 கட்டமைப்பியல் மாதிரிகளுக்கு, ஒரு FFmpeg/வடிகட்டி த்ரெடுக்கு, ஒரே `file`-மட்டுமே உள்ள நெறிமுறைகள் மற்றும் கொண்டெய்னர் அனுமதிகளுக்கு, 1 MiB செயல்முறை-வெளியீட்டு எல்லைக்கு, மற்றும் அதிகபட்சமாக 30 வினாடிகள் பரிமாற்றத்தின் பகிரப்பட்ட நிறுத்தம்/காலக்கெடு உள்ளே வரையறுக்கப்பட்டுள்ளது. இது எப்போது வேண்டுமானாலும் ஒரு கட்டளை, வடிகட்டி, பாதை, அல்லது URL-ஐ கோரிக்கையிலிருந்து ஏற்காது.

கட்டமைப்பியல் மதிப்புகள் தீர்மானமான மாதிரியாக்கும் சான்றுகள், அர்த்தமுள்ள வீடியோ புரிதல் அல்ல. அவை பொருட்கள், செயல்கள், தலைப்புகள், பேச்சு, அல்லது பயனர் நோக்கங்களை ஊகிக்கவில்லை. காட்சி மற்றும் உறை எல்லைகள் பகுதிகளை உருவாக்குகின்றன; உறை கவர்ச்சி, மங்கல், வெளிச்சம், இடவியல் விவரம், மற்றும் கால மாற்றம் மட்டுமே உள்ள 1–16 ஃப்ரேம் பட்ஜெட்டை எவ்வாறு ஒதுக்கப்படுகிறதென்பதை பாதிக்கின்றன. முழுமையாக உறைந்த பகுதி ஒரு ஃப்ரேமில் மட்டுமே கட்டுப்படுத்தப்படுகிறது, ஆனால் உறையாத பகுதிகள் மீதமுள்ள பட்ஜெட்டிற்காக போட்டியிடுகின்றன. எல்லைகள் ஃப்ரேம்களை மிஞ்சினால், ஒரே மாதிரியான கால அட்டவணை கவர்ச்சி retained ஆகிறது, எனவே விரைவான ஆரம்ப வெட்டுகள் நீண்ட பின்வட்டத்தை மறைக்க முடியாது. ஒரு உறை எல்லையின் 1-வினாடி அனாலிசிஸ் தீர்வுக்குள் உள்ள காட்சியின் எல்லைகள் ஒன்றிணைக்கப்படுகின்றன.

காணாமல் போன வடிகட்டிகள், தவறான/காலியான சான்றுகள், ஒரு கண்டுபிடிப்பாளர் பிழை, அல்லது வரையறுக்கப்பட்ட முன்-அனாலிசிஸ் நேரம் திறக்கப்படுவதற்கு சரியான ஒரே மாதிரியான மையக் கொள்கைக்கு தோல்வியுறுகிறது. ஒரு அழைப்பாளர் நிறுத்தம் அல்லது பரிமாற்ற காலக்கெடு திறக்காது: இது பறவையில் உள்ள துணை செயல்முறையை நிறுத்துகிறது, பின்னர் ஃப்ரேம் எடுப்பதைத் தடுக்கும், மற்றும் தனிப்பட்ட தற்காலிக மரத்தை `finally` இல் அகற்றுகிறது.

`scripts/perf/video-bridge-fu07-eval.ts` பின்விளைவுகளை அழிக்க, அடர்த்தி-இயங்கும் பட்ஜெட்டை ஒதுக்க, மங்கல்/வெளிச்சம்/SI-TI சான்றுகளை, நீண்ட வாலுடன் விரைவான வெட்டுகளை, மற்றும் மெதுவாக மங்கும் தவறான நேர்மறைகளை உருவாக்குவதற்கான தீர்மானமான உண்மையான FFmpeg அமைப்புகளை உருவாக்குகிறது. இது முன்-அனாலிசிஸ் சுவர் நேரத்தை பதிவு செய்கிறது மற்றும், `/usr/bin/time` கிடைக்கும்போது, குழந்தை CPU மற்றும் உச்ச RSS-ஐ பதிவு செய்கிறது. அதன் தரமான சோதனைகள் கட்டமைப்பியல் ஓரக்கோடிகள் மட்டுமே. உண்மையான தலைப்பு-மாதிரி தரம் `HOLD` ஆகவே உள்ளது, ஏனெனில் இந்த ஹார்னஸ் எந்த அதிகாரப்பூர்வமான முடிவெடுப்பதற்கோ அல்லது உறைந்த நீதிபதிக்கோ உட்பட்டது இல்லை. பணத்திற்கான சேமிப்புகள் `--caption-cost-per-call-usd` ஒரு தெளிவான நேர்மறை ஒவ்வொரு அழைப்பிற்கான மதிப்பீட்டை வழங்கும் வரை `HOLD` ஆகவே உள்ளது; ஸ்கிரிப்ட் எந்த முடிவையும் உருவாக்காது.

ஒவ்வொரு ஃப்ரேமுக்கும் 4 MiB வரை, அனைத்து கச்சா ஃப்ரேம்கள் ஒன்றாக 23 MiB வரை, மற்றும் வரிசைப்படுத்தப்பட்ட பரிமாற்ற பதில் 32 MiB வரை கட்டுப்படுத்தப்படுகிறது. ஒரு தனிப்பட்ட தற்காலிக அடைவு `finally` இல் அகற்றப்படுகிறது. OmniRoute FFmpeg-ஐ தொகுப்பதில்லை மற்றும் தனிப்பட்ட செயல்பாட்டுப் பாதையை ஏற்கவில்லை. தலைப்பிடுவதற்கு முன், பாலம் ஒரு பாதுகாப்பான காட்சி மறுபடியும் கடத்தலைச் செய்கிறது: ஒவ்வொரு JPEG-க்கும் 16×16 கிரேஸ்கேல் பஃபரில் குறைக்கப்படுகிறது மற்றும் கடைசி ஃப்ரேமுடன் மட்டுமே ஒப்பிடப்படுகிறது. ஒரு ஃப்ரேமுக்கு மேல் கோரப்பட்ட தலைப்பு பட்ஜெட்டிற்காக, எடுப்பது ஒரு வரையறுக்கப்பட்ட வேட்பாளர் கிண்டல்களை வழங்குகிறது, அதற்கான பட்ஜெட்டின் இரட்டிப்பு வரை மற்றும் 16 ஃப்ரேம்களுக்கு மேல் எப்போது வேண்டுமானாலும் இல்லை. மறுபடியும், முதலில் மற்றும் இறுதியாக தேர்ந்தெடுக்கப்பட்ட வேட்பாளர்கள் இறுதி குறுகலின் போது பாதுகாக்கப்படுகின்றனர், பட்ஜெட் குறைந்தது இரண்டு இருக்கும்போது. பதிப்பீட்டுள்ள `grayscale-16x16-mean-cells-v2` கொள்கை சராசரி லூமா டெல்டா மற்றும் குறைந்தது 0.05 ஆக உள்ள நார்மலைசேட் டெல்டாவின் விகிதத்தைப் பயன்படுத்துகிறது. நகல் மையம் 0.04 என்ற நிலையானது, கணிக்கையைப் பெறுவதற்காக தேர்ந்தெடுக்கப்பட்டுள்ளது, இயக்க நேர அமைப்பாக வெளிப்படுத்தப்படவில்லை. இந்த இரண்டாம் நிலை உயர்-கான்டிராஸ்ட் சிக்னல் சிறிய இயக்கம் மற்றும் காணக்கூடிய-உரை மாற்றங்களை பாதுகாக்கிறது, ஒரு சராசரி மட்டுமே ஒப்பீடு மறைக்கக்கூடியது. ஒப்பீட்டாளர் அல்லது டிகோடர் பிழைகள் திறக்கின்றன மற்றும் கவர்ச்சியைப் பாதுகாக்கின்றன. வெளியீட்டு மெட்டாடேட்டா எடுக்கப்பட்ட வேட்பாளர்களை, வெற்றிகரமாக பயன்படுத்திய ஃப்ரேம்களை, மற்றும் காட்சி நகல்களை பிரிக்கிறது.

ஒரு தெளிவாக குறிக்கப்பட்ட வீடியோ பகுதி ஒரு நேரமூட்டப்பட்ட தொடர்பு தாளை கோரலாம். பாலம் அதிகபட்சமாக 4-நெட்வெளி, 16-ஃப்ரேம் JPEG கிரிட் உருவாக்குகிறது. ஒவ்வொரு 512-பிக்சல் செலும் அதன் மூல நேரத்தை ஒரு உயர்-கான்டிராஸ்ட் கீழ் பட்டையில் எரிக்கிறது, அதே நேரங்கள் கீழே உள்ள தொடர்பு மற்றும் கணக்கீட்டிற்கான உரை மெட்டாடேட்டாவில் உள்ளன. முழுமையான JPEG 32 MiB இல் கட்டுப்படுத்தப்படுகிறது. `sharp` கிரிட்-ஐ டிகோட் அல்லது உருவாக்க முடியாதால், பாலம் தனிப்பட்ட JPEG ஃப்ரேம்களுக்கு மீண்டும் செல்லும்; ஒரு கிளையன்ட் நிறுத்தம் இன்னும் தாளின் செயல்பாட்டின் மூலம் பரவுகிறது.

புரோமோஷன் சான்றுகள் செயற்கை அமைப்பின் மைக்ரோபேஞ்ச்மார்க்கில் இருந்து故意மாகப் பிரிக்கப்பட்டுள்ளது. `scripts/perf/video-bridge-contact-sheet-eval.ts` உண்மையான OpenAI-இன் இணக்கமான காட்சி மாதிரிகளுக்கான ஒரு ஸ்கீமா-பதிப்பீட்டுள்ள A/B ஹார்னஸை வரையறுக்கிறது. இது வழங்குநர்-அறிக்கையிட்ட டோக்கன்களை, முடிவில் முடிவில் சுவர் தாமதத்தை (தாளின் அமைப்பை உள்ளடக்கியது), மாதிரி-அழை எண்ணிக்கையை, மற்றும் மானிபஸ்ட்-வரையறுக்கப்பட்ட உண்மை பராமரிப்பை அளவிடுகிறது. கச்சா மாதிரி பதில்கள் அறிக்கையில் எழுதப்படவில்லை; SHA-256 டிகஸ்ட் மற்றும் பொருந்திய உண்மை ID-கள் மட்டுமே பாதுகாக்கப்படுகின்றன. இந்த ஹார்னஸ் எந்த நெட்வொர்க் அல்லது பணம் செலுத்தும் மாதிரி அழைப்பைச் செய்யாது, `--execute-real` வழங்கப்பட்டால் மட்டுமே, மற்றும் `--model`, `OMNIROUTE_BASE_URL`, மற்றும் `OMNIROUTE_API_KEY` க்கான அமைப்புகள் உள்ளன. அந்த தெளிவான உண்மையான இயக்கம் இல்லாமல், அதன் இயந்திரம்-படிக்கக்கூடிய தீர்வு `HOLD` ஆகவே உள்ளது; செயற்கை payload/அழை-எண்ணிக்கை அளவீடுகள் மட்டுமே புரோமோஷன் சான்றுகள் அல்ல.

பிரித்த `scripts/perf/video-bridge-promotion-eval.ts` FU-07 அல்லது FU-09 கவனிப்புகளை உண்ணுகிறது. புரோமோஷன் அனுமதி எட்டு செயற்கை காட்சியியல் வகைகளை மற்றும் ஒரு சுத்தமான உண்மையான கிளிப்பை, ஒவ்வொரு வேடத்திற்கும் மற்றும் வழக்கத்திற்கு குறைந்தது மூன்று அளவீட்டுகளை, அனைத்து பத்து அறிவிக்கப்பட்ட அளவீடுகளை, உறைந்த ஊடகம்/குறிப்பு/எதிர்பார்க்கப்பட்ட-உண்மை/அமைப்புகள் டிகஸ்ட், தனித்துவமான கவனிப்பு ID-கள் மற்றும் சரிபார்க்கப்பட்ட விதிக்கப்பட்ட A/B வரிசையை தேவைப்படுகிறது. செயல்பாட்டின் ரசீது தொகுப்பின் டிகஸ்ட், சரியான வேட்பாளர் SHA மற்றும் மாதிரி திருத்தத்தை கட்டுப்படுத்துகிறது. காணாமல் போன அல்லது தவறான அளவீடுகள் `HOLD` ஆகவே உள்ளன, 30 வினாடிகள் மேல் CPU, 512 MiB மேல் உச்ச RSS அல்லது 30 வினாடிகள் மேல் முன்-அனாலிசிஸ் உட்பட. இவை சான்று-அனுமதி எல்லைகள், புதிய இயக்க நேர RSS கட்டுப்பாட்டுக் கொள்கை அல்ல.

FU-07 குறைந்தது 98% தரத்தை பராமரிக்கவும், p95 தாமதம் அடிப்படையில் 1.2x க்கும் அதிகமாக இருக்கக்கூடாது, மேலும் சமமான சராசரி கோப்பு அழைப்புகளில் 0.05 முழுமையான வழக்கில் சமநிலையாக்கப்பட்ட சராசரி மீட்டெடுப்பை மேம்படுத்தவும், அல்லது குறைந்தது 10% குறைவான சராசரி பிந்தைய-மீட்டெடுப்பு கோப்பு அழைப்புகளை தேவைப்படுகிறது. FU-09 குறைந்தது 0.85 தரம், 95% பராமரிப்பு, 20% p95 தாமதம் குறைப்பு மற்றும் 10% டோக்கன் குறைப்பு தேவைப்படுகிறது. முக்கியமான உண்மை இழப்பு, ஊடுருவல் ஒப்புதல் அல்லது காணாமல் போன பயன்பாடு முன்னேற்றத்தைத் தடுக்கும். ஒரு செயல்பாடு எதையும் முன்னேற்ற முடியாது: `--previous-report` ஒரே கொள்கை/மாதிரி திருத்தம்/தேர்வாளர்/கோப்புக்கான இரண்டு தனித்துவமான, மாறுபட்ட, தொடர்ச்சியான தகுதியான செயல்பாடுகளை உறுதிப்படுத்துகிறது. ஒரு மாதிரிப்பு பரிசோதனை தொடர்பு-பட்டியல் பரிசோதனையை உறுதிப்படுத்த முடியாது.

சேகரிப்பாளர்கள் நினைவில் பதில்களை மதிப்பீடு செய்ய வேண்டும் மற்றும் `responseDigest` மற்றும் அளவீடுகள் மற்றும் கவனிப்பு பிணைப்புகளை சேமிக்க வேண்டும், பதில் உரையை எப்போதும் அல்ல. நுகர்வோர் பழமையான கச்சா கவனிப்புகளைப் படிக்கிறது ஆனால் அந்த உரையை தனது அறிக்கைகளில் எப்போதும் நகலெடுக்காது. ஒவ்வொரு கவனிப்பிற்கும் `responseDigest` அல்லது `rawResponseText` இல் ஒன்றே ஏற்றுக்கொள்ளப்படுகிறது. பதிப்பீட்ட அனுமதியியல் காலியாகவே உள்ளது, மாற்றமற்ற `hold` இயல்பாக உள்ளது. ஒரு தகுதியான நுழைவுக்கு அதன் ஆதாரக் குறிப்புகள், கொள்கை, மாதிரி திருத்தம், சரியான தேர்வாளர் SHA, மானிபெஸ்ட் டைஜெஸ்ட் மற்றும் இரண்டு தனித்துவமான இயக்க ID கள் தேவை; மோதிக்கும் சூழ்நிலைகள் நிராகரிக்கப்படுகின்றன. இந்த மெட்டாடேட்டா ஒரு ஆடிட் ஒப்பந்தமாகும், குறிப்பிட்ட கோப்பு உண்மையான அளவீடுகளை உள்ளடக்கியது என்பதை நிரூபிக்காது. எந்த நுழைவையும் சேர்க்கும் முன் உண்மையான ரசீது காட்சிகளைப் பரிசீலிக்கவும். மேலாண்மை புள்ளிவிவரங்கள் முடிவுகள் மற்றும் வீடியோ டாஷ்போர்டு பாதுகாப்பான தயார்திறனை வெளிப்படுத்துகின்றன. ஒரு கட்டமைக்கப்பட்ட மாதிரி பெயர் மட்டுமே அதன் திருத்தத்தை அல்லது இயக்கத்தில் உள்ள தேர்வாளர் SHA ஐ நிறுவாது, எனவே தற்போதைய டாஷ்போர்ட் `HOLD` ஐப் புகாரளிக்கிறது, மற்றொரு செயல்பாட்டு சூழ்நிலையிலிருந்து தகுதியை மீண்டும் பயன்படுத்துவதற்குப் பதிலாக. தெளிவான பரிசோதனைத் தேர்வு முன்னேற்றத்திலிருந்து தனியாக உள்ளது; எந்த இயல்பும் தானாகவே மாறவில்லை.

அழைப்பாளர்கள் ஏற்கனவே ஒத்த உரையைப் பெற்றால் ஆதரிக்கப்படும் வீடியோப் பகுதியுடன் விருப்பமான `transcript.cues` வரிசையை இணைக்கலாம். ஒவ்வொரு குறியீட்டும் `text`, சோதனை செய்யப்பட்ட காலத்தில் உள்ள முடிவான `start`/`end` இடைவெளி மற்றும் ஒரு அனுமதிக்கப்பட்ட `source` (`client`, `embedded`, அல்லது `audio-bridge`) கொண்டிருக்க வேண்டும்; `confidence` இயல்பாக `1` ஆக இருக்கும் மற்றும் `0` மற்றும் `1` இடையே இருக்க வேண்டும். சரியான நகல் குறியீடுகள் ஒருங்கிணைக்கப்படுகின்றன. OmniRoute இந்த மெட்டாடேட்டாவில் இருந்து உரை எழுதுதல் தொடங்காது: சரிபார்க்கப்பட்ட குறியீடுகள் விளக்கப்பட்ட முடிவில் ஆதாரம், நம்பிக்கை மற்றும் இடைவெளியுடன் நகலெடுக்கப்படுகின்றன, மற்றும் கட்டம் தலைப்புகளுடன் இணைந்து நம்பிக்கையற்ற கவனிப்புகளாக உருவாக்கப்படுகின்றன. தவறான, வரம்புக்கு வெளியான, அல்லது ஆதாரமற்ற உரை கலக்கப்படுவதற்குப் பதிலாக நிராகரிக்கப்படுகிறது. இரண்டு கோரிக்கை-உடல் உரை சேனல்கள் வழங்கிய ஆதாரத்தை `client` ஆக சாதாரணமாக்குகின்றன, தன்னிச்சையாகக் கூறப்பட்ட `embedded` அல்லது `audio-bridge` லேபிள்களை உள்ளடக்கியது. நம்பகமான லேபிள்களை அந்த நம்பகமான லேபிள்களை `trustedSource` ஆவணத்தால் மட்டுமே ஒதுக்க முடியும்; ஒரு கோரிக்கை JSON புலம் அந்த ஆவணத்திற்குச் செல்ல முடியாது. உரை உரை நம்பகமற்ற ஊடகத்தால் உருவாக்கப்பட்ட உள்ளடக்கம் ஆகும், அதன் ஆதாரத்தைப் பொருட்படுத்தாமல், மற்றும் எப்போதும் அதிகாரத்தை நிர்ணயிக்கக்கூடாது.

ஒரு மேம்பட்ட அழைப்பாளர் ஒரே வீடியோவுக்கான `audioTranscript` தடத்தை வழங்கலாம்; இது சேவையக உரை எழுதுதலின் ஆதாரமாக அல்ல, கிளையன்ட் வழங்கிய உரையாகக் கருதப்படுகிறது. இணைப்பு சீல் ஒரு இறுதி நேரம் மற்றும் நிறுத்தக் குறியீட்டின் கீழ் காட்சி மற்றும் ஒலி கவனிப்புகளை இயக்குகிறது, அவற்றை பொதுவான காலவரிசையில் ஒழுங்குபடுத்துகிறது, சரியான நகல்களை ஒருங்கிணைக்கிறது, மற்றும் ஒரே பக்கம் வெற்றி பெற்றால் பகுதி முடிவை அறிவிக்கிறது. தவறான `audioTranscript` அந்த பகுதி முடிவுக்கு குறைகிறது - காட்சி விளக்கம் பாதுகாக்கப்படுகிறது மற்றும் ஒலி கிளை ஒரு சுத்தமான தோல்வி குறியீட்டை பதிவு செய்கிறது - முழு வீடியோவை தோல்வியுறாமல். கிளை அடிப்படையில் கிடைக்கும், பகுதி கொடுப்பனவு மற்றும் சுத்தமான தோல்வி குறியீடுகள் விளக்கப்பட்ட முடிவில், பாதுகாப்பு மெட்டாடேட்டாவில் (`audioFusionRuns`/`audioFusionPartials`/`audioFusionFailureCodes`), முடிவு-கேஷ் மெட்டாடேட்டாவில், மற்றும் பாலம் இணைப்பு எண்ணிக்கையில் பாதுகாக்கப்படுகின்றன. இயல்பான வீடியோ பாலம் பாதை உரை-வழி உரை எழுதுதல் அல்லது இரண்டாவது ஊடக நகலை பதிவிறக்கம் செய்யாது; அந்த தெளிவான தடம் இல்லாமல், இது வீடியோ மட்டுமே ஆகிறது.

**உரை பராமரிப்பு (#12150 P1).** இது வீடியோ பாலம் (தானாகவே தேர்வு செய்யப்படும்) ஒரு உரை குறியீட்டை உருவாக்கும் போது தானாகவே செயல்படுகிறது - தனிப்பட்ட பராமரிப்பு கொடுப்பனவு இல்லை. ஒரு கோரிக்கை எந்த உரை குறியீட்டை உருவாக்கும் போது (ஒரு அழைப்பாளர் அறிவித்த `transcript` அல்லது ஒரு இணைக்கப்பட்ட `audioTranscript`), பாதுகாப்பு `videoBridgeObserved` எனக் குறிக்கிறது மற்றும் வீடியோ விளக்கத்தின் ஒரு மறைக்கப்பட்ட நிழலை உருவாக்குகிறது - ஒவ்வொரு குறியீட்டின் இலவச உரை உடலை `[redacted-video-transcript]` என மாற்றுவதன் மூலம் உருவாக்கப்படும் ஒரே மாதிரியான rendering, கட்டமைக்கப்பட்ட குறியீட்டு புலத்தை சரம் கட்டுவதற்கு முன் மாற்றுவதன் மூலம் (எப்போதும் சுருக்கப்பட்ட உரையைப் பார்ச் செய்வதன் மூலம் அல்ல, எனவே எந்த குறியீட்டு உள்ளடக்கம் - எதிர்மறை அல்லது சாதாரணம், `]` உள்ள உடல்களை உள்ளடக்கியது போன்றவை `[inaudible]`/`[music]` - உயிர் வாழ முடியாது). நிலைத்த அழைப்பு-பதிவு கோரிக்கை உடல் ஒவ்வொரு வீடியோ-உற்பத்தி உரை பகுதியையும் அந்த மறைக்கப்பட்ட நிழலுக்கு மாற்றுகிறது, உள்ளடக்க சமத்துவத்தால் பொருத்தமாக; `fullText` அங்கீகாரம் முடிந்த முன்-கோல் பாதுகாப்பு payload இல் இருந்து மீண்டும் வாசிக்கப்படுகிறது, எனவே பின்னர் சங்கிலி பாதுகாப்புகள் (PII மற்றும் அங்கீகாரம் மறைக்கும், முன்னுரிமைகள் 10/95) விளக்க உரையை இடத்தில் மறுபடியும் எழுதும் போது பொருத்தம் இன்னும் வெற்றி பெறுகிறது மற்றும் பிறகு அமைப்பு-உதவிக்குறிப்பு/கையொப்பம்/நினைவுப் புழக்கம் செய்தி வரிசையை மறுபடியும் வடிவமைக்கிறது. மாதிரிக்கு மேலே அனுப்பப்படும் உடல் மாற்றமில்லாமல் உள்ளது. ஒரு கவனிக்கப்பட்ட கோரிக்கையும் எந்த நிலையான நினைவையும் நிரப்பாது (கோரிக்கை மற்றும் பதில் மூலம் பெறுதல் இரண்டும் தவிர்க்கப்படுகின்றன), எனவே மாதிரியின் சொந்த பதில் நினைவில் உரை உரையை ஒலிக்க முடியாது.

**கச்சா வீடியோ புலங்கள் (#12430).** பாலம் செயல்படுத்தப்பட்ட போது மற்றும் உள்ளூர் வீடியோ ஆதரவு தெரியாத அல்லது இல்லாத போது, வரையறுக்கப்பட்ட `transcript`/`audioTranscript` புலங்கள் `videoBridgeObserved` ஐ இயக்குகின்றன, விளக்கம் தோல்வி அல்லது `maxVideos` வரம்பிற்குப் பிறகும். `null` மற்றும் காலியான உரைகள் எண்ணிக்கையில் அடங்கும்; காணாமல் போன புலங்கள் மற்றும் வீடியோ அல்லாத மெட்டாடேட்டா அடங்குவதில்லை. பராமரிக்கப்பட்ட நகல்கள் இந்த புலங்களை மறைக்கவோ கோரிக்கையை தவிர்க்கவோ செய்கின்றன, மற்றும் கேஷ்/நினைவுகள் தவிர்க்கப்படுகின்றன.

இந்த fallback பாதைகளில், செல்லுபடியாகும் அழைப்பாளர் குறியீடுகள் ஆதரிக்கப்படும் `text`/`input_text` பகுதிகளாக மாறுகின்றன, அசாதாரண வழங்குநர் புலங்களாக அல்ல. இரண்டு கோரிக்கையால் வழங்கப்பட்ட பாட்டுகள் இரண்டும் நம்பகமற்ற `client` கணிப்புகளாகவே உள்ளன, வீடியோ விவரிக்கப்படவில்லை மற்றும் நேரம் மியூடியா எதிர்காலத்துடன் சரிபார்க்கப்படவில்லை என்ற தெளிவான எச்சரிக்கையுடன். உள்ள 256-cue/64-KiB மொத்தம் மற்றும் ஒவ்வொரு குறியீட்டிற்கான பட்ஜெட்டுகள் இரண்டு பாட்டுகளுக்கிடையே பொருந்துகின்றன; நேரங்கள் broker இன் 600-வினாடி மேலோட்டத்திற்கும் வழங்கப்பட்ட கவனக் கண்ணாடியிற்கும் பொருந்த வேண்டும். செல்லுபடியாகாத பாட்டுகள் நீக்கப்படுகின்றன, அசாதாரண உரையாக முன்னேற்றப்படுவதில்லை; ஒரு செல்லுபடியாகும் சகோதரனை இன்னும் பயன்படுத்தலாம், அவர்கள் இணைந்த பட்ஜெட் மீறப்படாத வரை. Null/காலி புலங்கள் எந்த உரையையும் சேர்க்கவில்லை. இந்த fallback மூலம் எந்த ஊடகப் பெறுதல் அல்லது உரை மாற்றம் சேர்க்கப்படவில்லை. உரை மாற்ற விரிவாக்க புலங்கள் fallback வீடியோ கேரியரிலிருந்து மற்றும் அதன் `video_url`/`source` பொருட்களிலிருந்து நீக்கப்படுகின்றன. OpenAI கம்பி அனுமதி பட்டியல் கடுமையாக இருக்கும்; அங்கீகாரம் பெறாத உள்ளூர் வீடியோ கேரியர்கள் கிடைக்க உள்ளன மற்றும் அறியப்பட்ட உரை மட்டுமே இலக்குகள் பாதுகாப்பான குறியீடுகளை வைத்திருக்கின்றன. கட்டமைக்கப்பட்ட மறைமுகங்கள் இணைக்கப்பட்ட உரை மாற்றத்தைப் பாதுகாக்கின்றன, அப்போது முதன்மை அழைப்பாளர் சொந்தமான கோரிக்கை மாற்றமின்றி உள்ளது. உள்ளூர் ஆதரிக்கப்படும் இலக்குகள் மற்றும் முடக்கப்பட்ட பாலங்கள் தங்கள் தற்போதைய புறக்கணிப்பு நடத்தையைப் பாதுகாக்கின்றன.

எனவே, கொள்கை மாற்றம் பழைய முழு-வீடியோ விளக்கத்தை மீண்டும் பயன்படுத்த முடியாது. முடிவுக் கச்சா v4 மெட்டாடேட்டா முறை மற்றும் கீறுகளை வைத்திருக்கிறது, ஒருபோதும் கச்சா பயனர் பணியை அல்ல. காப்பு மெட்டாடேட்டா கேட்கப்பட்ட மற்றும் செயல்திறன் வாய்ந்த பகுப்பாய்வு முறைகளை இரண்டும் புகாரளிக்கிறது; பயன்படுத்தக்கூடிய பயனர் உரை இல்லாமல் கேட்கப்பட்ட `focused` முறை செயல்திறன் வாய்ந்த `full` ஆகக் குறிப்பிடப்படுகிறது.

காப்பு ஒவ்வொரு ஆதரிக்கப்படும் வீடியோ பகுதியையும் எடுக்கிறது, ஆனால் `modalityBridgeVideoMaxVideos` ஐவிட அதிகமாக விவரிக்கவில்லை. `supportsVideo === false` என்பதற்கான இலக்கத்திற்கு, தோல்வியடைந்த மற்றும் வரம்புக்கு மிஞ்சிய வீடியோக்கள் தெளிவான பாதுகாப்பான உரை குறியீடாக மாறுகின்றன, எனவே எந்த கச்சா வீடியோவும் உயிர் வாழாது. திறன்கள் தெரியாத போது, அந்த பகுதிகள் தங்கள் வீடியோ கேரியரை வைத்திருக்கின்றன; எந்த fallback உரை மேலே உள்ள கட்டுப்படுத்தப்பட்ட உரை மாற்றத்தைப் பின்பற்றுகிறது. `supportsVideo === true` உடைய இலக்குகள் பாலத்தை மீறுகின்றன. கிளையன்ட் கோரிக்கையின் நிறுத்த சிக்னல் பதிவிறக்கம், வர்த்தக வரிசை, துணை செயல்முறைகள், மற்றும் தலைப்பு அழைப்புகளில் பரவுகிறது; நிறுத்தங்கள் வீடியோக்களின் இடையே நிறுத்தப்படுகின்றன மற்றும் ஒருபோதும் கச்சா ஊடகத்திற்கு திறக்காது.

இயற்கை அமைப்புகள் DB-ஆதாரமாகவும் Zod-சரிபார்க்கப்பட்டவையாகவும் உள்ளன:

| விசை                                | இயல்பு      | வரம்பு / நடத்தை                                                                                                              |
| ----------------------------------- | ----------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `modalityBridgeVideoEnabled`        | `false`     | விருப்ப இயல்பான, சேர்க்கவும்                                                                                                 |
| `modalityBridgeVideoAnalysisMode`   | `"full"`    | `full` பொதுவான தலைப்புகளை பாதுகாக்கிறது; `focused` கட்டுப்படுத்தப்பட்ட, நம்பமுடியாத சமீபத்திய பயனர் சூழலைப் பயன்படுத்துகிறது |
| `modalityBridgeVideoModel`          | `""`        | பார்வை பாலம் மாதிரியைப் பெறுகிறது                                                                                            |
| `modalityBridgeVideoFrameCount`     | `8`         | 1–16                                                                                                                         |
| `modalityBridgeVideoSamplingPolicy` | `"uniform"` | `uniform`, `scene_aware`, அல்லது சதவீத `segment_aware`; கண்டுபிடிப்பு தோல்வி `uniform` க்கு மீண்டும் செல்லும்                |
| `modalityBridgeVideoMaxVideos`      | `1`         | 1–4                                                                                                                          |
| `modalityBridgeVideoTimeout`        | `120000`    | 1000–120000 ms                                                                                                               |

Legacy persisted Video timeout values above 120 seconds are clamped to the
broker deadline; new settings writes above that limit are rejected.
`GET /api/modality-bridge/video/runtime` requires trusted stamped loopback
locality before authentication or runtime probing, then requires management
auth. It returns only `available`, sanitized FFmpeg/ffprobe versions, and a fixed
reason when the runtime is unavailable. The internal extraction endpoint is not
a public upload API: queue saturation returns `503` plus `Retry-After`, a caller
disconnect returns `499`, and the fixed broker deadline returns `504`. Converted responses add
`video->text;model=<visionModel>;parts=<videos>` to the central
`x-omniroute-modality-bridge` header without removing Vision or Audio segments.

### PII Masker (`piiMasker.ts`)

**இரு** நிலைகளிலும் இயங்குகிறது.

- **`preCall`** payload ஐ நகலெடுக்கிறது, `system`, `messages`, `input`, மற்றும்
  `prompt` (சரளமான சரம் உருப்படிகளை உள்ளடக்கியது) ஆகியவற்றை நடைமுறைப்படுத்துகிறது மற்றும்
  `processPII()` (from
  `@/shared/utils/inputSanitizer`) ஐ string `content`/`text` புலங்களுக்கு
  பயன்படுத்துகிறது. `PII_REDACTION_ENABLED=true` என்றால், கண்டறியப்பட்ட PII
  வெளியேறும் payload இல் மறைக்கப்படுகிறது. இது `INPUT_SANITIZER_MODE` இல்
  சார்ந்தது அல்ல (இது மட்டும் prompt-injection கொள்கையை கட்டுப்படுத்துகிறது).
  மறைப்பு отключ் செய்யப்படும்போது, அழைப்பு பதிவுகள் கண்டறிதல் எண்ணிக்கைகளை
  உள்ளடக்கத்தை மறுசீரமைக்காமல் பதிவு செய்கிறது.
- **`postCall`** பதிலை ஆழமாக நகலெடுக்கிறது, `sanitizePIIResponse()` மற்றும்
  Responses-API-வடிவ masker (`maskResponsesOutput` — `output_text` மற்றும்
  `output[].content[].text` ஐ உள்ளடக்குகிறது) ஐ இயக்குகிறது. எந்த மறைப்பு
  நிகழ்ந்தால், மாற்றிய பதில் முதன்மை பதிலைக் மாற்றுகிறது.

காதுகாப்பு எப்போதும் தடுப்பதில்லை; இது மட்டும் குறிப்பு செய்கிறது
(`meta.detections`, `meta.redacted`) அல்லது மறுசீரமைக்கிறது.

### Prompt Injection (`promptInjection.ts`)

பயனர் வழங்கிய உள்ளடக்கத்தில் எதிர்மறை கட்டமைப்புகளை கண்டறிந்து
கொடுக்கப்பட்ட கொள்கையை அமல்படுத்துகிறது. நடத்தை சுற்றுப்புற மாறிகள் மற்றும்
கட்டுப்பாட்டுப் விருப்பங்களால் இயக்கப்படுகிறது:

| அமைப்பு             | சுற்றுப்புற மாறி                                                                                         | இயல்புநிலை | விளைவு                                                                                                                                                                                                           |
| ------------------- | -------------------------------------------------------------------------------------------------------- | ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| செயல்படுத்தப்பட்டது | `INPUT_SANITIZER_ENABLED`                                                                                | `true`     | `false` என்றால், பாதுகாப்பு குறுக்கீடு செய்கிறது.                                                                                                                                                                |
| முறை                | `INJECTION_GUARD_MODE` / `INPUT_SANITIZER_MODE`                                                          | `warn`     | Injection கொள்கை: `block`, `warn`, அல்லது `log`. (`redact` என்பது பின்னணி-இணக்கத்திற்கு ஏற்றுக்கொள்ளப்படுகிறது ஆனால் **மறைக்காது**; PII மறைப்பு கோரிக்கை `PII_REDACTION_ENABLED` மூலம் கட்டுப்படுத்தப்படுகிறது.) |
| தடுப்பு தற்காலிகம்  | `blockThreshold` விருப்பம் / `INPUT_SANITIZER_BLOCK_THRESHOLD` (alias `INJECTION_GUARD_BLOCK_THRESHOLD`) | `high`     | தடுப்பதற்கான குறைந்தபட்ச தீவிரம் தேவை. மிதமானது இயல்புநிலையிலேயே கவனிக்கப்படுகிறது.                                                                                                                              |

**முறை முன்னுரிமை** (`getMode`): அழைப்பாளர் `options.mode` →
`INJECTION_GUARD_MODE` **DB அம்ச-கொடுக்கல்-விளக்கத்தை மீறுகிறது** (Dashboard → Settings →
Feature Flags) → `INJECTION_GUARD_MODE` சுற்றுப்புறம் → `INPUT_SANITIZER_MODE` சுற்றுப்புறம் →
`warn`. எனவே, ஒரு டாஷ்போர்ட் மீறுதல் சுற்றுப்புற மாறிகளை மீறுகிறது, எனவே அம்ச
Flags UI நேரடியாக பாதுகாப்பை இயக்குகிறது (மீண்டும் தொடங்க வேண்டாம்). DB வாசிப்பு பாதுகாப்பானது:
அது பிழை ஏற்படுமானால், பாதுகாப்பு சுற்றுப்புற அடிப்படையிலான நடத்தைக்கு
மீண்டும் செல்லும், மற்றும் எந்த மீறுதல் அமைக்கப்படவில்லை என்றால் நடத்தை
சுற்றுப்புறம் மட்டுமே தீர்வுக்கு சமமாக இருக்கும்.

கண்டறிதல் மூலங்கள்:

1. `sanitizeRequest()` from `@/shared/utils/inputSanitizer` (pipeline இல்
   வேறு இடங்களில் பயன்படுத்தப்படும் பகிர்ந்த கண்டுபிடிப்பாளர் அமைப்பு).
2. உள்ளமைவான `DEFAULT_GUARD_PATTERNS` (தற்போது `system_override_inline` மற்றும்
   `markdown_system_block`, இரண்டும் `high` தீவிரம்).
3. கட்டுப்பாட்டுப் விருப்பங்கள் மூலம் அனுப்பப்படும் விருப்ப `customPatterns` (சரங்கள், regex,
   அல்லது `{ name, pattern, severity }` பதிவுகள்).

`mode === "block"` **மற்றும்** குறைந்தது ஒரு கண்டறிதல் தீவிரம்
தரத்தை சந்திக்கும்போது, `preCall` `{ block: true, message: "Request rejected:
suspicious content detected" }` ஐ திருப்புகிறது. `warn`/`log` முறைகளில்
பாதுகாப்பு பதிவு செய்கிறது ஆனால் அழைப்பை அனுமதிக்கிறது. பகிர்ந்த உதவியாளர்
`evaluatePromptInjection()` ஐ அழைப்பாளர்களுக்கு வெளியேற்றப்பட்டுள்ளது
பதிவேற்றங்களை பதிவு செய்யாமல் மதிப்பீடு செய்ய வேண்டும்.

**Scan bound (v3.8.20):** கண்டுபிடிப்பாளர் **முதல் 16 KB** ஐ மட்டுமே
கண்டறிக்கையிடுகிறது — `MAX_INJECTION_SCAN_BYTES = 16 * 1024` (16 384 bytes) in
`src/shared/utils/inputSanitizer.ts`. `detectInjection()` மற்றும்
`evaluatePromptInjection()` `slice(0, MAX_INJECTION_SCAN_BYTES)` ஐ
முறைமுறை இயக்குவதற்கு முன் இயக்குகிறது. Injection இயக்கங்கள் உள்ளீட்டின்
மேல்புறத்தில் இருக்கின்றன, எனவே இது பல நூறு KB payload களில் regex CPU/GC ஐ
குறைவாகக் கட்டுப்படுத்துகிறது, கண்டறிதலை பலவீனமாக்காமல் (cf.
#3932, #4041).

### Credential Masker (`credentialMasker.ts`)

**இரு** நிலைகளிலும் இயங்குகிறது, இயல்பான சங்கிலியில் கடைசி (முன்னுரிமை `95`).
பெரிய அளவில் API-கீ / ரகசிய-டோக்கன் மாதிரிகளை வெளியேறும் payload இல் (செய்தி
உள்ளடக்கம், கருவி-அழைப்பு வாதங்கள், கருவி முடிவுகள்) **மற்றும்** வழங்குநர்
பதிலில் மறைக்கிறது, எனவே ஒரு credential ஒரு prompt இல் ஒட்டப்பட்டால் (அல்லது
ஒரு கருவி முடிவால் மீண்டும் ஒலிக்கப்படும்போது) மேல்நிலை வழங்குநருக்கு அல்லது
வாடிக்கையாளருக்கு மீண்டும் வெளியிடப்படாது.

- **Opt-in மட்டும்**, PII மறைவு போலவே அதே 관습 (Hard Rule #20-இன் அருகில்):
  `settings.credentialRedactionEnabled === true` **அல்லது**
  `CREDENTIAL_REDACTION_ENABLED=true` என்பதற்கு மாறுபட்டது. இது அண்மையில் выключено என்றால், பாதுகாப்பு ஒரு no-op ஆகும் —
  இது எப்போதும் தடுப்பதில்லை மற்றும் எப்போதும் மறுபடியும் எழுதுவதில்லை.
- `redactCredentials()` முழு payload/response மரத்தை நடைபயிற்சி செய்கிறது (`walkValue()`,
  prototype-pollution-safe, cycle-safe `WeakSet` மூலம்) மற்றும் பொருத்தங்களை
  `[REDACTED:<type>]` இடதுகோல் மூலம் மாற்றுகிறது, உண்மையில் மாறிய கிளைகளை மட்டுமே
  நகலெடுக்கிறது.
- `CREDENTIAL_PATTERNS` LLM வழங்குநர் விசைகளை (OpenAI, OpenAI-proj,
  Anthropic, Google, Hugging Face, Replicate), VCS/SaaS டோக்கன்களை (GitHub, Slack,
  Linear, Notion, npm, Postman, Discord), கட்டண விசைகளை (Stripe, Square), மேக
  விசைகளை (AWS access key, Twilio, SendGrid, Mailgun), தனிப்பட்ட விசைகள் / JWTs,
  சான்றிதழ் கொண்ட இணைப்பு சரங்கள் (`mongodb://user:pass@...`, மற்றும் பிற), மற்றும்
  ஒரு பொதுவான `Authorization`/`x-api-key`/`api-key`/`apikey` தலைப்பு-மதிப்பு
  மாதிரியை உள்ளடக்கியது. தலைப்பு-வடிவ விசைகள் (`authorization`, `x-api-key`, `api-key`,
  `apikey`) கட்டமைப்பாக மறைக்கப்படுகின்றன (மதிப்பு மட்டும், திட்டம் முன்னணி போன்ற
  `Bearer `/`Basic ` பாதுகாக்கப்படுகிறது) பொதுவான உரை regex மூலம் அல்ல.
- பாதுகாப்பு எப்போதும் தடுப்பதில்லை; இது மட்டுமே மறுபடியும் எழுதுகிறது (`modifiedPayload` /
  `modifiedResponse`) மற்றும் குறிப்பு செய்கிறது (`meta.credentialsRedacted`, `meta.count`).

மீள்பார்வை பாதுகாப்பு: `tests/unit/credential-masker-guardrail.test.ts`.

## அடிப்படை ஒப்பந்தம் (`base.ts`)

```typescript
class BaseGuardrail {
  enabled: boolean;
  name: string;
  priority: number;

  constructor(name: string, options?: { enabled?: boolean; priority?: number });

  async preCall(payload: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;

  async postCall(response: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;
}

interface GuardrailResult<TValue = unknown> {
  block?: boolean; // true சங்கிலியை உடனடியாக நிறுத்துகிறது
  message?: string; // தடுக்கும்போது வெளிப்படுத்தப்படும்
  meta?: Record<string, unknown> | null;
  modifiedPayload?: TValue; // கோரிக்கையை மாற்றியமைக்க preCall மூலம் திருப்பி அனுப்பப்படும்
  modifiedResponse?: TValue; // பதிலை மாற்றியமைக்க postCall மூலம் திருப்பி அனுப்பப்படும்
}

interface GuardrailContext {
  apiKeyInfo?: Record<string, unknown> | null;
  disabledGuardrails?: string[] | null;
  endpoint?: string | null;
  headers?: Headers | Record<string, unknown> | null;
  log?: GuardrailLog | Console | null;
  method?: string | null;
  model?: string | null;
  provider?: string | null;
  signal?: AbortSignal;
  sourceFormat?: string | null;
  stream?: boolean;
  targetFormat?: string | null;
}
```

ஒரு guardrail, `void`, `{}`, அல்லது `{ block: false }` ஆகியவற்றில் ஒன்றைத் திருப்பி அனுப்புவதன் மூலம் "மாற்றம் இல்லை" என்பதைக் குறிக்கிறது. `modifiedPayload`/`modifiedResponse`-ஐத் திருப்பி அனுப்புவது, அடுத்தடுத்த guardrail-களுக்குச் சங்கிலி வழியாகச் செல்லும் மதிப்பை மாற்றுகிறது.
`signal?: AbortSignal`, அழைப்பவரின் வாழ்க்கைச் சுழற்சியை guardrail-களுக்குக் கொண்டு செல்கிறது. ஒரு கோரிக்கை கைவிடப்படுவது திட்டமிட்ட fail-open விதிவிலக்காகும்: இலக்கு மூல ஊடகத்தை ஆதரிக்காது என்று அறியப்பட்டிருந்தால், media bridge-கள் அதை மீட்டமைக்காமல் பணியை நிறுத்தி சுத்தப்படுத்துகின்றன.

## பதிவகம் (`registry.ts`)

singleton `guardrailRegistry` பின்வருவனவற்றை வெளிப்படுத்துகிறது:

- `register(guardrail)` — ஒரு guardrail-ஐச் சேர்க்கிறது (அல்லது இயல்பாக்கப்பட்ட பெயரின் அடிப்படையில் மாற்றுகிறது) மற்றும் ஏறுவரிசை `priority` அடிப்படையில் மீண்டும் வரிசைப்படுத்துகிறது.
- `clear()` / `list()` — நிர்வாக உதவிச் செயல்பாடுகள்.
- `runPreCallHooks(payload, context)` — செயலில் உள்ள guardrail-களை வரிசையாகச் செயல்படுத்தி, `modifiedPayload` வழியாக payload-ஐ அனுப்பி, முதல் `block: true`-இல் நிறுத்துகிறது.
- `runPostCallHooks(response, context)` — பதில் பக்கத்தில் அதே செயலோட்டத்தைப் பயன்படுத்துகிறது.
- `resetGuardrailsForTests({ registerDefaults })` — நிலையை அழித்து, சுத்தமான சோதனைத் தனிமைப்படுத்தலுக்காக விருப்பப்பட்டால் இயல்புநிலைகளை மீண்டும் பதிவு செய்கிறது.

இரண்டு இயக்கிகளும் `{ blocked, payload|response, results, guardrail?, message? }`-ஐத் திருப்பி அனுப்புகின்றன; இதில் `results` என்பது ஒவ்வொரு guardrail-க்கும் உரிய `blocked`, `skipped`, `modified`, `error`, மற்றும் `meta` புலங்களை உள்ளடக்கிய `GuardrailExecutionResult` பதிவுகளின் வரிசையாகும்; இது தடமறிதலுக்குப் பயனுள்ளதாக இருக்கும்.

### ஒவ்வொரு கோரிக்கைக்கும் Guardrail-களை முடக்குதல்

`resolveDisabledGuardrails({ apiKeyInfo, body, headers })`, தற்போதைய கோரிக்கைக்குத் தவிர்க்கப்பட வேண்டிய guardrail பெயர்களின் நகல் நீக்கப்பட்ட பட்டியலைத் தொகுக்கிறது. மூலங்கள் (அனைத்தும் விருப்பமானவை, அனைத்தும் ஒன்றிணைக்கப்படும்):

- `apiKeyInfo.disabledGuardrails`
- கோரிக்கை body-யின் `disabledGuardrails` (மேல்நிலை)
- கோரிக்கை body-யின் `metadata.disabledGuardrails`
- Header `x-omniroute-disabled-guardrails` (அல்லது பழைய
  `x-disabled-guardrails`)

மதிப்புகள் string-களின் array-களாகவோ அல்லது காற்புள்ளியால் பிரிக்கப்பட்ட string ஆகவோ இருக்கலாம்; பெயர்கள் lowercase kebab-case-க்கு இயல்பாக்கப்படுகின்றன (`pii_masker` → `pii-masker`). முடிவு `context.disabledGuardrails` வழியாகப் பதிவகத்திற்கு அனுப்பப்படுகிறது; அது பொருந்தும் guardrail-களைத் தவிர்க்கிறது (`results`-இல் `skipped: true`).

## செயல்படுத்தும் வரிசை

`src/sse/handlers/chat.ts` மற்றும்
`open-sse/handlers/chatCore.ts` வழியாகச் செல்லும் ஒவ்வொரு கோரிக்கைக்கும்:

1. `resolveDisabledGuardrails(...)` ஆனது API விசை, உடல் மற்றும் தலைப்புகளிலிருந்து தவிர்ப்புப் பட்டியலை உருவாக்குகிறது.
2. `guardrailRegistry.runPreCallHooks(body, ctx)` ஆனது முன்னுரிமையின் ஏறுவரிசையில் பாதுகாப்புக் கட்டுப்பாடுகளை இயக்குகிறது:
   - முடக்கப்பட்ட பாதுகாப்புக் கட்டுப்பாடுகள் `skipped` எனப் பதிவு செய்யப்படுகின்றன.
   - ஒவ்வொரு பாதுகாப்புக் கட்டுப்பாட்டின் `preCall` ஆனதும் `modifiedPayload` மூலம் தரவுச்சுமையை மாற்றி எழுதலாம்.
   - முதலில் வரும் `block: true`, சங்கிலியின் செயல்பாட்டை உடனடியாக நிறுத்துகிறது; மேலும் கையாளுநர் பாதுகாப்புக் கட்டுப்பாட்டு நிராகரிப்புப் பதிலை வழங்குகிறார்.
3. மாற்றி எழுதப்பட்டிருக்கக்கூடிய தரவுச்சுமை, கூட்டு வழிப்படுத்தல் மற்றும் அப்ஸ்ட்ரீம் அனுப்புதலுக்குள் செல்கிறது.
4. பதில் உருவாக்கப்பட்ட பிறகு, `guardrailRegistry.runPostCallHooks(...)` ஆனது பதிலின் மீது அதே சங்கிலியை இயக்குகிறது. இங்கு `block: true` என்பது அப்ஸ்ட்ரீம் பதிலைக் கைவிடுகிறது.

விதிவிலக்கை எறியும் பாதுகாப்புக் கட்டுப்பாடுகள் `error: <message>` என்பதுடன் பதிவு செய்யப்பட்டு, `logger.warn` மூலம் பதிவேட்டில் எழுதப்படுகின்றன; ஆனால் சங்கிலி தொடர்ந்து இயங்கும் — இது வடிவமைப்பிலேயே தடையின்றித் தொடரும் அணுகுமுறையாகும்.

## தனிப்பயன் பாதுகாப்புத் தடுப்புகள்

```typescript
import { BaseGuardrail, guardrailRegistry } from "@/lib/guardrails";

class BudgetGuardrail extends BaseGuardrail {
  constructor() {
    super("budget", { priority: 50 });
  }

  async preCall(payload, ctx) {
    if (ctx.apiKeyInfo?.budgetExceeded) {
      return { block: true, message: "Daily budget exceeded" };
    }
    return { block: false };
  }
}

guardrailRegistry.register(new BudgetGuardrail());
```

படிகள்:

1. `BaseGuardrail`-ஐ நீட்டித்து `src/lib/guardrails/myGuardrail.ts`-ஐ உருவாக்கவும்.
2. `preCall` மற்றும்/அல்லது `postCall`-ஐச் செயல்படுத்தவும்.
3. இறக்குமதி செய்யும் நேரத்தில் பதிவுசெய்யவும் (`registerDefaultGuardrails`-இலிருந்து சேர்க்கவும்) அல்லது
   இயக்க நேரத்தில் `guardrailRegistry.register(...)`-ஐ அழைக்கவும் — அதே இயல்பாக்கப்பட்ட பெயரைக்
   கொண்ட முந்தைய பாதுகாப்புத் தடுப்பை பதிவகம் மாற்றிவிடும்.
4. `tests/unit/`-இன் கீழ் சோதனைகளைச் சேர்க்கவும் (தற்போதுள்ள எடுத்துக்காட்டுகள்:
   `tests/unit/guardrails-registry.test.ts`,
   `tests/unit/prompt-injection-guard.test.ts`,
   `tests/unit/guardrails/visionBridge.test.ts`).

## சோதனை

அறியப்பட்ட நிலையிலிருந்து தொடங்க, சோதனைகளுக்கு இடையே `resetGuardrailsForTests()`-ஐப் பயன்படுத்தவும்.
காலியான பதிவகத்துடன் தொடங்கி, சோதனையின் கீழுள்ள பாதுகாப்புத் தடுப்புகளை மட்டும்
பதிவுசெய்ய `{ registerDefaults: false }`-ஐ அனுப்பவும். Vision Bridge சார்பு
உட்செலுத்தலை (`deps.getSettings`, `deps.callVisionModel`) ஏற்கிறது; Audio Bridge,
அமைப்புகள், திறன்கள், STT மாதிரித் தேர்வு, நற்சான்றுச் சோதனைகள் மற்றும் படியெடுத்தல்
ஆகியவற்றுக்கான இணையான உட்புகும் புள்ளிகளை வழங்குகிறது. எனவே, சோதனைகள் DB அல்லது
பிணைய அணுகல் இல்லாமலேயே இரு ஓட்டங்களையும் பரிசோதிக்க முடியும்.

## மேலும் காண்க

- `src/lib/guardrails/` — செயலாக்கம்
- `src/shared/utils/inputSanitizer.ts` — prompt-injection மற்றும் PII மறைத்தலுக்கு
  ஆதாரமாகச் செயல்படும் பகிரப்பட்ட கண்டறிதல் கருவி
- `src/shared/constants/visionBridgeDefaults.ts` — Vision Bridge இயல்புநிலைகள் மற்றும்
  கட்டாய-bridge மாதிரிப் பட்டியல்
- `src/shared/constants/modalityBridgeDefaults.ts` — பகிரப்பட்ட Vision/Audio இயக்கநேர இயல்புநிலைகள்
- `docs/architecture/RESILIENCE_GUIDE.md` — செங்குத்தான அடுக்கு (circuit breaker, cooldowns)
- `docs/reference/ENVIRONMENT.md` — முழுமையான சூழல் மாறி மேற்கோள்

## Injection-guard வழித்தட உள்ளடக்கம் & red-team (கட்டம் 8 · தொகுதி D)

பயனர் prompts-ஐ ஏற்கும் அனைத்து வழித்தடங்களையும் injection-guard (`createInjectionGuard` / `withInjectionGuard`) உள்ளடக்குகிறது.
இது `INJECTION_GUARD_MODE`-ஐ மதிக்கிறது (இயல்புநிலை `warn` = பதிவு மட்டும்;
`block` = HTTP 400 `SECURITY_001`-ஐத் திருப்பியனுப்பும்).

| வகை                  | வழித்தடங்கள்                                                                                                                                         | இயல்புநிலை பயன்முறை |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------- |
| உரை (தற்போதுள்ளது)   | `/v1/chat/completions`, `/v1/completions`, `/v1/relay/chat/completions`                                                                              | warn                |
| உருவாக்கம் சார்ந்தது | `/v1/messages`, `/v1/responses`, `/v1/images/generations`, `/v1/images/edits`, `/v1/videos/generations`, `/v1/music/generations`, `/v1/audio/speech` | warn                |
| தரவு                 | `/v1/embeddings`, `/v1/rerank`, `/v1/search`, `/v1/moderations`                                                                                      | warn                |

உரைப் பிரித்தெடுத்தல் (`extractMessageContents`) `messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system` ஆகியவற்றை உள்ளடக்குகிறது.

**Red-team (இரவுதோறும், `nightly-llm-security.yml`):** `INJECTION_GUARD_MODE=block` நிலையில் ஒவ்வொரு வழித்தடமும்
OWASP-LLM corpus-ஐத் தடுக்கிறது என்பதை promptfoo சரிபார்க்கிறது; garak சோதனைத் தேடல்களை இயக்குகிறது (ரகசியம் இல்லாவிட்டால் தவிர்க்கும்).
ஒருமைத்தன்மைக்காக `moderations` சேர்க்கப்பட்டுள்ளது — block-mode-இல் உள்ள இயக்குநர்கள்
`resolveDisabledGuardrails` வழியாக இதற்கு விலக்கு அளிக்கலாம்.

இரவுநேர பணிப்பாய்வு (`.github/workflows/nightly-llm-security.yml`, cron + கைமுறை
dispatch) இரண்டு பணிகளைக் கொண்டுள்ளது:

- **`promptfoo-guard` (தடுக்கும்)** — `INJECTION_GUARD_MODE=block` உடன்
  `promptfoo eval -c promptfooconfig.yaml`-ஐ இயக்குகிறது. ஒவ்வொரு எதிர்மறைச் சோதனை நிலையும்
  (எ.கா. "முந்தைய அனைத்து அறிவுறுத்தல்களையும் புறக்கணிக்கவும்…", DAN-பாணி jailbreaks), பதிலில்
  `error.code === "SECURITY_001"` இருப்பதை உறுதிசெய்கிறது; அதாவது, பாதுகாப்புத் தடுப்பு உண்மையிலேயே கோரிக்கையை நிராகரித்தது.
- **`garak` (ஆலோசனை சார்ந்தது)** — உள்ளக OmniRoute instance-க்கு
  (`http://localhost:20128/v1`) எதிராக garak `--probes promptinject,dan,leakreplay`-ஐ இயக்குகிறது.
  இது வழங்குநர் ரகசியத்தை (`PROMPTFOO_PROVIDER_KEY`) சார்ந்தது; ரகசியம் இல்லாவிட்டால்
  சீராகத் தவிர்க்கப்பட்டு `|| true` பின்னொட்டுடன் இயக்கப்படும், எனவே CI-ஐத் தோல்வியடையச் செய்யாமல் அறிக்கையிடும்.

பாதுகாப்புத் தடுப்பு உதவிக்கருவியின் (`createInjectionGuard` / `withInjectionGuard`)
உள்ளடக்கம் prompt கொண்ட ஒவ்வொரு `/v1` வழித்தடத்தையும் உள்ளடக்குகிறது; prompt உரை
`src/shared/utils/inputSanitizer.ts`-இல் உள்ள `extractMessageContents()` மூலம்
`messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system` ஆகியவற்றிலிருந்து பெறப்படுகிறது.
