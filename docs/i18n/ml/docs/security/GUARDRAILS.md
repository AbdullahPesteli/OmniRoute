> **അവസാനം അപ്ഡേറ്റ് ചെയ്തത്:** 2026-08-29 — v3.8.51 (വീഡിയോ ബ്രിഡ്ജ് ട്രാൻസ്ക്രിപ്റ്റ് പ്രൂവനെൻസ് കോളർ-പ്രഖ്യാപിച്ചതാണ്,
> ഇതുവരെ സെർവർ-പരിശോധിച്ചിട്ടില്ല — #11661 അനുസരിച്ച് വ്യക്തമാക്കിയത്)

OmniRoute-നും അപ്സ്ട്രീം പ്രൊവൈഡർമാർക്കും ഇടയിലുള്ള അതിർത്തിയിൽ സുരക്ഷ, നയം, ഉള്ളടക്ക പരിവർത്തനങ്ങൾ എന്നിവ ഗാർഡ്റെയിലുകൾ നടപ്പിലാക്കുന്നു. ഓരോ ഗാർഡ്റെയിലിനും അഭ്യർത്ഥന പേലോഡുകളും (`preCall`) അപ്സ്ട്രീം പ്രതികരണങ്ങളും (`postCall`) പരിശോധിക്കാൻ (ഓപ്ഷണലായി നിരസിക്കുകയോ, രൂപാന്തരപ്പെടുത്തുകയോ, വ്യാഖ്യാനിക്കുകയോ ചെയ്യാം) കഴിയും.

സിസ്റ്റം **ഫെയിൽ-ഓപ്പൺ** ആണ്: ഒരു ഗാർഡ്റെയിൽ പ്രവർത്തിക്കുമ്പോൾ പിശക് സംഭവിച്ചാൽ, രജിസ്ട്രി പിശക് രേഖപ്പെടുത്തുകയും അഭ്യർത്ഥന പരാജയപ്പെടുത്തുന്നതിന് പകരം അടുത്ത ഗാർഡ്റെയിലുമായി മുന്നോട്ട് പോകുകയും ചെയ്യുന്നു. തടയുന്നത് ഒരു വ്യക്തമായ തീരുമാനമാണ് (`block: true`), ഒരിക്കലും ഒരു അപകടമല്ല.

## ബിൽറ്റ്-ഇൻ ഗാർഡ്‌റെയിൽസ്

റെജിസ്ട്രി ആറ്റോ-ലോഡ് ചെയ്യുന്നു ആറു ഗാർഡ്‌റെയിൽസ് പ്രായോജ്യമായ ക്രമത്തിൽ ഇറക്കുമതി ചെയ്യുമ്പോൾ
(കാണുക `registry.ts` → `registerDefaultGuardrails()`):

| പ്രായോജ്യം | പേര്                | ഘട്ടങ്ങൾ       | ഫയൽ                   |
| ---------- | ------------------- | -------------- | --------------------- |
| `5`        | `vision-bridge`     | `preCall`      | `visionBridge.ts`     |
| `6`        | `audio-bridge`      | `preCall`      | `audioBridge.ts`      |
| `7`        | `video-bridge`      | `preCall`      | `videoBridge.ts`      |
| `10`       | `pii-masker`        | `pre` + `post` | `piiMasker.ts`        |
| `20`       | `prompt-injection`  | `preCall`      | `promptInjection.ts`  |
| `95`       | `credential-masker` | `pre` + `post` | `credentialMasker.ts` |

കുറഞ്ഞ പ്രായോജ്യം നമ്പറുകൾ **മുൻപ്** പ്രവർത്തിക്കുന്നു.

### ദൃശ്യ ബ്രിഡ്ജ് (`visionBridge.ts`) — മോഡാലിറ്റി ബ്രിഡ്ജ് PR-1

**ദൃശ്യ മോഡലുകൾ** ലക്ഷ്യമിട്ടുള്ള ചിത്രങ്ങൾ അടങ്ങിയ അഭ്യർത്ഥനകൾ തടയുന്നു, അല്ലെങ്കിൽ
മുഴുവൻ അഭ്യർത്ഥന ഒരു ദൃശ്യ-ശേഷിയുള്ള മോഡലിലേക്ക് പുനർനിർദ്ദേശിക്കുന്നു അല്ലെങ്കിൽ ചിത്രത്തിന്റെ
ഭാഗങ്ങൾ ഒരു ക്രമീകരിക്കാവുന്ന ദൃശ്യ മോഡലാൽ നിർമ്മിച്ച വാചക വിവരണങ്ങളാൽ മാറ്റുന്നു
ഉപരിതല വിളിക്കലിന് മുമ്പ്. ഇത് വാചക മാത്രം നൽകുന്ന പ്രദാതാക്കൾക്ക്
മൾട്ടിമോഡൽ പേലോഡുകൾ പരസ്യമായി കൈകാര്യം ചെയ്യാൻ അനുവദിക്കുന്നു.

പ്രവാഹം:

1. ലക്ഷ്യ മോഡൽ ഇതിനകം ദൃശ്യത്തെ പിന്തുണയ്ക്കുന്നുവെങ്കിൽ ഒഴിവാക്കുക (അല്ലെങ്കിൽ അത്
   നിർബന്ധിത-ബ്രിഡ്ജ് പട്ടികയിൽ പ്രത്യക്ഷപ്പെടുന്നില്ലെങ്കിൽ `isVisionBridgeForcedModel`).
2. ചിത്രത്തിന്റെ ഭാഗങ്ങൾ `extractImageParts(messages)` വഴി എടുക്കുക
   (`visionBridgeHelpers.ts`), ഇത് **യൂണിഫൈഡ് മീഡിയ
   ഡിറ്റക്ടർ** `detectMediaParts()` ൽ委任 ചെയ്യുന്നു `open-sse/utils/mediaParts.ts` —
   കോമ്പോ അനുയോജ്യത ഫിൽട്ടറുമായി പങ്കുവെക്കുന്ന സത്യത്തിന്റെ ഏക ഉറവിടം.
   എടുക്കൽ `replaceImageParts` പുനർനിർദ്ദേശിക്കാവുന്ന രൂപങ്ങളുടെ മുകളിൽ
   ഭാഗങ്ങൾക്കായി അനുവദനീയമാണ് (എടുക്കൽ↔മാറ്റം കരാർ): OpenAI
   `image_url`, Anthropic base64 `source.type:"base64"`, Anthropic URL
   `source.type:"url"`, and Responses API `input_image`. Nested hits and
   indicator-only shapes are combo-filter material and are never extracted.
   ഒന്നും കണ്ടെത്തിയില്ലെങ്കിൽ ഒഴിവാക്കുക.
3. റൺടൈം കോൺഫിഗറേഷൻ `resolveVisionBridgeRuntimeSettings()`
   വഴി പരിഹരിക്കുക (`src/shared/constants/modalityBridgeDefaults.ts`): പുതിയ `modalityBridge*`
   ക്രമീകരണ കീകൾ വിജയിക്കുന്നു; പാരമ്പര്യ `visionBridge*` കീകൾ **ഒരു-ചക്രം
   പിന്‍വലിക്കൽ** (rollback window). ബ്രിഡ്ജ് അശക്തമാക്കിയാൽ ഏതെങ്കിലും മീഡിയ
   കടന്നുപോകുന്നതിന് മുമ്പ് ഒഴിവാക്കുക.
4. മോഡ് തിരഞ്ഞെടുക്കുന്നവ (`modalityBridgeVisionMode`, താഴെ കാണുന്ന പട്ടിക കാണുക)
   പുനർനിർദ്ദേശം vs വിവരണം തീരുമാനിക്കുന്നു. പുനർനിർദ്ദേശം `modifiedPayload`
   മാത്രം `model` മാറ്റിയതോടെ, കൂടാതെ മെറ്റാ `{ rerouted, fromModel, toModel, imagesKept }`
   തിരികെ നൽകുന്നു.
5. വിവരണ പാത: `maxImages` ൽ ചിത്രങ്ങൾ പരിമിതപ്പെടുത്തുക, ടാസ്‌ക്-അറിയുന്ന പ്രോംപ്റ്റ്
   രൂപകൽപ്പന ചെയ്യുക, വിവരണം കാഷ് പരിശോധിക്കുക, ദൃശ്യ മോഡലിനെ **സമാന്തരമായി**
   വിളിക്കുക (`Promise.allSettled`), അവിടെയുള്ള `[Image N]: <description>`
   വാചക ഭാഗങ്ങൾ ചേർക്കുക. ഒരു പരാജയപ്പെട്ട വിവരണം `null` നൽകുന്നു
   കൂടാതെ യഥാർത്ഥ ചിത്രം ഭാഗം **സംരക്ഷിക്കുന്നു** (#4012) —
   കോമ്പോ വിവരണ പാതയിൽ എല്ലാ വിവരണങ്ങളും പരാജയപ്പെട്ടപ്പോൾ,
   ഒരു സ്ഥിരീകരിച്ച ദൃശ്യമില്ലാത്ത ഉപരിതലത്തിന്
   `(unavailable — no vision-capable provider connected)` സ്റ്റബ് നൽകുന്നു (#8430).
6. `modifiedPayload` + മെറ്റാ (`imagesProcessed`, `descriptions`,
   `processingTimeMs`, `visionModel`) തിരികെ നൽകുക.

#### മോഡ് തിരഞ്ഞെടുക്കുന്നവ (`modalityBridgeVisionMode`)

| `reroute`  |           | നിർബന്ധിത പുനർനിർദ്ദേശം: ക്രെഡൻഷ്യൽ-മോഡൽ ഗാർഡ് ഒഴിവാക്കുന്നു. പുനർനിർദ്ദേശ-**ലക്ഷ്യം** ക്രെഡൻഷ്യൽ ഗാർഡ് ഇപ്പോഴും ബാധകമാണ് — ഉപയോഗിക്കാവുന്ന ദൃശ്യ ലക്ഷ്യം ഇല്ലെങ്കിൽ, അഭ്യർത്ഥന വിവരണത്തിലേക്ക് വീഴുന്നു, അതിനാൽ കച്ചവട ചിത്രങ്ങൾ ഒരിക്കലും വാചക-മാത്രം ബാക്ക്‌എൻഡിലേക്ക് എത്തുന്നില്ല (#8430). |

നിർബന്ധിത മോഡുകൾ **മുൻപ്** ഓട്ടോ ഹ്യൂറിസ്റ്റിക് പ്രവർത്തിക്കുന്നതിനു മുമ്പ് ഷോർട്ട്-സർക്കിറ്റ് ചെയ്യുന്നു; `auto` പെരുമാറ്റം
PR-1 ഗാർഡ്‌റെയിലിന്റെ മുൻകാലത്തെ പോലെ ബൈറ്റ്-ഐഡന്റിക്കൽ ആണ്.

#### API-കീ പരിധി (`visionBridgeKeyScope.ts`)

കോളറിന്റെ API കീ `allowedConnections`, quota pools
(`allowedQuotas`) അല്ലെങ്കിൽ മോഡലുകൾ (`allowedModels` / `blockedModels` /
`modelAccessMode: "restricted"` / `disableNonPublicModels`) നിയന്ത്രിക്കുന്നുവെങ്കിൽ,
ബ്രിഡ്ജ് കീ ഉപയോഗിക്കാവുന്ന പുനർനിർദ്ദേശവും വിവരണ മോഡലുകളും മാത്രം picks,
കീ ഉപയോഗിക്കാവുന്ന ബന്ധങ്ങളിൽ. വിവരണം വിളി എപ്പോഴും
`x-omniroute-self-loop-key-id` ഹെഡർ ഉപയോഗിച്ച് ഒമ്നി റൂട്ടിന്റെ സ്വയം-ലൂപ്പിലൂടെ കടന്നു പോകുന്നു,
അതുകൊണ്ട് സ്വീകരിക്കുന്ന ചാറ്റ് അഭ്യർത്ഥന വീണ്ടും ആ കീയുടെ ബന്ധവും മോഡൽ നയവും
പ്രവർത്തിപ്പിക്കുന്നു. `enforceApiKeyPolicy()`
ആ ഹെഡർ മാത്രം സ്വയം-ലൂപ്പ് ബെയററുമായി ചേർന്ന് മാന്യമാണ്, അതിനാൽ ഇത്
പ്രവേശനം കുറയ്ക്കാൻ മാത്രമേ കഴിയൂ, ഒരു പരിഹാരം ഇല്ലാത്ത ഐഡി നിരസിക്കപ്പെടുന്നു.

കീക്ക് വേണ്ടി ദൃശ്യ മോഡൽ അനുവദിച്ചില്ലെങ്കിൽ, വിവരണ പാത പിന്മാറുന്നു
അഭ്യർത്ഥന മാറ്റമില്ലാതെ കടന്നു പോകുന്നു,
ഒരു അശക്തമായ ഗാർഡ്‌റെയിലിന്റെ സമാനമായ ഫെയിൽ-ഓപ്പൺ പെരുമാറ്റം
(meta `{ skipped: true, reason: "no_permitted_vision_model" }`).
കീ ഇല്ലാത്ത അഭ്യർത്ഥനകൾ, ഈ നിയന്ത്രണങ്ങൾ ഇല്ലാത്ത കീകൾ,
മുമ്പത്തെ പോലെ തന്നെ പെരുമാറുന്നു.

#### ടാസ്‌ക്-അറിയുന്ന വിവരണം പ്രോംപ്റ്റ് (`modalityBridgeVisionTaskAware`)

ഡിഫോൾട്ട് **സത്യമാണ്**. `composeVisionPrompt()` (`visionBridgeHelpers.ts`) **അവസാന ഉപയോക്തൃ സന്ദേശത്തിന്റെ** (500 അക്ഷരങ്ങൾക്ക് ചുരുക്കിയ) ടെക്സ്റ്റ് അടിസ്ഥാന വിവരണം പ്രോംപ്റ്റിലേക്ക് ചേർക്കുന്നു, ഉപയോക്താവ് യഥാർത്ഥത്തിൽ ചോദിച്ച കാര്യത്തിലേക്ക് വിവരണത്തെ നയിക്കുന്നു (codex-vision-proxy മാതൃക) കൂടാതെ ദൃശ്യ മോഡലിന് ദൃശ്യമായ ടെക്സ്റ്റ് പുനരാഖ്യാനം ചെയ്യാൻ ആവശ്യപ്പെടുന്നു. ഫ്ലാഗ് ഓഫ് ചെയ്താൽ — അല്ലെങ്കിൽ ഉപയോക്തൃ ടെക്സ്റ്റ് ഇല്ലെങ്കിൽ — അടിസ്ഥാന പ്രോംപ്റ്റ് മാറ്റമില്ലാതെ ഉപയോഗിക്കുന്നു.

വിവരണം സ്വയം-ലൂപ്പിന്റെ സ്വന്തം OpenAI-സംബന്ധമായ അഭ്യർത്ഥന (`callVisionModelSingle()` `visionBridgeHelpers.ts`-ൽ) എല്ലായ്പ്പോഴും `image_url.detail: "high"` ആവശ്യപ്പെടുന്നു — എല്ലാ വിളിക്കലുകൾക്കും/പ്രവർത്തകർക്കും, ഏതെങ്കിലും ക്ലയന്റ് സിഗ്നലിൽ അടച്ചിട്ടില്ല. കുറഞ്ഞ-വിശദീകരണ സാമ്പിളിംഗ് OCR കൃത്യതയെ കുറയ്ക്കുന്നു, ഈ പ്രോംപ്റ്റ് ആവശ്യപ്പെടുന്ന ടെക്സ്റ്റ്-പുനരാഖ്യാനം പ്രവർത്തനത്തിനായി, അതിനാൽ വിവരണം വിളിക്കലുകൾ എല്ലായ്പ്പോഴും ഉയർന്ന വിശദീകരണം ആവശ്യപ്പെടുന്നു, യഥാർത്ഥ inbound അഭ്യർത്ഥന ഏത് വിശദീകരണ തലത്തിൽ ഉപയോഗിച്ചിരുന്നാലും. ഇത് ആന്തരിക വിവരണം അഭ്യർത്ഥനയുടെ ശരീരത്തെ മാത്രം ബാധിക്കുന്നു; ഇത് OmniRoute മുഖ്യ അഭ്യർത്ഥനയിൽ വിളിക്കലിന്റെ സ്വന്തം `image_url.detail` എങ്ങനെ മുന്നോട്ട് നൽകുന്നു എന്നതിനെ മാറ്റുന്നില്ല — ആ ഡിഫോൾട്ട് വ്യത്യസ്തമായി പ്രയോഗിക്കുന്നു, മാത്രമല്ല കണ്ടെത്തിയ OpenCode ക്ലയന്റുകൾക്കായി മാത്രം, `defaultImageDetail()` (`open-sse/handlers/chatCore/upstreamBody.ts`) ൽ. വിവരണത്തിന്റെ സ്വയം-ലൂപ്പിന്റെ Anthropic വയർ-ഫോർമാറ്റ് ശാഖയിൽ `detail` ഫീൽഡ് ഇല്ല, കൂടാതെ ഏതെങ്കിലും ഡിഫോൾട്ടിൽ ബാധിക്കപ്പെടുന്നില്ല.

#### വിവരണം ഔട്ട്‌പുട്ട് ക്യാപ് (`modalityBridgeVisionMaxChars`)

| കീ                             | ഡിഫോൾട്ട് | പരിധി                    |
| ------------------------------ | --------- | ------------------------ |
| `modalityBridgeVisionMaxChars` | `0`       | `0` അല്ലെങ്കിൽ 100–50000 |

`0` (ഡിഫോൾട്ട്) എന്നത് **ക്യാപ് ഇല്ല** എന്നതിനെ അർത്ഥമാക്കുന്നു — `callVisionModel()` വഴി തിരികെ ലഭിക്കുന്ന വിവരണം മാറ്റമില്ലാതെ കടന്നുപോകുന്നു, നിലവിലുള്ള പെരുമാറ്റം നിലനിര്‍ത്തുന്നു. 100–50000 പരിധിയിലെ ഏതെങ്കിലും മൂല്യം വിവരണത്തെ `…` സഫിക്ഷോടെ ചുരുക്കുന്നു, അത് `[Image N]: <description>` എന്നതായി വീണ്ടും ചേർക്കുന്നതിന് മുമ്പ്
(`VisionBridgeGuardrail.preCall()` `src/lib/guardrails/visionBridge.ts`-ൽ). താഴ്ന്ന വിശദീകരണ OCR പ്രവർത്തനങ്ങൾക്കായി ഇത് ഉയർത്തുക, താഴ്ന്നത് ചാറ്റി ദൃശ്യ മോഡലുകളിൽ ടോക്കൺ ഉപയോഗം നിയന്ത്രിക്കാൻ. ഡാഷ്ബോർഡ് ഫീൽഡ് Vision ടാബിന്റെ അഡ്വാൻസ്ഡ് പാനലിൽ സ്ഥിതിചെയ്യുന്നു
(`modality-bridge-max-chars` `ModalityBridgeVisionTab.tsx`-ൽ) 1 മുതൽ 99 വരെ ഏതെങ്കിലും മൂല്യം 100 നിലക്കായി ക്ളാമ്പ് ചെയ്യുന്നു, അതേസമയം വ്യക്തമായ `0` മാറ്റമില്ലാതെ തുടരുന്നു — `0` അതിന്റെ സ്വന്തം അവകാശത്തിൽ ഒരു സാധുവായ Zod മൂല്യമാണ്
(`z.union([z.literal(0), z.number().int().min(100).max(50000)])`), വെറും "unset" ഡിഫോൾട്ട് അല്ല.

#### വിവരണം കാഷെ (`modalityBridge/bridgeCache.ts`)

വിവരണം ഔട്ട്‌പുട്ടുകൾക്കായി ഇൻ-മെമ്മറി LRU + TTL കാഷെ, പങ്കുവെച്ച പ്രോസസ്-വൈഡ്.
കീ = `sha256(imageRef + composedPrompt + configuredBridgeModel)` നീളം-പ്രിഫിക്‌സ് ഫ്രെയിമിംഗ് (ഫീൽഡ്-ബൗണ്ടറി കൂട്ടിയിടികൾ ഇല്ല). മോഡൽ ഘടകം **ക്രമീകരിച്ച** ബ്രിഡ്ജ് മോഡലാണ്, യഥാർത്ഥത്തിൽ മറുപടി നൽകിയ മോഡൽ അല്ല — `callVisionModel` ആന്തരികമായി ബാക്ക് ഫാൾബാക്ക് ചെയ്യാം, കൂടാതെ ശ്രമംപ്രകാരം കീ ചെയ്യുന്നത് കാഷെ തകരാറിലാക്കും. പരാജയപ്പെട്ട വിവരണങ്ങൾ ഒരിക്കലും കാഷെയിൽ സൂക്ഷിക്കപ്പെടുന്നില്ല. ക്രമീകരണങ്ങൾ:

| കീ                              | ഡിഫോൾട്ട് | പരിധി   |
| ------------------------------- | --------- | ------- |
| `modalityBridgeCacheEnabled`    | `true`    | —       |
| `modalityBridgeCacheTtlMinutes` | `60`      | 1–1440  |
| `modalityBridgeCacheMaxEntries` | `200`     | 10–5000 |

#### ദൂര ദൃശ്യ നോർമലൈസേഷൻ (സ്വയം-ലൂപ്പ് വിവരണം/base64 ഫെച്ച്)

ബ്രിഡ്ജ് **ദൂര** ദൃശ്യത്തെ തന്നെ ഫെച്ച് ചെയ്യുമ്പോൾ — Anthropic വിവരണം സ്വയം-കാൾ, ക്ലോഡ്-വയർ-ഫോർമാറ്റ് base64 പരിവർത്തനം
(`ensureBase64ImagesForClaudeWire`), രണ്ടും `fetchRemoteImageAsDataUri()` വഴി `visionBridgeHelpers.ts`-ൽ — ഫലമായ ഡാറ്റാ URI `normalizeDataUri()` വഴി കടന്നുപോകുന്നു
(`open-sse/utils/imageNormalize.ts`) ദൃശ്യ-മോഡൽ അഭ്യർത്ഥനയിൽ ഉൾപ്പെടുത്തുന്നതിന് മുമ്പ്. വലുതായ ദൃശ്യങ്ങൾ **2048px നീളമുള്ള കിഴക്ക്** (OpenAI/Anthropic ഇതിനകം സർവർ-പക്ഷത്ത് പ്രയോഗിക്കുന്ന Resize ക്യാപ് അനുസരിച്ച്) കുറയ്ക്കുന്നു, അപ്‌ലോഡ് ബൈറ്റുകൾ/ലാറ്റൻസിയെ കുറയ്ക്കുന്നു, ദൃശ്യ മോഡൽ എന്ത് കാണുന്നു എന്നതിനെ മാറ്റാതെ. റീസൈസിംഗ് `sharp` ഉപയോഗിക്കുന്നു, ഡൈനാമിക് ഇമ്പോർട്ടിലൂടെ ലോഡ് ചെയ്യുന്നു: അതിന്റെ നാടൻ ബൈനറി ലോഡ് ചെയ്യാൻ പരാജയപ്പെടുന്ന പ്ലാറ്റ്ഫോമിൽ, `normalizeDataUri()` **ഒന്നും എറിയുന്നില്ല** — ഇത് യഥാർത്ഥ ബൈറ്റുകളുടെ പാസ്ത്രോയിൽ ബാക്ക് ഫാൾബാക്ക് ചെയ്യുന്നു, അതിനാൽ വിവരണം/base64-പരിവർത്തന പാത എപ്പോഴും പ്രവർത്തിക്കുന്നു. ദൃശ്യമായ ബൈറ്റുകൾ അല്ലാത്തവ (ഡികോഡുചെയ്യാവുന്ന ദൃശ്യത്തെ തിരികെ നൽകാത്ത ഒരു ഫെച്ച്) മാറ്റമില്ലാതെ കടന്നുപോകുന്നു. ഈ നോർമലൈസേഷൻ ബ്രിഡ്ജ് തന്റെ സ്വയം-കാൾക്കായി ഫെച്ച് ചെയ്യുന്ന ദൃശ്യങ്ങൾക്കാണ് — ഇത് വിളിക്കലിന്റെ കാഠിന്യമായ പാസ്ത്രോ പെയ്ലോഡിലേക്ക് പ്രയോഗിക്കപ്പെടുന്നില്ല, ഒപ്പം ഓപ്റ്റ്-ഇൻ മാത്രം മാറ്റം തത്വം (Hard Rule #20) അനുസരിച്ച്.

#### ക്രമീകരണ സ്കീമ + മൈഗ്രേഷൻ

പുതിയ `modalityBridge*` കീകൾ `updateSettingsSchema`-ൽ Zod-വാലിഡേറ്റുചെയ്യുന്നു
(`src/shared/validation/settingsSchemas.ts`): `modalityBridgeVisionEnabled`,
`modalityBridgeVisionMode`, `modalityBridgeVisionModel`,
`modalityBridgeVisionTaskAware`, `modalityBridgeVisionPrompt`,
`modalityBridgeVisionTimeout`, `modalityBridgeVisionMaxImages`,
`modalityBridgeVisionMaxChars`, `modalityBridgeCache*` ത്രയവും, ഓഡിയോ ബ്രിഡ്ജ് ഉപയോഗിക്കുന്ന `modalityBridgeAudio*` ഗ്രൂപ്പും. മൈഗ്രേഷൻ `141_modality_bridge_settings.sql` നിലവിലുള്ള പാരമ്പര്യ
`visionBridge*` മൂല്യങ്ങൾ സമാനമായ പുതിയ കീകളിലേക്ക് കോപ്പി ചെയ്യുന്നു (ഇഡെംപൊട്ടന്റ്, ഒരിക്കലും ഒരു ഓപ്പറേറ്റർ-സജ്ജീകരിച്ച `modalityBridge*` മൂല്യം മായ്ക്കുന്നില്ല); പാരമ്പര്യ കീകൾ ഒരു റിലീസ് ചക്രത്തിനായി വായനാ ഫാൾബാക്ക് ആയി സ്വീകരിക്കപ്പെടുന്നു.

#### പരദൃശ്യ തലക്കെട്ട് + സ്ഥിതിവിവരക്കണക്കുകൾ

`x-omniroute-modality-bridge: image->text;model=<visionModel>;parts=<n>`
(`buildModalityBridgeHeader()` `modalityBridge/bridgeStats.ts`-ൽ നിർമ്മിച്ച, `withModalityBridgeHeader()` `src/sse/handlers/chatHelpers.ts`-ൽ മുദ്രവയ്ക്കപ്പെട്ട). റീറൂട്ടുചെയ്ത അഭ്യർത്ഥനകൾക്ക് **ഒന്നും** തലക്കെട്ട് ഇല്ല — പെയ്ലോഡ് മാറ്റമില്ലാതെ ആയിരുന്നു, മോഡൽ സ്വാപ്പ് മറുപടി ശരീരത്തിലെ `model` ഫീൽഡിൽ ഇതിനകം ദൃശ്യമാണ്.

`GET /api/modality-bridge/stats` (മാനേജ്മെന്റ് ഓത്തന്റിക്കേഷൻ, `GET /api/settings`-ന്റെ സമാന തരം) ഓർമ്മയിൽ ഉള്ള ഓരോ മോഡാലിറ്റിക്കായി കൗണ്ടറുകൾ തിരികെ നൽകുന്നു
`{ attempts, successes, bridged, cacheHits, failures, totalLatencyMs,
latencySamples, averageLatencyMs, lastUsedAt }` `vision`, `audio`,
മറ്റു `video`-കൾക്കായി. `averageLatencyMs` `latencySamples` ഉപയോഗിക്കുന്നു, എല്ലാ ശ്രമങ്ങളും അല്ല, അതിന്റെ
ഗണിതത്തിൽ; സമയമില്ലാത്ത ഒരു പ്രവർത്തനം ശൂന്യമായ മില്ലിസെക്കൻഡ്
സാമ്പിൾ ഉണ്ടാക്കുന്നില്ല. വിജയകരമായ മാറ്റങ്ങൾക്കായി `bridged` പിന്നോട്ടു-സമാനമായ ആലിയസ് ആയി തുടരുന്നു; പരാജയപ്പെട്ട ശ്രമങ്ങൾ അതിനെ വർദ്ധിപ്പിക്കുന്നില്ല.
കൗണ്ടറുകൾ പ്രോസസ് പുനരാരംഭത്തിൽ ഡിസൈനിന്റെ അടിസ്ഥാനത്തിൽ പുനഃസജ്ജീകരിക്കുന്നു
(ടെലിമെട്രി, അക്കൗണ്ടിംഗ് അല്ല).

#### ഡാഷ്ബോർഡ് കോൺഫിഗറേഷൻ

നിശ്ചിത ഡാഷ്ബോർഡ് പേജ്
`/dashboard/settings/modality-bridge` ആണ്. അതിന്റെ URL-ലഭ്യമായ `Vision`, `Audio`,
`Video` ടാബുകൾ `tab` മൂല്യം മാറ്റുമ്പോൾ ക്വറി പാരാമീറ്ററുകൾ നിലനിർത്തുന്നു.
Vision ടാബ് സജീവമാക്കൽ, മോഡ്, മോഡൽ തിരഞ്ഞെടുപ്പ് (സ്വയം ഡിഫോൾട്ട് ഉൾപ്പെടുന്നു), ടാസ്‌ക്-അവബോധമുള്ള പ്രോംപ്റ്റിംഗ്, പുരോഗമന ടൈംഔട്ട്/ചിത്രം/വിവരണം-നീളം/കാഷ്
പരിമിതികൾ, റൺടൈം
കൗണ്ടറുകൾ, ഒരു സംരക്ഷിത സാമ്പിൾ അഭ്യർത്ഥന എന്നിവ വെളിപ്പെടുത്തുന്നു. Audio ടാബ് കൂടാതെ സജീവമാണ്: ഇത്
സജീവമാക്കൽ, STT-മാത്രം മോഡൽ പിക്കർ Auto, ടൈംഔട്ട്/മാക്സ്-ക്ലിപ്പ് പരിധികൾ, ഓഡിയോ
കൗണ്ടറുകൾ, ഒരു `input_audio` സാമ്പിൾ ടെസ്റ്റ് എന്നിവ വെളിപ്പെടുത്തുന്നു. Video ടാബ് പ്രവർത്തനക്ഷമമാണ്: ഇത് FFmpeg/ffprobe റൺടൈം നില റിപ്പോർട്ട് ചെയ്യുന്നു — നാല് വ്യക്തമായ UI നിലകളിൽ ഒന്നാണ് (`unknown` probe പറക്കുമ്പോൾ അല്ലെങ്കിൽ പൂർത്തിയാക്കാൻ കഴിയുന്നില്ല, `restricted` non-loopback
ഡാഷ്ബോർഡ് ഹോസ്റ്റിൽ probe ക്ലയന്റ്-പക്ഷത്ത് ഒഴിവാക്കുമ്പോൾ, `unavailable` probe ചെയ്ത ശേഷം
കുറഞ്ഞതായി സ്ഥിരീകരിക്കുമ്പോൾ, അല്ലെങ്കിൽ `available` FFmpeg/ffprobe പതിപ്പുകളുമായി) — സജീവമാക്കൽ/മോഡൽ/ഫ്രെയിം/വീഡിയോ/ടൈംഔട്ട് പരിധികൾ നിലനിർത്തുന്നു, മോഡൽ പിക്കർ ദൃശ്യ-ശേഷിയുള്ള
മോഡലുകൾക്കായി ഫിൽട്ടർ ചെയ്യുന്നു, ഓഡിയോ കൗണ്ടറുകൾ വെളിപ്പെടുത്തുന്നു.

AI ക്രമീകരണങ്ങൾക്കുള്ള മുൻകാല Vision Bridge കാർഡ് പുതിയ പേജിലേക്ക് ഒരു അനുയോജ്യമായ ലിങ്കാണ്; ഇത് ഫോമിന്റെ രണ്ടാമത്തെ പകർപ്പ് ഇനി ഉടമസ്ഥതയില്ല. മീഡിയ പ്രൊവൈഡർ
ഇമേജ്-ടു-ടെക്സ്റ്റ്, സ്പീച്ച്-ടു-ടെക്സ്റ്റ് പ്രവാഹങ്ങൾ അനുബന്ധ മോഡാലിറ്റി
Bridge ടാബുകൾക്കായി ലിങ്ക് ചെയ്യുന്നു, നിലവിലുള്ള സ്പീച്ച്-ടു-ടെക്സ്റ്റ് പ്ലേഗ്രൗണ്ട് നീക്കം ചെയ്യാതെ.

**സ്വയം-ലൂപ്പ് പ്രവേശന ബൈപാസ്:** വിവരണം വിളി OmniRoute-ന്റെ

`x-omniroute-admission-bypass: internal` എന്നത് പരിഹരിച്ച
സ്വയം-ലൂപ്പ് ക്രെഡൻഷ്യലുമായി ഓത്തന്റിക്കേറ്റ് ചെയ്യുന്നു — പ്രാദേശിക `sk_omniroute` സെന്റിനൽ പ്രാദേശിക മോഡിൽ, അല്ലെങ്കിൽ
ഓപ്പറേറ്റർ-ക്രമീകരിച്ച `OMNIROUTE_API_KEY` / `ROUTER_API_KEY` env കീ (#1350) അതിനാൽ
`REQUIRE_API_KEY=true` വിന്യസങ്ങൾ വിവരണം വിളി നടത്താൻ കഴിയുന്നു. ബൈപാസ്
അവിടെ മാത്രമേ അംഗീകരിക്കപ്പെടൂ, അതിനാൽ ബാഹ്യ ക്ലയന്റുകൾ ഹെഡർ ഉപയോഗിച്ച് പ്രവേശനം ഒഴിവാക്കാൻ കഴിയില്ല.

പഴയ ഡിഫോൾട്ടുകൾ `src/shared/constants/visionBridgeDefaults.ts`-ൽ ഉണ്ട്;
പുതിയ മോഡ്/ടാസ്‌ക്-അവബോധമുള്ള/കാഷ് ഡിഫോൾട്ടുകൾ, ക്രമീകരണ പരിഹാരവും
`src/shared/constants/modalityBridgeDefaults.ts`-ൽ ഉണ്ട്. ഗാർഡ്‌റെയിൽ ഒരു
`deps` കൺസ്ട്രക്ടർ ഓപ്ഷൻ വെളിപ്പെടുത്തുന്നു, അതിനാൽ പരീക്ഷണങ്ങൾ വ്യാജ `getSettings`
മറ്റു `callVisionModel` നടപ്പാക്കലുകൾ Inject ചെയ്യാൻ കഴിയും.

### ഓഡിയോ ബ്രിഡ്ജ് (`audioBridge.ts`) — മോഡാലിറ്റി ബ്രിഡ്ജ് PR-3

ഓഡിയോ ഉൾക്കൊള്ളുന്ന ചാറ്റ് അഭ്യർത്ഥനകൾ ലക്ഷ്യത്തിലേക്ക് എത്തുന്നതിന് മുമ്പ് തടയുന്നു, അത് ഓഡിയോ ഇൻപുട്ട് സ്വീകരിക്കാൻ അറിയപ്പെടുന്നില്ല. ഇത് ചാറ്റ് അഭ്യർത്ഥന വീണ്ടും റൂട്ടുചെയ്യുന്നില്ല: ഓഡിയോ ഭാഗങ്ങൾ നിലവിലുള്ള OpenAI-സമാനമായ മൾട്ടിപാർട്ട് എൻഡ്പോയിന്റിലൂടെ
ലേഖനം ചെയ്യപ്പെടുന്നു, തിരഞ്ഞെടുക്കപ്പെട്ട ചാറ്റ് മോഡൽ ടെക്സ്റ്റ് ലേഖനങ്ങളോടൊപ്പം തുടരുന്നു.

പ്രവാഹം:

1. `getResolvedModelCapabilities()` വഴി `supportsAudio` പരിഹരിക്കുക. വ്യക്തമായ
   പ്രൊവൈഡർ-രജിസ്ട്രി മെറ്റാഡാറ്റ വിജയിക്കുന്നു, തുടർന്ന് സ്റ്റാറ്റിക് മോഡൽ മെറ്റാഡാറ്റ, തുടർന്ന് സിങ്ക് ചെയ്ത
   `modalities_input`. `audio` ഇല്ലാത്ത ഒരു പ്രഖ്യാപിത ഇൻപുട്ട് പട്ടിക `false` ആണ്; യാതൊരു
   ശേഷി തെളിവും `null` ആയി തുടരുന്നു. `false`യും `null`യും സംരക്ഷിത ബ്രിഡ്ജ് സജീവമാക്കുന്നു, എന്നാൽ `true` അത് ഒഴിവാക്കുന്നു.
2. `modalityBridgeAudio*` ക്രമീകരണങ്ങൾ പരിഹരിക്കുക, ഓരോ സന്ദേശത്തിൽ നിന്നും പങ്കുവെക്കാവുന്ന ടോപ്പ്-ലവൽ
   ഓഡിയോ ഭാഗങ്ങൾ `detectMediaParts()`
   ഡിറ്റക്ടർ വഴി എടുക്കുക. പിന്തുണയുള്ള വയർ രൂപങ്ങൾ OpenAI `input_audio`, `audio_url`,
   `source.media_type: "audio/*"` ആണ്. നിക്ഷിപ്ത ഓഡിയോ റൂട്ടിംഗിന് കണ്ടെത്തുന്നു, എന്നാൽ
   സ്പ്ലൈസ് പാതയിലൂടെ നീക്കം ചെയ്യപ്പെടുന്നില്ല. ജോലി `modalityBridgeAudioMaxClips`-ൽ ക്യാപ് ചെയ്യുന്നു;
   പിന്നീട് ഭാഗങ്ങൾ untouched ആയി തുടരുന്നു.
3. ക്രമീകരിച്ച `provider/model`-നെ ആദരിക്കുക, അല്ലെങ്കിൽ `selectAudioBridgeModel()`-നെ
   സ്ഥിരമായ കാറ്റലോഗ് ക്രമത്തിൽ `AUDIO_TRANSCRIPTION_PROVIDERS`-ൽ നടക്കാൻ അനുവദിക്കുക
   ഉപയോഗിക്കാവുന്ന സജീവ പ്രൊവൈഡർ ക്രെഡൻഷ്യൽ ഉള്ള ആദ്യത്തെ മോഡൽ തിരഞ്ഞെടുക്കുക.
4. `callAudioTranscription()` base64/data-URI ഓഡിയോയെ ഒരു മൾട്ടിപാർട്ട്
   `file`-ലേക്ക് മാറ്റുന്നു, അല്ലെങ്കിൽ പൊതുവായ ഔട്ട്‌ബൗണ്ട് ഗാർഡ് വഴി DNS പിന്വലിക്കൽ
   ഉപയോഗിച്ച് 25 MB ബൗണ്ട് ഉള്ള ഒരു ദൂരത്തുള്ള `audio_url` ഡൗൺലോഡ് ചെയ്യുന്നു. തുടർന്ന് ഫയൽ
   തിരഞ്ഞെടുക്കപ്പെട്ട മോഡലുമായി പ്രാദേശിക `/v1/audio/transcriptions` സ്വയം-ലൂപ്പിലേക്ക് POST ചെയ്യുന്നു,
   `resolveSelfLoopBearer()`-ൽ ഓത്തന്റിക്കേറ്റ് ചെയ്യുന്നു. നിലവിലുള്ള ലേഖന മാർഗം സാധാരണ
   ക്രെഡൻഷ്യൽ ലുക്കപ്പ്, കൂൾഡൗൺ/റേറ്റ്-ലിമിറ്റ് കൈകാര്യം, പ്രൊവൈഡർ ഡിസ്‌പാച്ച് എന്നിവ നടത്തുന്നു.
5. വിജയകരമായ വിളികൾ അവരുടെ ഭാഗങ്ങൾ `[Audio N]: <transcript>`-ൽ മാറ്റുന്നു. വിളികൾ
   `Promise.allSettled`-ൽ പ്രവർത്തിക്കുന്നു: ഒരു വ്യക്തിഗത പരാജയം ആ ആദ്യത്തെ
   ഓഡിയോ ഭാഗം നിലനിർത്തുന്നു (#4012 കരാർ). എല്ലാ വിളികളും പരാജയപ്പെടുകയാണെങ്കിൽ, ലക്ഷ്യം
   `supportsAudio === false` എന്ന് തെളിയിച്ചാൽ, ഭാഗങ്ങൾ
   `[Audio N]: (unavailable — no STT provider connected)` (#8430 കരാർ) ആയി മാറുന്നു. ഒരു അറിയാത്ത ലക്ഷ്യത്തിന്
   (`null`), എല്ലാ പരാജയ ഫലങ്ങൾ untouched ആയി തുടരുന്നു. ഉപയോഗിക്കാവുന്ന STT ക്രെഡൻഷ്യൽ ഇല്ലാത്ത
   ഒരു തെളിയിച്ച ടെക്സ്റ്റ്-മാത്രം ലക്ഷ്യം സമാനമായ വ്യക്തമായ സ്റ്റബ് സ്വീകരിക്കുന്നു, നെറ്റ്‌വർക്കിൽ വിളി നടത്താതെ.

വിജയകരമായ ലേഖനങ്ങൾ പ്രോസസ്-വ്യാപകമായ മോഡാലിറ്റി ബ്രിഡ്ജ് LRU/TTL കാഷ് ഉപയോഗിക്കുന്നു.
കീ ഓഡിയോ റഫറൻസ്, സ്ഥിരമായ `audio-transcription` പ്രവർത്തന ലേബൽ,
തിരഞ്ഞെടുക്കപ്പെട്ട STT മോഡൽ എന്നിവ സംയോജിപ്പിക്കുന്നു; പരാജയങ്ങൾ ഒരിക്കലും കാഷ് ചെയ്യപ്പെടുന്നില്ല.
ഓഡിയോ ശ്രമങ്ങൾ പങ്കുവെച്ച `bridged`, `cacheHits`, `failures`,

#### FU-07 ഘടനാപരമായ സെഗ്മെന്റ് തെളിവുകൾ

`segment_aware` ഒരു ബൗണ്ടഡ് പ്രീ-അനാലിസിസ് പാസ് ഉപയോഗിക്കുന്നു, ഇതിനകം സ്ഥിരീകരിച്ച പ്രാദേശിക വീഡിയോ സ്ട്രീമിൽ. ഫിക്സഡ് ഫിൽട്ടർ ചെയിൻ ആദ്യം 320 പിക്സലുകൾക്ക് പരമാവധി സ്കെയിൽ ചെയ്യുന്നു, ദൃശ്യ മാറ്റങ്ങൾക്കും തണുത്ത ഇടവേളകൾക്കും തിരിച്ചറിയുന്നു, തുടർന്ന് 1 ഫ്രെയിം പ്രതിവർഷം ബ്ലർ, ശരാശരി ലൂമ, ആസ്പാഷ്യൽ/ടെംപറൽ വിവരങ്ങൾക്കായി സാമ്പിൾ ചെയ്യുന്നു. പാസ് 600 ഘടനാപരമായ സാമ്പിളുകൾ, ഒരു FFmpeg/filter ത്രെഡ്, സമാന `file`-മാത്രം പ്രോട്ടോക്കോൾ, കണ്ടെയ്നർ അലോവ്ലിസ്റ്റുകൾ, 1 MiB പ്രോസസ്-ഔട്ട്‌പുട്ട് ബൗണ്ട്, കൂടാതെ ബ്രോക്കറിന്റെ പങ്കുവെച്ച അബ്രട്ട്/ഡെഡ്‌ലൈൻ 30 സെക്കൻഡുകൾക്കുള്ളിൽ പരമാവധി. ഇത് ഒരിക്കലും ഒരു കമാൻഡ്, ഫിൽട്ടർ, പാത, അല്ലെങ്കിൽ URL സ്വീകരിക്കുന്നില്ല.

ഘടനാപരമായ മൂല്യങ്ങൾ നിശ്ചിത സാമ്പിളിംഗ് തെളിവുകൾ ആണ്, സെമാന്റിക് വീഡിയോ മനസ്സിലാക്കലല്ല. ഇവ വിഷയങ്ങൾ, പ്രവർത്തനങ്ങൾ, ക്യാപ്ഷനുകൾ, സംസാരണം, അല്ലെങ്കിൽ ഉപയോക്തൃ ഉദ്ദേശ്യം നിഗമനം ചെയ്യുന്നില്ല. ദൃശ്യവും തണുത്ത അതിരുകളും സെഗ്മെന്റുകൾ രൂപീകരിക്കുന്നു; തണുത്ത കവറേജ്, ബ്ലർ, എക്സ്പോഷർ, ആസ്പാഷ്യൽ വിശദാംശം, ടെംപറൽ മാറ്റം എന്നിവ നിലവിലുള്ള 1–16 ഫ്രെയിം ബജറ്റ് എങ്ങനെ വിനിയോഗിക്കപ്പെടുന്നുവെന്ന് മാത്രമേ സ്വാധീനിക്കുകയുള്ളു. ഒരു പൂർണ്ണമായ തണുത്ത സെഗ്മെന്റ് ഒരു ഫ്രെയിമിൽ പരമാവധി ക്യാപ് ചെയ്യുന്നു, അതേസമയം തണുത്തതല്ലാത്ത സെഗ്മെന്റുകൾ ശേഷിക്കുന്ന ബജറ്റിനായി മത്സരിക്കുന്നു. അതിരുകൾ ഫ്രെയിമുകൾക്കു മുകളിൽ ആകുമ്പോൾ, ഏകീകൃത ടൈംലൈൻ കവറേജ് നിലനിര്‍ത്തുന്നു, അതിനാൽ വേഗത്തിലുള്ള പ്രാരംഭ കട്ട് ഒരു ദീർഘമായ തൊലിഞ്ഞ സെഗ്മെന്റ് മറയ്ക്കാൻ കഴിയില്ല. 1-സെക്കൻഡ് വിശകലന പരിധിയിൽ ഒരു തണുത്ത അതിരിന്റെ ഉള്ളിൽ ദൃശ്യ അതിരുകൾ ചേർക്കുന്നു.

കുറഞ്ഞ ഫിൽട്ടറുകൾ, തെറ്റായ/ശൂന്യമായ തെളിവുകൾ, ഒരു ഡിറ്റക്ടർ പിശക്, അല്ലെങ്കിൽ ബൗണ്ടഡ് പ്രീ-അനാലിസിസ് ടൈംഔട്ട് കൃത്യമായ ഏകീകൃത മധ്യനില നയം തുറക്കുന്നു. ഒരു കോളർ അബ്രട്ട് അല്ലെങ്കിൽ ബ്രോക്കർ ഡെഡ്‌ലൈൻ തുറക്കുന്നതിന് പരാജയപ്പെടുന്നില്ല: ഇത് ഇൻ-ഫ്ലൈറ്റ് സബ്‌പ്രോസസ്സ് അവസാനിപ്പിക്കുന്നു, പിന്നീട് ഫ്രെയിം എക്സ്ട്രാക്ഷൻ തടയുന്നു, കൂടാതെ സ്വകാര്യ താൽക്കാലിക മരം `finally`-ൽ നീക്കം ചെയ്യുന്നു.

`scripts/perf/video-bridge-fu07-eval.ts` പോസ്റ്റ്-ഡെഡ്യൂപ്പ് ക്യാപ്ഷൻ-കാൾ സംരക്ഷണങ്ങൾ, കനത്ത-മോഷൻ ബജറ്റ് വിനിയോഗം, ബ്ലർ/എക്സ്പോഷർ/SI-TI തെളിവുകൾ, ദ്രുത കട്ടുകൾ ഒരു ദീർഘ തൊലിഞ്ഞതോടെ, കൂടാതെ ക്രമീകരണ-ഫേഡ് തെറ്റായ പോസിറ്റീവുകൾക്കായി നിശ്ചിതമായ യഥാർത്ഥ FFmpeg ഫിക്സ്ചറുകൾ സൃഷ്ടിക്കുന്നു. ഇത് പ്രീ-അനാലിസിസ് വാൾ ടൈം രേഖപ്പെടുത്തുന്നു, `/usr/bin/time` ലഭ്യമാണെങ്കിൽ, കുട്ടി CPUയും പീക്ക് RSSയും. അതിന്റെ ഗുണനിലവാര പരിശോധനകൾ ഘടനാപരമായ ഓറക്കിളുകൾ മാത്രമാണ്. യഥാർത്ഥ ക്യാപ്ഷൻ-മോഡൽ ഗുണനിലവാരം `HOLD` ആയി തുടരുന്നു, കാരണം ഈ ഹാർനെസ് അംഗീകൃത എണ്ട്പോയിന്റ് അല്ലെങ്കിൽ തണുത്ത ജഡ്ജ് ഇല്ല. സാമ്പത്തിക സംരക്ഷണങ്ങൾ `HOLD` ആയി തുടരുന്നു, അല്ലെങ്കിൽ `--caption-cost-per-call-usd` ഒരു വ്യക്തമായ പോസിറ്റീവ് പെർ-കാൾ അంచനമൊരുക്കുന്നില്ല; സ്ക്രിപ്റ്റ് ഒരിക്കലും ഈ ഫലങ്ങൾ നിർമ്മിക്കുകയില്ല.

ഓരോ ഫ്രെയിം 4 MiB-ൽ പരിമിതമാണ്, എല്ലാ റോ ഫ്രെയിമുകൾ 23 MiB-ലേക്ക്, serialized ബ്രോക്കർ പ്രതികരണം 32 MiB-ലേക്ക്. ഒരു സ്വകാര്യ താൽക്കാലിക ഡയറക്ടറി `finally`-ൽ നീക്കം ചെയ്യുന്നു. OmniRoute FFmpeg ബണ്ടിൽ ചെയ്യുന്നില്ല, കസ്റ്റം എക്സിക്യൂട്ടബിൾ പാത സ്വീകരിക്കുന്നില്ല. ക്യാപ്ഷൻ ചെയ്യുന്നതിന് മുമ്പ്, ബ്രിഡ്ജ് ഒരു സംരക്ഷിത ദൃശ്യ ഡെഡ്യൂപ്ലിക്കേഷൻ പാസ് പ്രയോഗിക്കുന്നു: ഓരോ JPEG-യും 16×16 ഗ്രേസ്കെയിൽ ബഫറിലേക്ക് കുറയ്ക്കുന്നു, മാത്രമല്ല അവസാന ഫ്രെയിമുമായി മാത്രം താരതമ്യം ചെയ്യുന്നു. ഒരു ഫ്രെയിമിന് മുകളിൽ ആവശ്യമായ ക്യാപ്ഷൻ ബജറ്റിനായി, എക്സ്ട്രാക്ഷൻ പരമാവധി ആ ബജറ്റിന്റെ ഇരട്ടിയോളം ഒരു ബൗണ്ടഡ് കാൻഡിഡേറ്റ് പൂലും നൽകുന്നു, ഒരിക്കലും 16 ഫ്രെയിമുകളിൽ കൂടുതൽ അല്ല. ഡെഡ്യൂപ്ലിക്കേഷന്റെ ശേഷം മാത്രമേ ആവശ്യമായ ക്യാപ് പ്രയോഗിക്കുകയുള്ളു, ബജറ്റ് കുറഞ്ഞത് രണ്ട് ആയപ്പോൾ ആദ്യവും അവസാനവും തിരഞ്ഞെടുക്കപ്പെട്ട കാൻഡിഡേറ്റുകൾ അന്തിമ തിന്മയിൽ സംരക്ഷിക്കുന്നു. പതിപ്പായ `grayscale-16x16-mean-cells-v2` നയം ശരാശരി ലൂമ ഡെൽറ്റയും 0.05-ൽ കുറഞ്ഞത് നോർമലൈസ്ഡ് ഡെൽറ്റുള്ള തംബ്‌നെയിൽ സെല്ലുകളുടെ അനുപാതവും ഉപയോഗിക്കുന്നു. ഡ്യൂപ്ലിക്കേറ്റ് ത്രെഷോൾഡ് 0.04 എന്ന സ്ഥിരമായ മൂല്യം ആണ്, പ്രവചനശേഷിയ്ക്കായി തിരഞ്ഞെടുക്കപ്പെട്ടത്, റൺടൈം സെറ്റിംഗായി വെളിപ്പെടുത്തിയിട്ടില്ല. ഈ രണ്ടാം ഉയർന്ന-കോൺട്രാസ്റ്റ് സിഗ്നൽ ചെറിയ ചലനങ്ങളും ദൃശ്യ-ടെക്സ്റ്റ് മാറ്റങ്ങളും സംരക്ഷിക്കുന്നു, ഒരു ശരാശരി മാത്രം താരതമ്യം മറയ്ക്കാൻ കഴിയും. താരതമ്യക്കാരൻ അല്ലെങ്കിൽ ഡികോഡർ പിശകുകൾ തുറക്കുന്നു, കവറേജ് നിലനിര്‍ത്തുന്നു. ഔട്ട്‌പുട്ട് മെറ്റാഡാറ്റ എക്സ്ട്രാക്റ്റ് ചെയ്ത കാൻഡിഡേറ്റുകൾ, വിജയകരമായി ഉപയോഗിച്ച ഫ്രെയിമുകൾ, ദൃശ്യ ഡ്യൂപ്ലിക്കേറ്റുകൾ എന്നിവയെ വേർതിരിക്കുന്നു.

ഒരു വ്യക്തമായി അടയാളപ്പെടുത്തിയ വീഡിയോ ഭാഗം ഒരു ടൈംസ്റ്റാമ്പ് കോൺടാക്റ്റ് ഷീറ്റ് ആവശ്യപ്പെടാം. ബ്രിഡ്ജ് പരമാവധി 4-കോളം, 16-ഫ്രെയിം JPEG ഗ്രിഡ് നിർമ്മിക്കുന്നു. ഓരോ 512-പിക്സൽ സെല്ലും അതിന്റെ ഉറവിട ടൈംസ്റ്റാമ്പ് ഉയർന്ന-കോൺട്രാസ്റ്റ് താഴത്തെ ബാൻഡിൽ കത്തിക്കുന്നു, അതേ ടൈംസ്റ്റാമ്പുകൾ താഴെയുള്ള അസോസിയേഷൻക്കും ഓഡിറ്റിനും ടെക്സ്റ്റ് മെറ്റാഡാറ്റയിൽ തുടരുന്നു. സമ്പൂർണ്ണ JPEG 32 MiB-ൽ പരമാവധി ക്യാപ് ചെയ്യുന്നു. `sharp` ഗ്രിഡ് ഡികോഡ് ചെയ്യാൻ അല്ലെങ്കിൽ രൂപകൽപ്പന ചെയ്യാൻ കഴിയുന്നില്ലെങ്കിൽ, ബ്രിഡ്ജ് വ്യക്തിഗത JPEG ഫ്രെയിമുകളിലേക്ക് വീണ്ടെടുക്കുന്നു; ഒരു ക്ലയന്റ് അബ്രട്ട് ഷീറ്റ് പ്രവർത്തനത്തിലൂടെ ഇപ്പോഴും പ്രചരിക്കുന്നു.

പ്രമോഷൻ തെളിവുകൾ സിന്തറ്റിക് ഘടനാ മൈക്രോബഞ്ച്മാർക്കിൽ നിന്ന്故意മായി വേർതിരിക്കപ്പെട്ടിരിക്കുന്നു. `scripts/perf/video-bridge-contact-sheet-eval.ts` യഥാർത്ഥ OpenAI-സംബന്ധമായ ദൃശ്യ മോഡലുകൾക്കായി ഒരു സ്കീമാ-വർഷിത A/B ഹാർനെസ് നിർവചിക്കുന്നു. ഇത് പ്രൊവൈഡർ-റിപ്പോർട്ടുചെയ്ത ടോക്കനുകൾ, എണ്ട്-ടു-എണ്ട് വാൾ ലാറ്റൻസി (ഷീറ്റ് ഘടന ഉൾപ്പെടെ), മോഡൽ-കാൾ എണ്ണം, മാനിഫസ്റ്റ്-നിർവചിതമായ വസ്തുത നിലനിര്‍ത്തൽ എന്നിവ അളക്കുന്നു. റോ മോഡൽ പ്രതികരണങ്ങൾ റിപ്പോർട്ടിൽ എഴുതുന്നില്ല; SHA-256 ഡിജസ്റ്റുകളും പൊരുത്തപ്പെടുന്ന വസ്തുത ID-കളും മാത്രം നിലനിര്‍ത്തുന്നു. ഹാർനെസ് `--execute-real` പാസ്സായില്ലെങ്കിൽ, നെറ്റ്‌വർക്കോ അല്ലെങ്കിൽ പെയ്ഡ് മോഡൽ കോളുകൾ നടത്തുന്നില്ല, `--model`, `OMNIROUTE_BASE_URL`, `OMNIROUTE_API_KEY` എന്നിവ ക്രമീകരിച്ചിട്ടില്ല. ആ വ്യക്തമായ യഥാർത്ഥ ഓട്ടം ഇല്ലാതെ, അതിന്റെ മെഷീൻ-വായനയോഗ്യമായ വിധി `HOLD` ആയി തുടരുന്നു; സിന്തറ്റിക് പേലോഡ്/കാൾ-എണ്ണം അളവുകൾ മാത്രം പ്രമോഷൻ തെളിവല്ല.

വേർതിരിച്ച `scripts/perf/video-bridge-promotion-eval.ts` FU-07 അല്ലെങ്കിൽ FU-09 നിരീക്ഷണങ്ങൾ ഉപയോഗിക്കുന്നു. പ്രമോഷൻ പ്രവേശനം എട്ട് സിന്തറ്റിക് സീനാരിയോ തരം മുഴുവൻ ആവശ്യമാണ്, കൂടാതെ ഒരു ശുദ്ധമായ യഥാർത്ഥ ക്ലിപ്പ്, ഓരോ റോളിലും കേസിലും കുറഞ്ഞത് മൂന്ന് അളക്കപ്പെട്ട ആവർത്തനങ്ങൾ, എല്ലാ പത്ത് പ്രഖ്യാപിച്ച മെട്രിക്‌സ്, തണുത്ത മീഡിയ/പ്രോംപ്റ്റ്/പ്രതീക്ഷിച്ച-വസ്തു/സജ്ജീകരണ ഡിജസ്റ്റുകൾ, ഏകീകൃത നിരീക്ഷണ ID-കൾ, സ്ഥിരീകരിച്ച വിത്ത് A/B ഓർഡർ എന്നിവ ആവശ്യമാണ്. എക്സിക്യൂഷൻ റിസീറ്റ് കോർപ്പസ് ഡിജസ്റ്റ്, കൃത്യമായ കാൻഡിഡേറ്റ് SHA, മോഡൽ പരിഷ്കരണം എന്നിവ ബന്ധിപ്പിക്കുന്നു. കുറവായ അല്ലെങ്കിൽ അസാധുവായ അളവുകൾ `HOLD` ആയി തുടരുന്നു, 30 സെക്കൻഡിന് മുകളിൽ CPU, 512 MiB-ൽ മുകളിൽ peak RSS അല്ലെങ്കിൽ 30 സെക്കൻഡിന് മുകളിൽ പ്രീ-അനാലിസിസ് ഉൾപ്പെടുന്നു. ഇവ തെളിവ്-പ്രവേശന ക്യാപ്‌സാണ്, പുതിയ റൺടൈം RSS നടപ്പാക്കൽ ഉറപ്പല്ല.

FU-07 കുറഞ്ഞത് 98% ഗുണനിലവാര നിലനിര്‍ത്തലും p95 വൈകിയതിന്റെ അടിസ്ഥാനത്തില്‍ 1.2x-ന് മുകളിലല്ലാത്തതും ആവശ്യമാണ്, കൂടാതെ സമാനമായ ശരാശരി ക്യാപ്ഷന്‍ വിളികളില്‍ 0.05 ആബ്സോല്യൂട്ട് കേസ്-ബാലന്‍സ് ചെയ്ത ശരാശരി റിക്കോള്‍ മെച്ചപ്പെടുത്തല്‍ അല്ലെങ്കില്‍ കുറഞ്ഞത് 10% കുറവുള്ള ശരാശരി പോസ്റ്റ്-ഡിഡ്യൂപ്പ് ക്യാപ്ഷന്‍ വിളികള്‍ ആവശ്യമാണ്. FU-09 കുറഞ്ഞത് 0.85 ഗുണനിലവാരം, 95% നിലനിര്‍ത്തല്‍, 20% p95 വൈകിയതിന്റെ കുറവ്, 10% ടോക്കണ്‍ കുറവ് ആവശ്യമാണ്. ക്രിറ്റിക്കൽ-ഫാക്റ്റ് നഷ്ടം, ഇഞ്ചക്ഷൻ അനുസരണ അല്ലെങ്കിൽ നഷ്ടമായ ഉപയോഗം പ്രമോഷനെ തടയുന്നു. ഒരു എക്സിക്യൂഷൻ ഒന്നും പ്രമോട്ട് ചെയ്യാൻ കഴിയുന്നില്ല: `--previous-report` സമാനമായ നയം/മോഡൽ പരിഷ്കരണം/കണ്ടിഡേറ്റ്/കോർപ്പസ് എന്നിവയുടെ രണ്ട് വ്യത്യസ്ത, ഒത്തുചേരാത്ത, തുടർച്ചയായ യോഗ്യതയുള്ള എക്സിക്യൂഷനുകൾ സ്ഥിരീകരിക്കുന്നു. ഒരു സാമ്പിളിംഗ് പരീക്ഷണം ഒരു കോൺടാക്റ്റ്-ഷീറ്റ് പരീക്ഷണം സ്ഥിരീകരിക്കാൻ കഴിയുന്നില്ല.

കോളക്ടർമാർ മറുപടികൾ മെമ്മറിയിൽ സ്കോർ ചെയ്യണം, `responseDigest` കൂടാതെ മെട്രിക്‌സും നിരീക്ഷണ ബൈൻഡിംഗുകളും സംരക്ഷിക്കണം, മറുപടി ടെക്സ്റ്റ് ഒരിക്കലും അല്ല. ഉപഭോക്താവ് പഴയ കച്ചവട നിരീക്ഷണങ്ങൾ വായിക്കുന്നു, എന്നാൽ ആ ടെക്സ്റ്റ് തന്റെ റിപ്പോർട്ടുകളിൽ ഒരിക്കലും പകർന്നെടുക്കുന്നില്ല. ഓരോ നിരീക്ഷണത്തിനും `responseDigest` അല്ലെങ്കിൽ `rawResponseText` എന്നതിൽ ഒരൊന്നാണ് സ്വീകരിക്കപ്പെടുന്നത്. പതിപ്പായ അനുവദനീയ പട്ടിക ശൂന്യമായിരിക്കുകയാണ്, ഒരു മാറ്റമില്ലാത്ത `hold` ഡിഫോൾട്ടുമായി. യോഗ്യതയുള്ള ഒരു എൻട്രിക്ക് അതിന്റെ തെളിവിന്റെ റഫറൻസ്, നയം, മോഡൽ പരിഷ്കരണം, കൃത്യമായ കണ്ടിഡേറ്റ് SHA, മാനിഫസ്റ്റ് ഡിജസ്റ്റ്, രണ്ട് വ്യത്യസ്ത റൺ ID എന്നിവ ആവശ്യമാണ്; സംഘർഷിക്കുന്ന സാഹചര്യങ്ങൾ നിരസിക്കപ്പെടുന്നു. ഈ മെറ്റാഡാറ്റ ഒരു ഓഡിറ്റ് കരാറാണ്, ഒരു റഫറൻസുചെയ്യുന്ന ഫയൽ യഥാർത്ഥ അളവുകൾ അടങ്ങിയിരിക്കുന്നതിന്റെ തെളിവല്ല. ഏതെങ്കിലും എൻട്രി ചേർക്കുന്നതിന് മുമ്പ് യഥാർത്ഥ റസീറ്റ് പരിശോധിക്കുക. മാനേജ്മെന്റ് സ്റ്റാറ്റ്സ് എൻഡ്പോയിന്റ്, വീഡിയോ ഡാഷ്ബോർഡ് സംരക്ഷിതമായ തയ്യാറെടുപ്പുകൾ വെളിപ്പെടുത്തുന്നു. ഒരു കോൺഫിഗർ ചെയ്ത മോഡൽ അലൈസ് മാത്രം അതിന്റെ പരിഷ്കരണം അല്ലെങ്കിൽ പ്രവർത്തനത്തിലുള്ള കണ്ടിഡേറ്റ് SHA സ്ഥാപിക്കുന്നില്ല, അതിനാൽ നിലവിലെ ഡാഷ്ബോർഡ് `HOLD` റിപ്പോർട്ട് ചെയ്യുന്നു, മറ്റൊരു എക്സിക്യൂഷൻ കോൺടക്സ്റ്റിൽ നിന്നുള്ള യോഗ്യത പുനരുപയോഗിക്കുന്നതിന് പകരം. വ്യക്തമായ പരീക്ഷണ തിരഞ്ഞെടുപ്പ് പ്രമോഷനിൽ നിന്ന് വേർതിരിച്ചിരിക്കുന്നു; യാതൊരു ഡിഫോൾട്ടും സ്വയം മാറ്റപ്പെടുന്നില്ല.

കോളർമാർ ഇതിനകം സജ്ജീകരിച്ച ടെക്സ്റ്റ് കൈവശമുള്ള supported video ഭാഗത്തിന് ഒരു ഓപ്ഷണൽ `transcript.cues` അറേ ചേർക്കാം. ഓരോ ക്യൂയും `text`, ഒരു പരിമിതമായ `start`/`end` ഇടവേള, ഒരു വെളിപ്പെടുത്തിയ `source` (`client`, `embedded`, അല്ലെങ്കിൽ `audio-bridge`) എന്നിവ കൈവശം വേണം; `confidence` ഡിഫോൾട്ടായി `1` ആണ്, അത് `0`നും `1`നും ഇടയിൽ തുടരേണ്ടതാണ്. കൃത്യമായ ഡ്യൂപ്ലിക്കേറ്റ് ക്യൂകൾ ചുരുക്കപ്പെടുന്നു. OmniRoute ഈ മെറ്റാഡാറ്റയിൽ നിന്ന് ട്രാൻസ്ക്രിപ്ഷൻ ആരംഭിക്കുന്നില്ല: സ്ഥിരീകരിച്ച ക്യൂകൾ വിവരണത്തിലുള്ള ഫലത്തിൽ ഉറപ്പുള്ളതും, ആത്മവിശ്വാസവും, ഇടവേളയും ഉൾപ്പെടെ പകർന്നെടുക്കുന്നു, കൂടാതെ ഫ്രെയിം ക്യാപ്ഷനുകൾക്കൊപ്പം വിശ്വസിക്കാത്ത നിരീക്ഷണങ്ങളായി അവതരിപ്പിക്കുന്നു. അസാധുവായ, പരിധി പുറത്തുള്ള, അല്ലെങ്കിൽ ഉത്ഭവമില്ലാത്ത ടെക്സ്റ്റ് ക്യാപ്ഷൻ സ്ട്രീമിൽ മിശ്രിതമാക്കുന്നതിന് പകരം നിരസിക്കപ്പെടുന്നു. രണ്ട് അഭ്യർത്ഥന-ബോഡി ട്രാൻസ്ക്രിപ്റ്റ് ചാനലുകൾ നൽകിയ ഉത്ഭവത്തെ `client` എന്നതിലേക്ക് സാധാരണവത്കരിക്കുന്നു, സ്വയം-അവകാശപ്പെട്ട `embedded` അല്ലെങ്കിൽ `audio-bridge` ലേബലുകൾ ഉൾപ്പെടുന്നു. വിശ്വസനീയമായ ലേബലുകൾ കോഡ്-മാത്രം `trustedSource` വാദത്തിലൂടെ ഒരു സർവർ-ഉടമയുള്ള അഡാപ്റ്റർ മാത്രം നൽകാം; ഒരു അഭ്യർത്ഥന JSON ഫീൽഡ് ആ വാദത്തിലേക്ക് എത്താൻ കഴിയില്ല. ട്രാൻസ്ക്രിപ്റ്റ് ടെക്സ്റ്റ് വിശ്വസിക്കാത്ത മീഡിയ-ഉത്ഭവ ഉള്ളടക്കമാണ്, അതിന്റെ ഉത്ഭവം എത്രയും കുറഞ്ഞത്, അതിന് അധികാരവകാശം നിശ്ചയിക്കേണ്ടതില്ല.

ഒരു പുരോഗമന കോളർ ഒരേ വീഡിയോയ്ക്ക് `audioTranscript` ട്രാക്ക് നൽകാം; ഇത് ക്ലയന്റ്-നൽകിയ ടെക്സ്റ്റ് എന്ന നിലയിൽ പരിഗണിക്കുന്നു, സർവർ ട്രാൻസ്ക്രിപ്ഷന്റെ തെളിവല്ല. ഫ്യൂഷൻ സീം ഒരു ഡെഡ്‌ലൈൻ, അബ്രട്ട് സിഗ്നൽ എന്നിവയുടെ കീഴിൽ ദൃശ്യവും ശബ്ദവും നിരീക്ഷണങ്ങൾ നടത്തുന്നു, അവയെ ഒരു പൊതുവായ ടൈംലൈൻയിൽ ക്രമീകരിക്കുന്നു, കൃത്യമായ ഡ്യൂപ്ലിക്കേറ്റുകൾ ചുരുക്കുന്നു, ഒരു ഭാഗിക ഫലത്തെ റിപ്പോർട്ട് ചെയ്യുന്നു, ഒരുകൈ മാത്രം വിജയിച്ചാൽ. അസാധുവായ `audioTranscript` ആ ഭാഗിക ഫലത്തിലേക്ക് താഴ്ന്നു — ദൃശ്യ വിവരണം സൂക്ഷിക്കപ്പെടുന്നു, ശബ്ദ ശാഖ ഒരു ശുദ്ധീകരിച്ച പരാജയ കോഡ് രേഖപ്പെടുത്തുന്നു — മുഴുവൻ വീഡിയോ പരാജയപ്പെടുന്നതിന് പകരം. ഓരോ ശാഖയുടെ ലഭ്യത, ഭാഗിക പതാക, ശുദ്ധീകരിച്ച പരാജയ കോഡുകൾ എന്നിവ വിവരണത്തിലുള്ള ഫലത്തിൽ, ഗാർഡ്‌റെയിൽ മെറ്റാഡാറ്റയിൽ (`audioFusionRuns`/`audioFusionPartials`/`audioFusionFailureCodes`), ഫല-കാഷ് മെറ്റാഡാറ്റയിൽ, ബ്രിഡ്ജ് ഫ്യൂഷൻ കൗണ്ടറുകളിൽ സംരക്ഷിക്കപ്പെടുന്നു. ഡിഫോൾട്ട് വീഡിയോ ബ്രിഡ്ജ് പാത സംസാരത്തെ ടെക്സ്റ്റിലേക്ക് മാറ്റുകയോ രണ്ടാം മീഡിയ പകർപ്പ് ഡൗൺലോഡ് ചെയ്യുകയോ ചെയ്യില്ല; ആ വ്യക്തമായ ട്രാക്ക് ഇല്ലാതെ, ഇത് വീഡിയോ മാത്രം തുടരുന്നു.

**ട്രാൻസ്ക്രിപ്റ്റ് നിലനിര്‍ത്തല്‍ (#12150 P1).** വീഡിയോ ബ്രിഡ്ജ് (സ്വയം-ഓപ്റ്റ് ഇൻ) ഒരു ട്രാൻസ്ക്രിപ്റ്റ് ക്യൂ അവതരിപ്പിക്കുമ്പോൾ ഇത് സ്വയം പ്രവർത്തിക്കുന്നു — ഒരു വ്യത്യസ്ത നിലനിര്‍ത്തല്‍ പതാക ഇല്ല. ഒരു അഭ്യർത്ഥന ഏതെങ്കിലും ട്രാൻസ്ക്രിപ്റ്റ് ക്യൂ (ഒരു കോളർ-പ്രഖ്യാപിത `transcript` അല്ലെങ്കിൽ ഒരു ഫ്യൂസ്ഡ് `audioTranscript`) അവതരിപ്പിക്കുമ്പോൾ, ഗാർഡ്‌റെയിൽ അത് `videoBridgeObserved` എന്ന നിലയിൽ അടയാളപ്പെടുത്തുന്നു, കൂടാതെ വീഡിയോ വിവരണത്തിന്റെ ഒരു റെഡാക്റ്റഡ് ഷാഡോ ഉത്പാദിപ്പിക്കുന്നു — ഓരോ ക്യൂയുടെ സ്വതന്ത്ര-ടെക്സ്റ്റ് ബോഡി `[redacted-video-transcript]` എന്നതാൽ മാറ്റുന്നു, ഘടനാപരമായ ക്യൂ ഫീൽഡ് സ്ട്രിംഗ് അസംബ്ല് ചെയ്യുന്നതിന് മുമ്പ് മാറ്റുന്നതിലൂടെ (ചുരുക്കിയ ടെക്സ്റ്റ് പാഴ്സിംഗ് ചെയ്യുന്നതിലൂടെ അല്ല, അതിനാൽ യാതൊരു ക്യൂ ഉള്ളടക്കവും — എതിരാളി അല്ലെങ്കിൽ സാധാരണ, `]` അടങ്ങിയ ബോഡികൾ ഉൾപ്പെടെ `[`[inaudible]`/`[music]`— നിലനിൽക്കാൻ കഴിയില്ല). നിലനിര്‍ത്തിയ കോളിന്റെ ലോഗ് അഭ്യർത്ഥന ബോഡി ഓരോ വീഡിയോ-ഉത്ഭവമുള്ള ടെക്സ്റ്റ് ഭാഗവും ആ റെഡാക്റ്റഡ് ഷാഡോയ്ക്ക് മാറ്റുന്നു, ഉള്ളടക്ക സമാനതയാൽ പൊരുത്തപ്പെടുന്നു;`fullText` ആങ്കർ പൂർത്തിയായ പ്രീ-കോളിന്റെ ഗാർഡ്‌റെയിൽ പേലോഡിൽ നിന്ന് വീണ്ടും വായിക്കുന്നു, അതിനാൽ പിന്നീട് ശൃംഖല ഗാർഡ്‌റെയിൽ (PII, ക്രെഡൻഷ്യൽ മാസ്കറുകൾ, പ്രാധാന്യം 10/95) വിവരണ ടെക്സ്റ്റ് സ്ഥലം മാറ്റുമ്പോഴും പൊരുത്തം വിജയിക്കുന്നു. മോഡലിലേക്ക് മുകളിലേക്ക് അയച്ച ബോഡി മാറ്റമില്ല. ഒരു നിരീക്ഷിച്ച അഭ്യർത്ഥനയും സ്ഥിരമായ മെമ്മറിയെ പൂരിപ്പിക്കുന്നില്ല (അഭ്യർത്ഥന-യും മറുപടി-ഉത്ഭവമുള്ള എക്സ്ട്രാക്ഷൻ skipped ചെയ്യുന്നു), അതിനാൽ മോഡലിന്റെ സ്വന്തം മറുപടി മെമ്മറിയിലേക്ക് ട്രാൻസ്ക്രിപ്റ്റ് ടെക്സ്റ്റ് പ്രതിഫലിപ്പിക്കാൻ കഴിയില്ല.

**റോ വീഡിയോ ഫീൽഡുകൾ (#12430).** ബ്രിഡ്ജ് സജീവമാകുമ്പോഴും സ്വാഭാവിക വീഡിയോ പിന്തുണ അറിയാത്തതും ഇല്ലാത്തതും ആയാൽ, നിർവചിച്ച `transcript`/`audioTranscript` ഫീൽഡുകൾ `videoBridgeObserved`-നെ സജീവമാക്കുന്നു, വിവരണ പരാജയമുണ്ടായാലും അല്ലെങ്കിൽ `maxVideos` പരിധി കഴിഞ്ഞാലും. `null`യും ശൂന്യമായ സ്ട്രിംഗുകളും എണ്ണപ്പെടുന്നു; അഭാവമുള്ള ഫീൽഡുകളും non-video മെറ്റാഡാറ്റയും എണ്ണപ്പെടുന്നില്ല. നിലനിര്‍ത്തിയ പകർപ്പുകൾ ഈ ഫീൽഡുകൾ റെഡാക്റ്റ് ചെയ്യുന്നു അല്ലെങ്കിൽ അഭ്യർത്ഥന ഒഴിവാക്കുന്നു, കാഷുകൾ/മെമ്മറി ബypass ചെയ്യുന്നു. പ്രൊവൈഡർ പേലോഡ് മാറ്റമില്ല.

അധികം നിലനിര്‍ത്തിയ പകര്‍പ്പുകള്‍ ഒരേ നിരീക്ഷിത-അഭ്യര്‍ത്ഥന സിഗ്നല്‍ ഉപയോഗിക്കുന്നു. കച്ചവടം മുന്‍-ഗാര്‍ഡ്‌റെയില്‍ ക്ലയന്റ്-അഭ്യര്‍ത്ഥന സ്നാപ്ഷോട്ട്, മെമ്മറിയില്‍ കാത്തിരിക്കുന്ന അഭ്യര്‍ത്ഥന, പ്രാരംഭമായി നിരസിച്ച അഭ്യര്‍ത്ഥന ലോഗ് എന്നിവ വീഡിയോ ഭാഗങ്ങളിലെ ട്രാൻസ്ക്രിപ്റ്റ് ഫീൽഡുകൾ ഘടനാപരമായി മാറ്റുന്നു; പൈപ്പ്‌ലൈൻ ഘട്ടങ്ങൾക്കും സാഹചര്യ കൈമാറ്റത്തിനും സൃഷ്ടിച്ച സ്ട്രിംഗ് പ്രോംപ്റ്റുകൾ നിലനിര്‍ത്തിയ അഭ്യര്‍ത്ഥന-ശരീര സിങ്കിൽ നിന്ന് മൂടിയിരിക്കുന്നു. നിലനിര്‍ത്തിയ `video_content_removed` മാർക്കർ `previous_response_id` തുടർച്ചയെ അടച്ചുപൂട്ടാൻ പരാജയപ്പെടുന്നു, മറിച്ച് ഉദ്ദേശ്യമായി ഉപേക്ഷിച്ച ടെക്സ്റ്റ് പുനർനിർമ്മിക്കാൻ. ഒരു നിരീക്ഷിത അഭ്യര്‍ത്ഥന logging-നു മുമ്പ് അതിന്റെ ഓരോ ഭാഗത്തെയും മൂടൽ നിഴൽ നഷ്ടപ്പെടുകയോ, അല്ലെങ്കിൽ പിന്നീട് അഭ്യര്‍ത്ഥന മാറ്റങ്ങൾക്കുശേഷം നിരവധി വീഡിയോ നിഴലുകളിൽ ഒന്നും പൊരുത്തപ്പെടുകയോ ചെയ്താൽ, നിലനിര്‍ത്തിയ അഭ്യര്‍ത്ഥന ശരീരത്തെ പൂർണ്ണമായും ഒഴിവാക്കുന്നു, ഭാഗികമായി മൂടിയ ട്രാൻസ്ക്രിപ്റ്റ് നിലനിര്‍ത്തുന്നതിന് പകരം.

ഒരു നിരീക്ഷിത അഭ്യര്‍ത്ഥനയ്ക്ക്, ഒരു മോഡൽ പ്രതികരണം ട്രാൻസ്ക്രിപ്റ്റിന്റെ ഏതെങ്കിലും ഭാഗം ഘടനാപരമായ സൂചനാ അതിരില്ലാതെ ഉദ്ധരിക്കാം. അതിന്റെ നിലനിര്‍ത്തിയ കോള്ലോഗ് `responseBody` അതിനാൽ ഒഴിവാക്കൽ മാർക്കർ കൊണ്ട് മാറ്റപ്പെടുന്നു; വിശദമായ പൈപ്പ്‌ലൈൻ ആർട്ടിഫാക്റ്റ് (ഉപരിതല/ക്ലയന്റ് ശരീരങ്ങളും സ്ട്രീം ചങ്കുകളും ഉൾക്കൊള്ളാം) നിലനിര്‍ത്തുന്നില്ല. അർത്ഥവത്തായ, ഐഡെംപൊട്ടൻസി, reasoning-replay കാഷുകൾ ആ അഭ്യര്‍ത്ഥനയ്ക്കുള്ള വായനകളും എഴുതലുകളും ഒഴിവാക്കുന്നു. പ്രൊവൈഡർ അഭ്യര്‍ത്ഥനയും ക്ലയന്റ്-ദൃശ്യമായ പ്രതികരണവും മാറ്റമില്ലാതെ തുടരുന്നു. വിശദമായ ആർട്ടിഫാക്റ്റ് ഒഴിവാക്കുമ്പോൾ താൽക്കാലിക ബഫറിൽ നിന്ന് പ്രാരംഭ keepalive ബൈറ്റുകൾ ഒഴുക്കുന്നു. കിറോയുടെ തെറ്റായ EventStream മുന്നറിയിപ്പ് payload ബൈറ്റ് എണ്ണത്തെ മാത്രം റിപ്പോർട്ട് ചെയ്യുന്നു, അതിന്റെ ഉള്ളടക്കം അല്ലെങ്കിൽ JSON പാഴ്സറിന്റെ കച്ചവട പിശക് ഒരിക്കലും ഇല്ല.

ഇത് എല്ലാ ബന്ധമില്ലാത്ത പ്രൊവൈഡർ/പ്ലഗിൻ ഡയഗ്നോസ്റ്റിക് പരിശോധിച്ചിട്ടില്ലെന്ന് അവകാശപ്പെടുന്നില്ല; വ്യാപകമായ നിലനിര്‍ത്തിയ-സിങ്ക് സ്വീപ്പ് #11658-ൽ ട്രാക്ക് ചെയ്യുന്നു.

ആന്തരിക `/api/modality-bridge/video/drilldown` ജീവിതചക്രം ഒരു വ്യത്യസ്തമായ, ലൂപ്പ്‌ബാക്ക്/ടോക്കൺ-അധികൃതമായ കാഷ് സബ്സ്ട്രേറ്റ് ആണ്. ഓരോ പ്രവർത്തനവും ഒരു കാനോണിക്കൽ ഒപാക് പ്രിൻസിപ്പൽ ID ആവശ്യമാണ്. ഒരു ഉൽപ്പന്ന കോളർ സജീവമാക്കുന്നതിന് മുമ്പ്, അത് അതിന്റെ ID ഓതന്റിക്കേറ്റു ചെയ്ത ടെനന്റ് നിന്ന് ഉത്പാദിപ്പിക്കണം, കൂടാതെ ക്ലയന്റ്-തിരഞ്ഞെടുത്ത മൂല്യം മുന്നോട്ട് നൽകരുത്. കാഷ് കീകൾ ആ പ്രിൻസിപ്പലിനെ കാനോണിക്കൽ സെഷൻ, വീഡിയോ-റഫറൻസ് ID-കളുമായി ബന്ധിപ്പിക്കുന്നു, അവയുടെ SHA-256-നിറവേറ്റിയ കീകൾ മാത്രം സൂക്ഷിക്കുന്നു, വായനകളും ഇല്ലാതാക്കലുകളും ഒരേ പ്രിൻസിപ്പലിലേക്ക് പരിധി ചെയ്യുന്നു. കാഷ് ഓരോ എൻട്രിയിലും പരമാവധി 16 ഉത്പന്ന JPEG ഫ്രെയിമുകൾ സൂക്ഷിക്കുന്നു, പത്ത് മിനിറ്റുകൾക്കുശേഷം അവ expire ചെയ്യുന്നു, കൂടാതെ പരിമിതമായ `start`/`end` വായനകൾ അല്ലെങ്കിൽ വ്യക്തമായ സെഷൻ ഇല്ലാതാക്കലുകൾ പിന്തുണയ്ക്കുന്നു.

ഓരോ പ്രിൻസിപ്പലും 16 എൻട്രികൾക്കും 64 MiB കാനോണിക്കൽ JPEG ഡാറ്റയ്ക്കും പരിമിതമാണ്. ആ പരിധികൾ ആഗോള 64-എൻട്രി/256 MiB മേൽക്കൂരയിൽ നിന്ന് സ്വതന്ത്രമാണ്: പ്രിൻസിപ്പൽ ക്വോട്ടാ സമ്മർദ്ദം ആ പ്രിൻസിപ്പലിന്റെ ഏറ്റവും കുറച്ച് ഉപയോഗിച്ച എൻട്രികൾ മാത്രം ഒഴിവാക്കുന്നു, ആഗോള LRU ഒഴിവാക്കലിന് മുൻപ്. കാലഹരണപ്പെട്ട എൻട്രികൾ കാഷ് പ്രവർത്തനത്തിൽ പ്രിൻസിപ്പലും ആഗോള അക്കൗണ്ടിംഗും നിന്ന് നീക്കം ചെയ്യപ്പെടുന്നു, കൂടാതെ റദ്ദാക്കലും സ്ഥിരീകരണ പരാജയവും ഭാഗികമായ മാറ്റം നടത്തുകയില്ല.

കാഷ് അസാധുവായ കാനോണിക്കൽ Base64, അധിക പാഡിംഗ്, അസാധുവായ JPEG മീഡിയ, തെറ്റായ അല്ലെങ്കിൽ ചുരുക്കിയ JPEG-കൾ, കൂടാതെ പരിമിതമായ പൂർണ്ണ-ചിത്ര `sharp` ഡികോഡിങ്ങിൽ മുന്നറിയിപ്പ് നൽകുന്ന JPEG-കൾ തള്ളുന്നു. അത് സ്വീകരിച്ച ഓരോ ചിത്രത്തെയും കാനോണിക്കൽ JPEG ആയി പുനർകോഡ് ചെയ്യുന്നു, ഡികോഡ് ചെയ്ത ബൈറ്റുകളിൽ നിന്ന് വീതിയും ഉയരവും ഉത്പാദിപ്പിക്കുന്നു, കോളർ ഫീൽഡുകൾക്ക് വിശ്വാസം വയ്ക്കാതെ, കൂടാതെ അവയെ നിലനിര്‍ത്തുന്നതിന് പകരം ഏതെങ്കിലും പിന്‍തുടർച്ചയുള്ള പോളിഗ്ലോട്ട് ബൈറ്റുകൾ ഒഴിവാക്കുന്നു. പരിമിതമായ കാനോണിക്കൽ കംപ്രസ്സ് ബഫർ മാത്രമാണ് ഇരുവരുടെയും ക്വോട്ടാസിന് ചാർജ് ചെയ്യുന്നത്. JSON വയർ പരിധി 32 MiB ഡികോഡ് ചെയ്ത-ഇൻപുട്ട് മേൽക്കൂരയ്ക്ക് Base64 ഓവർഹെഡ് ഉൾക്കൊള്ളുന്നു. ഓരോ സൂക്ഷിച്ച ഉത്പന്നവും അതിന്റെ സ്ഥിരീകരിച്ച JPEG ഫോർമാറ്റ്/റിസൊല്യൂഷൻ, സാമ്പ്ലിംഗ് നയം, ഉത്പന്ന പതിപ്പ്, സൃഷ്ടി സമയം, സർവർ-കണക്കാക്കുന്ന ഉള്ളടക്കം ഹാഷ്, കൂടാതെ ഹാഷ് ചെയ്ത മാതൃകാ റഫറൻസ് കൂടാതെ വിശ്വസനീയമായ കോളറിന്റെ മാതൃകാ-ഉള്ളടക്കം ഹാഷ് രേഖപ്പെടുത്തുന്നു. ആസിങ്ക്രണസ് ഡികോഡ്/ഹാഷ് ഘട്ടങ്ങൾക്കിടയിൽ റദ്ദാക്കലുകൾ പരിശോധിക്കുന്നു, ആറ്റോമിക് കാഷ് കമ്മിറ്റിന് മുമ്പ്.

ഉൽപ്പന്ന നിർമ്മാതാവ് വിജയകരമായ ദൃശ്യ വിശകലനത്തിന് ശേഷം മാത്രമേ ഇതിനകം ഉത്പാദിപ്പിച്ച ബ്രോക്കർ ഫ്രെയിമുകൾ പുനരുപയോഗിക്കുകയുള്ളു, രണ്ടാമത്തെ വീഡിയോ ഡൗൺലോഡ്/എക്സ്ട്രാക്ഷൻ ഇല്ല. ഇത് ഓപ്പറേറ്റർ `modalityBridgeVideoDrilldownEnabled=true`, കർശനമായ ഓരോ ഭാഗത്തെയും `drilldown: true`, കൂടാതെ ഒരു ഓതന്റിക്കേറ്റ API-കീ റെക്കോർഡ് ID ആവശ്യമാണ്. ക്ലയന്റ്-പ്രഖ്യാപിത പ്രിൻസിപ്പൽ/സെഷൻ മൂല്യങ്ങൾ ഉടമസ്ഥത സ്ഥാപിക്കുന്നില്ല. ഈ മൂന്ന് വ്യവസ്ഥകളും ഇല്ലാതെ, അത് ഹാഷ്, പുനർവലിച്ചുകൂടാതെ അല്ലെങ്കിൽ അധിക ഫ്രെയിമുകൾ നിലനിര്‍ത്തുകയില്ല. നിലനിര്‍ത്തൽ പരാജയം ഉപയോഗയോഗ്യമായ ദൃശ്യ പ്രതികരണം സംരക്ഷിക്കുന്നു. സമ്മതിച്ച അഭ്യര്‍ത്ഥനകൾ മുഴുവൻ-വീഡിയോ ഫല കാഷ് ഒഴിവാക്കുന്നു, അതിനാൽ കാഷ് ചെയ്ത ഫലങ്ങൾ ഒരിക്കലും കൈകാര്യം ചെയ്യുകയില്ല.

വിജയകരമായ JSON, SSE പ്രതികരണങ്ങൾ പരിമിതമായ `x-omniroute-video-drilldown` ഹെഡറിൽ പരമാവധി നാല് ഒപാക് കൈകളെ വെളിപ്പെടുത്തുന്നു. അധികൃതമായ ബ്രൗസർ ഉറവിടങ്ങൾ ആ ഹെഡർ വായിക്കാൻ കഴിയും, CORS ഉറവിട നയം വ്യാപിപ്പിക്കാതെ. പുതിയ കൈകൾ `v1.<32-byte random base64url token>` ഉപയോഗിക്കുന്നു, രജിസ്ട്രി അവയുടെ SHA-256 ഹാഷുകൾ മാത്രം നിലനിര്‍ത്തുന്നു. വായനക്കാരൻ/ഹെഡർ പാഴ്സർ പഴയ 64-ഹെക്‌സ് കൈകളെയും സ്വീകരിക്കുന്നു. ഓതന്റിക്കേറ്റ പബ്ലിക് ഉപഭോക്താവ് `GET /api/v1/video-bridge/drilldown?handle=...`, സ്വതന്ത്രമായി `modalityBridgeVideoDrilldownRemoteEnabled=true` വഴി ഗേറ്റുചെയ്യുന്നു. വ്യക്തമായ നിലനിര്‍ത്തിയ തെറ്റായത് ആക്സസ് റദ്ദാക്കുന്നു, പഴയ `OMNIROUTE_VIDEO_BRIDGE_DRILLDOWN_REMOTE_ENABLED` env ഫാൾബാക്ക് സജീവമായിട്ടും. ഉൽപ്പന്ന നിലനിര്‍ത്തലിന് സമാനമായ പഴയ `OMNIROUTE_VIDEO_BRIDGE_DRILLDOWN_ENABLED` ഫാൾബാക്ക് ഉണ്ട്. ഇരുവരും ഫാൾബാക്കുകൾ ഡിഫോൾട്ട് ഓഫ് ആണ്.

ഉപഭോക്താവ് ഓതന്റിക്കേറ്റ കീയിൽ നിന്ന് ഉടമസ്ഥത ഉത്പാദിപ്പിക്കുന്നു, കീ നയം പ്രയോഗിക്കുന്നു, അറിയാത്ത, കാലഹരണപ്പെട്ട, മറ്റൊരു കീയുടെ കൈകൾക്കായി ഒരേ 404 തിരികെ നൽകുന്നു. ഇത് `variant=preview|standard|detail` (പരമാവധി JPEG അളവ് 320/640/1280, ഒരിക്കലും ഉയർത്തിയിട്ടില്ല), `limit=1..8` (അല്ലെങ്കിൽ പഴയ `frames` അലൈസ്, ഒരിക്കലും ഇരുവരും അല്ല), ശൂന്യ-അടിസ്ഥാന `page`, കൂടാതെ ഐച്ഛിക `start`/`end` ഫോകസ് സെക്കൻഡുകൾ സ്വീകരിക്കുന്നു. പുനരാവൃതമായ ക്വറി കീകൾക്കും തിരിഞ്ഞ ഫോകസ് വിൻഡോകൾക്കും തള്ളുന്നു. ഓരോ തിരികെ ലഭിച്ച വകഭേദത്തിനും അതിന്റെ യഥാർത്ഥ ഉള്ളടക്കത്തിന്റെയും യഥാർത്ഥ റിസൊല്യൂഷൻ മെറ്റാഡാറ്റയുടെ ഒരു ഹാഷ് ഉണ്ട്, നിലനിര്‍ത്തിയ ഉറവിടവുമായി ബന്ധിപ്പിച്ചിരിക്കുന്നു. വകഭേദങ്ങൾ വായനയിൽ ഉത്പാദിപ്പിക്കുന്നു, അധികം നിലനിര്‍ത്തിയ പകർപ്പുകളായി സൂക്ഷിക്കുന്നില്ല. JSON പ്രതികരണം, Base64/envelope ഉൾപ്പെടെ, 32 MiB-ൽ പരിമിതമാണ്; ഒരു വലിയ പേജ് 413 തിരികെ നൽകുന്നു, ക്ലയന്റ് കുറച്ച് ഫ്രെയിമുകൾക്കായി അഭ്യർത്ഥിക്കണം. വായനകൾ ഓരോ പുനർവലിച്ചും റദ്ദാക്കലുകൾ പരിശോധിക്കുന്നു, കൈകളുടെ സാധുത തിരിച്ചറിയുന്നതിന് മുമ്പ്. ഉടമസ്ഥതയാൽ `DELETE` ഐഡെംപൊട്ടൻറ് ആണ്; ഇല്ലാതാക്കലോ TTL കാലഹരണപ്പെടലോ നിലനിര്‍ത്തിയ ഉറവിടവും ഉപയോഗ അക്കൗണ്ടിംഗും വിട്ടുനൽകുന്നു.

ശെയർ ചെയ്ത സ്റ്റോർ പ്രോസസ്-ലോകൽ ആണ്: കൈകാര്യം ചെയ്യലുകൾ പുനരാരംഭത്തിൽ കാലഹരണപ്പെടുന്നു, സ്വതന്ത്ര OmniRoute പ്രോസസുകൾക്കിടയിൽ കൈമാറാൻ കഴിയുന്നില്ല. മാനേജ്മെന്റ് സ്റ്റാറ്റുകൾ ഫലപ്രദമായ നിലനിൽപ്പ്/അകലം നയം പ്രദർശിപ്പിക്കുന്നു, കൂടാതെ സംഗ്രഹിച്ച നിലനിൽപ്പുള്ള എൻട്രികൾ/ബൈറ്റുകൾ മാത്രം, മീഡിയ, റഫറൻസുകൾ, പ്രിൻസിപ്പൽ ഐഡികൾ അല്ലെങ്കിൽ കൈകാര്യം ചെയ്യലുകൾ ഇല്ല. വീഡിയോ ക്രമീകരണ പാനൽ ആ മൂല്യങ്ങൾ കാണിക്കുന്നു, കൂടാതെ consent switches രണ്ടും നിലനിൽക്കാൻ കഴിയും. ഈ നടപ്പിലാക്കൽ ഡോക്യുമെന്റേഷൻ ലൈവ് വിനിയോഗം അല്ലെങ്കിൽ പ്രമോഷൻ തെളിവല്ല; യഥാർത്ഥ മോഡൽ അംഗീകാരം വ്യത്യസ്തമായി ട്രാക്ക് ചെയ്യുന്നു.

ഫ്രെയിംകൾ ക്രമീകരിച്ച വീഡിയോ മോഡലുമായി അനുക്രമമായി ക്യാപ്ഷൻ ചെയ്യപ്പെടുന്നു. ഒരു ശൂന്യമായ വീഡിയോ ഓവർറൈഡ് ദൃശ്യ ക്രമീകരണം പാരമ്പര്യമായി inherits ചെയ്യുന്നു; ഇരുവരും ശൂന്യമായാൽ, ദൃശ്യ ഓട്ടോ-റൂട്ടർ ഫലപ്രദമായ ദൃശ്യ-ശേഷിയുള്ള മോഡൽ തിരഞ്ഞെടുക്കുന്നു. വിജയകരമായ ക്യാപ്ഷനുകൾ സ്ഥിരമായ `[Video description:` പ്രിഫിക്‌സ് ഉപയോഗിച്ച് യഥാർത്ഥ ഭാഗം മാറ്റുന്നു, ഇത് ടെക്സ്റ്റ് ഒരു വിശ്വസിക്കാത്ത മീഡിയ-ഉദ്ഭവ നിരീക്ഷണമായി അടയാളപ്പെടുത്തുകയും, താഴത്തെ മോഡലുകൾക്ക് മീഡിയയിൽ കണ്ടെത്തിയ നിർദ്ദേശങ്ങൾ പിന്തുടരാൻ അനുവദിക്കുകയുമില്ല. ഫ്രെയിം-ക്യാപ്ഷൻ കാഷ് കീകൾ JPEG ബൈറ്റുകൾ, പ്രോംപ്റ്റ്, ടൈംസ്റ്റാമ്പ്, ഫലപ്രദമായ മോഡൽ എന്നിവ ഉൾക്കൊള്ളുന്നു; വിജയകരമായ ക്യാപ്ഷനുകൾ മാത്രം കാഷ് ചെയ്യപ്പെടുന്നു. കാഷ് എൻട്രികൾ യഥാർത്ഥ വിജയകരമായ പ്രൊഡ്യൂസർ മോഡൽ നിലനിര്‍ത്തുന്നു, ഒരു ഫാൾബാക്ക് മോഡൽ ഉൾപ്പെടുന്നു; ബ്രിഡ്ജ് വ്യത്യസ്ത മോഡലുകൾ വ്യത്യസ്ത ഫ്രെയിമുകൾ ഉൽപ്പാദിപ്പിച്ചപ്പോൾ `mixed` റിപ്പോർട്ട് ചെയ്യുന്നു. ഒരു കാഷ് ഹിറ്റ് ആ പ്രൊഡ്യൂസർ ഐഡന്റിറ്റി പുനരുപയോഗിക്കുന്നു, അതിനെ ആവശ്യമായ റൂട്ടിംഗ് പ്ലാൻ എന്ന നിലയിൽ പുനർലേബൽ ചെയ്യുന്നതിന് പകരം. മുഴുവൻ-വീഡിയോ ഫല കാഷ് ഔട്ട്‌പുട്ട് മാറ്റുന്ന ഓരോ ഇൻപുട്ടിലും കീ ചെയ്യുന്നു — പ്രോംപ്റ്റ്, ഫലപ്രദമായ മോഡൽ, സാമ്പിളിംഗ് നയം, ഫ്രെയിം എണ്ണം, സെമാന്റിക് വിശകലന മോഡ്, നോർമലൈസ്ഡ് ഫോകസ് ഹിന്റിന്റെ SHA-256 ഫിംഗർപ്രിന്റ്, ഫോകസ് വിൻഡോ, `transcript`, `audioTranscript`, കൂടാതെ കോൺടാക്റ്റ്-ഷീറ്റ് ഫ്ലാഗ് — അതിനാൽ ആ ഡിമെൻഷനുകളിൽ ഏതെങ്കിലും മാറ്റം ഒരു കാഷ് മിസ് ആണ്, ഒരിക്കലും പഴയ പുനരുപയോഗം അല്ല. ദൃശ്യ ഡിഡ്യൂപ്പ് നയം പതിപ്പ്, ത്രെഷോൾഡ്, കൂടാതെ ബൗണ്ടഡ് കാൻഡിഡേറ്റ്-ഫ്രെയിം എണ്ണം ഫല-കാഷ് കീയും മെറ്റാഡാറ്റയിലും വ്യക്തമാണ്; അതിനാൽ ഒരു നയം മാറ്റം പഴയ മുഴുവൻ-വീഡിയോ വിവരണം പുനരുപയോഗിക്കാൻ കഴിയില്ല. ഫല-കാഷ് v4 മെറ്റാഡാറ്റ മോഡ്, ഫിംഗർപ്രിന്റ് എന്നിവ നിലനിര്‍ത്തുന്നു, ഒരിക്കലും കച്ചവട ഉപയോക്തൃ ടാസ്‌ക് ഇല്ല. ഗാർഡ്‌റെയിൽ മെറ്റാഡാറ്റ ആവശ്യമായതും ഫലപ്രദമായതുമായ വിശകലന മോഡുകൾ റിപ്പോർട്ട് ചെയ്യുന്നു; ഉപയോഗിക്കാവുന്ന ഉപയോക്തൃ ടെക്സ്റ്റ് ഇല്ലാത്ത ആവശ്യമായ `focused` മോഡ് ഫലപ്രദമായ `full` എന്ന നിലയിൽ റിപ്പോർട്ട് ചെയ്യുന്നു.

ഗാർഡ്‌റെയിൽ എല്ലാ പിന്തുണയുള്ള വീഡിയോ ഭാഗങ്ങൾ എടുക്കുന്നു, എന്നാൽ `modalityBridgeVideoMaxVideos` എന്നതിൽ കൂടുതൽ വിവരിക്കുകയില്ല. `supportsVideo === false` എന്നതിൽ തെളിയിച്ച ലക്ഷ്യങ്ങൾ, പരാജയപ്പെട്ടതും അതിരുകൾക്കപ്പുറം ഉള്ള വീഡിയോകൾ വ്യക്തമായ സുരക്ഷിതമായ ടെക്സ്റ്റ് മാർക്കറുകളായി മാറുന്നു, അതിനാൽ ഒരു കച്ചവട വീഡിയോ നിലനിൽക്കുകയില്ല. കഴിവ് അറിയാത്തപ്പോൾ, ആ ഭാഗങ്ങൾ അശ്രദ്ധിതമായി തുടരുന്നു. `supportsVideo === true` ഉള്ള ലക്ഷ്യങ്ങൾ ബ്രിഡ്ജ് മറികടക്കുന്നു. ക്ലയന്റ് അഭ്യർത്ഥന ഉപേക്ഷണ സിഗ്നൽ ഡൗൺലോഡ്, ബ്രോക്കർ ക്യൂ, ഉപപ്രോസസ്സുകൾ, ക്യാപ്ഷൻ വിളികൾ എന്നിവയിലൂടെ പ്രചരിക്കുന്നു; ഉപേക്ഷണങ്ങൾ വീഡിയോകൾക്കിടയിൽ നിർത്തുന്നു, ഒരിക്കലും കച്ചവട മീഡിയയിലേക്ക് തുറക്കുകയില്ല.

റൺടൈം ക്രമീകരണങ്ങൾ DB-ബാക്കഡ് ആണ്, Zod-വാലിഡേറ്റഡ്:

| ----------------------------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `modalityBridgeVideoEnabled`        | `false`     | ഐച്ഛിക റൺടൈം, ഓപ്റ്റ്-ഇൻ                                                                                                       |

120 സെക്കൻഡുകൾക്കു മുകളിൽ നിലനിൽക്കുന്ന പാരമ്പര്യമായ വീഡിയോ ടൈംഔട്ട് മൂല്യങ്ങൾ ബ്രോക്കർ ഡെഡ്‌ലൈൻ വരെ ക്ളാമ്പ് ചെയ്യപ്പെടുന്നു; ആ പരിധിയിൽ പുതിയ ക്രമീകരണങ്ങൾ എഴുതുന്നത് നിരസിക്കപ്പെടുന്നു. `GET /api/modality-bridge/video/runtime` വിശ്വസനീയമായ സ്റ്റാമ്പ് ചെയ്ത ലൂപ്പ്ബാക്ക് ലോക്കാലിറ്റി ആവശ്യമാണ്, അതിന് മുമ്പ് ഓതന്റിക്കേഷൻ അല്ലെങ്കിൽ റൺടൈം പ്രോബിംഗ്, പിന്നീട് മാനേജ്മെന്റ് ഓത്ത് ആവശ്യമാണ്. ഇത് ഫലപ്രദമായ, ശുദ്ധീകരിച്ച FFmpeg/ffprobe പതിപ്പുകൾ മാത്രമേ തിരികെ നൽകുകയുള്ളു, റൺടൈം ലഭ്യമല്ലെങ്കിൽ ഒരു സ്ഥിരമായ കാരണം നൽകുന്നു. ആന്തരിക എക്സ്ട്രാക്ഷൻ എൻഡ്പോയിന്റ് ഒരു പൊതു അപ്‌ലോഡ് API അല്ല: ക്യൂ saturation `503` കൂടാതെ `Retry-After` തിരികെ നൽകുന്നു, ഒരു കോളർ ഡിസ്കണക്ട് `499` നൽകുന്നു, സ്ഥിരമായ ബ്രോക്കർ ഡെഡ്‌ലൈൻ `504` നൽകുന്നു. മാറ്റിയ മറുപടികൾ കേന്ദ്ര `x-omniroute-modality-bridge` ഹെഡറിൽ `video->text;model=<visionModel>;parts=<videos>` ചേർക്കുന്നു, ദൃശ്യ അല്ലെങ്കിൽ ഓഡിയോ സെഗ്മെന്റുകൾ നീക്കം ചെയ്യാതെ.

### PII Masker (`piiMasker.ts`)

**രണ്ടു** ഘട്ടങ്ങളിലും പ്രവർത്തിക്കുന്നു.

- **`preCall`** പേലോഡിനെ ക്ലോൺ ചെയ്യുന്നു, `system`, `messages`, `input`, കൂടാതെ `prompt` (സാധാരണ സ്ട്രിംഗ് ഇനങ്ങൾ ഉൾപ്പെടുന്നു) നടന്നു, `processPII()` ( `@/shared/utils/inputSanitizer` ൽ നിന്ന്) സ്ട്രിംഗ് `content`/`text` ഫീൽഡുകൾക്ക് പ്രയോഗിക്കുന്നു. `PII_REDACTION_ENABLED=true` ആയപ്പോൾ, കണ്ടെത്തിയ PII ഔട്ട്‌ബൗണ്ട് പേലോഡിൽ മൂടുന്നു. ഇത് `INPUT_SANITIZER_MODE` (പ്രോംപ്റ്റ്-ഇൻജക്ഷൻ നയം മാത്രം നിയന്ത്രിക്കുന്നു) നിൽക്കുന്നതിൽ സ്വതന്ത്രമാണ്. മൂടൽ ഇല്ലെങ്കിൽ, വിളി കണ്ടെത്തൽ എണ്ണങ്ങൾ രേഖപ്പെടുത്തുന്നു, ഉള്ളടക്കം പുനരാഖ്യാനം ചെയ്യാതെ.
- **`postCall`** മറുപടി ഡീപ്-ക്ലോൺ ചെയ്യുന്നു, `sanitizePIIResponse()` പ്രവർത്തിപ്പിക്കുന്നു, കൂടാതെ Responses-API-ആകൃതിയുടെ മസ്കർ (`maskResponsesOutput` — `output_text` കൂടാതെ `output[].content[].text` ഉൾക്കൊള്ളുന്നു). ഏതെങ്കിലും മൂടൽ സംഭവിച്ചാൽ, മാറ്റിയ മറുപടി യഥാർത്ഥത്തെ മാറ്റുന്നു.

ഗാർഡ്‌റെയിൽ ഒരിക്കലും തടയുന്നില്ല; ഇത് വെറും കുറിപ്പുകൾ ( `meta.detections`, `meta.redacted`) അല്ലെങ്കിൽ പുനരാഖ്യാനം ചെയ്യുന്നു.

### Prompt Injection (`promptInjection.ts`)

ഉപയോക്താവിന്റെ നൽകുന്ന ഉള്ളടക്കത്തിൽ എതിരാളി ഘടനകൾ കണ്ടെത്തുകയും ക്രമീകരിച്ച നയം നടപ്പിലാക്കുകയും ചെയ്യുന്നു. പെരുമാറ്റം പരിസ്ഥിതി മാറ്റങ്ങൾക്കും നിർമ്മാതാവിന്റെ ഓപ്ഷനുകൾക്കും അനുസൃതമാണ്:

| ക്രമീകരണം          | Env var                                                                                               | ഡിഫോൾട്ട് | ഫലങ്ങൾ                                                                                                                                                                                                                       |
| ------------------ | ----------------------------------------------------------------------------------------------------- | --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| സജീവമായത്          | `INPUT_SANITIZER_ENABLED`                                                                             | `true`    | `false` ആയാൽ, ഗാർഡ്‌റെയിൽ ഷോർട്ട്-സർക്യൂട്ടുകൾ.                                                                                                                                                                              |
| മോഡ്               | `INJECTION_GUARD_MODE` / `INPUT_SANITIZER_MODE`                                                       | `warn`    | ഇൻജക്ഷൻ നയം: `block`, `warn`, അല്ലെങ്കിൽ `log`. (`redact` ബാക്ക്-കമ്പാറ്റിന് സ്വീകരിക്കപ്പെടുന്നു, എന്നാൽ ഇൻജക്ഷൻ ടെക്സ്റ്റ് നീക്കം ചെയ്യുന്നില്ല; അഭ്യർത്ഥന PII പുനരാഖ്യാനം `PII_REDACTION_ENABLED` വഴി നിയന്ത്രിക്കുന്നു.) |
| ബ്ലോക്ക് ത്രെഷോൾഡ് | `blockThreshold` ഓപ്ഷൻ / `INPUT_SANITIZER_BLOCK_THRESHOLD` (അലിയസ് `INJECTION_GUARD_BLOCK_THRESHOLD`) | `high`    | ബ്ലോക്ക് ചെയ്യാൻ ആവശ്യമായ കുറഞ്ഞ ഗുരുത്വം. മധ്യമാണ് ഡിഫോൾട്ടിൽobserve-only.                                                                                                                                                  |

**മോഡ് മുൻഗണന** (`getMode`): caller `options.mode` →
`INJECTION_GUARD_MODE` **DB ഫീച്ചർ-ഫ്ലാഗ് ഓവർറൈഡ്** (ഡാഷ്ബോർഡ് → ക്രമീകരണങ്ങൾ →
ഫീച്ചർ ഫ്ലാഗുകൾ) → `INJECTION_GUARD_MODE` env → `INPUT_SANITIZER_MODE` env →
`warn`. അതിനാൽ, ഒരു ഡാഷ്ബോർഡ് ഓവർറൈഡ് പരിസ്ഥിതി മാറ്റങ്ങൾക്കു മേൽ വിജയിക്കുന്നു, അതിനാൽ ഫീച്ചർ ഫ്ലാഗുകൾ UI പ്രവർത്തന ഗാർഡ് നേരിട്ട് നിയന്ത്രിക്കുന്നു (പുതുക്കൽ ഇല്ല). DB വായന ഫെയിൽ-സേഫ് ആണ്: അത് പിഴവുണ്ടായാൽ, ഗാർഡ് പരിസ്ഥിതി അടിസ്ഥാനത്തിലുള്ള പെരുമാറ്റത്തിലേക്ക് വീഴുന്നു, കൂടാതെ ഒരു ഓവർറൈഡ് സജ്ജമല്ലെങ്കിൽ പെരുമാറ്റം പരിസ്ഥിതി മാത്രം പരിഹാരത്തിന് സമാനമാണ്.

കണ്ടെത്തൽ ഉറവിടങ്ങൾ:

1. `sanitizeRequest()` from `@/shared/utils/inputSanitizer` (pipeline-ൽ മറ്റിടങ്ങളിൽ ഉപയോഗിക്കുന്ന പങ്കുവെച്ച ഡിറ്റക്ടർ സെറ്റ്).
2. ബിൽറ്റ്-ഇൻ `DEFAULT_GUARD_PATTERNS` (ഇപ്പോൾ `system_override_inline` ഉം `markdown_system_block` ഉം, ഇരുവരും `high` ഗുരുത്വം).
3. നിർബന്ധമായ `customPatterns` നിർമ്മാതാവിന്റെ ഓപ്ഷനുകൾ വഴി നൽകുന്നു (സ്ട്രിംഗുകൾ, regex, അല്ലെങ്കിൽ `{ name, pattern, severity }` റെക്കോർഡുകൾ).

`mode === "block"` **മറ്റു** കുറഞ്ഞത് ഒരു കണ്ടെത്തൽ ഗുരുത്വ ത്രെഷോൾഡ് നിറവേറ്റുമ്പോൾ, `preCall` `{ block: true, message: "Request rejected: suspicious content detected" }` തിരികെ നൽകുന്നു. `warn`/`log` മോഡുകളിൽ ഗാർഡ്‌റെയിൽ ലോഗ് ചെയ്യുന്നു, എന്നാൽ വിളി അനുവദിക്കുന്നു. പങ്കുവെച്ച സഹായി `evaluatePromptInjection()` ആവശ്യമായ വിളിക്കാർക്കായി പ്രൊംപ്റ്റുകൾ വിലയിരുത്താൻ എക്സ്പോർട്ട് ചെയ്യുന്നു, രജിസ്ട്രിയിൽ നിന്ന് കടന്നുപോകാതെ.

**സ്കാൻ ബൗണ്ട് (v3.8.20):** ഡിറ്റക്ടർ **ആദ്യ 16 KB** ചേർന്ന പ്രൊംപ്റ്റ് ടെക്സ്റ്റ് പരിശോധിക്കുന്നു — `MAX_INJECTION_SCAN_BYTES = 16 * 1024` (16 384 ബൈറ്റുകൾ) `src/shared/utils/inputSanitizer.ts` ൽ. `detectInjection()` ഉം `evaluatePromptInjection()` ഉം `slice(0, MAX_INJECTION_SCAN_BYTES)` നടത്തുന്നതിന് മുമ്പ് പാറ്റേൺ ലൂപ്പിൽ. ഇൻജക്ഷൻ ഡയറക്ടീവ്‌കൾ ഒരു ഇൻപുട്ടിന്റെ മുകളിൽ ഇരിക്കുന്നു, അതിനാൽ ഇത് മൾട്ടി-ഹണ്ട്രഡ്-KB പേലോഡുകളിൽ regex CPU/GC നെ ക്യാപ് ചെയ്യുന്നു, കണ്ടെത്തലിനെ ദുർബലമാക്കാതെ (cf. #3932, #4041).

### ക്രെഡൻഷ്യൽ മാസ്കർ (`credentialMasker.ts`)

**രണ്ടു** ഘട്ടങ്ങളിലും പ്രവർത്തിക്കുന്നു, ഡിഫോൾട്ട് ചെയിനിൽ അവസാനത്തേയ്ക്ക് (പ്രാധാന്യം `95`). ഔട്ട്‌ബൗണ്ട് പേലോഡിൽ (സന്ദേശം ഉള്ളടക്കം, ടൂൾ-കാൾ ആർഗ്യുമെന്റുകൾ, ടൂൾ ഫലങ്ങൾ) അറിയപ്പെടുന്ന API-കീ / രഹസ്യ-ടോക്കൺ പാറ്റേൺ മായ്ക്കുന്നു **മറ്റു** പ്രൊവൈഡർ പ്രതികരണവും, അതിനാൽ പ്രൊംപ്റ്റിൽ പെയ്സ്റ്റ് ചെയ്ത ഒരു ക്രെഡൻഷ്യൽ (അല്ലെങ്കിൽ ഒരു ടൂൾ ഫലത്തിലൂടെ തിരിച്ചറിയപ്പെടുന്ന) മുകളിൽ പ്രൊവൈഡറിലേക്കോ ക്ലയന്റിലേക്കോ ചോർന്നുപോകുന്നില്ല.

- **ഓപ്റ്റ്-ഇൻ മാത്രം**, PII മായ്ക്കലിന്റെ സമാനമായ നിയമം (Hard Rule #20-അടുത്തത്): `settings.credentialRedactionEnabled === true` **അല്ലെങ്കിൽ** `CREDENTIAL_REDACTION_ENABLED=true` ഇല്ലാതെ അപ്രാപ്തമാക്കുന്നു. ഇത് ഓഫ് ആയാൽ, ഗാർഡ്‌റെയിൽ ഒരു നോ-ഓപ്പ് ആണ് — ഇത് ഒരിക്കലും ബ്ലോക്ക് ചെയ്യുകയോ പുനരാഖ്യാനം ചെയ്യുകയോ ചെയ്യില്ല.
- `redactCredentials()` മുഴുവൻ പേലോഡ്/പ്രതികരണ മരച്ചീനി നടന്നു (`walkValue()`, പ്രോട്ടോടൈപ്പ്-പോള്യൂഷൻ-സേഫ്, സൈക്കിൾ-സേഫ് `WeakSet` വഴി) കൂടാതെ മാറ്റങ്ങൾ `[REDACTED:<type>]` പ്ലേസ്‌ഹോൾഡറുമായി മാറ്റുന്നു, യഥാർത്ഥത്തിൽ മാറ്റം വന്ന ശാഖകൾ മാത്രം ക്ലോൺ ചെയ്യുന്നു.
- `CREDENTIAL_PATTERNS` LLM പ്രൊവൈഡർ കീകൾ (OpenAI, OpenAI-proj, Anthropic, Google, Hugging Face, Replicate), VCS/SaaS ടോക്കൺ (GitHub, Slack, Linear, Notion, npm, Postman, Discord), പേയ്മെന്റ് കീകൾ (Stripe, Square), ക്ലൗഡ് കീകൾ (AWS access key, Twilio, SendGrid, Mailgun), സ്വകാര്യ കീകൾ / JWTs, ക്രെഡൻഷ്യൽ-കണ്ടക്ഷൻ സ്ട്രിംഗ്‌ ( `mongodb://user:pass@...`, മുതലായവ), കൂടാതെ ഒരു ജനറിക് `Authorization`/`x-api-key`/`api-key`/`apikey` ഹെഡർ-വാല്യു പാറ്റേൺ. ഹെഡർ-ആകൃതിയിലുള്ള കീകൾ (`authorization`, `x-api-key`, `api-key`, `apikey`) ഘടനാപരമായി മായ്ക്കുന്നു (വാല്യു മാത്രം, സ്കീം പ്രിഫിക്സ് പോലുള്ള `Bearer `/`Basic ` സംരക്ഷിതമാണ്) ജനറിക് ടെക്സ്റ്റ് regex വഴി അല്ല.
- ഗാർഡ്‌റെയിൽ ഒരിക്കലും ബ്ലോക്ക് ചെയ്യുകയില്ല; ഇത് മാത്രം പുനരാഖ്യാനം ചെയ്യുന്നു (`modifiedPayload` / `modifiedResponse`) കൂടാതെ അടയാളപ്പെടുത്തുന്നു (`meta.credentialsRedacted`, `meta.count`).

റിഗ്രഷൻ ഗാർഡ്: `tests/unit/credential-masker-guardrail.test.ts`.

## അടിസ്ഥാന കരാർ (base.ts)

```typescript
class BaseGuardrail {
  enabled: boolean;
  name: string;
  priority: number;

  constructor(name: string, options?: { enabled?: boolean; priority?: number });

  async preCall(payload: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;

  async postCall(response: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;
}

interface GuardrailResult<TValue = unknown> {
  block?: boolean; // true short-circuits the chain
  message?: string; // തടയുമ്പോൾ ഇത് ദൃശ്യമാകും
  meta?: Record<string, unknown> | null;
  modifiedPayload?: TValue; // അഭ്യർത്ഥന മാറ്റിയെഴുതാൻ preCall തിരികെ നൽകുന്നത്
  modifiedResponse?: TValue; // പ്രതികരണം മാറ്റിയെഴുതാൻ postCall തിരികെ നൽകുന്നത്
}

interface GuardrailContext {
  apiKeyInfo?: Record<string, unknown> | null;
  disabledGuardrails?: string[] | null;
  endpoint?: string | null;
  headers?: Headers | Record<string, unknown> | null;
  log?: GuardrailLog | Console | null;
  method?: string | null;
  model?: string | null;
  provider?: string | null;
  signal?: AbortSignal;
  sourceFormat?: string | null;
  stream?: boolean;
  targetFormat?: string | null;
}
```

ഒരു ഗാർഡ്റെയിൽ "മാറ്റമില്ല" എന്ന് സൂചിപ്പിക്കുന്നത് ``void`, `{}`, അല്ലെങ്കിൽ `{ block: false }`തിരികെ നൽകിക്കൊണ്ടാണ്.`modifiedPayload`/`modifiedResponse`തിരികെ നൽകുന്നത്, താഴെയുള്ള ഗാർഡ്റെയിലുകൾക്കായി ചെയിനിലൂടെ ഒഴുകുന്ന മൂല്യത്തെ മാറ്റിസ്ഥാപിക്കുന്നു.`signal?: AbortSignal` കോളർ ലൈഫ്സൈക്കിളിനെ ഗാർഡ്റെയിലുകളിലേക്ക് എത്തിക്കുന്നു. ഒരു അഭ്യർത്ഥന റദ്ദാക്കൽ എന്നത് മനഃപൂർവമായ ഒരു ഫെയിൽ-ഓപ്പൺ അപവാദമാണ്: മീഡിയ ബ്രിഡ്ജുകൾ പ്രവർത്തിക്കുന്നത് നിർത്തുകയും, അസംസ്കൃത മീഡിയയെ പിന്തുണയ്ക്കാത്ത ഒരു ലക്ഷ്യസ്ഥാനത്തേക്ക് പുനഃസ്ഥാപിക്കാതെ വൃത്തിയാക്കുകയും ചെയ്യുന്നു.

## രജിസ്ട്രി (registry.ts)

സിംഗിൾട്ടൺ `guardrailRegistry` താഴെ പറയുന്നവ നൽകുന്നു:

- `register(guardrail)` — ഒരു ഗാർഡ്റെയിൽ ചേർക്കുന്നു (അല്ലെങ്കിൽ സാധാരണമാക്കിയ പേര് ഉപയോഗിച്ച് മാറ്റിസ്ഥാപിക്കുന്നു) കൂടാതെ ആരോഹണ ക്രമത്തിൽ `priority` അനുസരിച്ച് വീണ്ടും ക്രമീകരിക്കുന്നു.
- `clear()` / `list()` — അഡ്മിനിസ്ട്രേറ്റീവ് സഹായികൾ.
- `runPreCallHooks(payload, context)` — സജീവ ഗാർഡ്റെയിലുകളിലൂടെ ആവർത്തിക്കുന്നു, `modifiedPayload` വഴി പേലോഡിനെ കടത്തിവിടുന്നു, കൂടാതെ ആദ്യത്തെ `block: true` വരുമ്പോൾ നിർത്തുന്നു.
- `runPostCallHooks(response, context)` — പ്രതികരണ ഭാഗത്തും ഇതേ പ്രവാഹം.
- `resetGuardrailsForTests({ registerDefaults })` — നിലവിലെ അവസ്ഥ മായ്ക്കുന്നു കൂടാതെ വൃത്തിയുള്ള ടെസ്റ്റ് ഐസൊലേഷനായി ഡിഫോൾട്ടുകൾ ഓപ്ഷണലായി വീണ്ടും രജിസ്റ്റർ ചെയ്യുന്നു.

രണ്ട് റണ്ണറുകളും `{ blocked, payload|response, results, guardrail?, message? }` തിരികെ നൽകുന്നു, ഇവിടെ `results` എന്നത് `GuardrailExecutionResult` റെക്കോർഡുകളുടെ ഒരു നിരയാണ്, അതിൽ ഓരോ ഗാർഡ്റെയിലിനുമുള്ള `blocked`, `skipped`, `modified`, `error`, `meta` ഫീൽഡുകൾ ഉൾപ്പെടുന്നു, ഇത് ട്രേസിംഗിന് ഉപയോഗപ്രദമാണ്.

### ഓരോ അഭ്യർത്ഥനയ്ക്കും ഗാർഡ്റെയിലുകൾ പ്രവർത്തനരഹിതമാക്കുന്നു

`resolveDisabledGuardrails({ apiKeyInfo, body, headers })` നിലവിലെ അഭ്യർത്ഥനയ്ക്കായി ഒഴിവാക്കേണ്ട ഗാർഡ്റെയിൽ പേരുകളുടെ ഡ്യൂപ്ലിക്കേഷൻ ഒഴിവാക്കിയ ഒരു ലിസ്റ്റ് ശേഖരിക്കുന്നു. ഉറവിടങ്ങൾ (എല്ലാം ഓപ്ഷണൽ, എല്ലാം ലയിപ്പിച്ചത്):

- `apiKeyInfo.disabledGuardrails`
- അഭ്യർത്ഥന ബോഡി `disabledGuardrails` (ടോപ്പ്-ലെവൽ)
- അഭ്യർത്ഥന ബോഡി `metadata.disabledGuardrails`
- ഹെഡർ `x-omniroute-disabled-guardrails` (അല്ലെങ്കിൽ പഴയ `x-disabled-guardrails`)

മൂല്യങ്ങൾ സ്ട്രിംഗുകളുടെ നിരകളോ കോമയാൽ വേർതിരിച്ച സ്ട്രിംഗോ ആകാം; പേരുകൾ ലോവർകേസ് കെബാബ്-കേസിലേക്ക് സാധാരണമാക്കുന്നു (`pii_masker` → `pii-masker`). ഫലം `context.disabledGuardrails` വഴി രജിസ്ട്രിയിലേക്ക് കൈമാറുന്നു, ഇത് പൊരുത്തപ്പെടുന്ന ഗാർഡ്റെയിലുകളെ ഒഴിവാക്കുന്നു (`results`-ൽ `skipped: true`).

## എക്സിക്യൂഷൻ ഓർഡർ

`src/sse/handlers/chat.ts`, `open-sse/handlers/chatCore.ts` എന്നിവയിലൂടെ ഒഴുകുന്ന ഓരോ അഭ്യർത്ഥനയ്ക്കും:

1. `resolveDisabledGuardrails(...)` API കീ, ബോഡി, ഹെഡറുകൾ എന്നിവയിൽ നിന്ന് സ്കിപ്പ് ലിസ്റ്റ് നിർമ്മിക്കുന്നു.
2. `guardrailRegistry.runPreCallHooks(body, ctx)` ഗാർഡ്റെയിലുകൾ ആരോഹണ മുൻഗണനാ ക്രമത്തിൽ പ്രവർത്തിപ്പിക്കുന്നു:
   - പ്രവർത്തനരഹിതമാക്കിയ ഗാർഡ്റെയിലുകൾ `skipped` എന്ന് രേഖപ്പെടുത്തുന്നു.
   - ഓരോ ഗാർഡ്റെയിലിന്റെയും `preCall` `modifiedPayload` വഴി പേലോഡ് മാറ്റിയെഴുതിയേക്കാം.
   - ആദ്യത്തെ `block: true` ചെയിൻ ചുരുക്കുകയും ഹാൻഡ്ലർ ഒരു ഗാർഡ്റെയിൽ നിരസിക്കൽ പ്രതികരണം നൽകുകയും ചെയ്യുന്നു.
3. (സാധ്യതയുള്ള മാറ്റിയെഴുതിയ) പേലോഡ് കോംബോ റൂട്ടിംഗിലേക്കും അപ്സ്ട്രീം ഡിസ്പാച്ചിലേക്കും ഒഴുകുന്നു.
4. പ്രതികരണം കൂട്ടിച്ചേർത്ത ശേഷം, `guardrailRegistry.runPostCallHooks(...)` പ്രതികരണത്തിൽ അതേ ചെയിൻ പ്രവർത്തിപ്പിക്കുന്നു. ഇവിടെ `block: true` അപ്സ്ട്രീം പ്രതികരണം ഒഴിവാക്കുന്നു.

തെറ്റ് വരുത്തുന്ന ഗാർഡ്റെയിലുകൾ `error: <message>` എന്ന് രേഖപ്പെടുത്തുകയും `logger.warn` വഴി ലോഗ് ചെയ്യുകയും ചെയ്യുന്നു, പക്ഷേ ചെയിൻ തുടരുന്നു — രൂപകൽപ്പന പ്രകാരം ഫെയിൽ-ഓപ്പൺ.

## കോൺഫിഗറേഷൻ

ബിൽറ്റ്-ഇൻ ഗാർഡ്റെയിലുകൾ വായിക്കുന്ന എൻവയോൺമെന്റ് വേരിയബിളുകൾ:

| വേരിയബിൾ                              | ഉപയോഗിക്കുന്നത്           | പ്രഭാവം                                                                                                             |
| ------------------------------------- | ------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `INPUT_SANITIZER_ENABLED`             | `prompt-injection`        | കണ്ടെത്തൽ പൂർണ്ണമായും പ്രവർത്തനരഹിതമാക്കാൻ `false` എന്ന് സജ്ജമാക്കുക.                                               |
| `INPUT_SANITIZER_MODE`                | `prompt-injection`        | ഇൻജക്ഷൻ പോളിസി: `warn`, `block`, അല്ലെങ്കിൽ `log`. പഴയ മൂല്യം `redact` ഇൻജക്ഷൻ ടെക്സ്റ്റ് മാറ്റിയെഴുതുന്നില്ല.      |
| `INJECTION_GUARD_MODE`                | `prompt-injection`        | ഇൻജക്ഷൻ ഗാർഡിനായുള്ള മോഡ്; എൻവയോൺമെന്റ് വേരിയബിളുകളെ **അസാധുവാക്കുന്ന** ഒരു DB ഫീച്ചർ ഫ്ലാഗ് കൂടിയാണിത് (DB > ENV). |
| `INPUT_SANITIZER_BLOCK_THRESHOLD`     | `prompt-injection`        | `MODE=block` നിരസിക്കുന്ന ഏറ്റവും കുറഞ്ഞ തീവ്രത: `high` (സ്ഥിരസ്ഥിതി), `medium`, അല്ലെങ്കിൽ `low`.                  |
| `INJECTION_GUARD_BLOCK_THRESHOLD`     | `prompt-injection`        | `INPUT_SANITIZER_BLOCK_THRESHOLD` എന്നതിന്റെ പഴയ പേര്.                                                              |
| `PII_REDACTION_ENABLED`               | `pii-masker`              | `true` ആയിരിക്കുമ്പോൾ, അഭ്യർത്ഥന PII റെഡാക്ട് ചെയ്യപ്പെടുന്നു (ഇൻജക്ഷൻ മോഡിൽ നിന്ന് സ്വതന്ത്രമായി).                 |
| `PII_RESPONSE_SANITIZATION` / `_MODE` | `pii-masker` (ഡൗൺസ്ട്രീം) | പ്രതികരണ-വശത്തുള്ള മാസ്കർ സ്വഭാവം നിയന്ത്രിക്കുന്നു.                                                                |

മോഡാലിറ്റി ബ്രിഡ്ജ് ഗാർഡ്റെയിലുകൾ DB-ബാക്ക്ഡ് സെറ്റിംഗ്സ് സ്റ്റോറിൽ നിന്ന് (`getSettings()`) റൺടൈം കോൺഫിഗറേഷൻ വായിക്കുന്നു, എൻവയോൺമെന്റ് വേരിയബിളുകളിൽ നിന്നല്ല. വിഷന്റെ പ്രാഥമിക കീകൾ `modalityBridgeVisionEnabled`, `modalityBridgeVisionMode`, `modalityBridgeVisionModel`, `modalityBridgeVisionTaskAware`, `modalityBridgeVisionPrompt`, `modalityBridgeVisionTimeout`, `modalityBridgeVisionMaxImages`, `modalityBridgeVisionMaxChars`, `modalityBridgeCacheEnabled`, `modalityBridgeCacheTtlMinutes`, `modalityBridgeCacheMaxEntries` എന്നിവയാണ്. പഴയ `visionBridge*` കീകൾ ഡോക്യുമെന്റ് ചെയ്ത വൺ-സൈക്കിൾ റീഡ് ഫാൾബാക്കായി മാത്രമേ സ്വീകരിക്കുകയുള്ളൂ; ഡാഷ്ബോർഡ് റൈറ്റുകൾ പ്രാഥമിക കീകൾ ഉപയോഗിക്കുന്നു. സ്ഥിരസ്ഥിതികളും ഫാൾബാക്ക് റെസല്യൂവറും `src/shared/constants/modalityBridgeDefaults.ts` എന്നതിലാണ്, പഴയ സ്ഥിരാങ്കങ്ങൾ `src/shared/constants/visionBridgeDefaults.ts` എന്നതിൽ നിലനിർത്തുന്നു.

ഓഡിയോ `modalityBridgeAudioEnabled`, `modalityBridgeAudioModel`, `modalityBridgeAudioTimeout`, `modalityBridgeAudioMaxClips` എന്നിവയും പങ്കിട്ട `modalityBridgeCache*` ക്രമീകരണങ്ങളും ഉപയോഗിക്കുന്നു. മോഡാലിറ്റി ബ്രിഡ്ജ് സ്കീമയോടൊപ്പം ഈ കീകൾ അവതരിപ്പിച്ചതിനാൽ ഓഡിയോയ്ക്ക് പഴയ-കീ ഫാൾബാക്ക് ഇല്ല.

വീഡിയോ `modalityBridgeVideoEnabled`, `modalityBridgeVideoAnalysisMode`, `modalityBridgeVideoModel`, `modalityBridgeVideoFrameCount`, `modalityBridgeVideoSamplingPolicy`, `modalityBridgeVideoMaxVideos`, `modalityBridgeVideoTimeout` എന്നിവയും പങ്കിട്ട `modalityBridgeCache*` ക്രമീകരണങ്ങളും ഉപയോഗിക്കുന്നു. FFmpeg/ffprobe ഓപ്ഷണൽ ഓപ്പറേഷണൽ ഡിപൻഡൻസികളും ഫ്രെയിം ക്യാപ്ഷനിംഗ് ലേറ്റൻസിയും മോഡൽ ചെലവും വർദ്ധിപ്പിക്കുന്നതിനാൽ ഇത് സ്ഥിരസ്ഥിതിയായി പ്രവർത്തനരഹിതമാക്കിയിരിക്കുന്നു.

## കസ്റ്റം ഗാർഡ്റെയിലുകൾ

```typescript
import { BaseGuardrail, guardrailRegistry } from "@/lib/guardrails";

class BudgetGuardrail extends BaseGuardrail {
  constructor() {
    super("budget", { priority: 50 });
  }

  async preCall(payload, ctx) {
    if (ctx.apiKeyInfo?.budgetExceeded) {
      return { block: true, message: "Daily budget exceeded" };
    }
    return { block: false };
  }
}

guardrailRegistry.register(new BudgetGuardrail());
```

ഘട്ടങ്ങൾ:

1.  `BaseGuardrail` വികസിപ്പിച്ച് `src/lib/guardrails/myGuardrail.ts` ഉണ്ടാക്കുക.
2.  `preCall`, `postCall` എന്നിവ നടപ്പിലാക്കുക.
3.  ഇറക്കുമതി ചെയ്യുന്ന സമയത്ത് ( `registerDefaultGuardrails` ൽ നിന്ന് പുഷ് ചെയ്യുക) അല്ലെങ്കിൽ റൺടൈമിൽ `guardrailRegistry.register(...)` വിളിക്കുക — രജിസ്ട്രി, അതേ സാധാരണവൽക്കരിച്ച പേരുള്ള മുൻ ഗാർഡ്റെയിലിനെ മാറ്റിസ്ഥാപിക്കും.
4.  `tests/unit/` ന് കീഴിൽ ടെസ്റ്റുകൾ ചേർക്കുക (നിലവിലുള്ള ഉദാഹരണങ്ങൾ: `tests/unit/guardrails-registry.test.ts`, `tests/unit/prompt-injection-guard.test.ts`, `tests/unit/guardrails/visionBridge.test.ts`).

## പരിശോധന

അറിയപ്പെടുന്ന അവസ്ഥയിൽ നിന്ന് ആരംഭിക്കാൻ ടെസ്റ്റുകൾക്കിടയിൽ `resetGuardrailsForTests()` ഉപയോഗിക്കുക. ശൂന്യമായ ഒരു രജിസ്ട്രിയിൽ നിന്ന് ആരംഭിച്ച്, പരിശോധനയിലുള്ള ഗാർഡ്റെയിലുകൾ മാത്രം രജിസ്റ്റർ ചെയ്യാൻ `{ registerDefaults: false }` നൽകുക. വിഷൻ ബ്രിഡ്ജ് ഡിപൻഡൻസി ഇൻജക്ഷൻ (`deps.getSettings`, `deps.callVisionModel`) സ്വീകരിക്കുന്നു; ഓഡിയോ ബ്രിഡ്ജ് ക്രമീകരണങ്ങൾ, കഴിവുകൾ, STT മോഡൽ തിരഞ്ഞെടുക്കൽ, ക്രെഡൻഷ്യൽ പരിശോധനകൾ, ട്രാൻസ്ക്രിപ്ഷൻ എന്നിവയ്ക്കായി സമാനമായ സീമുകൾ നൽകുന്നു. അതിനാൽ, ഡാറ്റാബേസ് അല്ലെങ്കിൽ നെറ്റ്വർക്ക് ആക്സസ് ഇല്ലാതെ തന്നെ ടെസ്റ്റുകൾക്ക് രണ്ട് ഫ്ലോകളും പ്രവർത്തിപ്പിക്കാൻ കഴിയും.

- `src/shared/utils/inputSanitizer.ts` — പ്രോംപ്റ്റ്-ഇൻജക്ഷനും PII മാസ്കിംഗും പ്രവർത്തിപ്പിക്കുന്ന പങ്കിട്ട ഡിറ്റക്ടർ
- `src/shared/constants/visionBridgeDefaults.ts` — വിഷൻ ബ്രിഡ്ജ് ഡിഫോൾട്ടുകളും നിർബന്ധിത-ബ്രിഡ്ജ് മോഡൽ ലിസ്റ്റും
- `src/shared/constants/modalityBridgeDefaults.ts` — പങ്കിട്ട വിഷൻ/ഓഡിയോ റൺടൈം ഡിഫോൾട്ടുകൾ
- `docs/architecture/RESILIENCE_GUIDE.md` — ഓർത്തോഗണൽ ലെയർ (സർക്യൂട്ട് ബ്രേക്കർ, കൂൾഡൗണുകൾ)
- `docs/reference/ENVIRONMENT.md` — പൂർണ്ണമായ എൻവയോൺമെന്റ് വേരിയബിൾ റെഫറൻസ്

## ഇൻജക്ഷൻ-ഗാർഡ് റൂട്ട് കവറേജ് & റെഡ്-ടീം (ഘട്ടം 8 · ബ്ലോക്ക് D)

ഇൻജക്ഷൻ-ഗാർഡ് (`createInjectionGuard` / `withInjectionGuard`) ഉപയോക്തൃ പ്രോംപ്റ്റുകൾ സ്വീകരിക്കുന്ന എല്ലാ റൂട്ടുകളെയും ഉൾക്കൊള്ളുന്നു. ഇത് `INJECTION_GUARD_MODE` നെ മാനിക്കുന്നു (സ്ഥിരസ്ഥിതി `warn` = ലോഗ് മാത്രം; `block` = HTTP 400 `SECURITY_001` തിരികെ നൽകുന്നു).

| തരം             | റൂട്ടുകൾ                                                                                                                                      | സ്ഥിരസ്ഥിതി മോഡ് |
| :-------------- | :-------------------------------------------------------------------------------------------------------------------------------------------- | :--------------- |
| Text (existing) | `/v1/chat/completions`, `/v1/completions`, `/v1/relay/chat/completions`                                                                       | warn             |
| Generative      | `/v1/messages`, `/v1/responses`, `/v1/images/generations`, `/v1/edits`, `/v1/videos/generations`, `/v1/music/generations`, `/v1/audio/speech` | warn             |
| Data            | `/v1/embeddings`, `/v1/rerank`, `/v1/search`, `/v1/moderations`                                                                               | warn             |

ടെക്സ്റ്റ് എക്സ്ട്രാക്ഷൻ (`extractMessageContents`) `messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system` എന്നിവയെ ഉൾക്കൊള്ളുന്നു.

**റെഡ്-ടീം (രാത്രികാല, `nightly-llm-security.yml`):** `INJECTION_GUARD_MODE=block` ആയിരിക്കുമ്പോൾ ഓരോ റൂട്ടും OWASP-LLM കോർപ്പസിനെ തടയുന്നുവെന്ന് promptfoo സാധൂകരിക്കുന്നു; garak പ്രോബുകൾ പ്രവർത്തിപ്പിക്കുന്നു (രഹസ്യമില്ലാതെ ഒഴിവാക്കുന്നു). സ്ഥിരതയ്ക്കായി `moderations` ഉൾപ്പെടുത്തിയിട്ടുണ്ട് — ബ്ലോക്ക്-മോഡിലുള്ള ഓപ്പറേറ്റർമാർക്ക് `resolveDisabledGuardrails` വഴി ഇതിനെ ഒഴിവാക്കാം.

രാത്രികാല വർക്ക്ഫ്ലോ (`.github/workflows/nightly-llm-security.yml`, cron + മാനുവൽ ഡിസ്പാച്ച്) ന് രണ്ട് ജോലികളുണ്ട്:

- **`promptfoo-guard` (തടയുന്നത്)** — `INJECTION_GUARD_MODE=block` ഉപയോഗിച്ച് `promptfoo eval -c promptfooconfig.yaml` പ്രവർത്തിപ്പിക്കുന്നു. ഓരോ പ്രതികൂല സാഹചര്യവും (ഉദാഹരണത്തിന്, "മുമ്പത്തെ എല്ലാ നിർദ്ദേശങ്ങളും അവഗണിക്കുക...", DAN-ശൈലിയിലുള്ള ജയിൽബ്രേക്കുകൾ) പ്രതികരണത്തിൽ `error.code === "SECURITY_001"` ഉണ്ടെന്ന് ഉറപ്പാക്കുന്നു, അതായത് ഗാർഡ് യഥാർത്ഥത്തിൽ അഭ്യർത്ഥന നിരസിച്ചു.
- **`garak` (ഉപദേശക)** — ഒരു പ്രാദേശിക OmniRoute ഇൻസ്റ്റൻസിനെതിരെ (`http://localhost:20128/v1`) garak `--probes promptinject,dan,leakreplay` പ്രവർത്തിപ്പിക്കുന്നു. ഒരു പ്രൊവൈഡർ രഹസ്യം (`PROMPTFOO_PROVIDER_KEY`) വഴി നിയന്ത്രിക്കപ്പെടുന്നു; ഇത് ഭംഗിയായി ഒഴിവാക്കുകയും `|| true` എന്ന് ചേർക്കുകയും ചെയ്യുന്നു, അതിനാൽ CI പരാജയപ്പെടാതെ റിപ്പോർട്ട് ചെയ്യുന്നു.

ഗാർഡ് ഹെൽപ്പറിന്റെ (`createInjectionGuard` / `withInjectionGuard`) കവറേജ് എല്ലാ പ്രോംപ്റ്റ്-ഉൾക്കൊള്ളുന്ന `/v1` റൂട്ടുകളിലും വ്യാപിക്കുന്നു; പ്രോംപ്റ്റ് ടെക്സ്റ്റ് `src/shared/utils/inputSanitizer.ts` ലെ `extractMessageContents()` വഴി `messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system` എന്നിവയിൽ നിന്ന് വലിച്ചെടുക്കുന്നു.
