> **সর্বশেষ হালনাগাদ:** 2026-08-29 — v3.8.51 (Video Bridge ট্রান্সক্রিপ্টের উৎস কলকারী কর্তৃক ঘোষিত,
> এখনও সার্ভার দ্বারা যাচাইকৃত নয় — #11661 অনুযায়ী স্পষ্ট করা হয়েছে)

Guardrail-গুলো OmniRoute ও upstream provider-গুলোর মধ্যবর্তী সীমানায় নিরাপত্তা, নীতি এবং কনটেন্ট রূপান্তর বলবৎ করে। প্রতিটি guardrail request payload (`preCall`) এবং upstream response (`postCall`) পরিদর্শন করতে পারে (এবং ঐচ্ছিকভাবে প্রত্যাখ্যান, রূপান্তর বা টীকা যোগ করতে পারে)।

সিস্টেমটি **fail-open**: কোনো guardrail নির্বাহের সময় exception ছুড়লে, registry ত্রুটিটি রেকর্ড করে এবং request ব্যর্থ না করে পরবর্তী guardrail-এ অগ্রসর হয়। Blocking সর্বদা একটি সুস্পষ্ট সিদ্ধান্ত (`block: true`), কখনোই দুর্ঘটনাবশত নয়।

### ভিশন ব্রিজ (`visionBridge.ts`) — মডালিটি ব্রিজ PR-1

**অদৃশ্য মডেলগুলির** উদ্দেশ্যে চিত্র বহনকারী অনুরোধগুলি আটকায় এবং পুরো অনুরোধটিকে একটি ভিশন-সক্ষম মডেলে পুনঃনির্দেশ করে অথবা চিত্রের অংশগুলি একটি কনফিগারযোগ্য ভিশন মডেল দ্বারা উত্পাদিত টেক্সট বর্ণনাগুলির সাথে প্রতিস্থাপন করে উপরের কলের আগে। এটি টেক্সট-শুধু প্রদানকারীদের মাল্টিমোডাল পে-লোডগুলি স্বচ্ছভাবে পরিচালনা করতে দেয়।

প্রবাহ:

1. লক্ষ্য মডেল ইতিমধ্যেই ভিশন সমর্থন করে থাকলে বাদ দিন (যদি এটি জোরপূর্বক-ব্রিজ তালিকায় `isVisionBridgeForcedModel` উপস্থিত না থাকে)।
2. `extractImageParts(messages)` এর মাধ্যমে চিত্রের অংশগুলি বের করুন
   (`visionBridgeHelpers.ts`), যা **একক মিডিয়া ডিটেক্টর** `detectMediaParts()` কে `open-sse/utils/mediaParts.ts` এ ডেলিগেট করে — এটি কম্বো সামঞ্জস্য ফিল্টারের সাথে শেয়ার করা সত্যের একক উৎস।
   নিষ্কাশনটি `replaceImageParts` দ্বারা পুনঃস্থাপনযোগ্য শেপগুলির শীর্ষ স্তরের অংশগুলিতে অনুমোদিত: OpenAI `image_url`, Anthropic base64 `source.type:"base64"`, Anthropic URL `source.type:"url"`, এবং Responses API `input_image`। নেস্টেড হিট এবং সূচক-শুধু শেপগুলি কম্বো-ফিল্টার উপাদান এবং কখনও নিষ্কাশিত হয় না। কিছু পাওয়া না গেলে বাদ দিন।
3. `resolveVisionBridgeRuntimeSettings()` এর মাধ্যমে রানটাইম কনফিগারেশন সমাধান করুন
   (`src/shared/constants/modalityBridgeDefaults.ts`): নতুন `modalityBridge*`
   সেটিংস কী জিতবে; পুরানো `visionBridge*` কী একটি **এক-চক্রের ব্যাকফল** (রোলব্যাক উইন্ডো) হিসাবে থাকবে। ব্রিজ নিষ্ক্রিয় হলে কোনও মিডিয়া ট্রাভার্সালের আগে বাদ দিন।
4. মোড সিলেক্টর (`modalityBridgeVisionMode`, নিচের টেবিল দেখুন) পুনঃনির্দেশ বনাম বর্ণনা নির্ধারণ করে। পুনঃনির্দেশ `modifiedPayload` ফেরত দেয় যেখানে শুধুমাত্র `model` পরিবর্তিত হয়, প্লাস মেটা `{ rerouted, fromModel, toModel, imagesKept }`।
5. বর্ণনা পথ: চিত্রগুলি `maxImages` এ সীমাবদ্ধ করুন, কাজ-সচেতন প্রম্পট তৈরি করুন,
   বর্ণনা ক্যাশে পরামর্শ করুন, ভিশন মডেলকে **প্যারালেলে** কল করুন
   (`Promise.allSettled`), এবং তাদের স্থানে `[Image N]: <description>` টেক্সট অংশগুলি ইনজেক্ট করুন। একটি ব্যর্থ বর্ণনা `null` প্রদান করে এবং মূল চিত্র অংশটি **সংরক্ষিত** থাকে (#4012) — কম্বো বর্ণনা পথের ব্যতিক্রমে যখন প্রতিটি বর্ণনা ব্যর্থ হয়, যেখানে একটি নিশ্চিত অদৃশ্য উপরের `(unavailable — no vision-capable provider connected)` স্টাব পায় (#8430)।
6. `modifiedPayload` + মেটা (`imagesProcessed`, `descriptions`,
   `processingTimeMs`, `visionModel`) ফেরত দিন।

#### মোড সিলেক্টর (`modalityBridgeVisionMode`)

| মোড        | ডিফল্ট | আচরণ                                                                                                                                                                                                                                                            |
| ---------- | ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `auto`     | ✔      | পুরানো হিউরিস্টিক, অপরিবর্তিত (#6640/#7204): অ-কম্বো/`auto/` মডেলগুলি সেরা ভিশন মডেলে পুনঃনির্দেশিত হয় যতক্ষণ না মূল মডেলের ইতিমধ্যে ব্যবহারযোগ্য শংসাপত্র থাকে (তাহলে বর্ণনা); কম্বো লক্ষ্যগুলি সর্বদা বর্ণনা করে।                                            |
| `describe` |        | সর্বদা বর্ণনা করুন — পুনঃনির্দেশ ব্লক সম্পূর্ণরূপে বাদ দেওয়া হয়; ব্যবহারকারীর নির্বাচিত মডেল সর্বদা উত্তর দেয়।                                                                                                                                               |
| `reroute`  |        | জোরপূর্বক পুনঃনির্দেশ: শংসাপত্রযুক্ত মডেল গার্ডটি বাইপাস করা হয়। পুনঃনির্দেশ-**লক্ষ্য** শংসাপত্র গার্ড এখনও প্রযোজ্য — যখন কোনও ব্যবহারযোগ্য ভিশন লক্ষ্য নেই, অনুরোধটি বর্ণনায় পড়ে যায় যাতে কাঁচা চিত্রগুলি কখনও টেক্সট-শুধু ব্যাকএন্ডে পৌঁছায় না (#8430)। |

জোরপূর্বক মোডগুলি **অটো হিউরিস্টিক চালানোর আগে** শর্ট-সার্কিট করে; `auto` আচরণ প্রি-PR-1 গার্ডরেইলের সাথে বাইট-আইডেন্টিক্যাল।

#### API-কী স্কোপ (`visionBridgeKeyScope.ts`)

যখন কলারের API কী `allowedConnections`, কোটা পুল
(`allowedQuotas`) বা মডেলগুলি (`allowedModels` / `blockedModels` /
`modelAccessMode: "restricted"` / `disableNonPublicModels`) সীমাবদ্ধ করে, ব্রিজটি শুধুমাত্র পুনঃনির্দেশ এবং বর্ণনা মডেলগুলি বেছে নেয় যা কী ব্যবহার করতে পারে, সেই সংযোগগুলিতে যা কী ব্যবহার করতে পারে। বর্ণনা কল তখন সর্বদা `x-omniroute-self-loop-key-id` হেডার সহ OmniRoute স্ব-লুপের মাধ্যমে যায়, তাই প্রাপ্ত চ্যাট অনুরোধটি আবার সেই কী-এর সংযোগ এবং মডেল নীতিকে প্রয়োগ করে। `enforceApiKeyPolicy()`
শুধুমাত্র সেই হেডারকে স্ব-লুপ বেয়ারারের সাথে সম্মান করে, তাই এটি কেবল অ্যাক্সেস সংকীর্ণ করতে পারে, এবং একটি আইডি যা সমাধান হয় না তা প্রত্যাখ্যাত হয়।

যদি কী-এর জন্য কোনও ভিশন মডেল অনুমোদিত না হয়, তবে বর্ণনা পথটি সরে যায় এবং অনুরোধটি অপরিবর্তিতভাবে চলে যায়, নিষ্ক্রিয় গার্ডরেইলের মতো একই ফেইল-ওপেন আচরণ (মেটা `{ skipped: true, reason: "no_permitted_vision_model" }`)।
কী ছাড়া অনুরোধগুলি, এবং এই সীমাবদ্ধতা ছাড়া কীগুলি, পূর্বের মতোই আচরণ করে।

#### কাজ-সচেতন বর্ণনা প্রম্পট (`modalityBridgeVisionTaskAware`)

ডিফল্ট **সত্য**। `composeVisionPrompt()` (`visionBridgeHelpers.ts`) **শেষ ব্যবহারকারীর বার্তার** (500 অক্ষরে সংকুচিত) টেক্সটটি বেস বর্ণনা প্রম্পটে যুক্ত করে, বর্ণনাটি ব্যবহারকারী আসলে যা জিজ্ঞাসা করেছেন তার দিকে নির্দেশ করে (codex-vision-proxy প্যাটার্ন) এবং ভিশন মডেলকে দৃশ্যমান টেক্সট ট্রান্সক্রাইব করতে বলে। ফ্ল্যাগ বন্ধ থাকলে — অথবা কোনো ব্যবহারকারী টেক্সট না থাকলে — বেস প্রম্পট অপরিবর্তিতভাবে ব্যবহার করা হয়।

বর্ণনা স্ব-লুপের নিজস্ব OpenAI-সঙ্গত অনুরোধ (`callVisionModelSingle()` `visionBridgeHelpers.ts` এ) সর্বদা `image_url.detail: "high"` অনুরোধ করে — শর্তহীনভাবে, প্রতিটি কলার/প্রোভাইডারের জন্য, কোনো ক্লায়েন্ট সংকেতের উপর ভিত্তি করে নয়। নিম্ন-ডিটেইল স্যাম্পলিং OCR সঠিকতা হ্রাস করে ঠিক সেই টেক্সট-ট্রান্সক্রিপশন কাজের জন্য যা এই প্রম্পট জিজ্ঞাসা করে, তাই বর্ণনা কলটি সর্বদা উচ্চ বিস্তারিত জন্য অনুরোধ করে, মূল ইনবাউন্ড অনুরোধটি যে বিস্তারিত স্তর ব্যবহার করেছে তা নির্বিশেষে। এটি শুধুমাত্র অভ্যন্তরীণ বর্ণনা অনুরোধের শরীরকে প্রভাবিত করে; এটি OmniRoute-এর কলারের নিজস্ব `image_url.detail` কে প্রাথমিক অনুরোধে ফরওয়ার্ড করার পদ্ধতিকে পরিবর্তন করে না — সেই ডিফল্টটি আলাদাভাবে প্রয়োগ করা হয়, এবং শুধুমাত্র সনাক্তকৃত OpenCode ক্লায়েন্টের জন্য, `defaultImageDetail()` (`open-sse/handlers/chatCore/upstreamBody.ts`) এ। বর্ণনা স্ব-লুপের Anthropic ওয়্যার-ফরম্যাট শাখায় কোনো `detail` ক্ষেত্র নেই এবং এটি উভয় ডিফল্ট দ্বারা প্রভাবিত হয় না।

#### বর্ণনা আউটপুট ক্যাপ (`modalityBridgeVisionMaxChars`)

| কী                             | ডিফল্ট | পরিসীমা            |
| ------------------------------ | ------ | ------------------ |
| `modalityBridgeVisionMaxChars` | `0`    | `0` অথবা 100–50000 |

`0` (ডিফল্ট) মানে **কোনো ক্যাপ নেই** — `callVisionModel()` দ্বারা ফেরত দেওয়া বর্ণনাটি অপরিবর্তিতভাবে পাস করা হয়, বিদ্যমান আচরণ সংরক্ষণ করে। 100–50000 পরিসীমার মধ্যে কোনো মান বর্ণনাটি `…` সাফিক্স সহ সংকুচিত করে এর পরে `[Image N]: <description>` হিসাবে পুনরায় সংযুক্ত করার আগে
(`VisionBridgeGuardrail.preCall()` `src/lib/guardrails/visionBridge.ts` এ)। এইটি বিস্তারিত-ভারী OCR কাজের জন্য বাড়ান যেখানে নিম্নগামী মডেলকে সম্পূর্ণ ট্রান্সক্রিপশন প্রয়োজন; এটি চ্যাটি ভিশন মডেলগুলিতে টোকেন ব্যবহারের সীমাবদ্ধ করতে কমান। ড্যাশবোর্ড ক্ষেত্রটি ভিশন ট্যাবের অ্যাডভান্সড প্যানেলে থাকে
(`modality-bridge-max-chars` `ModalityBridgeVisionTab.tsx` এ) এবং 1 থেকে 99 এর মধ্যে কোনো মানকে 100 ফ্লোর পর্যন্ত সীমাবদ্ধ করে, যখন একটি স্পষ্ট `0` অপরিবর্তিত থাকে — `0` নিজেই একটি বৈধ Zod মান
(`z.union([z.literal(0), z.number().int().min(100).max(50000)])`), শুধুমাত্র "unset" ডিফল্ট নয়।

#### বর্ণনা ক্যাশে (`modalityBridge/bridgeCache.ts`)

বর্ণনা আউটপুটের জন্য ইন-মেমরি LRU + TTL ক্যাশ, প্রক্রিয়া-ব্যাপী শেয়ার করা হয়।
কী = `sha256(imageRef + composedPrompt + configuredBridgeModel)` দৈর্ঘ্য-পূর্বক ফ্রেমিং সহ (কোনো ক্ষেত্র-সীমার সংঘর্ষ নেই)। মডেল উপাদান হল **কনফিগার করা** ব্রিজ মডেল, যা আসলে উত্তর দিয়েছে তা নয় —
`callVisionModel` অভ্যন্তরীণভাবে ব্যাকআপ নিতে পারে, এবং প্রতি প্রচেষ্টার জন্য কী করা হলে ক্যাশটি টুকরো টুকরো হয়ে যাবে। ব্যর্থ বর্ণনাগুলি কখনও ক্যাশে করা হয় না। সেটিংস:

| কী                              | ডিফল্ট | পরিসীমা |
| ------------------------------- | ------ | ------- |
| `modalityBridgeCacheEnabled`    | `true` | —       |
| `modalityBridgeCacheTtlMinutes` | `60`   | 1–1440  |
| `modalityBridgeCacheMaxEntries` | `200`  | 10–5000 |

#### রিমোট ইমেজ নরমালাইজেশন (স্ব-লুপ বর্ণনা/base64 ফেচ)

যখন ব্রিজ একটি **রিমোট** ইমেজ নিজেই ফেচ করে — Anthropic বর্ণনা স্ব-কল এবং ক্লড-ওয়্যার-ফরম্যাট base64 রূপান্তর
(`ensureBase64ImagesForClaudeWire`), উভয়ই `fetchRemoteImageAsDataUri()` `visionBridgeHelpers.ts` এ — ফলস্বরূপ ডেটা URI `normalizeDataUri()` এর মাধ্যমে পাস করা হয়
(`open-sse/utils/imageNormalize.ts`) এর আগে ভিশন-মডেল অনুরোধে এম্বেড করা হয়। অতিরিক্ত আকারের ইমেজগুলি **2048px দীর্ঘ প্রান্তে** (যা OpenAI/Anthropic ইতিমধ্যে সার্ভার-সাইডে প্রয়োগ করে) কমিয়ে আনা হয়, যা আপলোড বাইট/লেটেন্সি হ্রাস করে ভিশন মডেল যা দেখে তা পরিবর্তন না করে। রিসাইজিং `sharp` ব্যবহার করে, যা ডাইনামিক ইম্পোর্টের মাধ্যমে লোড করা হয়: এমন একটি প্ল্যাটফর্মে যেখানে এর নেটিভ বাইনারি লোড হতে ব্যর্থ হয়, `normalizeDataUri()` **কখনও থ্রো করে না** — এটি মূল বাইটগুলির একটি পাসথ্রুতে ফিরে আসে, তাই বর্ণনা/base64-রূপান্তর পথ সর্বদা কাজ করতে থাকে। নন-ইমেজ বাইট (একটি ফেচ যা একটি ডিকোডেবল ইমেজ ফেরত দেয়নি) এছাড়াও অপরিবর্তিতভাবে পাস করা হয়। এই নরমালাইজেশনটি ইমেজগুলির জন্য সীমাবদ্ধ যা ব্রিজ তার নিজস্ব স্ব-কলের জন্য ফেচ করে — এটি কখনও কলারের কাঁচা পাসথ্রু পে-লোডে প্রয়োগ করা হয় না, অপ্ট-ইন-শুধুমাত্র মিউটেশন নীতির সাথে সামঞ্জস্যপূর্ণ (হার্ড রুল #20)।

#### সেটিংস স্কিমা + মাইগ্রেশন

নতুন `modalityBridge*` কীগুলি `updateSettingsSchema` এ Zod-ভ্যালিডেটেড হয়
(`src/shared/validation/settingsSchemas.ts`): `modalityBridgeVisionEnabled`,
`modalityBridgeVisionMode`, `modalityBridgeVisionModel`,
`modalityBridgeVisionTaskAware`, `modalityBridgeVisionPrompt`,
`modalityBridgeVisionTimeout`, `modalityBridgeVisionMaxImages`,
`modalityBridgeVisionMaxChars`, `modalityBridgeCache*` ত্রয়ী, এবং `modalityBridgeAudio*` গ্রুপ যা অডিও ব্রিজ দ্বারা ব্যবহৃত হয়। মাইগ্রেশন `141_modality_bridge_settings.sql` বিদ্যমান লেগেসি
`visionBridge*` মানগুলিকে মেলানো নতুন কীগুলিতে কপি করে (আইডেমপোটেন্ট, কখনও অপারেটর-সেট `modalityBridge*` মানকে ওভাররাইট করে না); লেগেসি কীগুলি একটি পড়ার ব্যাকফল হিসাবে এক রিলিজ সাইকেলের জন্য গ্রহণযোগ্য থাকে।

#### স্বচ্ছতা হেডার + পরিসংখ্যান

বর্ণনা-রূপান্তরিত প্রতিক্রিয়া বহন করে
`x-omniroute-modality-bridge: image->text;model=<visionModel>;parts=<n>`
(`buildModalityBridgeHeader()` দ্বারা নির্মিত `modalityBridge/bridgeStats.ts` এ,
`withModalityBridgeHeader()` দ্বারা স্ট্যাম্প করা `src/sse/handlers/chatHelpers.ts` এ)।
পুনঃনির্দেশিত অনুরোধগুলিতে **কোনো** হেডার নেই — পে-লোড অপরিবর্তিত ছিল এবং মডেল পরিবর্তন ইতিমধ্যে প্রতিক্রিয়া শরীরের `model` ক্ষেত্রে দৃশ্যমান।

`GET /api/modality-bridge/stats` (ম্যানেজমেন্ট অথরাইজেশন, একই স্তরের
`GET /api/settings`) ইন-মেমরি প্রতি-মোডালিটি কাউন্টারগুলি ফেরত দেয়
`{ attempts, successes, bridged, cacheHits, failures, totalLatencyMs,
latencySamples, averageLatencyMs, lastUsedAt }` জন্য `vision`, `audio`, এবং
`video`। `averageLatencyMs` ব্যবহার করে `latencySamples`, সব চেষ্টা নয়, এর
নির্দেশক; সময় ছাড়া একটি অপারেশন শূন্য-মিলিসেকেন্ডের
নমুনা তৈরি করে না। `bridged` সফল রূপান্তরের জন্য পেছনের সাথে সামঞ্জস্যপূর্ণ
উপনাম হিসেবে থাকে; ব্যর্থ প্রচেষ্টা এটি বাড়ায় না।
কাউন্টারগুলি প্রক্রিয়া পুনরায় চালু করার সময় ডিজাইনের দ্বারা রিসেট হয়
(টেলিমেট্রি, হিসাব নয়)।

#### ড্যাশবোর্ড কনফিগারেশন

নির্দিষ্ট ড্যাশবোর্ড পৃষ্ঠা হল
`/dashboard/settings/modality-bridge`। এর URL-অ্যাড্রেসযোগ্য `Vision`, `Audio`,
এবং `Video` ট্যাবগুলি `tab` মান পরিবর্তন করার সময় কোয়েরি প্যারামিটারগুলি
রক্ষা করে। ভিশন ট্যাব সক্ষমতা, মোড, মডেল নির্বাচন (স্বয়ংক্রিয়
ডিফল্ট সহ), কাজ-সচেতন প্রম্পটিং, উন্নত টাইমআউট/ছবি/বর্ণনা-দৈর্ঘ্য/ক্যাশ
সীমা, রানটাইম
কাউন্টার, এবং একটি সুরক্ষিত নমুনা অনুরোধ প্রকাশ করে। অডিও ট্যাবও লাইভ: এটি
সক্ষমতা, একটি STT-শুধুমাত্র মডেল পিকার সহ অটো, টাইমআউট/সর্বাধিক-ক্লিপ সীমা,
অডিও কাউন্টার, এবং একটি `input_audio` নমুনা পরীক্ষা প্রকাশ করে। ভিডিও ট্যাব কার্যকর: এটি
FFmpeg/ffprobe রানটাইম অবস্থার রিপোর্ট করে — চারটি স্পষ্ট UI অবস্থার মধ্যে একটি
(`unknown` যখন
প্রোব উড়ছে বা সম্পন্ন করতে পারেনি, `restricted` একটি নন-লুপব্যাক
ড্যাশবোর্ড হোস্টে যেখানে ক্লায়েন্ট-সাইডে প্রোবটি বাদ দেওয়া হয়, `unavailable` একবার প্রোব করা
এবং নিশ্চিত করা হয়েছে যে এটি অনুপস্থিত, অথবা `available` FFmpeg/ffprobe সংস্করণগুলির সাথে) —
সক্ষম/মডেল/ফ্রেম/ভিডিও/টাইমআউট সীমা স্থায়ী করে, মডেল পিকারকে ভিশন-সক্ষম
মডেলগুলিতে ফিল্টার করে, এবং ভিডিও কাউন্টার প্রকাশ করে।

AI সেটিংসের অধীনে পূর্ববর্তী ভিশন ব্রিজ কার্ডটি নতুন পৃষ্ঠার জন্য একটি সামঞ্জস্যপূর্ণ লিঙ্ক; এটি আর
ফর্মের দ্বিতীয় কপি মালিকানা করে না। মিডিয়া প্রদানকারীরাও
ছবি-থেকে-টেক্সট এবং স্পিচ-থেকে-টেক্সট ওয়ার্কফ্লোগুলিকে সংশ্লিষ্ট মোডালিটি
ব্রিজ ট্যাবগুলিতে লিঙ্ক করে বিদ্যমান স্পিচ-থেকে-টেক্সট প্লেগ্রাউন্ডটি সরিয়ে না।

নিজস্ব `/v1` স্ব-লুপ (অ-মানক প্রদানকারী মডেল) মাধ্যমে রুট করে, সাব-অনুরোধটি পাঠায়
`x-omniroute-admission-bypass: internal` এবং সমাধান করা স্ব-লুপ শংসাপত্রের সাথে
অথেন্টিকেট করা হয় — স্থানীয় `sk_omniroute` সেনটিনেল স্থানীয় মোডে, অথবা
অপারেটর-কনফিগার করা `OMNIROUTE_API_KEY` / `ROUTER_API_KEY` পরিবেশ কী (#1350) যাতে
`REQUIRE_API_KEY=true` ডিপ্লয়মেন্টগুলি এখনও বর্ণনা কল চালাতে পারে। বাইপাসটি
শুধুমাত্র সেই নির্দিষ্ট শংসাপত্রগুলির জন্য সম্মানিত হয়, তাই বাইরের ক্লায়েন্টরা
প্রবেশাধিকার এড়াতে হেডারটি ব্যবহার করতে পারে না।

লিগ্যাসি ডিফল্টগুলি `src/shared/constants/visionBridgeDefaults.ts`-এ রয়েছে; নতুন মোড/কাজ-সচেতন/ক্যাশ
ডিফল্ট এবং সেটিংস রিজলভার `src/shared/constants/modalityBridgeDefaults.ts`-এ রয়েছে। গার্ডরেইল একটি
`deps` কনস্ট্রাক্টর অপশন প্রকাশ করে যাতে পরীক্ষাগুলি ভুয়া `getSettings` এবং
`callVisionModel` বাস্তবায়নগুলি ইনজেক্ট করতে পারে।

### অডিও ব্রিজ (`audioBridge.ts`) — মোডালিটি ব্রিজ PR-3

অডিও ধারণকারী চ্যাট অনুরোধগুলি লক্ষ্যস্থলে পৌঁছানোর আগে আটকায় যা অডিও ইনপুট গ্রহণ করতে
জানা নেই। এটি কখনও চ্যাট অনুরোধটি পুনঃরূট করে না: অডিও অংশগুলি বিদ্যমান OpenAI-সঙ্গত
মাল্টিপার্ট এন্ডপয়েন্টের মাধ্যমে ট্রান্সক্রাইব করা হয় এবং নির্বাচিত চ্যাট মডেল
পাঠ্য ট্রান্সক্রিপ্টের সাথে চলতে থাকে।

প্রবাহ:

1. `supportsAudio` সমাধান করুন `getResolvedModelCapabilities()` মাধ্যমে। স্পষ্ট
   প্রদানকারী-রেজিস্ট্রি মেটাডেটা জয়ী হয়, তারপর স্ট্যাটিক মডেল মেটাডেটা, তারপর সিঙ্ক করা
   `modalities_input`। `audio` ছাড়া একটি ঘোষিত ইনপুট তালিকা `false`; কোন
   সক্ষমতা প্রমাণ `null` থাকে। উভয় `false` এবং `null` রক্ষণশীল ব্রিজ সক্রিয় করে, যখন `true` এটি বাইপাস করে।
2. `modalityBridgeAudio*` সেটিংস সমাধান করুন এবং প্রতিটি বার্তা থেকে শেয়ার করা `detectMediaParts()`
   ডিটেক্টর মাধ্যমে স্প্লাইসযোগ্য শীর্ষ স্তরের অডিও অংশগুলি বের করুন। সমর্থিত তারের আকারগুলি হল OpenAI `input_audio`, `audio_url`, এবং
   `source.media_type: "audio/*"`। নেস্টেড অডিও রুটিংয়ের জন্য সনাক্ত করা হয় কিন্তু
   স্প্লাইস পাথ দ্বারা সরানো হয় না। কাজটি `modalityBridgeAudioMaxClips` দ্বারা সীমাবদ্ধ;
   পরবর্তী অংশগুলি অপরিবর্তিত থাকে।
3. একটি কনফিগার করা `provider/model` সম্মান করুন, অথবা `selectAudioBridgeModel()` কে
   স্থিতিশীল ক্যাটালগ অর্ডারে `AUDIO_TRANSCRIPTION_PROVIDERS` হাঁটতে দিন এবং প্রথম
   মডেলটি নির্বাচন করুন যার একটি ব্যবহারযোগ্য সক্রিয় প্রদানকারী শংসাপত্র রয়েছে।
4. `callAudioTranscription()` base64/data-URI অডিওকে একটি মাল্টিপার্ট
   `file`-এ রূপান্তর করে, অথবা একটি পাবলিক-শুধুমাত্র আউটবাউন্ড
   গার্ডের মাধ্যমে DNS পিনিং এবং 25 MB সীমা সহ একটি দূরবর্তী `audio_url` ডাউনলোড করে। এটি তারপর ফাইল এবং নির্বাচিত
   মডেলকে স্থানীয় `/v1/audio/transcriptions` স্ব-লুপে POST করে, `resolveSelfLoopBearer()` দ্বারা
   অথেন্টিকেট করা হয়। বিদ্যমান ট্রান্সক্রিপশন রুট স্বাভাবিক
   শংসাপত্র অনুসন্ধান, কুলডাউন/রেট-লিমিট পরিচালনা, এবং প্রদানকারী বিতরণ করে।
5. সফল কলগুলি তাদের অংশগুলি `[Audio N]: <transcript>` দ্বারা প্রতিস্থাপন করে। কলগুলি
   `Promise.allSettled` সহ চলে: একটি পৃথক ব্যর্থতা সেই মূল
   অডিও অংশটি সংরক্ষণ করে (#4012 চুক্তি)। যদি প্রতিটি কল ব্যর্থ হয় এবং লক্ষ্যটি প্রমাণিত হয়
   `supportsAudio === false`, অংশগুলি হয়ে যায়
   `[Audio N]: (unavailable — no STT provider connected)` (#8430 চুক্তি)। একটি অজানা লক্ষ্য (`null`), একটি সব-ব্যর্থ ফলাফল অপরিবর্তিত থাকে। একটি প্রমাণিত
   টেক্সট-শুধুমাত্র লক্ষ্য যার কোন ব্যবহারযোগ্য STT শংসাপত্র নেই একই স্পষ্ট
   স্টাব পায় নেটওয়ার্ক কল ছাড়াই।

সফল ট্রান্সক্রিপ্টগুলি প্রক্রিয়া-ব্যাপী মোডালিটি ব্রিজ LRU/TTL ক্যাশ ব্যবহার করে। কীটি অডিও রেফারেন্স, স্থিতিশীল `audio-transcription` অপারেশন
লেবেল, এবং নির্বাচিত STT মডেলকে সংমিশ্রণ করে; ব্যর্থতাগুলি কখনও ক্যাশ করা হয় না। অডিও প্রচেষ্টা শেয়ার করা `bridged`, `cacheHits`, `failures`, এবং `lastUsedAt` কাউন্টারগুলি আপডেট করে।
রূপান্তরিত প্রতিক্রিয়াগুলি বহন করে
`x-omniroute-modality-bridge: audio->text;model=<sttModel>;parts=<n>`; অপরিবর্তিত
অনুরোধগুলি একটি অডিও ব্রিজ সেগমেন্ট পায় না।

রানটাইম সেটিংস DB-সমর্থিত এবং Zod-ভ্যালিডেটেড:

| কী                            | ডিফল্ট  | পরিসীমা          |
| ----------------------------- | ------- | ---------------- |
| `modalityBridgeAudioEnabled`  | `true`  | —                |
| `modalityBridgeAudioModel`    | `""`    | Auto অথবা STT ID |
| `modalityBridgeAudioTimeout`  | `60000` | 1000–300000      |
| `modalityBridgeAudioMaxClips` | `3`     | 1–10             |

শেয়ার করা ক্যাশ `modalityBridgeCacheEnabled`, `modalityBridgeCacheTtlMinutes`, এবং `modalityBridgeCacheMaxEntries` দ্বারা নিয়ন্ত্রিত থাকে।

### ভিডিও ব্রিজ (`videoBridge.ts`, `videoBridgePipeline.ts`)

Chat Completions `messages` এবং Responses API `input` এ একটি লক্ষ্যকে কল করার আগে টপ-লেভেল ভিডিও অংশগুলি আটকায় যেখানে পরিচিত নেটিভ ভিডিও সমর্থন নেই। সমর্থিত আকারগুলি হল `input_video`, `video_url`, `video_source`, HTTPS URLs, এবং `data:video/*;base64,...` ডেটা URI। টেক্সটে সাধারণ ফাইল নামগুলো ভিডিও হিসেবে বিবেচিত হয় না।

`VideoBridgeGuardrail.preCall` (`videoBridge.ts`) অনুরোধের অতিক্রম, সক্ষমতা/নীতির পরীক্ষা, প্রতি-অনুরোধের সমাহার, এবং প্রতিক্রিয়া পে-লোডের মালিক। প্রতি-ভিডিও কাজ — অধিগ্রহণ, সম্পূর্ণ-ফলাফল ক্যাশ, একটি ফ্রেম সিকোয়েন্স বর্ণনা করা (যা যে কোনো কলার-ঘোষিত অডিও ট্রান্সক্রিপ্টকে একত্রিত করে), এবং প্রতি-প্রয়াসের মেট্রিক্স/বাতিল/পরিষ্কার — `processVideoPart` এর পিছনে লুকানো থাকে `videoBridgePipeline.ts` এ, যা `preCall` এর লুপের মধ্যে প্রতি ভিডিও অংশে একবার কল করা হয়। সেই মডিউলটি স্পষ্ট পোর্ট সীমানাগুলি সংজ্ঞায়িত করে `VideoMediaBrokerPort` (বাইট অধিগ্রহণ এবং নমুনা ফ্রেমগুলি নিষ্কাশন করা), `VideoAudioTranscriptionPort` (একটি কলার-ঘোষিত অডিও ট্রান্সক্রিপ্টকে নমুনা ক্যাপশনগুলির সাথে একত্রিত করা), এবং `VideoDrilldownPort` (পুরাতন রাও-স্টোর আকার)। উৎপাদন STT এবং ফ্রেম ধারণা বর্ণনা করা পোর্টের চারপাশে গঠিত হয় `createVideoSttAdapter` এবং `createVideoDrilldownAdapter` এর মাধ্যমে; পরবর্তীটি শেয়ার করা অস্বচ্ছ-হ্যান্ডেল লাইফসাইকেল ব্যবহার করে।

জনসাধারণের `/v1` অনুরোধ পথ কখনও একটি সাবপ্রক্রিয়া আমদানি বা কল করে না। দূরবর্তী ভিডিওগুলি 50 MiB সীমার অধীনে ডাউনলোড করা হয়; ইনলাইন বেস64 ভিডিওগুলির একটি সংরক্ষণশীল 36 MiB ডিকোড করা প্রতি-ভিডিও ক্যাপ রয়েছে যাতে মডেল/বার্তা/ফ্রেমিং এনভেলপ জনসাধারণের JSON অনুরোধের প্রবেশ সীমা 50 MiB এর মধ্যে থাকতে পারে। বরাদ্দের আগে ইনলাইন দৈর্ঘ্য এবং ডিকোড-আকারের অনুমানগুলি পরীক্ষা করা হয়। প্রাথমিক দূরবর্তী URL এবং প্রতিটি রিডাইরেক্টে HTTPS প্রয়োজন, বিদ্যমান জনসাধারণ-শুধু আউটবাউন্ড গার্ড DNS পিনিং ব্যবহার করে। বাইটগুলি তখন সঠিক অভ্যন্তরীণ `POST /api/modality-bridge/video/extract` ব্রোকার সীমানা অতিক্রম করে। সেই রুটটি `LOCAL_ONLY` এবং `SPAWN_CAPABLE`, শুধুমাত্র একটি প্রতি-প্রক্রিয়া প্রমাণিত, বিশ্বাসযোগ্য-লুপব্যাক অনুরোধ গ্রহণ করে, এবং কখনও একটি URL, ফাইল সিস্টেম পাথ, কার্যকরী, বা আর্গুমেন্ট তালিকা গ্রহণ করে না। API বডি-আকার পাইপলাইন এবং হ্যান্ডলারের ইনক্রিমেন্টাল বডি রিডার স্বাধীনভাবে 50 MiB ব্রোকার ইনপুট ক্যাপ প্রয়োগ করে। এর সীমাবদ্ধ কিউ একবারে একটি নিষ্কাশন চালায়, চারটি মুলতুবি কাজের অনুমতি দেয়, এবং মুলতুবি ইনপুট 100 MiB এ সীমাবদ্ধ করে।

ব্রোকারের ভিতরে, `ffprobe` একটি ব্যক্তিগত স্থানীয় ফাইল পড়ে; স্থির ফরম্যাট অনুমোদন তালিকা প্লেলিস্ট এবং ম্যানিফেস্ট ফরম্যাটগুলি বাদ দেয়। অনুমোদিত MOV-পরিবারের কন্টেইনারগুলির জন্য, বাইরের MOV ডেটা রেফারেন্সগুলি ডিফল্টরূপে নিষ্ক্রিয় থাকে, এবং স্থির কমান্ড সেগুলিতে অপ্ট ইন করে না। উভয় `ffprobe` এবং `ffmpeg` `file`-শুধু প্রোটোকল হোয়াইটলিস্ট, একটি থ্রেড, স্থির আর্গুমেন্ট অ্যারে, কোনও শেল, এবং `PATH` থেকে সমাধান করা কার্যকরী ব্যবহার করে। সংযুক্ত-ছবির কভার স্ট্রিমগুলি প্লেবেল প্রার্থী নয়। সমস্ত প্লেবেল স্ট্রিমগুলি সীমাগুলি পূরণ করতে হবে, এবং একটি স্পষ্ট ডিফল্ট স্ট্রিম নির্ধারিত সর্বনিম্ন-সূচক ব্যাকআপের আগে পছন্দ করা হয়। ভিডিওগুলি 600 সেকেন্ড, 8,192 পিক্সেল প্রতি মাত্রা, এবং 33,554,432 সোর্স পিক্সেলে সীমাবদ্ধ। FFmpeg 1–16 মিডপয়েন্ট JPEG ফ্রেমের নমুনা নেয়, দীর্ঘ প্রান্তকে সর্বাধিক 1,024 পিক্সেলে স্কেল করে ছোট ইনপুটগুলিকে আপস্কেল না করে, এবং কখনও একটি URL গ্রহণ করে না। নমুনা নেওয়া ডিফল্টরূপে `uniform`। ঐচ্ছিক `scene_aware` এবং পরীক্ষামূলক `segment_aware` নীতিগুলি ইতিমধ্যে যাচাইকৃত স্থানীয় স্ট্রিমের উপর একটি অতিরিক্ত স্থির FFmpeg পাস সম্পাদন করে, সীমাবদ্ধ `showinfo` দৃশ্যের টাইমস্ট্যাম্পগুলি নির্বাচন করে, এবং ডিটেক্টর ব্যর্থতা, টাইমআউট, অশুদ্ধ আউটপুট, বা একটি খালি প্রার্থী সেটের ক্ষেত্রে নির্ধারিতভাবে একই ইউনিফর্ম মিডপয়েন্টে ফিরে আসে। সেগমেন্ট-অ্যাওয়্যার মোড যাচাইকৃত দৃশ্যের অন্তর্বর্তী সময়ের অনুপাতে মিডপয়েন্ট নমুনাগুলি বরাদ্দ করে; সেগমেন্ট-অ্যাওয়্যার প্রমাণ এবং ব্যাকআপ আচরণ নিচে বিস্তারিতভাবে বর্ণনা করা হয়েছে। কঠোর 16-ফ্রেম ক্যাপ প্রতিটি নীতিতে নির্বাচনের পরে প্রয়োগ করা হয়। যখন একটি দৃশ্য-অ্যাওয়্যার অনুরোধে শুধুমাত্র একটি ফ্রেম বাজেট থাকে, এটি সক্রিয় পূর্ণ-ভিডিও বা ফোকাস উইন্ডোর ইউনিফর্ম মিডপয়েন্ট ব্যবহার করে এবং রিপোর্ট করে `policyEffective: uniform`: একটি একক নির্বাচিত দৃশ্য ফ্রেম উভয় সময়কাল শেষ সংরক্ষণ করতে পারে না। একটি কলার ঐচ্ছিকভাবে একটি সীমিত ফোকাস উইন্ডো (`start`/`end` সেকেন্ড) প্রদান করতে পারে; সীমানাগুলি মিডিয়া সময়সীমার সাথে ক্ল্যাম্প করা হয়, বিপরীত বা অ-সীমিত উইন্ডোগুলি প্রত্যাখ্যাত হয়, এবং সমস্ত নমুনা নীতি শুধুমাত্র স্বাভাবিকীকৃত অন্তর্বর্তী সময়ের মধ্যে সম্পন্ন হয়। ফলস্বরূপ উইন্ডোটি নমুনা মেটাডেটা এবং অপ্রমাণিত বর্ণনা প্রিফিক্সে অন্তর্ভুক্ত করা হয় যাতে নিম্নবর্তী মডেলগুলি একটি ফোকাস করা উদ্ধৃতি সম্পূর্ণ টাইমলাইন থেকে আলাদা করতে পারে।

সেমান্টিক ক্যাপশন ফোকাস একটি আলাদা, স্পষ্ট সেটিং। ডিফল্ট `full` বিশ্লেষণ মোড বিদ্যমান ফ্রেম প্রম্পট সংরক্ষণ করে এবং কখনও অনুরোধের টেক্সট ক্যাপশন মডেলে ফরওয়ার্ড করে না। `focused` মোডে, ব্রিজ শুধুমাত্র একই Chat বা Responses কন্টেইনার থেকে সর্বশেষ অ-খালি ব্যবহারকারী-লিখিত `text`/`input_text` পড়ে, এটি NFC তে স্বাভাবিকীকৃত করে, নিয়ন্ত্রণ অক্ষর এবং শ্বেতস্থানগুলি সংকুচিত করে, এবং 500 ইউনিকোড কোড পয়েন্টে সীমাবদ্ধ করে। একটি খালি ফলাফল সঠিক `full` প্রম্পটে ফিরে আসে। একটি ব্যবহারযোগ্য হিন্ট একটি নিবেদিত অপ্রমাণিত-ব্যবহারকারী-প্রসঙ্গ ব্লকে JSON হিসাবে সিরিয়ালাইজ করা হয় এবং শুধুমাত্র পর্যবেক্ষণযোগ্য বিবরণকে অগ্রাধিকার দিতে পারে; এটি মিডিয়াতে দৃশ্যমান বা শ্রবণযোগ্য নির্দেশাবলীর বিরুদ্ধে আলাদা সতর্কতা অতিক্রম করতে পারে না। টেক্সচুয়াল ফোকাস কখনও `start`/`end` অনুমান করে না বা সময়কাল নমুনাকারী পরিবর্তন করে না।

#### FU-07 কাঠামোগত সেগমেন্ট প্রমাণ

`segment_aware` একটি সীমাবদ্ধ প্রি-অ্যানালাইসিস পাস ব্যবহার করে যা ইতিমধ্যে যাচাইকৃত স্থানীয় ভিডিও স্ট্রিমের উপর চলে। স্থির ফিল্টার চেইন প্রথমে সর্বাধিক 320 পিক্সেল প্রস্থে স্কেল করে, দৃশ্য পরিবর্তন এবং স্থির সময়কাল সনাক্ত করে, তারপর ব্লার, গড় লুমা, এবং স্থানীয়/কালীন তথ্যের জন্য প্রতি সেকেন্ডে 1 ফ্রেমে নমুনা নেয়। পাসটি 600 কাঠামোগত নমুনায় সীমাবদ্ধ, একটি FFmpeg/filter থ্রেড, একই `file`-মাত্রার প্রোটোকল এবং কন্টেইনার অ্যালাওলিস্ট, 1 MiB প্রক্রিয়া-আউটপুট সীমা, এবং ব্রোকারের শেয়ার করা অ্যাবোর্ট/ডেডলাইন এর মধ্যে সর্বাধিক 30 সেকেন্ড। এটি কখনোই অনুরোধ থেকে একটি কমান্ড, ফিল্টার, পথ, বা URL গ্রহণ করে না।

কাঠামোগত মানগুলি নির্ধারক নমুনা প্রমাণ, অর্থনৈতিক ভিডিও বোঝাপড়া নয়। এগুলি বিষয়, ক্রিয়া, ক্যাপশন, বক্তৃতা, বা ব্যবহারকারীর উদ্দেশ্য অনুমান করে না। দৃশ্য এবং স্থির সীমানাগুলি সেগমেন্ট গঠন করে; স্থির কভারেজ, ব্লার, এক্সপোজার, স্থানীয় বিশদ, এবং কালীন পরিবর্তন কেবলমাত্র প্রভাবিত করে কিভাবে বিদ্যমান 1–16 ফ্রেম বাজেট বরাদ্দ করা হয়। একটি সম্পূর্ণ স্থির সেগমেন্ট একটি ফ্রেমে সীমাবদ্ধ, যখন অস্থির সেগমেন্টগুলি অবশিষ্ট বাজেটের জন্য প্রতিযোগিতা করে। যখন সীমানাগুলি ফ্রেমের সংখ্যা ছাড়িয়ে যায়, তখন সমান টাইমলাইন কভারেজ বজায় রাখা হয় যাতে দ্রুত প্রাথমিক কাটগুলি একটি দীর্ঘ ট্রেইলিং সেগমেন্ট লুকাতে না পারে। একটি স্থির সীমানার 1 সেকেন্ডের বিশ্লেষণ রেজোলিউশনের মধ্যে দৃশ্য সীমানাগুলি একত্রিত হয়।

মিসিং ফিল্টার, অকার্যকর/শূন্য প্রমাণ, একটি ডিটেক্টর ত্রুটি, বা সীমাবদ্ধ প্রি-অ্যানালাইসিস টাইমআউট সঠিক সমান মধ্যপন্থা নীতিতে খোলার জন্য ব্যর্থ হয়। একটি কলার অ্যাবোর্ট বা ব্রোকার ডেডলাইন খোলার জন্য ব্যর্থ হয় না: এটি চলমান সাবপ্রসেসটি শেষ করে, পরবর্তী ফ্রেম নিষ্কাশন প্রতিরোধ করে, এবং ব্যক্তিগত অস্থায়ী গাছ `finally` এ মুছে ফেলা হয়।

`scripts/perf/video-bridge-fu07-eval.ts` পোস্ট-ডিডুপ ক্যাপশন-কল সঞ্চয়ের জন্য নির্ধারক বাস্তব FFmpeg ফিক্সচার তৈরি করে, ঘন-গতি বাজেট বরাদ্দ, ব্লার/এক্সপোজার/SI-TI প্রমাণ, দীর্ঘ লেজ সহ দ্রুত কাট, এবং ধীরে ধীরে ফেড মিথ্যা ইতিবাচক। এটি প্রি-অ্যানালাইসিস ওয়াল টাইম রেকর্ড করে এবং যেখানে `/usr/bin/time` উপলব্ধ, সেখানে শিশু CPU এবং পিক RSS। এর গুণমান পরীক্ষা কেবল কাঠামোগত ওরাকল। বাস্তব ক্যাপশন-মডেল গুণমান `HOLD` এ থাকে কারণ এই হার্নেসের কোন অনুমোদিত এন্ডপয়েন্ট বা স্থির বিচারক নেই। অর্থনৈতিক সঞ্চয়ও `HOLD` এ থাকে যতক্ষণ না `--caption-cost-per-call-usd` একটি স্পষ্ট ইতিবাচক প্রতি-কল অনুমান সরবরাহ করে; স্ক্রিপ্ট কখনোই কোন ফলাফল তৈরি করে না।

প্রতি ফ্রেম 4 MiB এ সীমাবদ্ধ, সমস্ত কাঁচা ফ্রেম একসাথে 23 MiB এ, এবং সিরিয়ালাইজড ব্রোকার প্রতিক্রিয়া 32 MiB এ। একটি ব্যক্তিগত অস্থায়ী ডিরেক্টরি `finally` এ মুছে ফেলা হয়। OmniRoute FFmpeg প্যাকেজ করে না এবং একটি কাস্টম এক্সিকিউটেবল পথ গ্রহণ করে না। ক্যাপশনিংয়ের আগে, ব্রিজ একটি সংরক্ষণশীল ভিজ্যুয়াল ডিডুপ্লিকেশন পাস প্রয়োগ করে: প্রতিটি JPEG একটি 16×16 গ্রেস্কেল বাফারে হ্রাস পায় এবং কেবলমাত্র শেষ ফ্রেমের সাথে তুলনা করা হয়। একটি অনুরোধ করা ক্যাপশন বাজেট এক ফ্রেমের উপরে হলে, নিষ্কাশন একটি সীমাবদ্ধ প্রার্থী পুল সরবরাহ করে যা বাজেটের দ্বিগুণ পর্যন্ত এবং কখনোই 16 ফ্রেমের বেশি নয়। অনুরোধ করা ক্যাপটি ডিডুপ্লিকেশনের পরে প্রয়োগ করা হয়, প্রথম এবং চূড়ান্ত নির্বাচিত প্রার্থীরা চূড়ান্ত পাতলা করার সময় সংরক্ষিত হয় যখন বাজেট অন্তত দুই হয়। সংস্করণযুক্ত `grayscale-16x16-mean-cells-v2` নীতি গড় লুমা ডেল্টা এবং থাম্বনেইল সেলের অনুপাতের মধ্যে বৃহত্তম ব্যবহার করে যার স্বাভাবিকীকৃত ডেল্টা অন্তত 0.05। ডুপ্লিকেট থ্রেশহোল্ড হল ধ্রুবক 0.04, যা পূর্বাভাসযোগ্যতার জন্য নির্বাচিত হয়েছে বরং এটি রানটাইম সেটিং হিসাবে প্রকাশিত হয়েছে। এই গৌণ উচ্চ-কনট্রাস্ট সংকেত ছোট গতিশীলতা এবং দৃশ্যমান-টেক্সট পরিবর্তনগুলি সংরক্ষণ করে যা একটি গড়-শুধু তুলনা লুকিয়ে রাখতে পারে। কম্প্যারেটর বা ডিকোডার ত্রুটি খোলার জন্য ব্যর্থ হয় এবং কভারেজ বজায় রাখে। আউটপুট মেটাডেটা নিষ্কাশিত প্রার্থীদের, সফলভাবে ব্যবহৃত ফ্রেমগুলি, এবং ভিজ্যুয়াল ডুপ্লিকেটগুলি আলাদা করে।

একটি স্পষ্টভাবে চিহ্নিত ভিডিও অংশ একটি টাইমস্ট্যাম্পযুক্ত যোগাযোগ শীটের জন্য অনুরোধ করতে পারে। ব্রিজ সর্বাধিক 4-কলাম, 16-ফ্রেম JPEG গ্রিড তৈরি করে। প্রতিটি 512-পিক্সেল সেল একটি উচ্চ-কনট্রাস্ট নীচের ব্যান্ডে তার উৎস টাইমস্ট্যাম্প জ্বালিয়ে দেয়, যখন একই টাইমস্ট্যাম্পগুলি নিম্নতর সমিতি এবং নিরীক্ষণের জন্য পাঠ্য মেটাডেটাতে থাকে। সম্পূর্ণ JPEG 32 MiB এ সীমাবদ্ধ থাকে। যদি `sharp` গ্রিডটি ডিকোড বা কম্পোজ করতে না পারে, তবে ব্রিজ পৃথক JPEG ফ্রেমগুলিতে ফিরে আসে; একটি ক্লায়েন্ট অ্যাবোর্ট এখনও শীট অপারেশনের মাধ্যমে ছড়িয়ে পড়ে।

প্রমোশন প্রমাণ ইচ্ছাকৃতভাবে সিন্থেটিক কম্পোজিশন মাইক্রোবেঞ্চমার্ক থেকে আলাদা। `scripts/perf/video-bridge-contact-sheet-eval.ts` বাস্তব OpenAI-সঙ্গত ভিশন মডেলের জন্য একটি স্কিমা-সংস্করণযুক্ত A/B হার্নেস সংজ্ঞায়িত করে। এটি প্রদানকারী-প্রতিবেদন করা টোকেন, শেষ থেকে শেষের ওয়াল লেটেন্সি (শীট কম্পোজিশন সহ), মডেল-কল সংখ্যা, এবং ম্যানিফেস্ট-সংজ্ঞায়িত তথ্য ধারণের পরিমাপ করে। কাঁচা মডেল প্রতিক্রিয়া রিপোর্টে লেখা হয় না; কেবল SHA-256 ডাইজেস্ট এবং মেলানো তথ্য আইডি সংরক্ষিত হয়। হার্নেসটি কোন নেটওয়ার্ক বা পেইড মডেল কল করে না যতক্ষণ না `--execute-real` পাস করা হয় এবং `--model`, `OMNIROUTE_BASE_URL`, এবং `OMNIROUTE_API_KEY` কনফিগার করা হয়। সেই স্পষ্ট বাস্তব রান ছাড়া, এর মেশিন-পঠনযোগ্য রায় `HOLD` এ থাকে; সিন্থেটিক পে-লোড/কল-সংখ্যার পরিমাপ একা প্রমোশন প্রমাণ নয়।

অলাদা `scripts/perf/video-bridge-promotion-eval.ts` FU-07 বা FU-09 পর্যবেক্ষণ গ্রহণ করে। প্রমোশন প্রবেশের জন্য সমস্ত আটটি সিন্থেটিক পরিস্থিতির প্রকার এবং একটি স্যানিটাইজড বাস্তব ক্লিপ প্রয়োজন, প্রতি ভূমিকা এবং ক্ষেত্রে অন্তত তিনটি পরিমাপিত পুনরাবৃত্তি, সমস্ত দশটি ঘোষিত মেট্রিক, স্থির মিডিয়া/প্রম্পট/প্রত্যাশিত-তথ্য/সেটিংস ডাইজেস্ট, অনন্য পর্যবেক্ষণ আইডি এবং যাচাইকৃত সিডেড A/B অর্ডার। কার্যকরী রসিদ কর্পাস ডাইজেস্ট, সঠিক প্রার্থী SHA এবং মডেল সংস্করণকে বাঁধে। মিসিং বা অকার্যকর পরিমাপগুলি `HOLD` এ থাকে, যার মধ্যে CPU 30 সেকেন্ডের উপরে, পিক RSS 512 MiB এর উপরে বা প্রি-অ্যানালাইসিস 30 সেকেন্ডের উপরে। এগুলি প্রমাণ-প্রবেশের সীমা, নতুন রানটাইম RSS প্রয়োগের গ্যারান্টি নয়।

FU-07 এর জন্য অন্তত 98% গুণমান রক্ষণাবেক্ষণ এবং p95 লেটেন্সি 1.2x বেসলাইন এর বেশি নয়, পাশাপাশি সমান গড় ক্যাপশন কলের ক্ষেত্রে 0.05 আবশ্যিক কেস-ব্যালেন্সড গড় রিকল উন্নতি অথবা অন্তত 10% কম গড় পোস্ট-ডিডুপ ক্যাপশন কল প্রয়োজন। FU-09 এর জন্য অন্তত 0.85 গুণমান, 95% রক্ষণাবেক্ষণ, 20% p95 লেটেন্সি হ্রাস এবং 10% টোকেন হ্রাস প্রয়োজন। ক্রিটিক্যাল-ফ্যাক্ট ক্ষতি, ইনজেকশন সম্মতি বা অনুপস্থিত ব্যবহার প্রচার প্রতিরোধ করে। একটি এক্সিকিউশন কিছুই প্রচার করতে পারে না: `--previous-report` একই নীতি/মডেল সংস্করণ/প্রার্থী/করপাসের দুটি স্বতন্ত্র, অ-অভিন্ন, পরপর যোগ্য এক্সিকিউশন নিশ্চিত করে। একটি স্যাম্পলিং পরীক্ষার মাধ্যমে একটি যোগাযোগ-শীট পরীক্ষার নিশ্চিতকরণ করা যায় না।

সংগ্রাহকদের স্মৃতিতে প্রতিক্রিয়া স্কোর করতে হবে এবং `responseDigest` সহ মেট্রিক্স এবং পর্যবেক্ষণ বাইন্ডিংস সংরক্ষণ করতে হবে, কখনও প্রতিক্রিয়া টেক্সট নয়। ভোক্তা পুরানো কাঁচা পর্যবেক্ষণও পড়ে কিন্তু কখনও সেই টেক্সট তার রিপোর্টে কপি করে না। প্রতিটি পর্যবেক্ষণের জন্য ঠিক একটি `responseDigest` অথবা `rawResponseText` গ্রহণযোগ্য। সংস্করণযুক্ত অনুমোদন তালিকা খালি থাকে একটি অপরিবর্তনীয় `hold` ডিফল্ট সহ। একটি যোগ্য এন্ট্রি তার প্রমাণ রেফারেন্স, নীতি, মডেল সংস্করণ, সঠিক প্রার্থী SHA, ম্যানিফেস্ট ডাইজেস্ট এবং দুটি স্বতন্ত্র রান আইডি প্রয়োজন; বিরোধী প্রসঙ্গগুলি প্রত্যাখ্যাত হয়। এই মেটাডেটা একটি অডিট চুক্তি, একটি উল্লেখিত ফাইলের সত্যিকারের পরিমাপ ধারণ করে তা প্রমাণ নয়। কোনও এন্ট্রি যোগ করার আগে প্রকৃত রসিদগুলি পর্যালোচনা করুন। ব্যবস্থাপনা পরিসংখ্যান এন্ডপয়েন্ট এবং ভিডিও ড্যাশবোর্ড সংরক্ষিত প্রস্তুতি প্রকাশ করে। একটি কনফিগার করা মডেল অ্যালিয়াস একা তার সংস্করণ বা চলমান প্রার্থী SHA প্রতিষ্ঠা করে না, তাই বর্তমান ড্যাশবোর্ড `HOLD` রিপোর্ট করে অন্য এক্সিকিউশন প্রসঙ্গ থেকে যোগ্যতা পুনরায় ব্যবহার করার পরিবর্তে। স্পষ্ট পরীক্ষামূলক নির্বাচন প্রচার থেকে আলাদা থাকে; কোনও ডিফল্ট স্বয়ংক্রিয়ভাবে পরিবর্তিত হয় না।

কলাররা যখন ইতিমধ্যে সঙ্গতিপূর্ণ টেক্সট ধারণ করে তখন একটি সমর্থিত ভিডিও অংশে একটি ঐচ্ছিক `transcript.cues` অ্যারে সংযুক্ত করতে পারে। প্রতিটি কিউতে `text`, একটি সীমিত `start`/`end` সময়সীমা থাকতে হবে যা পরীক্ষিত সময়সীমার মধ্যে, এবং একটি হোয়াইটলিস্টেড `source` (`client`, `embedded`, বা `audio-bridge`); `confidence` ডিফল্টভাবে `1` এবং `0` এবং `1` এর মধ্যে থাকতে হবে। সঠিক ডুপ্লিকেট কিউগুলি সংকুচিত হয়। OmniRoute কখনও এই মেটাডেটা থেকে ট্রান্সক্রিপশন শুরু করে না: যাচাইকৃত কিউগুলি বর্ণিত ফলাফলে উৎস, বিশ্বাস এবং সময়সীমা সহ কপি করা হয়, এবং ফ্রেম ক্যাপশনের সাথে অবিশ্বাস্য পর্যবেক্ষণ হিসাবে উপস্থাপিত হয়। অবৈধ, সীমার বাইরে, বা প্রমাণহীন টেক্সট প্রত্যাখ্যাত হয় বরং ক্যাপশন স্ট্রিমে মিশ্রিত হয়। উভয় অনুরোধ-বডি ট্রান্সক্রিপ্ট চ্যানেল সরবরাহিত প্রমাণকে `client` এ স্বাভাবিক করে, স্ব-প্রতিষ্ঠিত `embedded` বা `audio-bridge` লেবেল সহ। শুধুমাত্র একটি সার্ভার-মালিকানাধীন অ্যাডাপ্টার সেই বিশ্বাসযোগ্য লেবেলগুলি কোড-শুধু `trustedSource` আর্গুমেন্টের মাধ্যমে বরাদ্দ করতে পারে; একটি অনুরোধ JSON ক্ষেত্র সেই আর্গুমেন্টে পৌঁছাতে পারে না। ট্রান্সক্রিপ্ট টেক্সট অবিশ্বাস্য মিডিয়া-উৎপন্ন সামগ্রী থাকে, এর প্রমাণ নির্বিশেষে, এবং কখনও অনুমোদন নির্ধারণ করা উচিত নয়।

একটি উন্নত কলার একই ভিডিওর জন্য একটি `audioTranscript` ট্র্যাক প্রদান করতে পারে; এটি ক্লায়েন্ট-প্রদান করা টেক্সট হিসাবে বিবেচিত হয়, সার্ভার ট্রান্সক্রিপশনের প্রমাণ নয়। ফিউশন সিম একটি সময়সীমা এবং বাতিল সংকেতের অধীনে ভিজ্যুয়াল এবং অডিও পর্যবেক্ষণ চালায়, একটি সাধারণ টাইমলাইনে তাদের অর্ডার করে, সঠিক ডুপ্লিকেটগুলি সংকুচিত করে, এবং যখন শুধুমাত্র একটি পক্ষ সফল হয় তখন একটি আংশিক ফলাফল রিপোর্ট করে। একটি অবৈধ `audioTranscript` সেই আংশিক ফলাফলে অবনতি ঘটে — ভিজ্যুয়াল বর্ণনা রাখা হয় এবং অডিও শাখা একটি স্যানিটাইজড ব্যর্থ কোড রেকর্ড করে — পুরো ভিডিও ব্যর্থ হওয়ার পরিবর্তে। প্রতি-শাখার প্রাপ্যতা, আংশিক পতাকা, এবং স্যানিটাইজড ব্যর্থ কোডগুলি বর্ণিত ফলাফলে, গার্ডরেল মেটাডেটা (`audioFusionRuns`/`audioFusionPartials`/`audioFusionFailureCodes`), ফলাফল-ক্যাশ মেটাডেটা, এবং ব্রিজ ফিউশন কাউন্টারে সংরক্ষিত হয়। ডিফল্ট ভিডিও ব্রিজ পাথ স্পিচ-টু-টেক্সট আহ্বান করে না বা দ্বিতীয় মিডিয়া কপি ডাউনলোড করে না; সেই স্পষ্ট ট্র্যাক ছাড়া, এটি ভিডিও-শুধু থাকে।

**ট্রান্সক্রিপ্ট রক্ষণাবেক্ষণ (#12150 P1)।** যখনই ভিডিও ব্রিজ (এটি নিজেই অপ্ট-ইন) একটি ট্রান্সক্রিপ্ট কিউ রেন্ডার করে তখন এটি স্বয়ংক্রিয়ভাবে প্রযোজ্য — আলাদা কোনও রক্ষণাবেক্ষণ পতাকা নেই। যখন একটি অনুরোধ কোনও ট্রান্সক্রিপ্ট কিউ (একটি কলার-ঘোষিত `transcript` অথবা একটি ফিউজড `audioTranscript`) রেন্ডার করে, গার্ডরেল এটি `videoBridgeObserved` চিহ্নিত করে এবং ভিডিও বর্ণনার একটি রেড্যাক্টেড ছায়া তৈরি করে — একটি অভিন্ন রেন্ডারিং যেখানে প্রতিটি কিউয়ের ফ্রি-টেক্সট বডি `[redacted-video-transcript]` দ্বারা প্রতিস্থাপিত হয়, যা স্ট্রিংটি সংকলনের আগে কাঠামোগত কিউ ক্ষেত্রটি প্রতিস্থাপন করে তৈরি করা হয় (কখনও সমতল টেক্সট পার্সিং দ্বারা নয়, তাই কোনও কিউ সামগ্রী — শত্রুতাপূর্ণ বা সাধারণ, যেমন বডিগুলি যা `]` ধারণ করে যেমন `[inaudible]`/`[music]` — টিকে থাকতে পারে না)। সংরক্ষিত কল-লগ অনুরোধ বডি প্রতিটি ভিডিও-উৎপন্ন টেক্সট অংশকে সেই রেড্যাক্টেড ছায়ার জন্য পরিবর্তন করে, সামগ্রী সমতা দ্বারা মেলানো; `fullText` অ্যাঙ্কর সম্পন্ন প্রি-কল গার্ডরেল পে-লোড থেকে পুনরায় পড়া হয়, তাই ম্যাচটি পরে চেইন গার্ডরেলগুলি (PII এবং ক্রেডেনশিয়াল মাস্কার, অগ্রাধিকার 10/95) বর্ণনা টেক্সটকে স্থানে পুনরায় লেখার পরেও সফল হয়। মডেলকে উপরে পাঠানো বডি অপরিবর্তিত থাকে। একটি পর্যবেক্ষিত অনুরোধও কোনও স্থায়ী মেমোরি পূরণ করে না (অনুরোধ এবং প্রতিক্রিয়া উভয়ই নিষ্কাশন এড়ানো হয়), তাই মডেলের নিজস্ব উত্তর ট্রান্সক্রিপ্ট টেক্সটকে মেমোরিতে প্রতিধ্বনিত করতে পারে না।

**কাঁচা ভিডিও ক্ষেত্র (#12430)।** যখন ব্রিজ সক্ষম হয় এবং স্থানীয় ভিডিও সমর্থন অজানা বা অনুপস্থিত থাকে, সংজ্ঞায়িত `transcript`/`audioTranscript` ক্ষেত্রগুলি `videoBridgeObserved` সক্রিয় করে, বর্ণনা ব্যর্থতা বা `maxVideos` সীমার পরেও। `null` এবং খালি স্ট্রিংগুলি গণনা হয়; অনুপস্থিত ক্ষেত্র এবং অ-ভিডিও মেটাডেটা হয় না। সংরক্ষিত কপিগুলি এই ক্ষেত্রগুলি রেড্যাক্ট করে বা অনুরোধটি বাদ দেয়, এবং ক্যাশ/মেমোরি বাইপাস করা হয়।

সেই ফ্যালব্যাক পাথগুলিতে, বৈধ কলার কিউগুলি সমর্থিত `text`/`input_text` অংশে পরিণত হয়, যা অ-মানক প্রদানকারী ক্ষেত্রের পরিবর্তে। উভয় অনুরোধ-সরবরাহিত ট্র্যাকগুলি অবিশ্বাস্য `client` পর্যবেক্ষণ হিসাবে রয়ে যায়, একটি স্পষ্ট সতর্কতার সাথে যে ভিডিওটি বর্ণনা করা হয়নি এবং টাইমস্ট্যাম্পগুলি মিডিয়ার বিরুদ্ধে যাচাই করা হয়নি। বিদ্যমান 256-কিউ/64-KiB মোট এবং প্রতি-কিউ বাজেট উভয় ট্র্যাকের জন্য প্রযোজ্য; টাইমস্ট্যাম্পগুলি ব্রোকারের 600-সেকেন্ড সিলিং এবং যে কোনও সরবরাহিত ফোকাস উইন্ডোর মধ্যে ফিট করতে হবে। অবৈধ ট্র্যাকগুলি বাতিল করা হয়, অযৌক্তিক টেক্সট হিসাবে ফরওয়ার্ড করা হয় না; একটি বৈধ সিবলিং এখনও ব্যবহার করা যেতে পারে যতক্ষণ না তাদের সম্মিলিত বাজেট অতিক্রম করা হয়। শূন্য/খালি ক্ষেত্রগুলি কোনও টেক্সট যোগ করে না। এই ফ্যালব্যাক দ্বারা কোনও মিডিয়া ফেচ বা ট্রান্সক্রিপশন যোগ করা হয় না। ট্রান্সক্রিপ্ট এক্সটেনশন ক্ষেত্রগুলি ফ্যালব্যাক ভিডিও ক্যারিয়ার এবং এর `video_url`/`source` অবজেক্ট থেকে সরানো হয়। OpenAI ওয়্যার অ্যালাওলিস্ট কঠোর থাকে; অজানা-স্থানীয় ভিডিও ক্যারিয়ারগুলি উপলব্ধ থাকে এবং পরিচিত টেক্সট-শুধু লক্ষ্যগুলি নিরাপদ মার্কার রাখে। কাঠামোগত রিডাকশন শ্যাডোগুলি সংযুক্ত ট্রান্সক্রিপ্ট টেক্সটকে রক্ষা করে, যখন মূল কলার-মালিকানাধীন অনুরোধ অপরিবর্তিত থাকে। স্থানীয়-সমর্থিত লক্ষ্য এবং অক্ষম ব্রিজগুলি তাদের বিদ্যমান বাইপাস আচরণ বজায় রাখে।

অতিরিক্ত সংরক্ষিত কপিগুলি একই পর্যবেক্ষিত-অনুরোধ সংকেত ব্যবহার করে। কাঁচা প্রি-গার্ডরেল ক্লায়েন্ট-অনুরোধ স্ন্যাপশট, মেমরিতে মুলতুবি থাকা অনুরোধ, এবং প্রাথমিক বাতিল-অনুরোধ লগ কাঠামোগতভাবে ভিডিও অংশগুলিতে ট্রান্সক্রিপ্ট ক্ষেত্রগুলি প্রতিস্থাপন করে; পাইপলাইন পর্যায় এবং প্রসঙ্গ হ্যান্ডঅফ দ্বারা সংশ্লেষিত স্ট্রিং প্রম্পটগুলি সংরক্ষিত-অনুরোধ-বডি সিঙ্কে রিডাক্ট করা হয়। সংরক্ষিত `video_content_removed` মার্কার `previous_response_id` অব্যাহতিকে বন্ধ করে দেয় বরং সেই টেক্সট পুনর্গঠন করে যা ইচ্ছাকৃতভাবে বাতিল করা হয়েছিল। যদি একটি পর্যবেক্ষিত অনুরোধ তার প্রতি-অংশ রিডাকশন শ্যাডো লগ করার আগে হারিয়ে যায়, অথবা এমনকি কয়েকটি ভিডিও শ্যাডোর মধ্যে একটি পরে অনুরোধের পরিবর্তনের পরে মেলেনি, তবে সংরক্ষিত অনুরোধ বডিটি সম্পূর্ণরূপে বাদ দেওয়া হয় পরিবর্তে আংশিকভাবে রিডাক্ট করা ট্রান্সক্রিপ্ট বজায় রাখার।

একটি পর্যবেক্ষিত অনুরোধের জন্য, একটি মডেল প্রতিক্রিয়া ট্রান্সক্রিপ্টের যেকোনো অংশ উদ্ধৃত করতে পারে একটি কাঠামোগত কিউ সীমানা ছাড়াই। এর সংরক্ষিত কল-লগ `responseBody` তাই একটি বাদ দেওয়া মার্কার দ্বারা প্রতিস্থাপিত হয়; বিস্তারিত পাইপলাইন আর্টিফ্যাক্ট (যা উপরের/ক্লায়েন্ট বডি এবং স্ট্রিম চাঙ্ক অন্তর্ভুক্ত করতে পারে) সংরক্ষিত হয় না। অর্থনৈতিক, আইডেম্পোটেন্সি, এবং যুক্তি-রিপ্লে ক্যাশগুলি সেই অনুরোধের জন্য পড়া এবং লেখাকে বাইপাস করে। প্রদানকারী অনুরোধ এবং ক্লায়েন্ট-দৃশ্যমান প্রতিক্রিয়া অপরিবর্তিত থাকে। বিস্তারিত আর্টিফ্যাক্ট বাদ দেওয়ার সময় অগ্রিম কিপঅলাইভ বাইটগুলি অস্থায়ী বাফার থেকে নিষ্কাশিত হয়। কিরোর ভুল ফর্ম্যাটের ইভেন্টস্ট্রিম সতর্কতা শুধুমাত্র পে-লোড বাইটের সংখ্যা রিপোর্ট করে, কখনও তার বিষয়বস্তু বা JSON পার্সারের কাঁচা ত্রুটি নয়। এটি দাবি করে না যে প্রতিটি অ-সম্পর্কিত প্রদানকারী/প্লাগইন ডায়াগনস্টিক নিরীক্ষিত হয়েছে; বিস্তৃত সংরক্ষিত-সিঙ্কSweep #11658-এ ট্র্যাক করা হয়।

অভ্যন্তরীণ `/api/modality-bridge/video/drilldown` জীবনচক্র একটি পৃথক, লুপব্যাক/টোকেন-প্রমাণিত ক্যাশ সাবস্ট্রেট। প্রতিটি অপারেশন একটি ক্যানোনিকাল অপাক প্রধান আইডি প্রয়োজন। একটি উৎপাদন কলার সক্ষম করার আগে, এটি প্রমাণিত টেন্যান্ট থেকে সেই আইডি বের করতে হবে এবং কখনও ক্লায়েন্ট-নির্বাচিত মান ফরওয়ার্ড করা উচিত নয়। ক্যাশ কী সেই প্রধানকে ক্যানোনিকাল সেশন এবং ভিডিও-রেফারেন্স আইডির সাথে বাঁধে, শুধুমাত্র তাদের SHA-256-উৎপন্ন কীগুলি সংরক্ষণ করে, এবং পড়া এবং মুছা উভয়কেই একই প্রধানের জন্য সীমাবদ্ধ করে। ক্যাশে প্রতি এন্ট্রিতে সর্বাধিক 16টি উৎপন্ন JPEG ফ্রেম সংরক্ষণ করে, দশ মিনিট পরে তাদের মেয়াদ শেষ করে, এবং সীমাবদ্ধ `start`/`end` পড়া বা স্পষ্ট সেশন মুছার সমর্থন করে।

প্রতিটি প্রধান 16টি এন্ট্রি এবং 64 MiB ক্যানোনিকাল JPEG ডেটাতে সীমাবদ্ধ। এই সীমাগুলি বৈশ্বিক 64-এন্ট্রি/256 MiB সিলিং থেকে স্বাধীন: প্রধান কোটা চাপ শুধুমাত্র সেই প্রধানের সর্বনিম্ন-সাম্প্রতিক-ব্যবহৃত এন্ট্রিগুলি বাতিল করে, তার আগে বৈশ্বিক LRU বাতিল করা হয়। মেয়াদ শেষ হওয়া এন্ট্রিগুলি ক্যাশ কার্যকলাপের উপর প্রধান এবং বৈশ্বিক হিসাব থেকে মুছে ফেলা হয়, যখন বাতিলকরণ এবং যাচাইকরণ ব্যর্থতা আংশিক প্রতিস্থাপন সম্পন্ন করে না।

ক্যাশে অ-ক্যানোনিকাল বেস64, অতিরিক্ত প্যাডিং, অ-জেপিজি মিডিয়া, ভুল ফর্ম্যাট বা কাটা জেপিজি, এবং সীমাবদ্ধ পূর্ণ-ছবি `sharp` ডিকোডের সময় একটি সতর্কতা উৎপন্ন করা জেপিজি প্রত্যাখ্যান করে। এটি প্রতিটি গৃহীত চিত্রকে একটি ক্যানোনিকাল JPEG হিসাবে পুনরায় কোড করে, কলার ক্ষেত্রগুলির উপর নির্ভর না করে ডিকোড করা বাইট থেকে প্রস্থ এবং উচ্চতা বের করে, এবং কোনও ট্রেইলিং পলিগ্লট বাইট ফেলে দেয় পরিবর্তে তাদের বজায় রাখার। শুধুমাত্র সীমাবদ্ধ ক্যানোনিকাল কম্প্রেসড বাফার উভয় কোটা চার্জ করা হয়। JSON ওয়্যার সীমা 32 MiB ডিকোড-ইনপুট সিলিংয়ের জন্য বেস64 অতিরিক্ত অন্তর্ভুক্ত করে। প্রতিটি সংরক্ষিত উৎপত্তি তার যাচাইকৃত JPEG ফরম্যাট/রেজোলিউশন, স্যাম্পলিং নীতি, উৎপত্তি সংস্করণ, সৃষ্টির সময়, সার্ভার-গণনা করা বিষয়বস্তু হ্যাশ, এবং হ্যাশ করা প্যারেন্ট রেফারেন্সের পাশাপাশি বিশ্বাসযোগ্য কলারের প্যারেন্ট-কনটেন্ট হ্যাশ রেকর্ড করে। বাতিলকরণ অ্যাসিঙ্ক্রোনাস ডিকোড/হ্যাশ পর্যায়ের মধ্যে পরীক্ষা করা হয় পারমাণবিক ক্যাশ কমিটের আগে।

উৎপাদন প্রযোজক ইতিমধ্যেই-উৎপন্ন ব্রোকার ফ্রেমগুলি শুধুমাত্র সফল ভিজ্যুয়াল বিশ্লেষণের পরে পুনরায় ব্যবহার করে, দ্বিতীয় ভিডিও ডাউনলোড/এক্সট্রাকশন ছাড়াই। এটি অপারেটর `modalityBridgeVideoDrilldownEnabled=true`, কঠোর প্রতি-অংশ `drilldown: true`, এবং একটি প্রমাণিত API-কী রেকর্ড আইডি প্রয়োজন। ক্লায়েন্ট-ঘোষিত প্রধান/সেশন মানগুলি কখনও মালিকানা প্রতিষ্ঠা করে না। এই তিনটি শর্ত ছাড়া এটি হ্যাশ, রিসাইজ বা অতিরিক্ত ফ্রেমগুলি বজায় রাখে না। রিটেনশন ব্যর্থতা ব্যবহারযোগ্য ভিজ্যুয়াল প্রতিক্রিয়া সংরক্ষণ করে। সম্মত অনুরোধগুলি সম্পূর্ণ-ভিডিও ফলাফল ক্যাশ বাইপাস করে যাতে ক্যাশে করা ফলাফলগুলি কখনও পুনরায় হ্যান্ডেল না করে।

সফল JSON এবং SSE প্রতিক্রিয়া সর্বাধিক চারটি অস্বচ্ছ হ্যান্ডেল প্রকাশ করে `x-omniroute-video-drilldown` হেডারে। অনুমোদিত ব্রাউজার উত্সগুলি সেই হেডারটি পড়তে পারে CORS উত্স নীতি প্রসারিত না করেই। নতুন হ্যান্ডেলগুলি ব্যবহার করে `v1.<32-byte random base64url token>` এবং রেজিস্ট্রি শুধুমাত্র তাদের SHA-256 হ্যাশ সংরক্ষণ করে। পাঠক/হেডার পার্সার পুরানো 64-হেক্স টোকেনও গ্রহণ করে। প্রমাণীকৃত পাবলিক কনজিউমার হল `GET /api/v1/video-bridge/drilldown?handle=...`, যা স্বতন্ত্রভাবে গেটেড `modalityBridgeVideoDrilldownRemoteEnabled=true` দ্বারা। স্পষ্টভাবে সংরক্ষিত মিথ্যা অ্যাক্সেস বাতিল করে এমনকি যখন পুরানো `OMNIROUTE_VIDEO_BRIDGE_DRILLDOWN_REMOTE_ENABLED` env ফFallback সক্ষম থাকে। উৎপাদন সংরক্ষণে সমান্তরাল পুরানো `OMNIROUTE_VIDEO_BRIDGE_DRILLDOWN_ENABLED` ফFallback রয়েছে। উভয় ফFallback ডিফল্টভাবে বন্ধ থাকে।

কনজিউমার প্রমাণীকৃত কী থেকে মালিকানা অর্জন করে, কী নীতি প্রয়োগ করে এবং অজানা, মেয়াদোত্তীর্ণ এবং অন্য কী-এর হ্যান্ডেলের জন্য একই 404 ফেরত দেয়। এটি গ্রহণ করে `variant=preview|standard|detail` (সর্বাধিক JPEG মাত্রা 320/640/1280, কখনও আপস্কেল করা হয় না), `limit=1..8` (অথবা পুরানো `frames` উপনাম, কখনও উভয় নয়), শূন্য-ভিত্তিক `page`, এবং ঐচ্ছিক `start`/`end` ফোকাস সেকেন্ড। ডুপ্লিকেট কোয়েরি কী এবং বিপরীত ফোকাস উইন্ডোগুলি প্রত্যাখ্যাত হয়। প্রত্যেকটি ফেরত দেওয়া ভেরিয়েন্টের একটি হ্যাশ থাকে তার প্রকৃত বিষয়বস্তু এবং প্রকৃত রেজোলিউশন মেটাডেটা, যা সংরক্ষিত উৎসের সাথে সংযুক্ত। ভেরিয়েন্টগুলি পড়ার সময় তৈরি হয় বরং অতিরিক্ত সংরক্ষিত কপি হিসাবে সংরক্ষিত হয়। JSON প্রতিক্রিয়া, Base64/envelope সহ, 32 MiB এ সীমাবদ্ধ; একটি বৃহৎ পৃষ্ঠা 413 ফেরত দেয় এবং ক্লায়েন্টকে কম ফ্রেমের জন্য অনুরোধ করতে হবে। পড়া প্রতিটি আকার পরিবর্তনের চারপাশে বাতিলকরণ পরীক্ষা করে এবং ফেরত দেওয়ার আগে হ্যান্ডেলের বৈধতা পুনরায় পরীক্ষা করে। মালিক দ্বারা `DELETE` আইডেম্পোটেন্ট; মুছে ফেলা বা TTL মেয়াদ শেষ হওয়া সংরক্ষিত উৎস এবং ব্যবহার হিসাব মুক্ত করে।

শেয়ার করা স্টোর প্রক্রিয়া-স্থানীয়: হ্যান্ডেলগুলি পুনরায় চালু করার সময় মেয়াদ শেষ হয় এবং স্বাধীন OmniRoute প্রক্রিয়াগুলির মধ্যে স্থানান্তরযোগ্য নয়। ব্যবস্থাপনা পরিসংখ্যান কার্যকর সংরক্ষণ/দূরবর্তী নীতি এবং মোট সংরক্ষিত এন্ট্রি/বাইট প্রকাশ করে, কখনও মিডিয়া, রেফারেন্স, প্রধান আইডি বা হ্যান্ডেল নয়। ভিডিও সেটিংস প্যানেল সেই মানগুলি দেখায় এবং উভয় সম্মতি সুইচ সংরক্ষণ করতে পারে। এই বাস্তবায়ন ডকুমেন্টেশন লাইভ স্থাপন বা প্রচারের প্রমাণ নয়; বাস্তব-মডেল গ্রহণ আলাদাভাবে ট্র্যাক করা হয়।

ফ্রেমগুলি কনফিগার করা ভিডিও মডেলের সাথে ক্রমাগত ক্যাপশন করা হয়। একটি খালি ভিডিও ওভাররাইড ভিশন সেটিং উত্তরাধিকারী; যদি উভয়ই খালি হয়, তবে ভিশন অটো-রাউটার কার্যকর ভিশন-সক্ষম মডেল নির্বাচন করে। সফল ক্যাপশনগুলি মূল অংশটি একটি স্থিতিশীল `[Video description:` প্রিফিক্স দিয়ে প্রতিস্থাপন করে যা পাঠ্যটিকে একটি অবিশ্বস্ত মিডিয়া-উৎপন্ন পর্যবেক্ষণ হিসাবে চিহ্নিত করে এবং নিম্নবর্তী মডেলগুলিকে মিডিয়াতে পাওয়া নির্দেশনাগুলি অনুসরণ করতে বলে। ফ্রেম-ক্যাপশন ক্যাশ কী JPEG বাইট, প্রম্পট, টাইমস্ট্যাম্প এবং কার্যকর মডেল অন্তর্ভুক্ত করে; শুধুমাত্র সফল ক্যাপশনগুলি ক্যাশ করা হয়। ক্যাশ এন্ট্রিগুলি প্রকৃত সফল প্রযোজক মডেল সংরক্ষণ করে, একটি ব্যাকআপ মডেল সহ; ব্রিজ রিপোর্ট করে `mixed` যখন বিভিন্ন ফ্রেম বিভিন্ন মডেলের দ্বারা উত্পাদিত হয়। একটি ক্যাশ হিট সেই প্রযোজক পরিচয় পুনরায় ব্যবহার করে পরিবর্তে এটি অনুরোধ করা রাউটিং পরিকল্পনা হিসাবে পুনঃলেবেল করে। সম্পূর্ণ-ভিডিও ফলাফল ক্যাশ প্রতিটি ইনপুটের উপর কী করা হয় যা আউটপুট পরিবর্তন করে — প্রম্পট, কার্যকর মডেল, স্যাম্পলিং নীতি, ফ্রেম সংখ্যা, অর্থনৈতিক বিশ্লেষণ মোড, স্বাভাবিকীকৃত ফোকাস হিন্টের SHA-256 ফিঙ্গারপ্রিন্ট, ফোকাস উইন্ডো, `transcript`, `audioTranscript`, এবং যোগাযোগ-শীট পতাকা — তাই এই যে কোনও মাত্রা পরিবর্তন একটি ক্যাশ মিস, কখনও একটি পুরনো পুনঃব্যবহার নয়। ভিজ্যুয়াল ডিডুপ নীতি সংস্করণ, থ্রেশহোল্ড, এবং সীমাবদ্ধ প্রার্থী-ফ্রেম সংখ্যা ফলাফল-ক্যাশ কী এবং মেটাডেটাতে স্পষ্ট; একটি নীতি পরিবর্তন তাই একটি পুরনো সম্পূর্ণ-ভিডিও বর্ণনা পুনরায় ব্যবহার করতে পারে না। ফলাফল-ক্যাশ v4 মেটাডেটা মোড এবং ফিঙ্গারপ্রিন্ট রাখে, কখনও কাঁচা ব্যবহারকারী কাজ নয়। গার্ডরেল মেটাডেটা উভয় অনুরোধ করা এবং কার্যকর বিশ্লেষণ মোড রিপোর্ট করে; একটি অনুরোধ করা `focused` মোড ব্যবহারযোগ্য ব্যবহারকারী পাঠ্য ছাড়া কার্যকরভাবে `full` হিসাবে রিপোর্ট করা হয়।

গার্ডরেল প্রতিটি সমর্থিত ভিডিও অংশ বের করে কিন্তু `modalityBridgeVideoMaxVideos` এর বেশি বর্ণনা করে না। একটি লক্ষ্য যা প্রমাণিত হয়েছে `supportsVideo === false`, ব্যর্থ এবং সীমার বাইরে ভিডিওগুলি স্পষ্ট নিরাপদ পাঠ্য চিহ্নক হয়ে যায় যাতে কোনও কাঁচা ভিডিও বেঁচে না থাকে। যখন সক্ষমতা অজানা, সেই অংশগুলি তাদের ভিডিও ক্যারিয়ার সংরক্ষণ করে; কোনও ব্যাকআপ ট্রান্সক্রিপ্ট উপরের সীমাবদ্ধ পাঠ্য রূপান্তরের পরে অনুসরণ করে। `supportsVideo === true` সহ লক্ষ্যগুলি ব্রিজকে বাইপাস করে। ক্লায়েন্ট অনুরোধ বাতিল সংকেত ডাউনলোড, ব্রোকার কিউ, সাবপ্রসেস এবং ক্যাপশন কলগুলির মাধ্যমে প্রেরিত হয়; বাতিলগুলি ভিডিওগুলির মধ্যে থামিয়ে দেয় এবং কখনও কাঁচা মিডিয়াতে ব্যর্থ হয় না।

রানটাইম সেটিংস DB-সমর্থিত এবং Zod-ভ্যালিডেটেড:

| কী                                  | ডিফল্ট      | পরিসীমা / আচরণ                                                                                           |
| ----------------------------------- | ----------- | -------------------------------------------------------------------------------------------------------- |
| `modalityBridgeVideoEnabled`        | `false`     | ঐচ্ছিক রানটাইম, অপ্ট-ইন                                                                                  |
| `modalityBridgeVideoAnalysisMode`   | `"full"`    | `full` সাধারণ ক্যাপশন সংরক্ষণ করে; `focused` সীমাবদ্ধ, অবিশ্বস্ত সর্বশেষ-ব্যবহারকারী প্রসঙ্গ ব্যবহার করে |
| `modalityBridgeVideoModel`          | `""`        | ভিশন ব্রিজ মডেল উত্তরাধিকারী                                                                             |
| `modalityBridgeVideoFrameCount`     | `8`         | 1–16                                                                                                     |

লিগ্যাসি সংরক্ষিত ভিডিও টাইমআউট মান 120 সেকেন্ডের উপরে ব্রোকার ডেডলাইনে ক্ল্যাম্প করা হয়; সেই সীমার উপরে নতুন সেটিংস লেখা প্রত্যাখ্যাত হয়। `GET /api/modality-bridge/video/runtime` প্রমাণীকরণ বা রানটাইম প্রোবিংয়ের আগে বিশ্বস্ত স্ট্যাম্পড লুপব্যাক লোকালিটি প্রয়োজন, তারপর ব্যবস্থাপনা প্রমাণীকরণ প্রয়োজন। এটি শুধুমাত্র `available`, স্যানিটাইজড FFmpeg/ffprobe সংস্করণ এবং রানটাইম অপ্রাপ্য হলে একটি নির্দিষ্ট কারণ ফেরত দেয়। অভ্যন্তরীণ নিষ্কাশন এন্ডপয়েন্ট একটি পাবলিক আপলোড API নয়: কিউ স্যাচুরেশন `503` এবং `Retry-After` ফেরত দেয়, একটি কলার ডিসকানেক্ট `499` ফেরত দেয়, এবং নির্দিষ্ট ব্রোকার ডেডলাইন `504` ফেরত দেয়। রূপান্তরিত প্রতিক্রিয়া কেন্দ্রীয় `x-omniroute-modality-bridge` হেডারে `video->text;model=<visionModel>;parts=<videos>` যোগ করে ভিশন বা অডিও সেগমেন্টগুলি সরিয়ে না ফেলে।

### PII Masker (`piiMasker.ts`)

**দুইটি** স্তরে চলে।

- **`preCall`** পে-লোড ক্লোন করে, `system`, `messages`, `input`, এবং `prompt` (সাধারণ স্ট্রিং আইটেম সহ) হাঁটে, এবং স্ট্রিং `content`/`text` ক্ষেত্রগুলিতে `processPII()` (থেকে `@/shared/utils/inputSanitizer`) প্রয়োগ করে। যখন `PII_REDACTION_ENABLED=true`, সনাক্ত করা PII আউটবাউন্ড পে-লোডে রেড্যাক্ট করা হয়। এটি `INPUT_SANITIZER_MODE` এর উপর নির্ভরশীল নয় (যা শুধুমাত্র প্রম্পট-ইনজেকশন নীতিকে নিয়ন্ত্রণ করে)। যখন রেড্যাকশন বন্ধ থাকে, কল রেকর্ড সনাক্তকরণ গণনা করে বিষয়বস্তু পুনরায় লেখার ছাড়া।
- **`postCall`** প্রতিক্রিয়া গভীরভাবে ক্লোন করে, `sanitizePIIResponse()` চালায় এবং Responses-API-আকৃতির মাস্কার (`maskResponsesOutput` — `output_text` এবং `output[].content[].text` কভার করে)। যদি কোনো রেড্যাকশন ঘটে, পরিবর্তিত প্রতিক্রিয়া মূলটির পরিবর্তে আসে।

গার্ডরেল কখনোই ব্লক করে না; এটি শুধুমাত্র মন্তব্য করে (`meta.detections`, `meta.redacted`) বা পুনরায় লেখে।

### Prompt Injection (`promptInjection.ts`)

ব্যবহারকারী সরবরাহিত বিষয়বস্তুতে শত্রুতাপূর্ণ কাঠামো সনাক্ত করে এবং কনফিগার করা নীতি প্রয়োগ করে। আচরণ পরিবেশ ভেরিয়েবল এবং কনস্ট্রাক্টর বিকল্প দ্বারা চালিত হয়:

| সেটিং           | Env var                                                                                               | ডিফল্ট | প্রভাব                                                                                                                                                                                    |
| --------------- | ----------------------------------------------------------------------------------------------------- | ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| সক্ষম           | `INPUT_SANITIZER_ENABLED`                                                                             | `true` | যখন `false`, গার্ডরেল শর্ট-সার্কিট করে।                                                                                                                                                   |
| মোড             | `INJECTION_GUARD_MODE` / `INPUT_SANITIZER_MODE`                                                       | `warn` | ইনজেকশন নীতি: `block`, `warn`, বা `log`। (`redact` ব্যাক-কাম্প্যাটের জন্য গৃহীত কিন্তু ইনজেকশন টেক্সট মুছে ফেলে না; PII পুনরায় লেখার অনুরোধ `PII_REDACTION_ENABLED` দ্বারা নিয়ন্ত্রিত।) |
| ব্লক থ্রেশহোল্ড | `blockThreshold` বিকল্প / `INPUT_SANITIZER_BLOCK_THRESHOLD` (উপনাম `INJECTION_GUARD_BLOCK_THRESHOLD`) | `high` | ব্লক করার জন্য প্রয়োজনীয় সর্বনিম্ন তীব্রতা। ডিফল্টে মিডিয়াম শুধুমাত্র পর্যবেক্ষণ।                                                                                                      |

**মোড অগ্রাধিকার** (`getMode`): কলার `options.mode` →
`INJECTION_GUARD_MODE` **ডিবি ফিচার-ফ্ল্যাগ ওভাররাইড** (ড্যাশবোর্ড → সেটিংস →
ফিচার ফ্ল্যাগ) → `INJECTION_GUARD_MODE` env → `INPUT_SANITIZER_MODE` env →
`warn`। একটি ড্যাশবোর্ড ওভাররাইড তাই env ভেরিয়েবলগুলির উপর জয়ী হয়, তাই ফিচার ফ্ল্যাগস UI চলমান গার্ড লাইভ নিয়ন্ত্রণ করে (কোনও পুনরায় শুরু ছাড়াই)। ডিবি পড়া নিরাপদ: যদি এটি ত্রুটি করে, গার্ড env-ভিত্তিক আচরণে ফিরে আসে, এবং যখন কোনও ওভাররাইড সেট করা হয় না তখন আচরণ env-শুধুমাত্র সমাধানের সাথে অভিন্ন।

সনাক্তকরণ উৎস:

1. `sanitizeRequest()` থেকে `@/shared/utils/inputSanitizer` (পাইপলাইনে অন্যত্র ব্যবহৃত শেয়ারড ডিটেক্টর সেট)।
2. বিল্ট-ইন `DEFAULT_GUARD_PATTERNS` (বর্তমানে `system_override_inline` এবং `markdown_system_block`, উভয়ই `high` তীব্রতা)।
3. কনস্ট্রাক্টর বিকল্পের মাধ্যমে পাস করা ঐচ্ছিক `customPatterns` (স্ট্রিং, রেগেক্স, বা `{ name, pattern, severity }` রেকর্ড)।

যখন `mode === "block"` **এবং** অন্তত একটি সনাক্তকরণ তীব্রতা থ্রেশহোল্ড পূরণ করে, `preCall` ফেরত দেয় `{ block: true, message: "Request rejected: suspicious content detected" }`। `warn`/`log` মোডে গার্ডরেল লগ করে কিন্তু কলটিকে অনুমতি দেয়। শেয়ারড হেল্পার `evaluatePromptInjection()` কলারদের জন্যও রপ্তানি করা হয়েছে যারা রেজিস্ট্রি ছাড়াই প্রম্পটগুলি মূল্যায়ন করতে চান।

**স্ক্যান বাউন্ড (v3.8.20):** ডিটেক্টর শুধুমাত্র **প্রথম 16 KB** যোগ করা প্রম্পট টেক্সট পরিদর্শন করে — `MAX_INJECTION_SCAN_BYTES = 16 * 1024` (16 384 বাইট) `src/shared/utils/inputSanitizer.ts` এ। উভয় `detectInjection()` এবং `evaluatePromptInjection()` `slice(0, MAX_INJECTION_SCAN_BYTES)` প্যাটার্ন লুপ চালানোর আগে। ইনজেকশন নির্দেশিকা ইনপুটের শীর্ষের কাছে থাকে, তাই এটি বহু-শত-কেবি পে-লোডে রেগেক্স CPU/GC সীমাবদ্ধ করে সনাক্তকরণ দুর্বল না করে (cf. #3932, #4041)।

### Credential Masker (`credentialMasker.ts`)

**দুইটি** স্তরে চলে, ডিফল্ট চেইনে শেষ (অগ্রাধিকার `95`)। আউটবাউন্ড পে-লোড (বার্তা বিষয়বস্তু, টুল-কল যুক্তি, টুল ফলাফল) **এবং** প্রদানকারী প্রতিক্রিয়া থেকে পরিচিত API-কী / সিক্রেট-টোকেন প্যাটার্নগুলি রেড্যাক্ট করে, তাই একটি প্রম্পটে পেস্ট করা একটি শংসাপত্র (অথবা একটি টুল ফলাফলে প্রতিধ্বনিত) আপস্ট্রিম প্রদানকারী বা ক্লায়েন্টের কাছে ফাঁস হয় না।

- **অপ্ট-ইন শুধুমাত্র**, PII রিডাকশন এর মতো একই রীতি (হার্ড রুল #20-সংলগ্ন):
  `settings.credentialRedactionEnabled === true` **অথবা**
  `CREDENTIAL_REDACTION_ENABLED=true` না হওয়া পর্যন্ত অক্ষম। এটি বন্ধ থাকলে, গার্ডরেল একটি নো-অপ —
  এটি কখনো ব্লক করে না এবং কখনো পুনরায় লেখে না।
- `redactCredentials()` সম্পূর্ণ পেলোড/প্রতিক্রিয়া গাছটি হাঁটে (`walkValue()`,
  প্রোটোটাইপ-দূষণ-নিরাপদ, `WeakSet` এর মাধ্যমে সাইকেল-নিরাপদ) এবং মেলানো অংশগুলোকে
  `[REDACTED:<type>]` প্লেসহোল্ডার দিয়ে প্রতিস্থাপন করে, শুধুমাত্র সেই শাখাগুলো ক্লোন করে
  যা সত্যিই পরিবর্তিত হয়েছে।
- `CREDENTIAL_PATTERNS` LLM প্রদানকারী কী (OpenAI, OpenAI-proj,
  Anthropic, Google, Hugging Face, Replicate), VCS/SaaS টোকেন (GitHub, Slack,
  Linear, Notion, npm, Postman, Discord), পেমেন্ট কী (Stripe, Square), ক্লাউড
  কী (AWS অ্যাক্সেস কী, Twilio, SendGrid, Mailgun), প্রাইভেট কী / JWTs,
  ক্রেডেনশিয়াল-বহনকারী সংযোগ স্ট্রিং (`mongodb://user:pass@...`, ইত্যাদি), এবং
  একটি সাধারণ `Authorization`/`x-api-key`/`api-key`/`apikey` হেডার-মান
  প্যাটার্ন। হেডার-আকৃতির কী (`authorization`, `x-api-key`, `api-key`,
  `apikey`) কাঠামোগতভাবে রিডাক্ট করা হয় (শুধুমাত্র মান, স্কিম প্রিফিক্স যেমন
  `Bearer `/`Basic ` সংরক্ষিত) সাধারণ টেক্সট রেগেক্সের মাধ্যমে নয়।
- গার্ডরেল কখনো ব্লক করে না; এটি শুধুমাত্র পুনরায় লেখে (`modifiedPayload` /
  `modifiedResponse`) এবং মন্তব্য করে (`meta.credentialsRedacted`, `meta.count`)।

রিগ্রেশন গার্ড: `tests/unit/credential-masker-guardrail.test.ts`।

## বেস কনট্র্যাক্ট (`base.ts`)

```typescript
class BaseGuardrail {
  enabled: boolean;
  name: string;
  priority: number;

  constructor(name: string, options?: { enabled?: boolean; priority?: number });

  async preCall(payload: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;

  async postCall(response: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;
}

interface GuardrailResult<TValue = unknown> {
  block?: boolean; // true হলে চেইনটি তাৎক্ষণিকভাবে থেমে যায়
  message?: string; // ব্লক করার সময় প্রদর্শিত হয়
  meta?: Record<string, unknown> | null;
  modifiedPayload?: TValue; // অনুরোধটি পুনর্লিখতে preCall দ্বারা ফেরত দেওয়া হয়
  modifiedResponse?: TValue; // প্রতিক্রিয়াটি পুনর্লিখতে postCall দ্বারা ফেরত দেওয়া হয়
}

interface GuardrailContext {
  apiKeyInfo?: Record<string, unknown> | null;
  disabledGuardrails?: string[] | null;
  endpoint?: string | null;
  headers?: Headers | Record<string, unknown> | null;
  log?: GuardrailLog | Console | null;
  method?: string | null;
  model?: string | null;
  provider?: string | null;
  signal?: AbortSignal;
  sourceFormat?: string | null;
  stream?: boolean;
  targetFormat?: string | null;
}
```

একটি গার্ডরেল `void`, `{}`, অথবা `{ block: false }` ফেরত দিয়ে "কোনো পরিবর্তন নেই" নির্দেশ করে। `modifiedPayload`/`modifiedResponse` ফেরত দিলে, পরবর্তী গার্ডরেলগুলোর জন্য চেইনের মধ্য দিয়ে প্রবাহিত মানটি প্রতিস্থাপিত হয়।
`signal?: AbortSignal` কলারের লাইফসাইকেলটি গার্ডরেলগুলোতে বহন করে। অনুরোধ বাতিল হওয়া ইচ্ছাকৃত fail-open ব্যতিক্রম: কোনো টার্গেট raw media সমর্থন করে না বলে জানা থাকলে, media bridge-গুলো সেখানে raw media পুনরুদ্ধার না করেই কাজ বন্ধ করে এবং cleanup সম্পন্ন করে।

## রেজিস্ট্রি (`registry.ts`)

singleton `guardrailRegistry` নিম্নলিখিতগুলো প্রকাশ করে:

- `register(guardrail)` — একটি গার্ডরেল যোগ করে (অথবা normalized name অনুযায়ী প্রতিস্থাপন করে) এবং ঊর্ধ্বক্রমিক `priority` অনুযায়ী পুনরায় সাজায়।
- `clear()` / `list()` — প্রশাসনিক সহায়ক।
- `runPreCallHooks(payload, context)` — সক্রিয় গার্ডরেলগুলোর মধ্য দিয়ে পুনরাবৃত্তি করে, `modifiedPayload`-এর মাধ্যমে payload প্রবাহিত করে এবং প্রথম `block: true`-এ থেমে যায়।
- `runPostCallHooks(response, context)` — response-এর ক্ষেত্রেও একই প্রবাহ অনুসরণ করে।
- `resetGuardrailsForTests({ registerDefaults })` — পরিষ্কার test isolation-এর জন্য state মুছে দেয় এবং ঐচ্ছিকভাবে default-গুলো পুনরায় register করে।

উভয় runner `{ blocked, payload|response, results, guardrail?, message? }` ফেরত দেয়, যেখানে `results` হলো `GuardrailExecutionResult` record-এর একটি array, যাতে প্রতিটি guardrail-এর `blocked`, `skipped`, `modified`, `error`, এবং `meta` field অন্তর্ভুক্ত থাকে, যা tracing-এর জন্য উপযোগী।

### প্রতিটি অনুরোধে গার্ডরেল নিষ্ক্রিয় করা

`resolveDisabledGuardrails({ apiKeyInfo, body, headers })` বর্তমান অনুরোধের জন্য বাদ দেওয়া উচিত এমন guardrail name-এর একটি duplicate-মুক্ত list একত্রিত করে। উৎসগুলো (সবই ঐচ্ছিক এবং সবগুলো merge করা হয়):

- `apiKeyInfo.disabledGuardrails`
- Request body-এর top-level `disabledGuardrails`
- Request body-এর `metadata.disabledGuardrails`
- Header `x-omniroute-disabled-guardrails` (অথবা legacy `x-disabled-guardrails`)

মানগুলো string-এর array অথবা comma-separated string হতে পারে; name-গুলো lowercase kebab-case-এ normalize করা হয় (`pii_masker` → `pii-masker`)। ফলাফলটি `context.disabledGuardrails`-এর মাধ্যমে registry-তে পাঠানো হয়, যা মিলে যাওয়া guardrail-গুলো বাদ দেয় (`results`-এ `skipped: true`)।

## কার্যকরকরণের ক্রম

`src/sse/handlers/chat.ts` এবং
`open-sse/handlers/chatCore.ts`-এর মধ্য দিয়ে প্রবাহিত প্রতিটি অনুরোধের জন্য:

1. `resolveDisabledGuardrails(...)` API key, body এবং headers থেকে বাদ দেওয়ার তালিকা তৈরি করে।
2. `guardrailRegistry.runPreCallHooks(body, ctx)` ঊর্ধ্বক্রমিক
   priority অনুযায়ী guardrail চালায়:
   - নিষ্ক্রিয় guardrail-গুলো `skipped` হিসেবে রেকর্ড করা হয়।
   - প্রতিটি guardrail-এর `preCall`, `modifiedPayload`-এর মাধ্যমে payload পুনর্লিখতে পারে।
   - প্রথম `block: true` chain-টিকে তাৎক্ষণিকভাবে থামিয়ে দেয় এবং handler একটি
     guardrail প্রত্যাখ্যানের response ফেরত দেয়।
3. (সম্ভাব্যভাবে পুনর্লিখিত) payload combo routing এবং upstream
   dispatch-এ প্রবাহিত হয়।
4. response তৈরি হয়ে যাওয়ার পর, `guardrailRegistry.runPostCallHooks(...)`
   response-এর ওপর একই chain চালায়। এখানে `block: true` upstream
   response-টি বাদ দেয়।

যেসব guardrail exception ছোড়ে, সেগুলো `error: <message>` সহ রেকর্ড করা হয় এবং
`logger.warn`-এর মাধ্যমে log করা হয়, তবে chain চলতে থাকে—নকশাগতভাবেই এটি fail-open।

| ------------------------------------- | ------------------------- | ------------------------------------------------------------------------------------------------------- |
| `INPUT_SANITIZER_ENABLED`             | `prompt-injection`        | শনাক্তকরণ সম্পূর্ণরূপে নিষ্ক্রিয় করতে `false` সেট করুন।                                                |

`modalityBridgeCacheMaxEntries`। Legacy
`visionBridge*` key-গুলো কেবল নথিভুক্ত এক-cycle read
fallback হিসেবে গৃহীত হয়; dashboard-এর write operation-গুলো primary key ব্যবহার করে। Default এবং fallback
resolver রয়েছে `src/shared/constants/modalityBridgeDefaults.ts`-এ, আর legacy
constant-গুলো `src/shared/constants/visionBridgeDefaults.ts`-এ সংরক্ষিত আছে।

Audio, `modalityBridgeAudioEnabled`, `modalityBridgeAudioModel`,
`modalityBridgeAudioTimeout`, এবং `modalityBridgeAudioMaxClips` ব্যবহার করে, সঙ্গে shared
`modalityBridgeCache*` setting-গুলোও ব্যবহার করে। Audio-তে কোনো legacy-key fallback নেই, কারণ এই
key-গুলো Modality Bridge schema-এর সঙ্গে প্রবর্তিত হয়েছিল।

Video, `modalityBridgeVideoEnabled`, `modalityBridgeVideoAnalysisMode`,
`modalityBridgeVideoModel`,
`modalityBridgeVideoFrameCount`, `modalityBridgeVideoSamplingPolicy`,
`modalityBridgeVideoMaxVideos`, এবং
`modalityBridgeVideoTimeout` ব্যবহার করে, সঙ্গে shared `modalityBridgeCache*` setting-গুলোও ব্যবহার করে।
এটি default হিসেবে নিষ্ক্রিয় থাকে, কারণ FFmpeg/ffprobe ঐচ্ছিক operational
dependency এবং frame captioning অতিরিক্ত latency ও model cost যোগ করে।

## কাস্টম গার্ডরেইল

```typescript
import { BaseGuardrail, guardrailRegistry } from "@/lib/guardrails";

class BudgetGuardrail extends BaseGuardrail {
  constructor() {
    super("budget", { priority: 50 });
  }

  async preCall(payload, ctx) {
    if (ctx.apiKeyInfo?.budgetExceeded) {
      return { block: true, message: "Daily budget exceeded" };
    }
    return { block: false };
  }
}

guardrailRegistry.register(new BudgetGuardrail());
```

ধাপসমূহ:

1. `BaseGuardrail` সম্প্রসারণ করে `src/lib/guardrails/myGuardrail.ts` তৈরি করুন।
2. `preCall` এবং/অথবা `postCall` ইমপ্লিমেন্ট করুন।
3. হয় ইমপোর্টের সময় নিবন্ধন করুন (`registerDefaultGuardrails` থেকে পুশ করুন), অথবা
   রানটাইমে `guardrailRegistry.register(...)` কল করুন — একই নর্মালাইজড নামের
   পূর্ববর্তী যেকোনো গার্ডরেইল রেজিস্ট্রি প্রতিস্থাপন করে।
4. `tests/unit/`-এর অধীনে টেস্ট যোগ করুন (বিদ্যমান উদাহরণ:
   `tests/unit/guardrails-registry.test.ts`,
   `tests/unit/prompt-injection-guard.test.ts`,
   `tests/unit/guardrails/visionBridge.test.ts`)।

## টেস্টিং

একটি পরিচিত অবস্থা থেকে শুরু করতে টেস্টগুলোর মধ্যে `resetGuardrailsForTests()` ব্যবহার করুন।
একটি খালি রেজিস্ট্রি দিয়ে শুরু করতে `{ registerDefaults: false }` পাস করুন এবং
শুধু পরীক্ষাধীন গার্ডরেইলগুলো নিবন্ধন করুন। Vision Bridge ডিপেন্ডেন্সি
ইনজেকশন (`deps.getSettings`, `deps.callVisionModel`) গ্রহণ করে; Audio Bridge সেটিংস,
সক্ষমতা, STT মডেল নির্বাচন, ক্রেডেনশিয়াল যাচাই এবং ট্রান্সক্রিপশনের জন্য
সমতুল্য সংযোগবিন্দু প্রকাশ করে। তাই টেস্টগুলো DB বা নেটওয়ার্ক অ্যাক্সেস ছাড়াই উভয়
ফ্লো পরীক্ষা করতে পারে।

## ইনজেকশন-গার্ড রুট কভারেজ ও রেড-টিম (পর্যায় 8 · ব্লক D)

ইনজেকশন-গার্ড (`createInjectionGuard` / `withInjectionGuard`) ব্যবহারকারীর প্রম্পট
গ্রহণ করে এমন সব রুট কভার করে। এটি `INJECTION_GUARD_MODE` মেনে চলে (ডিফল্ট `warn` = শুধু লগ;
`block` = HTTP 400 `SECURITY_001` রিটার্ন করে)।

| ধরন               | রুটসমূহ                                                                                                                                              | ডিফল্ট মোড |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ---------- |
| টেক্সট (বিদ্যমান) | `/v1/chat/completions`, `/v1/completions`, `/v1/relay/chat/completions`                                                                              | warn       |
| জেনারেটিভ         | `/v1/messages`, `/v1/responses`, `/v1/images/generations`, `/v1/images/edits`, `/v1/videos/generations`, `/v1/music/generations`, `/v1/audio/speech` | warn       |
| ডেটা              | `/v1/embeddings`, `/v1/rerank`, `/v1/search`, `/v1/moderations`                                                                                      | warn       |

টেক্সট এক্সট্রাকশন (`extractMessageContents`) `messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system` কভার করে।

**রেড-টিম (রাত্রিকালীন, `nightly-llm-security.yml`):** promptfoo যাচাই করে যে প্রতিটি রুট
`INJECTION_GUARD_MODE=block`-এ OWASP-LLM কর্পাস ব্লক করে; garak প্রোব চালায় (সিক্রেট না থাকলে এড়িয়ে যায়)।
সামঞ্জস্যের জন্য `moderations` অন্তর্ভুক্ত করা হয়েছে — ব্লক-মোডে অপারেটররা
`resolveDisabledGuardrails`-এর মাধ্যমে এটিকে অব্যাহতি দিতে পারেন।

রাত্রিকালীন ওয়ার্কফ্লোতে (`.github/workflows/nightly-llm-security.yml`, cron + ম্যানুয়াল
ডিসপ্যাচ) দুটি জব রয়েছে:

- **`promptfoo-guard` (ব্লকিং)** — `INJECTION_GUARD_MODE=block` সহ
  `promptfoo eval -c promptfooconfig.yaml` চালায়। প্রতিটি প্রতিকূল কেস (যেমন, "আগের সব
  নির্দেশনা উপেক্ষা করো…", DAN-ধাঁচের জেলব্রেক) নিশ্চিত করে যে রেসপন্সে
  `error.code === "SECURITY_001"` রয়েছে, অর্থাৎ গার্ডটি বাস্তবে রিকোয়েস্টটি প্রত্যাখ্যান করেছে।
- **`garak` (পরামর্শমূলক)** — একটি স্থানীয় OmniRoute ইনস্ট্যান্সের
  (`http://localhost:20128/v1`) বিপরীতে garak `--probes promptinject,dan,leakreplay`
  চালায়। এটি একটি প্রোভাইডার সিক্রেটের (`PROMPTFOO_PROVIDER_KEY`) ওপর নির্ভরশীল; সিক্রেট না থাকলে
  স্বাভাবিকভাবে এড়িয়ে যায় এবং এর শেষে `|| true` যুক্ত থাকে, তাই এটি CI ব্যর্থ না করে
  রিপোর্ট করে।

গার্ড হেলপারের (`createInjectionGuard` / `withInjectionGuard`) কভারেজ
প্রম্পট-বহনকারী প্রতিটি `/v1` রুটজুড়ে বিস্তৃত; প্রম্পট টেক্সট
`src/shared/utils/inputSanitizer.ts`-এর `extractMessageContents()` দ্বারা
`messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system` থেকে নেওয়া হয়।
