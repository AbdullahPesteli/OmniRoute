تفرض الحواجز (Guardrails) السلامة والسياسة وتحويلات المحتوى عند الحدود
بين OmniRoute ومقدمي الخدمة المصدر. يمكن لكل حاجز فحص (ورفض أو تحويل أو إضافة تعليق اختياريًا) حمولات الطلبات (`preCall`)
واستجابات المصدر (`postCall`).

النظام **مفتوح عند الفشل (fail-open)**: إذا ألقى حاجز خطأ أثناء التنفيذ، فإن السجل
يسجل الخطأ ويستمر مع الحاجز التالي بدلاً من إفشال الطلب.
المنع هو قرار صريح (`block: true`)، وليس حادثًا أبدًا.

## الحواجز المدمجة

يقوم السجل بتحميل ستة حواجز تلقائيًا بترتيب الأولوية عند الاستيراد
(انظر `registry.ts` → `registerDefaultGuardrails()`):

| الأولوية | الاسم               | المرحلة(s)     | الملف                 |
| -------- | ------------------- | -------------- | --------------------- |
| `5`      | `vision-bridge`     | `preCall`      | `visionBridge.ts`     |
| `6`      | `audio-bridge`      | `preCall`      | `audioBridge.ts`      |
| `7`      | `video-bridge`      | `preCall`      | `videoBridge.ts`      |
| `10`     | `pii-masker`        | `pre` + `post` | `piiMasker.ts`        |
| `20`     | `prompt-injection`  | `preCall`      | `promptInjection.ts`  |
| `95`     | `credential-masker` | `pre` + `post` | `credentialMasker.ts` |

تعمل الأرقام ذات الأولوية المنخفضة **أولاً**.

### جسر الرؤية (`visionBridge.ts`) — جسر الوضعية PR-1

يت intercept طلبات تحمل صور موجهة إلى **نماذج غير بصرية** ويقوم إما
بتوجيه الطلب بالكامل إلى نموذج قادر على الرؤية أو يستبدل أجزاء الصورة
بوصف نصي تم إنتاجه بواسطة نموذج رؤية قابل للتكوين قبل
الاتصال العلوي. هذا يسمح لمقدمي الخدمات النصية فقط بالتعامل بشفافية مع
الأحمال متعددة الأوضاع.

التدفق:

1. تخطى إذا كان النموذج المستهدف يدعم الرؤية بالفعل (ما لم يظهر في
   قائمة الجسر الإجباري `isVisionBridgeForcedModel`).
2. استخراج أجزاء الصورة عبر `extractImageParts(messages)`
   (`visionBridgeHelpers.ts`)، الذي يفوض إلى **كاشف الوسائط الموحد**
   `detectMediaParts()` في `open-sse/utils/mediaParts.ts` — المصدر الوحيد
   للحقيقة المشتركة مع فلتر التوافق المدمج.
   يتم السماح بالاستخراج لأجزاء المستوى الأعلى من الأشكال
   التي يمكن لـ `replaceImageParts` إعادة تركيبها (عقدة الاستخراج↔الاستبدال): OpenAI
   `image_url`، Anthropic base64 `source.type:"base64"`، Anthropic URL
   `source.type:"url"`، وResponses API `input_image`. الضربات المتداخلة والأشكال
   التي تحتوي على مؤشرات فقط هي مواد فلتر مدمجة ولا يتم استخراجها أبدًا.
   تخطى إذا لم يتم العثور على أي منها.
3. حل إعدادات وقت التشغيل عبر `resolveVisionBridgeRuntimeSettings()`
   (`src/shared/constants/modalityBridgeDefaults.ts`): مفاتيح إعدادات `modalityBridge*`
   الجديدة تفوز؛ تبقى مفاتيح `visionBridge*` القديمة كـ **احتياطي لدورة واحدة**
   (نافذة التراجع). تخطى قبل أي عبور وسائط عندما يكون الجسر معطلاً.
4. يحدد محدد الوضع (`modalityBridgeVisionMode`، انظر الجدول أدناه)
   ما إذا كان سيتم إعادة التوجيه أو الوصف. تعيد إعادة التوجيه `modifiedPayload` مع
   استبدال `model` فقط، بالإضافة إلى البيانات الوصفية `{ rerouted, fromModel, toModel, imagesKept }`.
5. مسار الوصف: يحدد عدد الصور عند `maxImages`، ويقوم بتكوين الطلب الواعي بالمهمة،
   ويستشير ذاكرة التخزين المؤقت للوصف، ويستدعي نموذج الرؤية **بالتوازي**
   (`Promise.allSettled`)، ويحقن أجزاء النص `[Image N]: <description>` في
   أماكنها. يؤدي الفشل في الوصف إلى إرجاع `null` ويتم **الحفاظ على** جزء الصورة الأصلي
   (#4012) — باستثناء مسار الوصف المدمج عندما يفشل كل وصف، حيث يحصل
   الاتصال غير البصري المؤكد على
   `(غير متاح — لا يوجد مزود قادر على الرؤية متصل)` كبديل (#8430).
6. إرجاع `modifiedPayload` + البيانات الوصفية (`imagesProcessed`, `descriptions`,
   `processingTimeMs`, `visionModel`).

#### محدد الوضع (`modalityBridgeVisionMode`)

| الوضع      | الافتراضي | السلوك                                                                                                                                                                                                                                       |
| ---------- | --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `auto`     | ✔         | خوارزمية قديمة، غير متأثرة (#6640/#7204): نماذج غير المدمجة/`auto/` تعيد التوجيه إلى أفضل نموذج للرؤية ما لم يكن للنموذج الأصلي بيانات اعتماد قابلة للاستخدام (ثم يتم الوصف)؛ الأهداف المدمجة دائمًا تصف.                                    |
| `describe` |           | دائمًا وصف — يتم تخطي كتلة إعادة التوجيه تمامًا؛ النموذج الذي اختاره المستخدم دائمًا يجيب.                                                                                                                                                   |
| `reroute`  |           | إعادة التوجيه القسري: يتم تجاوز حارس النموذج المحتفظ بالاعتماد. لا يزال ينطبق حارس الاعتماد لنموذج **الهدف** — عندما لا يوجد هدف للرؤية قابل للاستخدام، يسقط الطلب إلى الوصف بحيث لا تصل الصور الخام أبدًا إلى واجهة خلفية نصية فقط (#8430). |

تقطع الأوضاع القسرية **قبل** تشغيل الخوارزمية التلقائية؛ سلوك `auto`
هو مطابق تمامًا لسياج الحماية قبل PR-1.

#### نطاق مفتاح API (`visionBridgeKeyScope.ts`)

عندما يقيد مفتاح API الخاص بالمتصل `allowedConnections`، أو تجمعات الحصص
(`allowedQuotas`) أو النماذج (`allowedModels` / `blockedModels` /
`modelAccessMode: "restricted"` / `disableNonPublicModels`)، يختار الجسر فقط
نماذج إعادة التوجيه والوصف التي يمكن أن يستخدمها المفتاح، على الاتصالات التي يمكن أن يستخدمها المفتاح.
ثم يمر طلب الوصف دائمًا عبر حلقة OmniRoute الذاتية مع
رأس `x-omniroute-self-loop-key-id`، لذا فإن طلب الدردشة المستلم
يفرض سياسة الاتصال والنموذج الخاصة بذلك المفتاح مرة أخرى. تقوم `enforceApiKeyPolicy()`
بتقدير ذلك الرأس فقط مع حامله الذاتي، لذا يمكنها فقط
تضييق الوصول، ويتم رفض أي معرف لا يتم حله.

إذا لم يُسمح بنموذج رؤية للمفتاح، فإن مسار الوصف يتراجع ويمر الطلب دون تغيير،
نفس سلوك الفشل المفتوح كحاجز معطل (البيانات الوصفية `{ skipped: true, reason: "no_permitted_vision_model" }`).
تتصرف الطلبات بدون مفتاح، والمفاتيح بدون هذه القيود، تمامًا كما كانت من قبل.

#### وصف الطلب الواعي بالمهمة (`modalityBridgeVisionTaskAware`)

الإعداد الافتراضي **صحيح**. `composeVisionPrompt()` (`visionBridgeHelpers.ts`) يضيف
نص **آخر رسالة من المستخدم** (مقتطع إلى 500 حرف) إلى قاعدة
وصف الطلب، مما يوجه الوصف نحو ما طلبه المستخدم فعليًا
(نمط codex-vision-proxy) ويطلب من نموذج الرؤية نسخ النص المرئي. مع إيقاف العلم — أو عدم وجود نص من المستخدم — يتم استخدام الطلب الأساسي دون تغيير.

طلب حلقة وصف الذات المتوافقة مع OpenAI (`callVisionModelSingle()`
في `visionBridgeHelpers.ts`) يطلب دائمًا `image_url.detail: "high"` —
بشكل غير مشروط، لكل متصل/مزود، وليس مشروطًا بأي إشارة من العميل.
تدهور دقة OCR عند استخدام عينات منخفضة التفاصيل بالنسبة تمامًا لمهمة نسخ النص التي يطلبها هذا الطلب، لذا فإن طلب الوصف نفسه يطلب دائمًا تفاصيل عالية بغض النظر عن مستوى التفاصيل الذي استخدمه الطلب الوارد الأصلي. هذا يؤثر فقط على جسم الطلب الداخلي للوصف؛ لا يغير كيفية توجيه OmniRoute لـ `image_url.detail` الخاص بالمتصل في الطلب الأساسي —
يتم تطبيق هذا الافتراضي بشكل منفصل، وفقط للعملاء الذين تم اكتشافهم باستخدام OpenCode، في
`defaultImageDetail()` (`open-sse/handlers/chatCore/upstreamBody.ts`). فرع تنسيق السلك الخاص بـ Anthropic لحلقة وصف الذات لا يحتوي على حقل `detail`
ولن يتأثر بأي من الافتراضات.

#### حد مخرجات الوصف (`modalityBridgeVisionMaxChars`)

| المفتاح                        | الافتراضي | النطاق           |
| ------------------------------ | --------- | ---------------- |
| `modalityBridgeVisionMaxChars` | `0`       | `0` أو 100–50000 |

`0` (الافتراضي) يعني **لا حد** — يتم تمرير الوصف الذي تم إرجاعه بواسطة
`callVisionModel()` دون تعديل، مما يحافظ على السلوك الحالي. أي قيمة في نطاق 100–50000 تقطع الوصف مع
لاحقة `…` قبل أن يتم دمجه مرة أخرى كـ `[Image N]: <description>`
(`VisionBridgeGuardrail.preCall()` في `src/lib/guardrails/visionBridge.ts`).
قم بزيادة هذا للمهام التي تتطلب OCR كثيفة التفاصيل حيث يحتاج النموذج اللاحق إلى النسخ الكامل؛ قللها للحد من استخدام الرموز في نماذج الرؤية النشطة.
يعيش حقل لوحة المعلومات في لوحة متقدمة في علامة الرؤية
(`modality-bridge-max-chars` في `ModalityBridgeVisionTab.tsx`) ويقيد أي
قيمة بين 1 و 99 إلى الحد الأدنى 100 بينما يترك `0` صريحًا دون تغيير — `0` هو قيمة Zod صالحة في حد ذاتها
(`z.union([z.literal(0), z.number().int().min(100).max(50000)])`)، وليس مجرد
الافتراضي "غير المحدد".

#### ذاكرة التخزين المؤقت للوصف (`modalityBridge/bridgeCache.ts`)

ذاكرة تخزين مؤقت LRU + TTL في الذاكرة لمخرجات الوصف، مشتركة على مستوى العملية.
المفتاح = `sha256(imageRef + composedPrompt + configuredBridgeModel)` مع
إطار طول سابق (لا توجد تصادمات حدود الحقول). مكون النموذج هو
النموذج الجسر **المكون**، وليس النموذج الذي أجاب فعليًا —
قد يتراجع `callVisionModel` داخليًا، وسيؤدي استخدام المفتاح لكل محاولة إلى تجزئة الذاكرة المؤقتة. لا يتم تخزين الوصفات الفاشلة في الذاكرة المؤقتة. الإعدادات:

| المفتاح                         | الافتراضي | النطاق  |
| ------------------------------- | --------- | ------- |
| `modalityBridgeCacheEnabled`    | `true`    | —       |
| `modalityBridgeCacheTtlMinutes` | `60`      | 1–1440  |
| `modalityBridgeCacheMaxEntries` | `200`     | 10–5000 |

#### تطبيع الصورة عن بُعد (الوصف الذاتي/استرجاع base64)

عندما يقوم الجسر باسترجاع صورة **عن بُعد** بنفسه — استدعاء وصف Anthropic الذاتي وتحويل base64 بتنسيق claude-wire
(`ensureBase64ImagesForClaudeWire`)، كلاهما عبر
`fetchRemoteImageAsDataUri()` في `visionBridgeHelpers.ts` — يتم تمرير URI البيانات الناتج عبر `normalizeDataUri()`
(`open-sse/utils/imageNormalize.ts`) قبل أن يتم تضمينه في طلب نموذج الرؤية. يتم تقليل حجم الصور الكبيرة إلى **حافة بطول 2048 بكسل** (مطابقة
لحد إعادة الحجم الذي تطبقه OpenAI/Anthropic بالفعل على جانب الخادم)، مما يقلل
من بايتات التحميل/الكمون دون تغيير ما تراه نموذج الرؤية. يستخدم تغيير الحجم `sharp`، المحملة عبر استيراد ديناميكي: على منصة حيث يفشل تحميل ثنائياتها الأصلية، فإن `normalizeDataUri()` **لا ترمي أبدًا** — بل تتراجع
إلى تمرير البايتات الأصلية، لذا فإن مسار الوصف/تحويل base64
يستمر في العمل. يتم أيضًا تمرير بايتات غير الصورة (استرجاع لم يعد صورة قابلة للتشفير) دون تغيير. يتم تحديد هذا التطبيع للصور التي يسترجعها الجسر لاستدعائه الذاتي — لا يتم تطبيقه أبدًا على الحمولة الخام للمتصل، بما يتماشى مع مبدأ التحوير القائم على الاختيار فقط (قاعدة صارمة #20).

#### مخطط الإعدادات + الهجرة

المفاتيح الجديدة `modalityBridge*` يتم التحقق منها بواسطة Zod في `updateSettingsSchema`
(`src/shared/validation/settingsSchemas.ts`): `modalityBridgeVisionEnabled`,
`modalityBridgeVisionMode`, `modalityBridgeVisionModel`,
`modalityBridgeVisionTaskAware`, `modalityBridgeVisionPrompt`,
`modalityBridgeVisionTimeout`, `modalityBridgeVisionMaxImages`,
`modalityBridgeVisionMaxChars`, الثلاثي `modalityBridgeCache*`، ومجموعة
`modalityBridgeAudio*` المستخدمة بواسطة جسر الصوت. تقوم الهجرة
`141_modality_bridge_settings.sql` بنسخ القيم القديمة الموجودة
`visionBridge*` إلى المفاتيح الجديدة المطابقة (غير قابلة للتكرار، لا تكتب أبدًا
قيمة `modalityBridge*` تم تعيينها بواسطة المشغل)؛ تبقى المفاتيح القديمة مقبولة كخيار قراءة احتياطي لدورة إصدار واحدة.

#### رأس الشفافية + الإحصائيات

تحمل الاستجابات المحولة بواسطة الوصف
`x-omniroute-modality-bridge: image->text;model=<visionModel>;parts=<n>`
(تم إنشاؤه بواسطة `buildModalityBridgeHeader()` في `modalityBridge/bridgeStats.ts`,
مختوم بواسطة `withModalityBridgeHeader()` في `src/sse/handlers/chatHelpers.ts`).
لا تحصل الطلبات المعاد توجيهها على **أي** رأس — كانت الحمولة غير متغيرة وتبديل النموذج
مرئي بالفعل في حقل `model` لجسم الاستجابة.

`GET /api/modality-bridge/stats` (إدارة المصادقة، نفس المستوى مثل
`GET /api/settings`) يعيد العدادات في الذاكرة لكل نمط
`{ attempts, successes, bridged, cacheHits, failures, totalLatencyMs,
latencySamples, averageLatencyMs, lastUsedAt }` لـ `vision`, `audio`, و
`video`. يستخدم `averageLatencyMs` `latencySamples`، وليس جميع المحاولات، كقاسم له؛ عملية بدون توقيت لا تصنع عينة صفرية بالمللي ثانية. يبقى `bridged` الاسم البديل المتوافق مع الإصدارات السابقة للتحويلات الناجحة؛ المحاولات الفاشلة لا تزيده.
تُعيد العدادات تعيينها عند إعادة تشغيل العملية حسب التصميم
(التليمتري، وليس المحاسبة).

#### تكوين لوحة التحكم

صفحة لوحة التحكم المخصصة هي
`/dashboard/settings/modality-bridge`. تحافظ علامات التبويب `Vision`, `Audio`,
و `Video` القابلة للوصول عبر URL على معلمات الاستعلام أثناء تغيير قيمة `tab`.
تظهر علامة التبويب Vision خيارات التمكين، الوضع، اختيار النموذج (بما في ذلك الافتراضي التلقائي)، التوجيه المدرك للمهام، حدود المهلة/الصورة/طول الوصف/التخزين المؤقت المتقدمة، العدادات
وقت التشغيل، وطلب عينة محمي. علامة التبويب Audio نشطة أيضًا: تعرض
التمكين، مختار نموذج STT فقط مع Auto، حدود المهلة/القص القصوى، عدادات الصوت، واختبار عينة `input_audio`. علامة التبويب Video وظيفية: تبلغ
عن حالة وقت التشغيل لـ FFmpeg/ffprobe — واحدة من أربع حالات واجهة مستخدم صريحة (`unknown` بينما
التحقيق قيد التنفيذ أو لم يكتمل، `restricted` على مضيف لوحة تحكم غير حلقي حيث يتم تخطي التحقيق من جانب العميل، `unavailable` بمجرد التحقيق والتأكيد على عدم وجوده، أو `available` مع إصدارات FFmpeg/ffprobe) — تستمر
في الحفاظ على حدود enable/model/frame/video/timeout، وتصفية مختار النموذج لنماذج قادرة على الرؤية، وتعرض عدادات الفيديو.

تحتوي بطاقة Vision Bridge السابقة ضمن إعدادات AI على رابط توافق إلى
الصفحة الجديدة؛ لم تعد تمتلك نسخة ثانية من النموذج. توفر وسائل الإعلام أيضًا
روابط لعمليات تحويل الصورة إلى نص وتحويل الكلام إلى نص إلى علامات تبويب Modality
Bridge المقابلة دون إزالة ملعب تحويل الكلام إلى نص الموجود.

**تجاوز قبول الحلقة الذاتية:** عندما يمر استدعاء الوصف عبر حلقة OmniRoute
الذاتية `/v1` (نموذج مزود غير قياسي)، يرسل الطلب الفرعي
`x-omniroute-admission-bypass: internal` ويتم المصادقة عليه باستخدام بيانات اعتماد الحلقة الذاتية المحلولة — `sk_omniroute` المحلي في الوضع المحلي، أو
مفتاح البيئة المكون من قبل المشغل `OMNIROUTE_API_KEY` / `ROUTER_API_KEY` (#1350) بحيث يمكن لنشر `REQUIRE_API_KEY=true` أن يستمر في تشغيل استدعاء الوصف. يتم احترام التجاوز
فقط لتلك البيانات الاعتماد المحددة، لذا لا يمكن للعملاء الخارجيين استخدام
الرأس لتخطي القبول.

تعيش القيم الافتراضية القديمة في `src/shared/constants/visionBridgeDefaults.ts`؛
تعيش القيم الافتراضية الجديدة المدركة للمهام/التخزين المؤقت ومحلل الإعدادات في
`src/shared/constants/modalityBridgeDefaults.ts`. يكشف الحاجز عن خيار منشئ `deps`
حتى تتمكن الاختبارات من حقن تنفيذات وهمية لـ `getSettings` و
`callVisionModel`.

### جسر الصوت (`audioBridge.ts`) — Modality Bridge PR-3

يعترض طلبات الدردشة التي تحتوي على صوت قبل أن تصل إلى هدف غير معروف لقبول إدخال الصوت. لا يعيد توجيه طلب الدردشة أبدًا: يتم نسخ أجزاء الصوت من خلال نقطة النهاية متعددة الأجزاء المتوافقة مع OpenAI الموجودة ويستمر نموذج الدردشة المختار مع النصوص المنقولة.

التدفق:

1. حل `supportsAudio` من خلال `getResolvedModelCapabilities()`. تفوز بيانات التعريف الخاصة بسجل المزود، ثم بيانات التعريف الثابتة للنموذج، ثم `modalities_input` المتزامنة. قائمة الإدخال المعلنة بدون `audio` هي `false`؛ لا تبقى أي أدلة على القدرة `null`. كل من `false` و `null` تنشط الجسر المحافظ، بينما `true` تتجاوزها.
2. حل إعدادات `modalityBridgeAudio*` واستخراج أجزاء الصوت القابلة للتقطيع من كل رسالة من خلال كاشف `detectMediaParts()` المشترك. الأشكال المدعومة هي OpenAI `input_audio`, `audio_url`, و `source.media_type: "audio/*"`. يتم اكتشاف الصوت المتداخل للتوجيه ولكن لا يتم إزالته بواسطة مسار التقطيع. يتم تحديد العمل بواسطة `modalityBridgeAudioMaxClips`؛ تبقى الأجزاء اللاحقة دون تغيير.
3. احترام `provider/model` المكون، أو دع `selectAudioBridgeModel()` يتجول في `AUDIO_TRANSCRIPTION_PROVIDERS` بترتيب الكتالوج المستقر ويختار أول نموذج مع بيانات اعتماد مزود نشطة قابلة للاستخدام.
4. يقوم `callAudioTranscription()` بتحويل صوت base64/data-URI إلى ملف متعدد الأجزاء، أو يقوم بتنزيل `audio_url` عن بُعد من خلال الحارس الخارجي العام مع تثبيت DNS وحدود 25 ميجابايت. ثم يقوم بإرسال الملف والنموذج المختار إلى حلقة `/v1/audio/transcriptions` الذاتية، مصادقًا عليه باستخدام `resolveSelfLoopBearer()`. يقوم مسار النسخ الموجود بإجراء بحث عادي عن بيانات الاعتماد، ومعالجة فترة الانتظار/حدود المعدل، وإرسال المزود.
5. تستبدل المكالمات الناجحة أجزاءها بـ `[Audio N]: <transcript>`. تعمل المكالمات مع `Promise.allSettled`: فشل فردي يحافظ على تلك الجزء الصوتي الأصلي (#4012 العقد). إذا فشلت كل مكالمة وتم إثبات أن الهدف هو `supportsAudio === false`، تصبح الأجزاء
   `[Audio N]: (غير متاح — لا يوجد مزود STT متصل)` (#8430 العقد). بالنسبة لهدف غير معروف (`null`)، تبقى نتيجة الفشل الكامل دون تغيير. يتلقى هدف نصي مثبت بدون بيانات اعتماد STT قابلة للاستخدام نفس
   السدادة الصريحة دون إصدار مكالمة شبكة.

تستخدم النسخ الناجحة ذاكرة التخزين المؤقت LRU/TTL لجسر Modality على مستوى العملية. يجمع المفتاح مرجع الصوت، ووسم عملية `audio-transcription` المستقرة، ونموذج STT المختار؛ لا يتم تخزين الفشل أبدًا. تقوم محاولات الصوت بتحديث العدادات المشتركة `bridged`, `cacheHits`, `failures`, و `lastUsedAt`.
تحمل الاستجابات المحولة
`x-omniroute-modality-bridge: audio->text;model=<sttModel>;parts=<n>`؛ لا تتلقى الطلبات غير المتأثرة جزء جسر الصوت.

الإعدادات الزمنية مدعومة من قاعدة البيانات ومصادق عليها بواسطة Zod:

| المفتاح                       | الافتراضي | النطاق           |
| ----------------------------- | --------- | ---------------- |
| `modalityBridgeAudioEnabled`  | `true`    | —                |
| `modalityBridgeAudioModel`    | `""`      | تلقائي أو STT ID |
| `modalityBridgeAudioTimeout`  | `60000`   | 1000–300000      |
| `modalityBridgeAudioMaxClips` | `3`       | 1–10             |

تظل الذاكرة المشتركة تحت السيطرة بواسطة `modalityBridgeCacheEnabled`،
`modalityBridgeCacheTtlMinutes`، و `modalityBridgeCacheMaxEntries`.

### جسر الفيديو (`videoBridge.ts`, `videoBridgePipeline.ts`)

يIntercepts أجزاء الفيديو على المستوى الأعلى في Chat Completions `messages` و Responses
API `input` قبل استدعاء هدف بدون دعم فيديو أصلي معروف.
الأشكال المدعومة هي `input_video`، `video_url`، `video_source`، روابط HTTPS،
و `data:video/*;base64,...` بيانات URIs. الأسماء البسيطة للملفات في النص لا تُعتبر
فيديو.

يمتلك `VideoBridgeGuardrail.preCall` (`videoBridge.ts`) عبور الطلب،
التحقق من القدرة/السياسة، التجميع لكل طلب، وحمولة الاستجابة.
يتم إخفاء العمل لكل فيديو — الاستحواذ، ذاكرة التخزين المؤقت للنتيجة الكاملة، وصف تسلسل الإطار
(الذي يدمج أي نص صوتي تم إعلانه من قبل المتصل)، وقياسات/إلغاء/تنظيف لكل محاولة — خلف `processVideoPart` في
`videoBridgePipeline.ts`، يتم استدعاؤه مرة واحدة لكل جزء فيديو داخل حلقة `preCall`.
تحدد تلك الوحدة أيضًا حدود المنفذ الصريحة `VideoMediaBrokerPort`
(الذي يستحوذ على البايتات ويستخرج الإطارات المأخوذة)، `VideoAudioTranscriptionPort`
(الذي يدمج نص الصوت المعلن من قبل المتصل مع الترجمة المأخوذة)، و
`VideoDrilldownPort` (شكل التخزين الخام القديم). يتم تجميع STT والإبقاء على الإطارات
حول المنفذ الوصفي من خلال `createVideoSttAdapter` و
`createVideoDrilldownAdapter`؛ يستخدم الأخير دورة حياة مقبض غير شفاف مشترك.

مسار الطلب العام `/v1` لا يستورد أو يستدعي عملية فرعية. يتم تنزيل
الفيديوهات البعيدة تحت حد 50 ميغابايت؛ الفيديوهات المضمنة بتنسيق base64 لها
حد متحفظ يبلغ 36 ميغابايت مفكوك لكل فيديو حتى تظل النموذج/الرسائل/غلاف الإطار
داخل حد قبول طلب JSON العام البالغ 50 ميغابايت. يتم التحقق من تقديرات الطول والحجم المفكوك قبل التخصيص. يتطلب HTTPS
على عنوان URL البعيد الأول وكل إعادة توجيه، باستخدام الحماية العامة فقط
الخارجية الموجودة مع تثبيت DNS. ثم تعبر البايتات حدود الوسيط الداخلي
`POST /api/modality-bridge/video/extract` بالضبط. هذا المسار هو كل من
`LOCAL_ONLY` و `SPAWN_CAPABLE`، يقبل فقط طلب موثوق معتمد لكل عملية،
ولا يقبل أبدًا عنوان URL، مسار نظام الملفات، برنامجًا تنفيذيًا،
أو قائمة وسائط. يفرض خط أنابيب حجم جسم API وحامل الجسم القارئ المتزايد حد إدخال
وسيط يبلغ 50 ميغابايت. تعمل قائمة الانتظار المحدودة الخاصة به
على استخراج واحد في كل مرة، وتسمح بأربعة وظائف معلقة، وتحدد الحد الأقصى للإدخال المعلق عند
100 ميغابايت.

داخل الوسيط، يقرأ `ffprobe` ملفًا محليًا خاصًا؛ قائمة التنسيق الثابتة
تستبعد تنسيقات قائمة التشغيل والتجميع. بالنسبة لحاويات عائلة MOV المسموح بها،
تظل مراجع بيانات MOV الخارجية معطلة بشكل افتراضي، والأمر الثابت لا يختارها. يستخدم كل من `ffprobe` و `ffmpeg`
قائمة بيضاء لبروتوكول `file` فقط، خيط واحد، مصفوفات معلمات ثابتة، لا شل،
وبرامج تنفيذية تم حلها من `PATH`. لا تعتبر تدفقات الغلاف المرفقة بالصور
مرشحة قابلة للتشغيل. يجب أن تلبي جميع التدفقات القابلة للتشغيل الحدود، ويفضل أن يكون هناك
تدفق افتراضي صريح قبل أقل فهرس محدد. يتم تحديد الفيديوهات بحد أقصى 600 ثانية، 8192 بكسل لكل بُعد، و
33554432 بكسل مصدر. يقوم FFmpeg بأخذ عينات من 1–16 إطار JPEG في المنتصف، ويقوم بتقليص
الحافة الطويلة إلى 1024 بكسل كحد أقصى دون تحسين المدخلات الأصغر، و
لا يتلقى أبدًا عنوان URL. تكون العينة `uniform` بشكل افتراضي. السياسات الاختيارية
`scene_aware` و `segment_aware` تقوم بإجراء تمريرة FFmpeg ثابتة إضافية على التدفق المحلي الذي تم التحقق منه بالفعل، وتختار
طوابع زمنية مشهد `showinfo` المحدودة، وتعود بشكل حتمي إلى نفس
النقاط المنتظمة في حالة فشل الكاشف، أو انتهاء الوقت، أو الإخراج غير الصحيح، أو مجموعة المرشحين الفارغة. يخصص وضع الوعي بالقطعة عينات المنتصف بشكل متناسب مع
فترات المشهد التي تم التحقق منها؛ يتم تفصيل أدلة الوعي بالقطعة وسلوك التراجع أدناه. يتم تطبيق الحد الثابت البالغ 16 إطارًا
بعد الاختيار في كل سياسة. عندما يحتوي الطلب المعتمد على المشهد على ميزانية إطار واحدة فقط،
يستخدم النقطة المنتظمة من الفيديو الكامل النشط أو نافذة التركيز ويبلغ عن `policyEffective: uniform`: لا يمكن لإطار مشهد واحد مختار الحفاظ على كلا الطرفين الزمني. يمكن للمتصل اختيارياً تقديم نافذة تركيز محدودة (`start`/`end` ثواني)؛ يتم تقليم الحدود إلى مدة الوسائط، وتُرفض النوافذ المعكوسة أو غير المحدودة، وتُنفذ جميع سياسات العينة فقط داخل الفاصل الزمني العادي. يتم تضمين النافذة الناتجة في بيانات العينة وفي وصف البادئة غير الموثوق بها حتى تتمكن النماذج اللاحقة من تمييز مقتطف مركز من الجدول الزمني الكامل.

تركيز الترجمة الدلالية هو إعداد منفصل وصريح. وضع التحليل الافتراضي `full`
يحافظ على موجه الإطار الحالي ولا يقوم أبدًا بإعادة توجيه نص الطلب إلى نموذج الترجمة. في وضع `focused`، يقرأ الجسر فقط أحدث
`text`/`input_text` غير الفارغ الذي كتبه المستخدم من نفس حاوية الدردشة أو الردود، ويقوم بتطبيعه إلى NFC، ويقلص الأحرف التحكمية والمسافات البيضاء،
ويحده إلى 500 نقطة رمز Unicode. النتيجة الفارغة تعود إلى الموجه `full` بالضبط. يتم تسلسل تلميح قابل للاستخدام كـ JSON في كتلة سياق المستخدم غير الموثوق بها وقد تعطي الأولوية فقط للتفاصيل المرئية؛ لا يمكنها تجاوز التحذير المنفصل ضد اتباع التعليمات المرئية أو المسموعة في الوسائط. لا يستنتج التركيز النصي `start`/`end` أو يغير
العينة الزمنية.

#### FU-07 دليل القطعة الهيكلية

`segment_aware` يستخدم تمرير تحليل مسبق محدود على تدفق الفيديو المحلي الذي تم التحقق منه بالفعل. سلسلة الفلاتر الثابتة أولاً تقوم بتقليص العرض إلى 320 بكسل كحد أقصى، ثم تكشف عن تغييرات المشهد والفترات المجمدة، ثم تأخذ عينات بمعدل إطار واحد في الثانية للضباب، ومتوسط اللمعان، والمعلومات المكانية/الزمانية. يتم تحديد التمرير بـ 600 عينة هيكلية، خيط واحد من FFmpeg/filter، نفس بروتوكول `file`-only وقوائم الحاويات المسموح بها، حد إخراج عملية 1 ميجابايت، وما لا يزيد عن 30 ثانية داخل مهلة الإلغاء/الموعد النهائي المشتركة للوسيط. لا يقبل أبداً أمرًا أو فلترًا أو مسارًا أو عنوان URL من الطلب.

القيم الهيكلية هي أدلة أخذ عينات حتمية، وليست فهمًا دلاليًا للفيديو. لا تستنتج الموضوعات أو الأفعال أو التسميات أو الكلام أو نية المستخدم. تشكل حدود المشهد والتجميد مقاطع؛ تغطي التجميد، الضباب، التعرض، التفاصيل المكانية، والتغير الزمني تؤثر فقط على كيفية تخصيص ميزانية الإطارات الحالية من 1 إلى 16. يتم تحديد الحد الأقصى لمقطع مجمد بإطار واحد، بينما تتنافس المقاطع غير المجمدة على الميزانية المتبقية. عندما تتجاوز الحدود عدد الإطارات، يتم الاحتفاظ بتغطية زمنية موحدة بحيث لا يمكن أن تخفي القطع السريعة المبكرة مقطعًا طويلًا متأخرًا. يتم دمج حدود المشهد ضمن دقة التحليل البالغة 1 ثانية لحدود التجميد.

تؤدي الفلاتر المفقودة، أو الأدلة غير الصحيحة/الفارغة، أو خطأ في الكاشف، أو مهلة التحليل المسبق المحدودة إلى الفشل المفتوح وفقًا لسياسة منتصف النقطة الموحدة الدقيقة. لا يؤدي إلغاء المتصل أو الموعد النهائي للوسيط إلى الفشل المفتوح: بل ينهي العملية الفرعية الجارية، ويمنع استخراج الإطارات لاحقًا، ويتم إزالة الشجرة المؤقتة الخاصة في `finally`.

`scripts/perf/video-bridge-fu07-eval.ts` يولد تركيبات FFmpeg حقيقية حتمية لتوفير التكاليف بعد إزالة التكرار، وتخصيص ميزانية الحركة الكثيفة، وأدلة الضباب/التعرض/SI-TI، والقطع السريعة مع ذيل طويل، وإيجابيات كاذبة للتلاشي التدريجي. يسجل وقت الجدار للتحليل المسبق، وعندما يكون `/usr/bin/time` متاحًا، يسجل استخدام وحدة المعالجة المركزية للطفل وذروة RSS. تحقق الجودة الخاصة به هي أوacles هيكلية فقط. تظل جودة نموذج التسميات الحقيقية `HOLD` لأن هذه الأداة ليس لديها نقطة نهاية مصرح بها أو قاضي مجمد. تظل التوفير المالي أيضًا `HOLD` ما لم يوفر `--caption-cost-per-call-usd` تقديرًا إيجابيًا صريحًا لكل مكالمة؛ لا يقوم البرنامج أبدًا بتصنيع أي من النتائج.

يتم تحديد كل إطار بحد أقصى 4 ميجابايت، وجميع الإطارات الخام معًا إلى 23 ميجابايت، واستجابة الوسيط المسلسلة إلى 32 ميجابايت. يتم إزالة دليل مؤقت خاص في `finally`. لا يقوم OmniRoute بتجميع FFmpeg ولا يقبل مسارًا تنفيذيًا مخصصًا. قبل إضافة التسميات، يقوم الجسر بتطبيق تمرير إزالة التكرار البصري المحافظ: يتم تقليل كل JPEG إلى مخزن رمادي 16×16 ويتم مقارنته فقط مع الإطار الأخير المحتفظ به. بالنسبة لميزانية التسميات المطلوبة التي تتجاوز إطارًا واحدًا، يوفر الاستخراج مجموعة مرشحة محدودة تصل إلى ضعف تلك الميزانية ولا تزيد أبدًا عن 16 إطارًا. يتم تطبيق الحد المطلوب فقط بعد إزالة التكرار، مع الحفاظ على المرشحين المختارين الأول والأخير خلال التخفيف النهائي عندما تكون الميزانية لا تقل عن اثنين. تستخدم السياسة المحدثة `grayscale-16x16-mean-cells-v2` الأكبر من دلتا اللمعان المتوسط ونسبة خلايا الصورة المصغرة التي تكون دلتا المعيارية لها على الأقل 0.05. عتبة التكرار هي الثابت 0.04، الذي تم اختياره من أجل التنبؤ بدلاً من أن يتم الكشف عنه كإعداد وقت التشغيل. هذه الإشارة الثانوية عالية التباين تحافظ على الحركة الصغيرة والتغيرات النصية المرئية التي يمكن أن تخفيها المقارنة التي تعتمد فقط على المتوسط. تفشل أخطاء المقارن أو فك التشفير بشكل مفتوح وتحافظ على التغطية. تفصل بيانات التعريف الناتجة بين المرشحين المستخرجين، والإطارات المستخدمة بنجاح، والتكرارات المرئية التي تم إسقاطها.

**حقول الفيديو الخام (#12430).** عندما يكون الجسر مفعلًا والدعم الأصلي
للفيديو غير معروف أو غائب، فإن الحقول المعرفة `transcript`/`audioTranscript`

الفيديو لا تحتسب. النسخ المحتفظ بها تحجب هذه الحقول أو تتجاهل الطلب، ويتم
تجاوز ذاكرات التخزين المؤقت. تظل الحمولة المقدمة دون تغيير.

نسخ النسخ المحتفظ بها الإضافية تستخدم نفس إشارة الطلب الملاحظة. لقطة طلب العميل الخام قبل الحواجز، الطلب المعلق في الذاكرة، وسجل الطلبات المرفوضة المبكرة تحل هيكليًا محل حقول النص في أجزاء الفيديو؛ يتم حذف العبارات النصية التي تم توليدها بواسطة مراحل خط الأنابيب وتسليم السياق عند مصب جسم الطلب المحتفظ به. علامة `video_content_removed` المحتفظ بها تجعل استمرار `previous_response_id` يفشل بشكل مغلق بدلاً من إعادة بناء النص الذي تم التخلص منه عمدًا. إذا فقد طلب ملاحظ ظله الخاص بالتحرير لكل جزء قبل التسجيل، أو حتى إذا فشل أحد الظلال الفيديو المتعددة في المطابقة بعد تغييرات الطلب اللاحقة، يتم حذف جسم الطلب المحتفظ به بالكامل بدلاً من الاحتفاظ بنص جزئي المحرر.

بالنسبة لطلب ملاحظ، قد تقتبس استجابة النموذج أي جزء من النص بدون حدود إشارة هيكلية. لذلك، يتم استبدال `responseBody` في سجل المكالمات المحتفظ به بعلامة حذف؛ لا يتم الاحتفاظ بالقطعة التفصيلية من خط الأنابيب (التي يمكن أن تشمل أجسام upstream/العميل وقطع البث). تتجاوز ذاكرات التخزين الدلالية، والهوية، وإعادة تشغيل التفكير عمليات القراءة والكتابة لذلك الطلب. تظل طلبات المزود واستجابة العميل المرئية دون تغيير. يتم تصريف بايتات keepalive المبكرة من المخزن المؤقت المؤقت عندما يتم حذف القطعة التفصيلية. تحذر تحذيرات Kiro من EventStream غير الصالحة فقط عدد بايت الحمولة، وليس محتوياتها أو خطأ المحلل JSON الخام.
هذا لا يدعي أن كل تشخيص غير ذي صلة من المزود/الإضافة قد تم تدقيقه؛ يتم تتبع عملية الاحتفاظ الأوسع في #11658.

دورة حياة `/api/modality-bridge/video/drilldown` الداخلية هي قاعدة بيانات مؤقتة منفصلة، معتمدة على حلقة/توكن. تتطلب كل عملية أيضًا معرف رئيسي غير شفاف قياسي. قبل تمكين المتصل الإنتاجي، يجب أن يستمد ذلك المعرف من المستأجر المعتمد ويجب ألا يقوم أبدًا بتمرير قيمة يختارها العميل. تربط مفاتيح التخزين هذا المعرف الرئيسي بمعرفات الجلسة القياسية ومعرفات الفيديو، وتخزن فقط مفاتيحها المستمدة من SHA-256، وتحدد كل من عمليات القراءة والحذف لنفس المعرف الرئيسي. يخزن التخزين في أقصى حد 16 إطار JPEG مستمد لكل إدخال، وينتهي صلاحيتها بعد عشر دقائق، ويدعم عمليات القراءة المحدودة `start`/`end` أو حذف الجلسة الصريح.

يقتصر كل معرف رئيسي على 16 إدخال و64 ميجابايت من بيانات JPEG القياسية. هذه الحدود مستقلة عن السقف العالمي المكون من 64 إدخال/256 ميجابايت: ضغط حصة المعرف الرئيسي يطرد فقط إدخالات ذلك المعرف الأقل استخدامًا مؤخرًا قبل النظر في الطرد العالمي LRU. يتم مسح الإدخالات المنتهية من كل من المحاسبة الرئيسية والعالمية عند نشاط التخزين، بينما لا تؤدي الإلغاء وفشل التحقق إلى تنفيذ استبدال جزئي.

يرفض التخزين Base64 غير القياسي، والحشو الزائد، ووسائط غير JPEG، وJPEGs غير الصالحة أو المقطوعة، وJPEGs التي تنتج تحذيرًا أثناء فك تشفير الصورة الكاملة المحدودة `sharp`. يعيد ترميز كل صورة مقبولة كـ JPEG قياسي، ويستمد العرض والارتفاع من البايتات المفككة بدلاً من الوثوق في حقول المتصل، ويتخلص من أي بايتات متعددة اللغات متبقية بدلاً من الاحتفاظ بها. يتم تحميل فقط المخزن المضغوط القياسي المحدود على كل من الحصص. تشمل حدود wire JSON تكاليف Base64 لسقف الإدخال المفكك البالغ 32 ميجابايت. كل
استنتاج مخزن يسجل تنسيق JPEG/دقة التحقق، سياسة العينة، إصدار الاستنتاج، وقت الإنشاء، تجزئة المحتوى المحسوبة بواسطة الخادم، وتجزئة المرجع الأب بالإضافة إلى تجزئة محتوى الأب للمتصل الموثوق. يتم التحقق من الإلغاء بين مراحل فك التشفير/التجزئة غير المتزامنة قبل الالتزام الذري للتخزين.

يعيد المنتج الإنتاجي استخدام إطارات الوسيط المستمدة مسبقًا فقط بعد التحليل البصري الناجح، دون تحميل/استخراج فيديو ثانٍ. يتطلب `modalityBridgeVideoDrilldownEnabled=true` من المشغل، و`drilldown: true` صارم لكل جزء، ومعرف سجل مفتاح API معتمد. قيم المعرف الرئيسي/الجلسة المعلنة من قبل العميل لا تؤسس ملكية. بدون جميع الشروط الثلاثة، لا يقوم بتجزئة أو تغيير حجم أو الاحتفاظ بإطارات إضافية. فشل الاحتفاظ يحافظ على الاستجابة المرئية القابلة للاستخدام. تتجاوز الطلبات المتفقة ذاكرة التخزين الخاصة بنتيجة الفيديو الكامل بحيث لا تعيد نتائج التخزين التعاملات.

تظهر استجابات JSON وSSE الناجحة في أقصى حد أربعة مقبضات غير شفافة في رأس `x-omniroute-video-drilldown` المحدود. يمكن للأصول المصرح بها من المتصفح قراءة ذلك الرأس دون توسيع سياسة أصل CORS. تستخدم المقبضات الجديدة `v1.<32-byte random base64url token>`، ويحتفظ السجل فقط بتجزئات SHA-256 الخاصة بها. يقبل محلل القارئ/الرأس أيضًا رموز 64-hex القديمة.
المستهلك العام المعتمد هو
`GET /api/v1/video-bridge/drilldown?handle=...`، محجوز بشكل مستقل بواسطة
`modalityBridgeVideoDrilldownRemoteEnabled=true`. إلغاء الصلاحية الصريح المحتفظ به يرفض الوصول حتى عندما يتم تمكين تراجع البيئة القديمة `OMNIROUTE_VIDEO_BRIDGE_DRILLDOWN_REMOTE_ENABLED`. الاحتفاظ الإنتاجي له تراجع قديم مماثل `OMNIROUTE_VIDEO_BRIDGE_DRILLDOWN_ENABLED`. كلا التراجعين افتراضيان مغلقان.

يستمد المستهلك الملكية من المفتاح المعتمد، ويطبق سياسة المفتاح، ويعيد نفس 404 للمقبضات غير المعروفة، المنتهية الصلاحية ومقبضات مفتاح آخر. يقبل `variant=preview|standard|detail` (أقصى أبعاد JPEG 320/640/1280، لا يتم تكبيرها أبدًا)، `limit=1..8` (أو الاسم المستعار القديم `frames`، لا يتم استخدام كلاهما أبدًا)، `page` المعتمد على الصفر، وثواني التركيز الاختيارية `start`/`end`. يتم رفض مفاتيح الاستعلام المكررة ونوافذ التركيز المعكوسة. يحتوي كل متغير تم إرجاعه على تجزئة لمحتواه الفعلي وبيانات دقة الفعلي، مرتبطة بالمصدر المحتفظ به. يتم اشتقاق المتغيرات عند القراءة بدلاً من تخزينها كنسخ محتفظ بها إضافية. يتم تحديد حد استجابة JSON، بما في ذلك Base64/Envelope، عند 32 ميجابايت؛ تعيد الصفحة الكبيرة 413 ويجب على العميل طلب عدد أقل من الإطارات. تتحقق عمليات القراءة من الإلغاء حول كل تغيير حجم وتعيد التحقق من صلاحية المقبض قبل الإرجاع. `DELETE` من قبل المالك هو عملية متكررة؛ يؤدي الحذف أو انتهاء صلاحية TTL إلى تحرير المصدر المحتفظ به ومحاسبة الاستخدام.

المتجر المشترك محلي للعملية: تنتهي الصلاحيات عند إعادة التشغيل ولا يمكن نقلها بين عمليات OmniRoute المستقلة. تكشف إحصائيات الإدارة عن سياسة الاحتفاظ/التحويل الفعالة وتجمع الإدخالات/البايتات المحتفظ بها فقط، وليس الوسائط أو المراجع أو معرفات الأصول أو الصلاحيات. تعرض لوحة إعدادات الفيديو تلك القيم ويمكن أن تحتفظ بكل من مفاتيح الموافقة. هذه الوثائق التنفيذية ليست دليل نشر مباشر أو ترويج؛ يتم تتبع قبول النموذج الحقيقي بشكل منفصل.

يتم وضع تسميات على الإطارات بالتتابع مع نموذج الفيديو المكون. يرث تجاوز الفيديو الفارغ إعداد الرؤية؛ إذا كانت كلاهما فارغة، يختار جهاز التوجيه التلقائي للرؤية النموذج القابل للرؤية الفعالة. تحل التسميات الناجحة الجزء الأصلي مع بادئة ثابتة `[Video description:` التي تحدد أيضًا النص كملاحظة مستمدة من وسائط غير موثوقة وتخبر النماذج اللاحقة بعدم اتباع التعليمات الموجودة في الوسائط. تشمل مفاتيح ذاكرة التخزين المؤقت لتسميات الإطارات بايتات JPEG، والمطالبة، والطابع الزمني، والنموذج الفعال؛ يتم تخزين التسميات الناجحة فقط في الذاكرة المؤقتة. تحتفظ إدخالات الذاكرة المؤقتة بالنموذج المنتج الناجح الفعلي، بما في ذلك نموذج احتياطي؛ يُبلغ الجسر عن `mixed` عندما يتم إنتاج إطارات مختلفة بواسطة نماذج مختلفة. تعيد ضربة الذاكرة المؤقتة استخدام هوية المنتج بدلاً من إعادة تسميتها كخطة توجيه مطلوبة. يتم تعيين ذاكرة التخزين المؤقت لنتيجة الفيديو الكامل على كل إدخال يغير المخرجات — المطالبة، النموذج الفعال، سياسة العينة، عدد الإطارات، وضع التحليل الدلالي، بصمة SHA-256 لتلميح التركيز العادي، نافذة التركيز، `transcript`، `audioTranscript`، وعلم ورقة الاتصال — لذا فإن تغيير أي من تلك الأبعاد يعد ضربة للذاكرة المؤقتة، وليس إعادة استخدام قديمة. إصدار سياسة إزالة التكرار البصرية، والعتبة، وعدد إطارات المرشحين المحدودين واضح أيضًا في مفتاح ذاكرة التخزين المؤقت للنتيجة والبيانات الوصفية؛ لذلك لا يمكن لتغيير السياسة إعادة استخدام وصف فيديو كامل قديم. تحتفظ بيانات وصفية ذاكرة التخزين المؤقت للنتيجة v4 بوضع وبصمة، ولا تحتفظ أبدًا بمهمة المستخدم الخام. تُبلغ بيانات وصفية الحواجز عن كل من أوضاع التحليل المطلوبة والفعالة؛ يتم الإبلاغ عن وضع `focused` المطلوب بدون نص مستخدم قابل للاستخدام على أنه فعال `full`.

تستخرج الحواجز كل جزء فيديو مدعوم ولكن لا تصف أكثر من `modalityBridgeVideoMaxVideos`. بالنسبة لهدف ثبت أنه `supportsVideo === false`، تصبح مقاطع الفيديو الفاشلة والتي تتجاوز الحد علامات نصية آمنة صريحة بحيث لا تبقى أي وسائط خام. عندما تكون القدرة غير معروفة، تبقى تلك الأجزاء دون مساس. تتجاوز الأهداف التي تحتوي على `supportsVideo === true` الجسر. تنتشر إشارة إلغاء طلب العميل عبر التنزيل، قائمة وسطاء، العمليات الفرعية، واستدعاءات التسميات؛ تتوقف عمليات الإلغاء بين مقاطع الفيديو ولا تفشل أبدًا في فتح الوسائط الخام.

تكون إعدادات وقت التشغيل مدعومة من قاعدة البيانات ومصادق عليها بواسطة Zod:

| المفتاح                             | الافتراضي   | النطاق / السلوك                                                                          |
| ----------------------------------- | ----------- | ---------------------------------------------------------------------------------------- |
| `modalityBridgeVideoEnabled`        | `false`     | وقت تشغيل اختياري، اختيارية                                                              |
| `modalityBridgeVideoAnalysisMode`   | `"full"`    | `full` يحتفظ بالتسميات العامة؛ `focused` يستخدم سياق المستخدم الأخير غير الموثوق المحدود |
| `modalityBridgeVideoModel`          | `""`        | وراثة نموذج جسر الرؤية                                                                   |
| `modalityBridgeVideoFrameCount`     | `8`         | 1–16                                                                                     |
| `modalityBridgeVideoSamplingPolicy` | `"uniform"` | `uniform`، `scene_aware`، أو `segment_aware` النسبي؛ فشل الكاشف يعود إلى `uniform`       |
| `modalityBridgeVideoMaxVideos`      | `1`         | 1–4                                                                                      |
| `modalityBridgeVideoTimeout`        | `120000`    | 1000–120000 مللي ثانية                                                                   |

تُقيد قيم مهلة الفيديو القديمة التي تتجاوز 120 ثانية إلى موعد الوسيط؛ تُرفض الكتابات الجديدة التي تتجاوز هذا الحد. يتطلب `GET /api/modality-bridge/video/runtime` موثوقية محلية مختومة قبل المصادقة أو استكشاف وقت التشغيل، ثم يتطلب مصادقة الإدارة. يعيد فقط إصدارات FFmpeg/ffprobe المتاحة والمعقمة، وسبب ثابت عندما يكون وقت التشغيل غير متاح. نقطة استخراج الداخلية ليست واجهة تحميل عامة: يعود تشبع القائمة بـ `503` بالإضافة إلى `Retry-After`، ويعود قطع الاتصال بالمتصل بـ `499`، ويعود الموعد الثابت للوسيط بـ `504`. تضيف الاستجابات المحولة `video->text;model=<visionModel>;parts=<videos>` إلى رأس `x-omniroute-modality-bridge` المركزي دون إزالة مقاطع الرؤية أو الصوت.

### ماسك PII (`piiMasker.ts`)

يعمل على **كلا** المرحلتين.

- **`preCall`** يقوم باستنساخ الحمولة، ويمشي عبر `system`، `messages`، `input`، و `prompt` (بما في ذلك العناصر النصية العادية)، ويطبق `processPII()` (من `@/shared/utils/inputSanitizer`) على حقول النص `content`/`text`. عندما يكون `PII_REDACTION_ENABLED=true`، يتم حذف PII المكتشفة في الحمولة الخارجة. هذا مستقل عن `INPUT_SANITIZER_MODE` (الذي يتحكم فقط في سياسة حقن المطالبات). عندما يكون الحذف غير مفعل، تسجل المكالمة عدد الاكتشافات دون إعادة كتابة المحتوى.
- **`postCall`** يقوم باستنساخ الاستجابة بعمق، ويشغل `sanitizePIIResponse()` بالإضافة إلى ماسك شكل واجهة برمجة التطبيقات للاستجابات (`maskResponsesOutput` — يغطي `output_text` و `output[].content[].text`). إذا حدث أي حذف، تحل الاستجابة المعدلة محل الأصلية.

لا تمنع الحواجز أبدًا؛ إنها فقط تضيف تعليقات توضيحية (`meta.detections`، `meta.redacted`) أو تعيد الكتابة.

### حقن المطالبات (`promptInjection.ts`)

يكتشف الهياكل العدائية في المحتوى المقدم من المستخدم ويفرض السياسة المكونة. يتم توجيه السلوك بواسطة متغيرات البيئة وخيارات المُنشئ:

| الإعداد    | متغير البيئة                                                                                             | الافتراضي | التأثير                                                                                                                                                                                 |
| ---------- | -------------------------------------------------------------------------------------------------------- | --------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| مفعل       | `INPUT_SANITIZER_ENABLED`                                                                                | `true`    | عندما يكون `false`، يتم اختصار الحماية.                                                                                                                                                 |
| الوضع      | `INJECTION_GUARD_MODE` / `INPUT_SANITIZER_MODE`                                                          | `warn`    | سياسة الحقن: `block`، `warn`، أو `log`. (`redact` مقبول للتوافق مع الإصدارات السابقة ولكنه لا يقوم بإزالة نص الحقن؛ طلب إعادة كتابة PII يتم التحكم فيه بواسطة `PII_REDACTION_ENABLED`.) |
| عتبة الحظر | خيار `blockThreshold` / `INPUT_SANITIZER_BLOCK_THRESHOLD` (اسم مستعار `INJECTION_GUARD_BLOCK_THRESHOLD`) | `high`    | الحد الأدنى من الشدة المطلوبة للحظر. الشدة المتوسطة تكون للمراقبة فقط بشكل افتراضي.                                                                                                     |

**أولوية الوضع** (`getMode`): `options.mode` للمتصل → `INJECTION_GUARD_MODE` **تجاوز علم ميزة DB** (لوحة التحكم → الإعدادات → أعلام الميزات) → متغير البيئة `INJECTION_GUARD_MODE` → متغير البيئة `INPUT_SANITIZER_MODE` → `warn`. لذلك، فإن تجاوز لوحة التحكم يفوز على متغيرات البيئة، لذا تتحكم واجهة المستخدم لأعلام الميزات في تشغيل الحماية مباشرة (بدون إعادة تشغيل). قراءة DB آمنة: إذا حدث خطأ، تعود الحماية إلى السلوك المعتمد على البيئة، وعندما لا يتم تعيين أي تجاوز، يكون السلوك مطابقًا لحل البيئة فقط.

مصادر الكشف:

1. `sanitizeRequest()` من `@/shared/utils/inputSanitizer` (مجموعة الكاشف المشتركة المستخدمة في أماكن أخرى في السلسلة).
2. أنماط الحماية المدمجة `DEFAULT_GUARD_PATTERNS` (حاليًا `system_override_inline` و `markdown_system_block`، كلاهما بشدة `high`).
3. أنماط `customPatterns` الاختيارية الممررة عبر خيارات المُنشئ (سلاسل نصية، regex، أو سجلات `{ name, pattern, severity }`).

عندما يكون `mode === "block"` **و** يلبي كشف واحد على الأقل عتبة الشدة، ترجع `preCall` `{ block: true, message: "تم رفض الطلب: تم اكتشاف محتوى مشبوه" }`. في أوضاع `warn`/`log`، تقوم الحماية بتسجيل ولكن تسمح بالاتصال. يتم تصدير المساعد المشترك `evaluatePromptInjection()` أيضًا للمتصلين الذين يحتاجون إلى تقييم المطالبات دون المرور عبر السجل.

**حد المسح (v3.8.20):** يقوم الكاشف بفحص **أول 16 كيلوبايت** من نص المطالبة المجمعة — `MAX_INJECTION_SCAN_BYTES = 16 * 1024` (16,384 بايت) في `src/shared/utils/inputSanitizer.ts`. كل من `detectInjection()` و `evaluatePromptInjection()` `slice(0, MAX_INJECTION_SCAN_BYTES)` قبل تشغيل حلقة الأنماط. تقع توجيهات الحقن بالقرب من الجزء العلوي من الإدخال، لذا فإن هذا يحد من استخدام وحدة المعالجة المركزية/GC على الحمولة التي تتجاوز مئات الكيلوبايت دون إضعاف الكشف (راجع #3932، #4041).

### ماسك الاعتماديات (`credentialMasker.ts`)

يعمل في **كلا** المرحلتين، آخر في سلسلة الافتراضية (الأولوية `95`). يقوم بإزالة أنماط مفاتيح API / رموز السر المعروفة من الحمولة الصادرة (محتوى الرسالة، وسائط استدعاء الأداة، نتائج الأداة) **وأيضًا** استجابة المزود، بحيث لا يتم تسريب اعتماد تم لصقه في مطالبة (أو تم إعادته بواسطة نتيجة أداة) إلى المزود العلوي أو إلى العميل.

- **اختياري فقط**، نفس القاعدة مثل إزالة PII (القاعدة الصعبة رقم 20 المجاورة): معطلة ما لم يكن `settings.credentialRedactionEnabled === true` **أو** `CREDENTIAL_REDACTION_ENABLED=true`. مع إيقاف تشغيله، تكون الحماية لا تعمل — فهي لا تحظر أبدًا ولا تعيد كتابة.
- `redactCredentials()` يتجول في شجرة الحمولة/الاستجابة الكاملة (`walkValue()`، آمنة من تلوث النموذج، آمنة من الدورات عبر `WeakSet`) ويستبدل المطابقات بـ `[REDACTED:<type>]` كعنصر نائب، مع استنساخ فقط الفروع التي تغيرت فعليًا.
- تغطي `CREDENTIAL_PATTERNS` مفاتيح مزود LLM (OpenAI، OpenAI-proj، Anthropic، Google، Hugging Face، Replicate)، رموز VCS/SaaS (GitHub، Slack، Linear، Notion، npm، Postman، Discord)، مفاتيح الدفع (Stripe، Square)، مفاتيح السحابة (مفتاح وصول AWS، Twilio، SendGrid، Mailgun)، المفاتيح الخاصة / JWTs، سلاسل الاتصال الحاملة للاعتماد (`mongodb://user:pass@...`، إلخ)، ونمط قيمة رأس عام `Authorization`/`x-api-key`/`api-key`/`apikey`. يتم إزالة المفاتيح ذات الشكل الرأسي (`authorization`، `x-api-key`، `api-key`، `apikey`) هيكليًا (القيمة فقط، يتم الحفاظ على بادئة المخطط مثل `Bearer `/`Basic `) بدلاً من استخدام regex النص العام.
- لا تحظر الحماية أبدًا؛ إنها تعيد الكتابة فقط (`modifiedPayload` / `modifiedResponse`) وتعلق (`meta.credentialsRedacted`، `meta.count`).

حماية التراجع: `tests/unit/credential-masker-guardrail.test.ts`.

```typescript
  provider?: string | null;
  signal?: AbortSignal;
  sourceFormat?: string | null;
  stream?: boolean;
  targetFormat?: string | null;
}
```

تشير الحواجز إلى "لا تغيير" من خلال إرجاع إما `void` أو `{}` أو
`{ block: false }`. إرجاع `modifiedPayload`/`modifiedResponse` يستبدل
القيمة المتدفقة عبر السلسلة للحواجز السفلية.
`signal?: AbortSignal` يحمل دورة حياة المتصل إلى الحواجز. يعتبر إلغاء الطلب استثناءً متعمدًا للفشل المفتوح: تتوقف جسور الوسائط عن العمل وتنظف دون استعادة الوسائط الخام إلى هدف معروف أنه لا يدعمه.

## السجل (`registry.ts`)

يكشف `guardrailRegistry` الأحادي عن:

- `register(guardrail)` — يضيف (أو يستبدل بالاسم المعياري) حاجزًا و
  يعيد الترتيب حسب `priority` التصاعدي.
- `clear()` / `list()` — مساعدات إدارية.
- `runPreCallHooks(payload, context)` — يكرر الحواجز النشطة، يمرر
  الحمولة عبر `modifiedPayload`، ويتوقف عند أول `block: true`.
- `runPostCallHooks(response, context)` — نفس التدفق على جانب الاستجابة.
- `resetGuardrailsForTests({ registerDefaults })` — يمسح الحالة و
  يعيد تسجيل الإعدادات الافتراضية اختياريًا لعزل الاختبار النظيف.

يعيد كل من المشغلين `{ blocked, payload|response, results, guardrail?, message? }`
حيث `results` هي مصفوفة من سجلات `GuardrailExecutionResult` التي تتضمن
حقول `blocked`, `skipped`, `modified`, `error`, و `meta` لكل حاجز،
مفيدة للتتبع.

### تعطيل الحواجز لكل طلب

يقوم `resolveDisabledGuardrails({ apiKeyInfo, body, headers })` بتجميع قائمة
غير مكررة لأسماء الحواجز التي يجب تخطيها للطلب الحالي. المصادر (جميعها اختيارية، وجميعها مدمجة):

- `apiKeyInfo.disabledGuardrails`
- نص الطلب `disabledGuardrails` (على المستوى الأعلى)
- نص الطلب `metadata.disabledGuardrails`
- الرأس `x-omniroute-disabled-guardrails` (أو القديم
  `x-disabled-guardrails`)

يمكن أن تكون القيم مصفوفات من السلاسل أو سلسلة مفصولة بفاصلة؛ يتم
تطبيع الأسماء إلى صيغة kebab-case بالأحرف الصغيرة (`pii_masker` ← `pii-masker`).
يتم تمرير النتيجة عبر `context.disabledGuardrails` إلى السجل، الذي يتخطى
الحواجز المطابقة (`skipped: true` في `results`).

## ترتيب التنفيذ

لكل طلب يمر عبر `src/sse/handlers/chat.ts` و `open-sse/handlers/chatCore.ts`:

1.  يقوم `resolveDisabledGuardrails(...)` بإنشاء قائمة التخطي من مفتاح API، والنص الأساسي، والرؤوس.
2.  يقوم `guardrailRegistry.runPreCallHooks(body, ctx)` بتشغيل الحواجز الأمنية بترتيب تصاعدي للأولوية:
    - يتم تسجيل الحواجز الأمنية المعطلة على أنها `skipped`.
    - قد يقوم `preCall` لكل حاجز أمني بإعادة كتابة الحمولة عبر `modifiedPayload`.
    - أول `block: true` يقطع السلسلة ويعيد المعالج استجابة رفض الحاجز الأمني.
3.  تتدفق الحمولة (التي قد تكون أعيدت كتابتها) إلى توجيه التحرير والسرد والإرسال الأولي.
4.  بعد تجميع الاستجابة، يقوم `guardrailRegistry.runPostCallHooks(...)` بتشغيل نفس السلسلة على الاستجابة. `block: true` هنا يسقط الاستجابة الأولية.

يتم تسجيل الحواجز الأمنية التي تثير خطأ بـ `error: <message>` ويتم تسجيلها عبر `logger.warn`، لكن السلسلة تستمر — تصميم يسمح بالفشل المفتوح.

## التكوين

متغيرات البيئة التي تقرأها الحواجز الأمنية المدمجة:

| المتغير | يستخدم بواسطة | التأثير |
| `INPUT_SANITIZER_ENABLED` | `prompt-injection` | تعيين `false` لتعطيل الكشف بالكامل. |
| `INPUT_SANITIZER_MODE` | `prompt-injection` | سياسة الحقن: `warn` (تحذير)، `block` (حظر)، أو `log` (تسجيل). القيمة القديمة `redact` لا تعيد كتابة نص الحقن. |
| `INJECTION_GUARD_MODE` | `prompt-injection` | وضع حماية الحقن؛ وهو أيضًا علامة ميزة قاعدة بيانات **تتجاوز** متغيرات البيئة (قاعدة البيانات > البيئة). |
| `INPUT_SANITIZER_BLOCK_THRESHOLD` | `prompt-injection` | الحد الأدنى للخطورة الذي يرفضه `MODE=block`: `high` (مرتفع، افتراضي)، `medium` (متوسط)، أو `low` (منخفض). |
| `INJECTION_GUARD_BLOCK_THRESHOLD` | `prompt-injection` | اسم مستعار قديم لـ `INPUT_SANITIZER_BLOCK_THRESHOLD`. |
| `PII_REDACTION_ENABLED` | `pii-masker` | عندما يكون `true`، يتم تنقيح معلومات التعريف الشخصية (PII) للطلب (بصرف النظر عن وضع الحقن). |
| `PII_RESPONSE_SANITIZATION` / `_MODE` | `pii-masker` (downstream) | يتحكم في سلوك قناع الاستجابة. |

تقرأ الحواجز الأمنية لـ Modality Bridge التكوين في وقت التشغيل من مخزن الإعدادات المدعوم بقاعدة البيانات (`getSettings()`)، وليس من متغيرات البيئة. المفاتيح الأساسية لـ Vision هي `modalityBridgeVisionEnabled`, `modalityBridgeVisionMode`, `modalityBridgeVisionModel`, `modalityBridgeVisionTaskAware`, `modalityBridgeVisionPrompt`, `modalityBridgeVisionTimeout`, `modalityBridgeVisionMaxImages`, `modalityBridgeVisionMaxChars`, `modalityBridgeCacheEnabled`, `modalityBridgeCacheTtlMinutes`, و `modalityBridgeCacheMaxEntries`. يتم قبول المفاتيح القديمة `visionBridge*` فقط كخيار احتياطي للقراءة لمرة واحدة كما هو موثق؛ تستخدم عمليات الكتابة في لوحة التحكم المفاتيح الأساسية. توجد القيم الافتراضية ومحلل الاحتياطي في `src/shared/constants/modalityBridgeDefaults.ts`، مع الاحتفاظ بالثوابت القديمة في `src/shared/constants/visionBridgeDefaults.ts`.

يستخدم الصوت `modalityBridgeAudioEnabled`, `modalityBridgeAudioModel`, `modalityBridgeAudioTimeout`, و `modalityBridgeAudioMaxClips`, بالإضافة إلى إعدادات `modalityBridgeCache*` المشتركة. لا يحتوي الصوت على خيار احتياطي للمفاتيح القديمة لأن هذه المفاتيح تم تقديمها مع مخطط Modality Bridge.

يستخدم الفيديو `modalityBridgeVideoEnabled`, `modalityBridgeVideoAnalysisMode`, `modalityBridgeVideoModel`, `modalityBridgeVideoFrameCount`, `modalityBridgeVideoSamplingPolicy`, `modalityBridgeVideoMaxVideos`, و `modalityBridgeVideoTimeout`, بالإضافة إلى إعدادات `modalityBridgeCache*` المشتركة. يتم تعطيله افتراضيًا لأن FFmpeg/ffprobe هي تبعيات تشغيلية اختيارية، وإضافة تسميات الإطارات تزيد من زمن الاستجابة وتكلفة النموذج.

## حواجز حماية مخصصة

```typescript
import { BaseGuardrail, guardrailRegistry } from "@/lib/guardrails";

class BudgetGuardrail extends BaseGuardrail {
  constructor() {
    super("budget", { priority: 50 });
  }

  async preCall(payload, ctx) {
    if (ctx.apiKeyInfo?.budgetExceeded) {
      return { block: true, message: "Daily budget exceeded" };
    }
    return { block: false };
  }
}

guardrailRegistry.register(new BudgetGuardrail());
```

الخطوات:

1.  أنشئ `src/lib/guardrails/myGuardrail.ts` يوسع `BaseGuardrail`.
2.  نفّذ `preCall` و/أو `postCall`.
3.  سجّل إما وقت الاستيراد (ادفع من `registerDefaultGuardrails`) أو
    استدعِ `guardrailRegistry.register(...)` في وقت التشغيل — يحل السجل محل
    أي حاجز حماية سابق بنفس الاسم المعياري.
4.  أضف اختبارات تحت `tests/unit/` (أمثلة موجودة:
    `tests/unit/guardrails-registry.test.ts`,
    `tests/unit/prompt-injection-guard.test.ts`,
    `tests/unit/guardrails/visionBridge.test.ts`).

## الاختبار

استخدم `resetGuardrailsForTests()` بين الاختبارات للبدء من حالة معروفة.
مرر `{ registerDefaults: false }` للبدء بسجل فارغ و
تسجيل حواجز الحماية قيد الاختبار فقط. يقبل Vision Bridge حقن التبعية
(`deps.getSettings`, `deps.callVisionModel`)؛ يعرض Audio Bridge
الوصلات المكافئة للإعدادات، والقدرات، واختيار نموذج STT، وفحوصات الاعتماد،
والنسخ. وبالتالي يمكن للاختبارات ممارسة كلا التدفقين بدون قاعدة بيانات
أو الوصول إلى الشبكة.

## تغطية مسار حماية الحقن والاختبار الأحمر (المرحلة 8 · الكتلة D)

يغطي حارس الحقن (`createInjectionGuard` / `withInjectionGuard`) جميع المسارات
التي تقبل مطالبات المستخدم. وهو يحترم `INJECTION_GUARD_MODE` (الافتراضي `warn` = تسجيل فقط؛
`block` = يعيد HTTP 400 `SECURITY_001`).

| النوع      | المسارات                                                                                                                                             | الوضع الافتراضي |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | --------------- |
| نص (موجود) | `/v1/chat/completions`, `/v1/completions`, `/v1/relay/chat/completions`                                                                              | warn            |
| توليدي     | `/v1/messages`, `/v1/responses`, `/v1/images/generations`, `/v1/images/edits`, `/v1/videos/generations`, `/v1/music/generations`, `/v1/audio/speech` | warn            |
| بيانات     | `/v1/embeddings`, `/v1/rerank`, `/v1/search`, `/v1/moderations`                                                                                      | warn            |

تغطية استخراج النص (`extractMessageContents`) تشمل `messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system`.

**الفريق الأحمر (ليلي، `nightly-llm-security.yml`):** يتحقق promptfoo من أن كل مسار يحظر
مجموعة OWASP-LLM في `INJECTION_GUARD_MODE=block`؛ يقوم garak بتشغيل الفحوصات (يتخطى بدون سر).
يتم تضمين `moderations` من أجل الاتساق — يمكن للمشغلين في وضع الحظر إعفائها عبر
`resolveDisabledGuardrails`.

يحتوي سير العمل الليلي (`.github/workflows/nightly-llm-security.yml`، cron +
التشغيل اليدوي) على وظيفتين:

- **`promptfoo-guard` (حظر)** — يشغل `promptfoo eval -c promptfooconfig.yaml`
  مع `INJECTION_GUARD_MODE=block`. تؤكد كل حالة عدائية (مثل "تجاهل جميع
  التعليمات السابقة..."، اختراقات على غرار DAN) أن الاستجابة تحمل
  `error.code === "SECURITY_001"`، أي أن الحارس رفض الطلب بالفعل.
- **`garak` (استشاري)** — يشغل garak `--probes promptinject,dan,leakreplay`
  مقابل مثيل OmniRoute محلي (`http://localhost:20128/v1`). يتم التحكم فيه بواسطة
  سر مزود (`PROMPTFOO_PROVIDER_KEY`)؛ يتخطى بأمان ويتم إلحاقه بـ
  `|| true`، لذلك يتم الإبلاغ عنه دون فشل CI.

تغطية مساعد الحارس (`createInjectionGuard` / `withInjectionGuard`)
تمتد عبر كل مسار `/v1` يحمل مطالبة؛ يتم سحب نص المطالبة من
`messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system` بواسطة
`extractMessageContents()` في `src/shared/utils/inputSanitizer.ts`.
