تفرض الحواجز (Guardrails) السلامة والسياسة وتحويلات المحتوى عند الحدود
بين OmniRoute ومقدمي الخدمة المصدر. يمكن لكل حاجز فحص (ورفض أو تحويل أو إضافة تعليق اختياريًا) حمولات الطلبات (`preCall`)
واستجابات المصدر (`postCall`).

النظام **مفتوح عند الفشل (fail-open)**: إذا ألقى حاجز خطأ أثناء التنفيذ، فإن السجل
يسجل الخطأ ويستمر مع الحاجز التالي بدلاً من إفشال الطلب.
المنع هو قرار صريح (`block: true`)، وليس حادثًا أبدًا.

## الحواجز المدمجة

يقوم السجل بتحميل ستة حواجز تلقائيًا بترتيب الأولوية عند الاستيراد
(انظر `registry.ts` → `registerDefaultGuardrails()`):

| الأولوية | الاسم               | المرحلة(s)     | الملف                 |
| -------- | ------------------- | -------------- | --------------------- |
| `5`      | `vision-bridge`     | `preCall`      | `visionBridge.ts`     |
| `6`      | `audio-bridge`      | `preCall`      | `audioBridge.ts`      |
| `7`      | `video-bridge`      | `preCall`      | `videoBridge.ts`      |
| `10`     | `pii-masker`        | `pre` + `post` | `piiMasker.ts`        |
| `20`     | `prompt-injection`  | `preCall`      | `promptInjection.ts`  |
| `95`     | `credential-masker` | `pre` + `post` | `credentialMasker.ts` |

تعمل الأرقام ذات الأولوية المنخفضة **أولاً**.

### جسر الرؤية (`visionBridge.ts`) — جسر الوضعية PR-1

يIntercepts الطلبات التي تحتوي على صور الموجهة إلى **نماذج غير بصرية** ويقوم إما
بتوجيه الطلب بالكامل إلى نموذج قادر على الرؤية أو يستبدل أجزاء الصورة
بوصف نصي تنتجه نموذج رؤية قابل للتكوين قبل الاتصال العلوي. هذا يسمح لمقدمي النصوص فقط بالتعامل بشفافية مع
الأحمال متعددة الأوضاع.

التدفق:

1. تخطى إذا كان النموذج المستهدف يدعم الرؤية بالفعل (ما لم يظهر في قائمة الجسر الإجباري `isVisionBridgeForcedModel`).
2. استخراج أجزاء الصورة عبر `extractImageParts(messages)`
   (`visionBridgeHelpers.ts`)، الذي يفوض إلى **الكاشف الموحد للوسائط**
   `detectMediaParts()` في `open-sse/utils/mediaParts.ts` — المصدر الوحيد للحقيقة المشتركة مع فلتر التوافق المدمج.
   يتم السماح بالاستخراج لأجزاء المستوى الأعلى من الأشكال
   التي يمكن لـ `replaceImageParts` إعادة دمجها (عقدة الاستخراج↔الاستبدال): OpenAI
   `image_url`، Anthropic base64 `source.type:"base64"`، Anthropic URL
   `source.type:"url"`، وResponses API `input_image`. الضربات المتداخلة والأشكال التي تحتوي على مؤشرات فقط هي مواد فلتر مدمجة ولا يتم استخراجها أبدًا.
   تخطى إذا لم يتم العثور على أي منها.
3. حل إعدادات وقت التشغيل عبر `resolveVisionBridgeRuntimeSettings()`
   (`src/shared/constants/modalityBridgeDefaults.ts`): مفاتيح إعدادات `modalityBridge*`
   الجديدة تفوز؛ تبقى مفاتيح `visionBridge*` القديمة كـ **احتياطي لدورة واحدة**
   (نافذة التراجع). تخطى قبل أي عبور وسائط عندما يكون الجسر معطلاً.
4. يحدد محدد الوضع (`modalityBridgeVisionMode`، انظر الجدول أدناه)
   ما إذا كان سيتم إعادة التوجيه أو الوصف. تعيد إعادة التوجيه `modifiedPayload` مع استبدال `model` فقط، بالإضافة إلى البيانات الوصفية `{ rerouted, fromModel, toModel, imagesKept }`.
5. مسار الوصف: يحدد عدد الصور عند `maxImages`، ويقوم بتكوين الطلب الواعي بالمهمة،
   ويستشير ذاكرة التخزين المؤقت للوصف، ويستدعي نموذج الرؤية **بالتوازي**
   (`Promise.allSettled`)، ويحقن أجزاء النص `[Image N]: <description>` في
   أماكنها. يؤدي الفشل في الوصف إلى إرجاع `null` وتبقى جزء الصورة الأصلي
   **محفوظًا** (#4012) — باستثناء في مسار الوصف المدمج عندما يفشل كل
   وصف، حيث يحصل مصدر غير بصري مؤكد على
   `(غير متاح - لا يوجد مزود قادر على الرؤية متصل)` بدلاً من ذلك (#8430).
6. إرجاع `modifiedPayload` + البيانات الوصفية (`imagesProcessed`, `descriptions`,
   `processingTimeMs`, `visionModel`).

#### محدد الوضع (`modalityBridgeVisionMode`)

| الوضع      | الافتراضي | السلوك                                                                                                                                                                                                                                         |
| ---------- | --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `auto`     | ✔         | خوارزمية قديمة، غير متأثرة (#6640/#7204): النماذج غير المدمجة/`auto/` تعيد التوجيه إلى أفضل نموذج بصري ما لم يكن للنموذج الأصلي بيانات اعتماد قابلة للاستخدام (ثم يتم الوصف)؛ الأهداف المدمجة دائمًا تصف.                                      |
| `describe` |           | دائمًا وصف — يتم تخطي كتلة إعادة التوجيه تمامًا؛ النموذج الذي اختاره المستخدم دائمًا يجيب.                                                                                                                                                     |
| `reroute`  |           | إعادة التوجيه القسري: يتم تجاوز حارس النموذج المحتفظ بالاعتماد. لا يزال ينطبق حارس الاعتماد لنموذج إعادة التوجيه — عندما لا يوجد هدف بصري قابل للاستخدام، يسقط الطلب إلى الوصف بحيث لا تصل الصور الخام أبدًا إلى واجهة خلفية نصية فقط (#8430). |

تقطع الأوضاع القسرية **قبل** تشغيل الخوارزمية التلقائية؛ سلوك `auto`
هو مطابق تمامًا للحاجز قبل PR-1.

#### نطاق مفتاح API (`visionBridgeKeyScope.ts`)

عندما يقيد مفتاح API الخاص بالمتصل `allowedConnections`، تجمع الحصص
(`allowedQuotas`) أو النماذج (`allowedModels` / `blockedModels` /
`modelAccessMode: "restricted"` / `disableNonPublicModels`)، يختار الجسر فقط
نماذج إعادة التوجيه والوصف التي يمكن أن يستخدمها المفتاح، على الاتصالات التي يمكن أن يستخدمها المفتاح.
ثم يمر مكالمة الوصف دائمًا عبر حلقة OmniRoute الذاتية مع
رأس `x-omniroute-self-loop-key-id`، لذا فإن طلب الدردشة المستلم
يفرض سياسة الاتصال والنموذج الخاصة بذلك المفتاح مرة أخرى. تحترم `enforceApiKeyPolicy()`
هذا الرأس فقط مع حامل الحلقة الذاتية، لذا يمكنها فقط
تضييق الوصول، ويتم رفض معرف لا يتم حله.

إذا لم يكن هناك نموذج بصري مسموح به للمفتاح، فإن مسار الوصف يتراجع
ويمر الطلب دون تغيير، نفس سلوك الفشل المفتوح كحاجز معطل
(البيانات الوصفية `{ skipped: true, reason: "no_permitted_vision_model" }`).
تتصرف الطلبات بدون مفتاح، والمفاتيح بدون هذه القيود، تمامًا كما كانت من قبل.

#### وصف الطلب الواعي بالمهمة (`modalityBridgeVisionTaskAware`)

الإعداد الافتراضي **صحيح**. `composeVisionPrompt()` (`visionBridgeHelpers.ts`) يضيف
نص **آخر رسالة من المستخدم** (مقتطع إلى 500 حرف) إلى قاعدة
وصف الطلب، موجهًا الوصف نحو ما طلبه المستخدم فعليًا
(نمط codex-vision-proxy) ويطلب من نموذج الرؤية نسخ النص المرئي. مع إيقاف العلم — أو عدم وجود نص من المستخدم — يتم استخدام الطلب الأساسي دون تغيير.

طلب حلقة وصف الذات المتوافقة مع OpenAI (`callVisionModelSingle()`
في `visionBridgeHelpers.ts`) يطلب دائمًا `image_url.detail: "high"` —
بدون شروط، لكل متصل/مزود، وليس مشروطًا بأي إشارة من العميل.
تدهور دقة OCR عند استخدام عينات منخفضة التفاصيل تمامًا لمهمة نسخ النص
التي يطلبها هذا الطلب، لذا فإن طلب الوصف نفسه يطلب دائمًا تفاصيل عالية بغض النظر عن مستوى التفاصيل الذي استخدمه الطلب الوارد الأصلي. هذا يؤثر فقط على جسم الطلب الداخلي للوصف؛ لا يغير كيفية
إعادة توجيه OmniRoute لـ `image_url.detail` الخاص بالمتصل في الطلب الأساسي —
يتم تطبيق هذا الافتراضي بشكل منفصل، وفقط للعملاء المكتشفين من OpenCode، في
`defaultImageDetail()` (`open-sse/handlers/chatCore/upstreamBody.ts`). فرع تنسيق السلك الخاص بـ Anthropic لحلقة وصف الذات لا يحتوي على حقل `detail`
ولن يتأثر بأي افتراضي.

#### حد مخرجات الوصف (`modalityBridgeVisionMaxChars`)

| المفتاح                        | الافتراضي | النطاق           |
| ------------------------------ | --------- | ---------------- |
| `modalityBridgeVisionMaxChars` | `0`       | `0` أو 100–50000 |

`0` (افتراضي) يعني **لا حد** — يتم تمرير الوصف الذي تم إرجاعه بواسطة
`callVisionModel()` دون تعديل، مما يحافظ على السلوك الحالي. أي قيمة في نطاق 100–50000 تقطع الوصف مع
لاحقة `…` قبل أن يتم دمجه مرة أخرى كـ `[Image N]: <description>`
(`VisionBridgeGuardrail.preCall()` في `src/lib/guardrails/visionBridge.ts`).
قم بزيادة هذا للمهام الثقيلة بالتفاصيل في OCR حيث يحتاج النموذج السفلي إلى النسخ الكامل؛ قللها للحد من استخدام الرموز في نماذج الرؤية المتحدثة. حقل لوحة المعلومات موجود في لوحة متقدمة في علامة الرؤية
(`modality-bridge-max-chars` في `ModalityBridgeVisionTab.tsx`) ويقيد أي
قيمة بين 1 و 99 إلى الحد الأدنى 100 بينما يترك `0` صريحًا دون تغيير — `0` هو قيمة Zod صالحة في حد ذاتها
(`z.union([z.literal(0), z.number().int().min(100).max(50000)])`)، وليس مجرد
الافتراضي "غير المحدد".

#### ذاكرة التخزين المؤقت للوصف (`modalityBridge/bridgeCache.ts`)

ذاكرة تخزين مؤقت LRU + TTL في الذاكرة لمخرجات الوصف، مشتركة على مستوى العملية.
المفتاح = `sha256(imageRef + composedPrompt + configuredBridgeModel)` مع
إطار طول سابق (لا توجد تصادمات حدود الحقول). مكون النموذج هو
النموذج الجسر **المكون**، وليس النموذج الذي أجاب فعليًا —
قد يتراجع `callVisionModel` داخليًا، وسيؤدي استخدام المفتاح لكل محاولة إلى
تجزئة الذاكرة المؤقتة. لا يتم تخزين الأوصاف الفاشلة في الذاكرة المؤقتة. الإعدادات:

| المفتاح                         | الافتراضي | النطاق  |
| ------------------------------- | --------- | ------- |
| `modalityBridgeCacheEnabled`    | `true`    | —       |
| `modalityBridgeCacheTtlMinutes` | `60`      | 1–1440  |
| `modalityBridgeCacheMaxEntries` | `200`     | 10–5000 |

#### تطبيع الصورة عن بُعد (الوصف الذاتي/استرجاع base64)

عندما يقوم الجسر باسترجاع صورة **عن بُعد** بنفسه — استدعاء وصف Anthropic الذاتي وتحويل base64 بتنسيق claude-wire
(`ensureBase64ImagesForClaudeWire`)، كلاهما عبر
`fetchRemoteImageAsDataUri()` في `visionBridgeHelpers.ts` — يتم تمرير URI البيانات الناتجة عبر `normalizeDataUri()`
(`open-sse/utils/imageNormalize.ts`) قبل أن يتم تضمينه في طلب نموذج الرؤية. يتم تقليل حجم الصور الكبيرة إلى **حافة بطول 2048 بكسل** (مطابقة
للحد الأقصى لحجم إعادة التحجيم الذي تطبقه OpenAI/Anthropic بالفعل على الخادم)، مما يقلل
من بايتات التحميل/الكمون دون تغيير ما تراه نموذج الرؤية. يستخدم إعادة التحجيم `sharp`، المحملة عبر استيراد ديناميكي: على منصة حيث يفشل تحميل ثنائيها الأصلي، فإن `normalizeDataUri()` **لا ترمي أبدًا** — بل تتراجع
إلى تمرير البايتات الأصلية، لذا فإن مسار الوصف/تحويل base64 يبقى يعمل دائمًا. يتم أيضًا تمرير بايتات غير الصورة (استرجاع لم يُرجع صورة قابلة للتشفير) دون تغيير. يتم تحديد هذا التطبيع للصور التي يسترجعها الجسر لاستدعائه الذاتي — لا يتم تطبيقه أبدًا على الحمولة الخام للمتصل، بما يتماشى مع مبدأ التحوير القائم على الاختيار فقط (قاعدة صارمة #20).

المفاتيح الجديدة `modalityBridge*` يتم التحقق منها بواسطة Zod في `updateSettingsSchema`
(`src/shared/validation/settingsSchemas.ts`): `modalityBridgeVisionEnabled`,
`modalityBridgeVisionMode`, `modalityBridgeVisionModel`,
`modalityBridgeVisionTaskAware`, `modalityBridgeVisionPrompt`,
`modalityBridgeVisionTimeout`, `modalityBridgeVisionMaxImages`,
`modalityBridgeVisionMaxChars`، الثلاثي `modalityBridgeCache*`، ومجموعة
`modalityBridgeAudio*` المستخدمة بواسطة جسر الصوت. يقوم الترحيل
`141_modality_bridge_settings.sql` بنسخ القيم القديمة الموجودة
`visionBridge*` إلى المفاتيح الجديدة المطابقة (غير قابلة للتكرار، لا تكتب أبدًا
قيمة `modalityBridge*` تم تعيينها بواسطة المشغل)؛ تبقى المفاتيح القديمة مقبولة كخيار احتياطي للقراءة لدورة إصدار واحدة.

#### رأس الشفافية + الإحصائيات

تحمل الاستجابات المحولة بواسطة الوصف
`x-omniroute-modality-bridge: image->text;model=<visionModel>;parts=<n>`
(تم إنشاؤه بواسطة `buildModalityBridgeHeader()` في `modalityBridge/bridgeStats.ts`,
مختوم بواسطة `withModalityBridgeHeader()` في `src/sse/handlers/chatHelpers.ts`).
لا تحصل الطلبات المعاد توجيهها على **أي** رأس — كانت الحمولة غير متغيرة وتبديل النموذج
مرئي بالفعل في حقل `model` في جسم الاستجابة.

`GET /api/modality-bridge/stats` (إدارة المصادقة، نفس المستوى مثل
`GET /api/settings`) يعيد العدادات لكل نمط في الذاكرة
`{ attempts, successes, bridged, cacheHits, failures, totalLatencyMs,
latencySamples, averageLatencyMs, lastUsedAt }` لـ `vision`, `audio`, و
`video`. يستخدم `averageLatencyMs` `latencySamples`، وليس جميع المحاولات، كقاسم له؛ عملية بدون توقيت لا تصنع عينة صفرية من المللي ثانية. يبقى `bridged` الاسم البديل المتوافق مع الإصدارات السابقة للتحويلات الناجحة؛ المحاولات الفاشلة لا تزيده.
تُعيد العدادات تعيينها عند إعادة تشغيل العملية حسب التصميم
(التليمتري، وليس المحاسبة).

#### تكوين لوحة التحكم

صفحة لوحة التحكم المخصصة هي
`/dashboard/settings/modality-bridge`. تحافظ علامات التبويب `Vision`, `Audio`,
و `Video` القابلة للوصول عبر عنوان URL على معلمات الاستعلام أثناء تبديل قيمة `tab`.
تظهر علامة التبويب Vision خيارات التمكين، الوضع، اختيار النموذج (بما في ذلك الافتراضي التلقائي)، التحفيز الواعي بالمهمة، حدود المهلة/الصورة/طول الوصف/التخزين المؤقت المتقدمة، العدادات
الوقت الحقيقي، وطلب عينة محمي. علامة التبويب Audio نشطة أيضًا: تعرض
التمكين، مختار نموذج STT فقط مع Auto، حدود المهلة/القص القصوى، العدادات الصوتية، واختبار عينة `input_audio`. علامة التبويب Video تعمل: تبلغ
عن حالة وقت التشغيل لـ FFmpeg/ffprobe — واحدة من أربع حالات واجهة مستخدم صريحة (`unknown` بينما
التحقيق في الطيران أو لم يكتمل، `restricted` على مضيف لوحة تحكم غير حلقي حيث يتم تخطي التحقيق من جانب العميل، `unavailable` بمجرد التحقيق والتأكيد على عدم وجوده، أو `available` مع إصدارات FFmpeg/ffprobe) — تستمر
في الحفاظ على حدود enable/model/frame/video/timeout، وتصفية مختار النموذج إلى
نماذج قادرة على الرؤية، وتعرض العدادات الفيديو.

تحتوي بطاقة Vision Bridge السابقة ضمن إعدادات AI على رابط توافق إلى
الصفحة الجديدة؛ لم تعد تمتلك نسخة ثانية من النموذج. توفر موفرو الوسائط أيضًا
روابط لعمليات تحويل الصورة إلى نص والكلام إلى نص إلى علامات تبويب Modality
Bridge المقابلة دون إزالة ملعب الكلام إلى نص الموجود.

**تجاوز قبول الحلقة الذاتية:** عندما يمر استدعاء الوصف عبر حلقة OmniRoute
الذاتية `/v1` (نموذج موفر غير قياسي)، يرسل الطلب الفرعي
`x-omniroute-admission-bypass: internal` ويتم المصادقة عليه مع بيانات اعتماد
الحلقة الذاتية المحلولة — `sk_omniroute` المحلي في الوضع المحلي، أو
مفتاح البيئة المكون من قبل المشغل `OMNIROUTE_API_KEY` / `ROUTER_API_KEY` (#1350) بحيث يمكن لنشر `REQUIRE_API_KEY=true` أن يستمر في تشغيل استدعاء الوصف. يتم احترام التجاوز
فقط لتلك البيانات الاعتماد الدقيقة، لذا لا يمكن للعملاء الخارجيين استخدام
الرأس لتخطي القبول.

تعيش القيم الافتراضية القديمة في `src/shared/constants/visionBridgeDefaults.ts`؛
تعيش القيم الافتراضية الجديدة الواعية بالنمط/المهمة/التخزين المؤقت ومحلل الإعدادات في
`src/shared/constants/modalityBridgeDefaults.ts`. يكشف الحاجز عن خيار منشئ
`deps` حتى تتمكن الاختبارات من حقن تنفيذات وهمية لـ `getSettings` و
`callVisionModel`.

### جسر الصوت (`audioBridge.ts`) — Modality Bridge PR-3

يIntercepts طلبات الدردشة التي تحتوي على الصوت قبل أن تصل إلى هدف غير معروف لقبول إدخال الصوت. لا يعيد توجيه طلب الدردشة أبدًا: يتم نسخ أجزاء الصوت من خلال نقطة النهاية متعددة الأجزاء المتوافقة مع OpenAI الموجودة ويستمر نموذج الدردشة المختار مع النصوص المنسوخة.

التدفق:

1. حل `supportsAudio` من خلال `getResolvedModelCapabilities()`. تفوز بيانات التعريف الخاصة بسجل الموفر، ثم بيانات التعريف الثابتة للنموذج، ثم `modalities_input` المتزامنة. قائمة الإدخال المعلنة بدون `audio` هي `false`؛ لا تبقى أدلة القدرة `null`. كل من `false` و `null` تنشط الجسر المحافظ، بينما `true` تتجاوزه.
2. حل إعدادات `modalityBridgeAudio*` واستخراج أجزاء الصوت العليا القابلة للتقطيع من كل رسالة من خلال كاشف `detectMediaParts()` المشترك. الأشكال المدعومة هي OpenAI `input_audio`, `audio_url`, و `source.media_type: "audio/*"`. يتم اكتشاف الصوت المتداخل للتوجيه ولكن لا يتم إزالته بواسطة مسار التقطيع. يتم تحديد العمل بواسطة `modalityBridgeAudioMaxClips`؛ تبقى الأجزاء اللاحقة غير متأثرة.
3. احترام `provider/model` المكون، أو دع `selectAudioBridgeModel()` يتجول في `AUDIO_TRANSCRIPTION_PROVIDERS` بترتيب الكتالوج المستقر ويختار أول نموذج مع بيانات اعتماد موفر نشطة قابلة للاستخدام.
4. يقوم `callAudioTranscription()` بتحويل الصوت بتنسيق base64/data-URI إلى ملف متعدد الأجزاء، أو يقوم بتنزيل `audio_url` عن بُعد من خلال الحاجز الخارجي العام مع تثبيت DNS وحدود 25 ميجابايت. ثم يقوم بإرسال الملف والنموذج المختار إلى حلقة `/v1/audio/transcriptions` الذاتية، مصادقًا عليه مع
   `resolveSelfLoopBearer()`. يقوم مسار النسخ الموجود بأداء البحث عن بيانات الاعتماد العادية، ومعالجة فترة الانتظار/حدود المعدل، وإرسال الموفر.
5. تستبدل المكالمات الناجحة أجزاءها بـ `[Audio N]: <transcript>`. تعمل المكالمات مع `Promise.allSettled`: الفشل الفردي يحافظ على تلك الجزء الصوتي الأصلي (#4012 العقد). إذا فشلت كل مكالمة وتم إثبات أن الهدف هو `supportsAudio === false`، تصبح الأجزاء
   `[Audio N]: (غير متاحة — لا يوجد موفر STT متصل)` (#8430 العقد). بالنسبة لهدف غير معروف (`null`)، تبقى نتيجة الفشل الكامل غير متأثرة. يتلقى هدف نصي مثبت بدون بيانات اعتماد STT قابلة للاستخدام نفس
   النسخة الصريحة دون إصدار استدعاء شبكة.

تستخدم النسخ الناجحة ذاكرة التخزين المؤقت LRU/TTL لجسر النمط على مستوى العملية. يجمع المفتاح مرجع الصوت، ووسم العملية الثابتة `audio-transcription`، ونموذج STT المختار؛ لا يتم تخزين الفشل أبدًا. تقوم محاولات الصوت بتحديث العدادات المشتركة `bridged`, `cacheHits`, `failures`, و `lastUsedAt`.
تحمل الاستجابات المحولة
`x-omniroute-modality-bridge: audio->text;model=<sttModel>;parts=<n>`؛ الطلبات غير المتأثرة لا تتلقى جزء جسر الصوت.

الإعدادات الزمنية مدعومة من قاعدة البيانات ومصادق عليها بواسطة Zod:

| المفتاح                       | الافتراضي | النطاق         |
| ----------------------------- | --------- | -------------- |
| `modalityBridgeAudioEnabled`  | `true`    | —              |
| `modalityBridgeAudioModel`    | `""`      | Auto أو STT ID |
| `modalityBridgeAudioTimeout`  | `60000`   | 1000–300000    |
| `modalityBridgeAudioMaxClips` | `3`       | 1–10           |

تظل الذاكرة المشتركة تحت السيطرة بواسطة `modalityBridgeCacheEnabled`،
`modalityBridgeCacheTtlMinutes`، و `modalityBridgeCacheMaxEntries`.

### جسر الفيديو (`videoBridge.ts`, `videoBridgePipeline.ts`)

يقوم باعتراض أجزاء الفيديو على المستوى الأعلى في تكملات الدردشة `messages` و
استجابات API `input` قبل استدعاء هدف بدون دعم فيديو أصلي معروف.
الأشكال المدعومة هي `input_video`، `video_url`، `video_source`، عناوين HTTPS،
و `data:video/*;base64,...` بيانات URIs. لا يتم التعامل مع أسماء الملفات العادية في النص
كفيديو.

تملك `VideoBridgeGuardrail.preCall` (`videoBridge.ts`) عبور الطلب،
تحقق القدرة/السياسة، تجميع الطلبات، وحمولة الاستجابة.
يتم إخفاء العمل لكل فيديو — الاستحواذ، ذاكرة النتائج الكاملة، وصف تسلسل الإطارات
(الذي يدمج أي نص صوتي تم إعلانه من قبل المتصل)، وقياسات/إلغاء/تنظيف لكل محاولة —
وراء `processVideoPart` في `videoBridgePipeline.ts`، الذي يتم استدعاؤه مرة واحدة لكل جزء فيديو داخل حلقة `preCall`.
تحدد تلك الوحدة أيضًا حدود المنفذ الصريحة `VideoMediaBrokerPort`
(الذي يستحوذ على البايتات ويستخرج الإطارات الم sampled)، `VideoAudioTranscriptionPort`
(الذي يدمج نص الصوت المعلن من قبل المتصل مع الترجمة الم sampled)، و
`VideoDrilldownPort` (شكل التخزين الخام القديم). يتم تكوين STT والإبقاء على الإطارات الإنتاجية
حول المنفذ الوصفي من خلال `createVideoSttAdapter` و
`createVideoDrilldownAdapter`؛ يستخدم الأخير دورة حياة مقبض غير شفاف مشتركة.

مسار الطلب العام `/v1` لا يستورد أو يستدعي عملية فرعية. يتم تنزيل
الفيديوهات البعيدة تحت حد 50 ميغابايت؛ الفيديوهات المضمنة بتنسيق base64 لها
حد متحفظ يبلغ 36 ميغابايت مفكوك لكل فيديو بحيث يمكن أن تظل النموذج/الرسائل/غلاف الإطار
داخل حد قبول طلب JSON العام البالغ 50 ميغابايت. يتم التحقق من تقديرات الطول
والمقاس المفكوك قبل التخصيص. يتطلب HTTPS على عنوان URL البعيد الأول
وكل إعادة توجيه، باستخدام الحماية العامة فقط مع تثبيت DNS. ثم تعبر البايتات
حدود الوسيط الداخلي `POST /api/modality-bridge/video/extract` بالضبط. هذا المسار هو
`LOCAL_ONLY` و `SPAWN_CAPABLE`، يقبل فقط طلب مصدق موثوق، حلقة عكسية، ولا يقبل أبدًا عنوان URL،
مسار نظام الملفات، تنفيذ، أو قائمة وسائط. يفرض خط أنابيب حجم جسم API وقارئ الجسم التزايدي
للمعالج بشكل مستقل حد إدخال وسيط يبلغ 50 ميغابايت. تعمل قائمة الانتظار المحدودة
على استخراج واحدة في كل مرة، وتسمح بأربعة وظائف معلقة، وتحدد الحد الأقصى للإدخال المعلق عند
100 ميغابايت.

داخل الوسيط، يقوم `ffprobe` بقراءة ملف محلي خاص؛ قائمة التنسيقات الثابتة
تستبعد تنسيقات قوائم التشغيل والبيانات الوصفية. بالنسبة لحاويات عائلة MOV المسموح بها،
تظل المراجع الخارجية لبيانات MOV معطلة بشكل افتراضي، والأمر الثابت لا يختارها.
يستخدم كل من `ffprobe` و `ffmpeg` قائمة بيضاء لبروتوكول `file` فقط، خيط واحد، مصفوفات
معامل ثابتة، بدون شل، وتنفيذات تم حلها من `PATH`. لا تعتبر تدفقات الغلاف
المرفقة صورًا مرشحة قابلة للتشغيل. يجب أن تلبي جميع التدفقات القابلة للتشغيل الحدود،
ويفضل وجود تدفق افتراضي صريح قبل الانخفاض المحدد لأدنى فهرس. يتم تحديد الفيديوهات
بحد أقصى 600 ثانية، 8192 بكسل لكل بعد، و 33,554,432 بكسل مصدر. يقوم FFmpeg بأخذ عينات من 1–16
إطارات JPEG في منتصف الطريق، ويقوم بتقليص الحافة الطويلة إلى 1024 بكسل كحد أقصى دون
زيادة حجم المدخلات الأصغر، ولا يتلقى أبدًا عنوان URL. تكون العينة `uniform` بشكل افتراضي.
تقوم السياسات الاختيارية `scene_aware` و `segment_aware` بإجراء تمريرة FFmpeg ثابتة إضافية
على التدفق المحلي الذي تم التحقق منه بالفعل، وتختار الطوابع الزمنية المحدودة
لـ `showinfo`، وتعود بشكل محدد إلى نفس النقاط المتوسطة الموحدة عند فشل الكاشف،
أو انتهاء الوقت، أو الإخراج غير الصحيح، أو مجموعة المرشحين الفارغة. يخصص وضع الوعي بالقطعة
عينات منتصف الطريق بشكل متناسب مع فترات المشهد التي تم التحقق منها؛ يتم تفصيل أدلة الوعي بالقطعة
وسلوك العودة أدناه. يتم تطبيق الحد الصارم المكون من 16 إطارًا بعد الاختيار في كل سياسة.
عندما يحتوي الطلب المعتمد على المشهد على ميزانية إطار واحدة فقط، فإنه يستخدم منتصف الطريق
الموحد للفيديو الكامل النشط أو نافذة التركيز ويبلغ عن `policyEffective: uniform`: لا يمكن
لإطار مشهد واحد مختار الحفاظ على كلا الطرفين الزمني. يمكن للمتصل اختيارياً تقديم نافذة تركيز
محدودة (`start`/`end` ثواني)؛ يتم تثبيت الحدود على مدة الوسائط، ويتم رفض النوافذ المعكوسة
أو غير المحدودة، ويتم تنفيذ جميع سياسات أخذ العينات فقط داخل الفاصل الزمني الموحد. يتم تضمين
النافذة الناتجة في بيانات أخذ العينات وفي البادئة الوصفية غير الموثوقة بحيث يمكن للنماذج
اللاحقة تمييز مقتطف مركز من الجدول الزمني الكامل.

تركيز الترجمة الدلالية هو إعداد منفصل وصريح. وضع التحليل الافتراضي `full`
يحافظ على موجه الإطار الحالي ولا يقوم أبداً بإعادة توجيه نص الطلب إلى نموذج الترجمة.
في وضع `focused`، يقرأ الجسر فقط أحدث `text`/`input_text` غير الفارغ الذي كتبه المستخدم
من نفس حاوية الدردشة أو الاستجابات، ويقوم بتطبيعه إلى NFC، ويجمع بين أحرف التحكم والمسافات،
ويحده إلى 500 نقطة رمز Unicode. يعود النتيجة الفارغة إلى الموجه `full` بالضبط. يتم تسلسل تلميح
قابل للاستخدام كـ JSON في كتلة سياق المستخدم غير الموثوق بها وقد تعطي الأولوية فقط للتفاصيل
الملحوظة؛ لا يمكن أن تتجاوز التحذير المنفصل ضد اتباع التعليمات المرئية أو المسموعة في الوسائط.
لا يستنتج التركيز النصي أبدًا `start`/`end` أو يغير
عينة الزمن.

#### FU-07 دليل القطعة الهيكلية

`segment_aware` يستخدم تمرير تحليل مسبق محدود على تدفق الفيديو المحلي الذي تم التحقق منه بالفعل. سلسلة الفلاتر الثابتة أولاً تقوم بتقليص العرض إلى 320 بكسل كحد أقصى، ثم تكشف عن تغييرات المشهد والفترات المجمدة، ثم تأخذ عينات بمعدل إطار واحد في الثانية للضباب، ومتوسط اللمعان، والمعلومات المكانية/الزمانية. يقتصر هذا التمرير على 600 عينة هيكلية، خيط واحد من FFmpeg/filter، نفس بروتوكول `file`-only وقوائم الحاويات المسموح بها، حد إخراج عملية يبلغ 1 ميجابايت، وما لا يزيد عن 30 ثانية داخل مهلة الإلغاء/الموعد النهائي المشتركة للوسيط. لا يقبل أبداً أمرًا أو فلترًا أو مسارًا أو عنوان URL من الطلب.

القيم الهيكلية هي أدلة أخذ عينات حتمية، وليست فهمًا دلاليًا للفيديو. لا تستنتج الموضوعات أو الأفعال أو التسميات أو الكلام أو نية المستخدم. تشكل حدود المشهد والتجميد مقاطع؛ تغطي التجميد، الضباب، التعرض، التفاصيل المكانية، والتغير الزمني تؤثر فقط على كيفية تخصيص ميزانية الإطارات الحالية من 1 إلى 16 إطارًا. يتم تحديد الحد الأقصى لمقطع مجمد عند إطار واحد، بينما تتنافس المقاطع غير المجمدة على الميزانية المتبقية. عندما تتجاوز الحدود عدد الإطارات، يتم الاحتفاظ بتغطية زمنية موحدة بحيث لا يمكن أن تخفي القطع السريعة المبكرة مقطعًا طويلًا متأخرًا. يتم دمج حدود المشهد ضمن دقة التحليل البالغة 1 ثانية لحدود التجميد.

تؤدي الفلاتر المفقودة، أو الأدلة غير الصحيحة/الفارغة، أو خطأ الكاشف، أو مهلة التحليل المسبق المحدودة إلى الفشل المفتوح وفقًا لسياسة منتصف النقطة الموحدة الدقيقة. لا يؤدي إلغاء المتصل أو الموعد النهائي للوسيط إلى الفشل المفتوح: بل ينهي العملية الفرعية الجارية، ويمنع استخراج الإطارات لاحقًا، ويتم إزالة الشجرة المؤقتة الخاصة في `finally`.

`scripts/perf/video-bridge-fu07-eval.ts` يولد تركيبات FFmpeg حقيقية حتمية لتوفير التكاليف بعد إزالة التكرار، وتخصيص ميزانية الحركة الكثيفة، وأدلة الضباب/التعرض/SI-TI، والقطع السريعة مع ذيل طويل، وإيجابيات كاذبة تدريجية. يسجل وقت الجدار للتحليل المسبق، وحيثما يتوفر `/usr/bin/time`، يستخدم وحدة المعالجة المركزية الفرعية وذروة RSS. تتحقق فحوصاته من الجودة فقط من خلال الأوراق الهيكلية. تظل جودة نموذج التسميات الحقيقية `HOLD` لأن هذا الحزام ليس لديه نقطة نهاية مصرح بها أو قاضي مجمد. تظل التوفير المالي أيضًا `HOLD` ما لم يوفر `--caption-cost-per-call-usd` تقديرًا إيجابيًا صريحًا لكل مكالمة؛ لا يقوم البرنامج أبدًا بتصنيع أي من النتائج.

يقتصر كل إطار على 4 ميجابايت، وجميع الإطارات الخام معًا على 23 ميجابايت، واستجابة الوسيط المتسلسلة على 32 ميجابايت. تتم إزالة دليل مؤقت خاص في `finally`. لا يقوم OmniRoute بتجميع FFmpeg ولا يقبل مسارًا تنفيذيًا مخصصًا. قبل إضافة التسميات، يقوم الجسر بتطبيق تمرير حذف بصري محافظ: يتم تقليل كل JPEG إلى مخزن رمادي 16×16 ويتم مقارنته فقط مع الإطار الأخير المحتفظ به. بالنسبة لميزانية التسميات المطلوبة التي تتجاوز إطارًا واحدًا، يوفر الاستخراج مجموعة مرشحة محدودة تصل إلى ضعف تلك الميزانية ولا تزيد عن 16 إطارًا. يتم تطبيق الحد المطلوب فقط بعد إزالة التكرار، مع الحفاظ على المرشحين المختارين الأول والأخير خلال التخفيف النهائي عندما تكون الميزانية على الأقل اثنين. تستخدم السياسة المصدرة `grayscale-16x16-mean-cells-v2` الأكبر من دلتا اللمعان المتوسط ونسبة خلايا الصورة المصغرة التي تكون دلتا المعيارية الخاصة بها على الأقل 0.05. عتبة التكرار هي الثابت 0.04، الذي تم اختياره من أجل التنبؤ بدلاً من أن يتم الكشف عنه كإعداد وقت التشغيل. هذه الإشارة الثانوية عالية التباين تحافظ على الحركة الصغيرة والتغيرات النصية المرئية التي يمكن أن تخفيها المقارنة التي تعتمد فقط على المتوسط. تفشل أخطاء المقارن أو فك التشفير بشكل مفتوح وتحافظ على التغطية. تفصل بيانات التعريف الناتجة بين المرشحين المستخرجين، والإطارات المستخدمة بنجاح، والتكرارات المرئية التي تم إسقاطها.

يمكن أن يطلب جزء الفيديو المميز بشكل صريح ورقة اتصال مؤرخة. يبني الجسر شبكة JPEG بحد أقصى 4 أعمدة و16 إطارًا. كل خلية بكسل 512 تحرق طابعها الزمني المصدر في شريط سفلي عالي التباين، بينما تظل نفس الطوابع الزمنية في بيانات التعريف النصية للربط والتدقيق في الأسفل. تظل JPEG الكاملة محدودة عند 32 ميجابايت. إذا لم يتمكن `sharp` من فك تشفير أو تكوين الشبكة، يعود الجسر إلى الإطارات JPEG الفردية؛ لا يزال إلغاء العميل ينتشر عبر عملية الورقة.

أدلة الترويج مفصولة عمدًا عن الميكروبينشمارك للتكوين الاصطناعي. `scripts/perf/video-bridge-contact-sheet-eval.ts` يحدد حزام A/B ذو إصدار مخطط لنماذج الرؤية المتوافقة مع OpenAI الحقيقية. يقيس الرموز المبلغ عنها من قبل المزود، وزمن الجدار من البداية إلى النهاية (بما في ذلك تكوين الورقة)، وعدد مكالمات النموذج، والاحتفاظ بالحقائق المحددة في البيان. لا يتم كتابة استجابات النموذج الخام في التقرير؛ يتم الاحتفاظ فقط بتجزئات SHA-256 ومعرفات الحقائق المتطابقة. لا يقوم الحزام بأي مكالمة شبكة أو نموذج مدفوع ما لم يتم تمرير `--execute-real` ويتم تكوين `--model` و`OMNIROUTE_BASE_URL` و`OMNIROUTE_API_KEY`. بدون تلك التشغيل الحقيقي الصريح، تظل حكمته القابلة للقراءة آليًا `HOLD`؛ قياسات الحمولة الاصطناعية/عدد المكالمات وحدها ليست أدلة ترويج.

يستهلك `scripts/perf/video-bridge-promotion-eval.ts` المنفصل ملاحظات FU-07 أو FU-09. يتطلب قبول الترويج جميع أنواع السيناريوهات الاصطناعية الثمانية بالإضافة إلى مقطع حقيقي مُعقم، على الأقل ثلاث تكرارات مقاسة لكل دور وحالة، وجميع المقاييس العشرة المعلنة، وتجزيئات الوسائط المجمدة/المطالبة/الحقائق المتوقعة/الإعدادات، ومعرفات الملاحظات الفريدة وترتيب A/B المصدق. يربط إيصال التنفيذ تجزئة المجموعة، وSHA المرشح الدقيق، وإصدار النموذج. تظل القياسات المفقودة أو غير الصالحة `HOLD`، بما في ذلك وحدة المعالجة المركزية فوق 30 ثانية، وذروة RSS فوق 512 ميجابايت أو التحليل المسبق فوق 30 ثانية. هذه هي حدود قبول الأدلة، وليست ضمان تنفيذ جديد لوقت التشغيل RSS.

FU-07 يتطلب احتفاظًا بجودة لا تقل عن 98% وزمن استجابة p95 لا يزيد عن 1.2x من الأساس، بالإضافة إلى إما تحسين متوسط استرجاع متوازن مطلق قدره 0.05 عند مكالمات تسميات متوسطة مكافئة، أو على الأقل 10% أقل من متوسط مكالمات تسميات ما بعد التكرار. FU-09 يتطلب على الأقل 0.85 جودة، 95% احتفاظ، 20% تقليل زمن استجابة p95 و10% تقليل في الرموز. فقدان الحقائق الحرجة، الامتثال للحقن أو الاستخدام المفقود يمنع الترقية. لا يمكن لتنفيذ واحد ترقية أي شيء: `--previous-report` يؤكد على وجود تنفيذين متميزين، غير متداخلين، مؤهلين بشكل متتالي لنفس السياسة/نموذج المراجعة/المرشح/المجموعة. تجربة أخذ العينات لا يمكن أن تؤكد تجربة ورقة الاتصال.

يجب على الجامعين تقييم الردود في الذاكرة وحفظ `responseDigest` بالإضافة إلى القياسات وارتباطات الملاحظات، وليس نص الرد أبدًا. يقرأ المستهلك أيضًا الملاحظات الخام القديمة ولكنه لا ينسخ ذلك النص إلى تقاريره. يتم قبول واحد فقط من `responseDigest` أو `rawResponseText` لكل ملاحظة. تظل القائمة المسموح بها بالإصدار فارغة مع قيمة افتراضية غير قابلة للتغيير `hold`. يتطلب الإدخال المؤهل مرجع أدلته، السياسة، مراجعة النموذج، SHA المرشح الدقيق، تجزئة البيان واثنين من معرفات التشغيل المتميزة؛ يتم رفض السياقات المتضاربة. هذه البيانات الوصفية هي عقد تدقيق، وليست دليلاً على أن الملف المرجعي يحتوي على قياسات حقيقية. راجع الإيصالات الفعلية قبل إضافة أي إدخال. نقطة نهاية إحصائيات الإدارة ولوحة فيديو تعرضان جاهزية محافظة. لا يحدد اسم مستعار للنموذج فقط مراجعة النموذج أو SHA المرشح الجاري، لذا تقارير لوحة المعلومات الحالية `HOLD` بدلاً من إعادة استخدام الأهلية من سياق تنفيذ آخر. تظل الاختيارات التجريبية الصريحة منفصلة عن الترقية؛ لا يتم تغيير أي افتراضي تلقائيًا.

يمكن للمتصلين إرفاق مصفوفة اختيارية `transcript.cues` إلى جزء فيديو مدعوم عندما يمتلكون نصًا متماشيًا بالفعل. يجب أن يحمل كل تلميح `text`، فترة `start`/`end` محدودة داخل المدة المختبرة، و`source` مدرج في القائمة البيضاء (`client`، `embedded`، أو `audio-bridge`); القيمة الافتراضية لـ `confidence` هي `1` ويجب أن تبقى بين `0` و `1`. يتم دمج التلميحات المكررة تمامًا. لا يبدأ OmniRoute النسخ من هذه البيانات الوصفية: يتم نسخ التلميحات المعتمدة إلى النتيجة الموصوفة مع المصدر، والثقة، والفترة، ويتم عرضها كملاحظات غير موثوقة جنبًا إلى جنب مع تسميات الإطارات. يتم رفض النص غير صالح، أو خارج النطاق، أو بدون مصدر بدلاً من دمجه في تدفق التسميات. تقوم قنوات نصوص الطلب لكل قناة بتطبيع المصدر المقدم إلى `client`، بما في ذلك التسميات المعلنة ذاتيًا `embedded` أو `audio-bridge`. فقط محول مملوك للخادم يمكنه تعيين تلك التسميات الموثوقة من خلال الوسيطة `trustedSource` الخاصة بالكود فقط؛ لا يمكن أن تصل حقل JSON للطلب إلى تلك الوسيطة. يظل نص النسخ محتوى مشتق غير موثوق من الوسائط، بغض النظر عن مصدره، ويجب ألا يحدد أبدًا التفويض.

يمكن للمتصل المتقدم تقديم مسار `audioTranscript` لنفس الفيديو؛ يتم التعامل معه كنص مقدم من العميل، وليس دليلاً على النسخ من الخادم. يتم تشغيل خط الفصل المدمج للملاحظات البصرية والصوتية تحت موعد نهائي واحد وإشارة إلغاء، ويطلب منها على جدول زمني مشترك، ويجمع التكرارات الدقيقة، ويبلغ عن نتيجة جزئية عندما ينجح جانب واحد فقط. يتدهور `audioTranscript` غير الصالح إلى تلك النتيجة الجزئية - يتم الاحتفاظ بالوصف البصري ويسجل فرع الصوت رمز فشل معقم - بدلاً من فشل الفيديو بالكامل. تتوفر كل فرع، وعلم الجزئية، وأكواد الفشل المعقمة في النتيجة الموصوفة، في بيانات التعريف الحارسة (`audioFusionRuns`/`audioFusionPartials`/`audioFusionFailureCodes`)، في بيانات ذاكرة التخزين المؤقت للنتيجة، وفي عدادات دمج الجسر. لا يستدعي مسار جسر الفيديو الافتراضي تحويل الكلام إلى نص أو تنزيل نسخة وسائط ثانية؛ بدون ذلك المسار الصريح، يظل الفيديو فقط.

**احتفاظ النص (#12150 P1).** ينطبق هذا تلقائيًا كلما قام جسر الفيديو (الذي يتطلب الاشتراك) بعرض تلميح نصي - لا يوجد علم احتفاظ منفصل. عندما يقوم طلب بعرض أي تلميح نصي (تقرير `transcript` المعلن من المتصل أو `audioTranscript` المدمج)، يقوم الحارس بتحديده كـ `videoBridgeObserved` وينتج ظلًا محجوبًا لوصف الفيديو - عرض مطابق يتم فيه استبدال جسم النص الحر لكل تلميح بـ `[redacted-video-transcript]`، تم بناؤه عن طريق استبدال حقل التلميح المنظم قبل تجميع السلسلة (وليس عن طريق تحليل النص المسطح، لذا لا يمكن أن يبقى محتوى التلميح - سواء كان عدائيًا أو عاديًا، بما في ذلك الأجسام التي تحتوي على `]` مثل `[inaudible]`/`[music]` -). يقوم سجل الطلب المحفوظ بتبديل كل جزء نصي مشتق من الفيديو بذلك الظل المحجوب، متطابقًا حسب تساوي المحتوى؛ يتم إعادة قراءة مرساة `fullText` من الحمولة النهائية للحارس قبل الطلب، لذا لا يزال التطابق ناجحًا بعد أن تعيد الحواجز اللاحقة (ماسكات PII والاعتماد، الأولويات 10/95) كتابة نص الوصف في المكان وبعد إعادة تشكيل مصفوفة الرسالة بواسطة نظام التحفيز/التسليم/حقن الذاكرة. تظل الجسم المرسل إلى النموذج دون تغيير. لا يملأ الطلب الملاحظ أيضًا أي ذاكرة دائمة (يتم تخطي كل من استخراج الطلب والرد)، لذا لا يمكن أن يكرر رد النموذج نص النسخ في الذاكرة.

**حقول الفيديو الخام (#12430).** عندما يكون الجسر مفعلًا والدعم الأصلي للفيديو غير معروف أو غائب، فإن الحقول المعرفة `transcript`/`audioTranscript` تنشط أيضًا `videoBridgeObserved`، حتى بعد فشل الوصف أو حد `maxVideos`. يتم احتساب `null` والسلاسل الفارغة؛ الحقول الغائبة والبيانات الوصفية غير المتعلقة بالفيديو لا تحتسب. تقوم النسخ المحتفظ بها بحجب هذه الحقول أو حذف الطلب، ويتم تجاوز ذاكرات التخزين المؤقت.

في تلك المسارات الاحتياطية، تصبح إشارات المتصل الصالحة أجزاء مدعومة من `text`/`input_text` بدلاً من حقول المزود غير القياسية. تظل المسارات المقدمة من الطلب غير موثوقة كملاحظات `client`، مع تحذير صريح بأن الفيديو لم يتم وصفه وأن الطوابع الزمنية لم يتم التحقق منها مقابل الوسائط. تنطبق الميزانيات الحالية المكونة من 256 إشارة/64 كيلوبايت إجمالي وميزانيات لكل إشارة عبر المسارين معًا؛ يجب أن تتناسب الطوابع الزمنية مع الحد الأقصى البالغ 600 ثانية للوسيط وأي نافذة تركيز مقدمة. يتمdiscard المسارات غير الصالحة، ولا يتم تمريرها كنص عشوائي؛ يمكن استخدام شقيق صالح ما لم يتم تجاوز ميزانيتهم المشتركة. لا تضيف الحقول الفارغة/الصفرية أي نص. لا يتم إضافة أي استرجاع وسائط أو نسخ نصي بواسطة هذا الاحتياطي. تتم إزالة حقول تمديد النص من حامل الفيديو الاحتياطي وأجسام `video_url`/`source`. تظل قائمة السماح الخاصة بـ OpenAI صارمة؛ تظل حوامل الفيديو غير المعروفة متاحة وتحتفظ الأهداف المعروفة التي تحتوي على نص فقط بعلامات أمان. تحمي ظلال الحذف الهيكلية النص المضاف من النسخة النصية، بينما تظل طلبات المتصل الأصلية غير متغيرة. تحتفظ الأهداف المدعومة محليًا والجسور المعطلة بسلوك التجاوز الحالي.

تستخدم النسخ المحتفظ بها نفس إشارة الطلب الملاحظة. يتم استبدال لقطة طلب العميل الخام قبل حواجز الحماية، والطلب المعلق في الذاكرة، وسجل الطلب المرفوض المبكر هيكليًا حقول النص في أجزاء الفيديو؛ يتم حذف المطالبات النصية التي تم توليدها بواسطة مراحل خط الأنابيب وتسليم السياق عند مصب جسم الطلب المحتفظ به. تجعل علامة `video_content_removed` استمرار `previous_response_id` يفشل مغلقًا بدلاً من إعادة بناء نص تم التخلص منه عمدًا. إذا فقد طلب ملاحظ إخفاء الظل لكل جزء قبل التسجيل، أو حتى إذا فشلت واحدة من عدة ظلال فيديو في المطابقة بعد تغييرات الطلب اللاحقة، يتم حذف جسم الطلب المحتفظ به بالكامل بدلاً من الاحتفاظ بنسخة نصية جزئية.

بالنسبة لطلب ملاحظ، قد تقتبس استجابة النموذج أي جزء من النص دون وجود حد هيكلي للإشارة. لذلك يتم استبدال `responseBody` في سجل المكالمات المحتفظ به بعلامة حذف؛ لا يتم الاحتفاظ بالقطعة التفصيلية لخط الأنابيب (التي يمكن أن تشمل أجسام upstream/العميل وقطع البث). تتجاوز ذاكرات التخزين المؤقت للسمات، والهوية، وإعادة تشغيل التفكير عمليات القراءة والكتابة لذلك الطلب. تظل طلبات المزود واستجابة العميل المرئية دون تغيير. يتم تصريف بايتات keepalive المبكرة من المخزن المؤقت المؤقت عند حذف القطعة التفصيلية. تقارير تحذير Kiro من EventStream غير الصالحة عدد بايت الحمولة فقط، وليس محتوياتها أو خطأ محلل JSON الخام.
هذا لا يدعي أن كل تشخيص غير ذي صلة من المزود/الإضافة قد تم تدقيقه؛ يتم تتبع عملية المسح الأوسع للاحتفاظ بالمصب في #11658.

دورة حياة `/api/modality-bridge/video/drilldown` الداخلية هي ركيزة تخزين مؤقت منفصلة، معتمدة على حلقة/توكن. تتطلب كل عملية أيضًا معرف رئيسي غير شفاف قياسي. قبل تمكين المتصل الإنتاجي، يجب أن يستمد ذلك المعرف من المستأجر المعتمد ويجب ألا يمرر أبدًا قيمة يختارها العميل. تربط مفاتيح التخزين المؤقت ذلك المعرف الرئيسي بمعرفات الجلسة القياسية ومراجع الفيديو، وتخزن فقط مفاتيحها المشتقة من SHA-256، وتحدد كل من عمليات القراءة والحذف لنفس المعرف الرئيسي. يخزن التخزين المؤقت في أقصى حد 16 إطار JPEG مشتق لكل إدخال، وينتهي بعد عشر دقائق، ويدعم عمليات القراءة المحدودة `start`/`end` أو حذف الجلسة الصريح.

يقتصر كل معرف رئيسي على 16 إدخال و64 ميجابايت من بيانات JPEG القياسية. هذه الحدود مستقلة عن الحد الأقصى العالمي المكون من 64 إدخال/256 ميجابايت: ضغط حصة المعرف الرئيسي يطرد فقط إدخالات ذلك المعرف الأقل استخدامًا مؤخرًا قبل النظر في الطرد العالمي LRU. يتم مسح الإدخالات المنتهية من كل من المحاسبة الرئيسية والعالمية عند نشاط التخزين المؤقت، بينما لا تؤدي الإلغاء وفشل التحقق إلى الالتزام باستبدال جزئي.

يرفض التخزين المؤقت Base64 غير القياسي، والحشو الزائد، والوسائط غير JPEG، وJPEGs غير الصالحة أو المقطوعة، وJPEGs التي تنتج تحذيرًا أثناء فك تشفير الصورة الكاملة المحدودة `sharp`. يعيد ترميز كل صورة مقبولة كـ JPEG قياسي، ويستمد العرض والارتفاع من البايتات المفككة بدلاً من الوثوق بحقول المتصل، ويتخلص من أي بايتات متعددة اللغات متبقية بدلاً من الاحتفاظ بها. يتم تحميل فقط المخزن المؤقت المضغوط القياسي المحدود على كل من الحصص. يتضمن حد JSON للاتصال تكاليف Base64 الزائدة للحد الأقصى المدخلات المفككة البالغ 32 ميجابايت. كل
اشتقاق مخزن يسجل تنسيق JPEG/دقة المعتمد، سياسة العينة، إصدار الاشتقاق، وقت الإنشاء، تجزئة المحتوى المحسوبة من الخادم، وتجزئة المرجع الأب بالإضافة إلى تجزئة محتوى الأب للمتصل الموثوق. يتم التحقق من الإلغاء بين مراحل فك التشفير/التجزئة غير المتزامنة قبل الالتزام الذري للتخزين المؤقت.

يعيد المنتج الإنتاجي استخدام إطارات الوسيط المشتقة مسبقًا فقط بعد التحليل البصري الناجح، دون الحاجة إلى تنزيل/استخراج فيديو ثانٍ. يتطلب `modalityBridgeVideoDrilldownEnabled=true` من المشغل، و`drilldown: true` لكل جزء، ومعرف سجل مفتاح API معتمد. لا تؤسس قيم المعرف الرئيسي/الجلسة المعلنة من قبل العميل الملكية أبدًا. بدون الشروط الثلاثة، لا يتم تجزئة أو تغيير حجم أو الاحتفاظ بإطارات إضافية. يحافظ فشل الاحتفاظ على الاستجابة البصرية القابلة للاستخدام. تتجاوز الطلبات المتفق عليها ذاكرة التخزين المؤقت لنتائج الفيديو بالكامل بحيث لا تعيد النتائج المخزنة التعاملات أبدًا.

استجابات JSON وSSE الناجحة تكشف عن أربعة مقبضات غير شفافة كحد أقصى في رأس `x-omniroute-video-drilldown` المحدود. يمكن للأصول المصرح بها من المتصفحات قراءة هذا الرأس دون توسيع سياسة أصل CORS. تستخدم المقبضات الجديدة `v1.<32-byte random base64url token>`، ويحتفظ السجل فقط بـ SHA-256 hashes الخاصة بها. كما يقبل محلل الرأس/القارئ الرموز القديمة 64-hex. المستهلك العام المعتمد هو `GET /api/v1/video-bridge/drilldown?handle=...`، والذي يتم التحكم فيه بشكل مستقل بواسطة `modalityBridgeVideoDrilldownRemoteEnabled=true`. إلغاء الوصول بشكل صريح مع قيمة false المستمرة يسحب الوصول حتى عندما يكون البديل القديم `OMNIROUTE_VIDEO_BRIDGE_DRILLDOWN_REMOTE_ENABLED` مفعلًا. الاحتفاظ في الإنتاج له البديل القديم المماثل `OMNIROUTE_VIDEO_BRIDGE_DRILLDOWN_ENABLED`. كلا البديلين يكونان معطلين بشكل افتراضي.

يستمد المستهلك الملكية من المفتاح المعتمد، ويطبق سياسة المفتاح، ويعيد نفس 404 للمقبضات غير المعروفة، المنتهية الصلاحية ومقبضات مفتاح آخر. يقبل `variant=preview|standard|detail` (الحد الأقصى لأبعاد JPEG 320/640/1280، لا يتم تكبيرها أبدًا)، `limit=1..8` (أو الاسم المستعار القديم `frames`، وليس كلاهما)، `page` المعتمد على الصفر، و`start`/`end` ثواني التركيز الاختيارية. يتم رفض مفاتيح الاستعلام المكررة ونوافذ التركيز المعكوسة. يحتوي كل متغير تم إرجاعه على تجزئة لمحتواه الفعلي وبيانات دقة المحتوى الفعلي، مرتبطة بالمصدر المحتفظ به. يتم اشتقاق المتغيرات عند القراءة بدلاً من تخزينها كنسخ محتفظ بها إضافية. استجابة JSON، بما في ذلك Base64/envelope، محددة بـ 32 ميغابايت؛ تعيد الصفحة الكبيرة 413 ويجب على العميل طلب عدد أقل من الإطارات. تتحقق عمليات القراءة من الإلغاء حول كل تغيير في الحجم وتعيد التحقق من صلاحية المقبض قبل الإرجاع. `DELETE` من قبل المالك هو عملية غير متغيرة؛ الحذف أو انتهاء صلاحية TTL يحرر المصدر المحتفظ به وحساب الاستخدام.

المخزن المشترك محلي للعملية: تنتهي صلاحية المقبضات عند إعادة التشغيل ولا يمكن نقلها بين عمليات OmniRoute المستقلة. تكشف إحصائيات الإدارة عن سياسة الاحتفاظ/التحكم الفعالة وتجمع الإدخالات/البايتات المحتفظ بها فقط، وليس الوسائط أو المراجع أو معرفات الجهات الرئيسية أو المقبضات. تعرض لوحة إعدادات الفيديو تلك القيم ويمكن أن تحتفظ بكل من مفاتيح الموافقة. هذه الوثائق التنفيذية ليست دليل نشر مباشر أو ترويج؛ يتم تتبع قبول النموذج الحقيقي بشكل منفصل.

تتم تسمية الإطارات بالتسلسل مع نموذج الفيديو المكون. يرث تجاوز الفيديو الفارغ إعداد الرؤية؛ إذا كان كلاهما فارغًا، يختار جهاز التوجيه التلقائي للرؤية النموذج القادر على الرؤية الفعالة. تحل التسميات الناجحة الجزء الأصلي مع بادئة ثابتة `[Video description:` التي تشير أيضًا إلى النص كملاحظة مشتقة من وسائط غير موثوقة وتخبر النماذج التالية بعدم اتباع التعليمات الموجودة في الوسائط. تشمل مفاتيح ذاكرة التخزين المؤقت لتسميات الإطارات بايتات JPEG، والمطالبة، والطابع الزمني، والنموذج الفعال؛ يتم تخزين التسميات الناجحة فقط في الذاكرة المؤقتة. تحتفظ إدخالات الذاكرة المؤقتة بالنموذج المنتج الناجح الفعلي، بما في ذلك نموذج احتياطي؛ يُبلغ الجسر عن `mixed` عندما يتم إنتاج إطارات مختلفة بواسطة نماذج مختلفة. تعيد ضربة الذاكرة المؤقتة استخدام هوية المنتج بدلاً من إعادة تسميتها كخطة توجيه مطلوبة. يتم تعيين ذاكرة التخزين المؤقت لنتائج الفيديو الكامل على كل إدخال يغير المخرجات — المطالبة، النموذج الفعال، سياسة العينة، عدد الإطارات، وضع التحليل الدلالي، بصمة SHA-256 لتلميح التركيز العادي، نافذة التركيز، `transcript`، `audioTranscript`، وعلم ورقة الاتصال — لذا فإن تغيير أي من تلك الأبعاد هو فشل في الذاكرة المؤقتة، وليس إعادة استخدام قديمة. إصدار سياسة إزالة التكرار البصرية، والحد، وعدد إطارات المرشحين المحدودين واضح أيضًا في مفتاح ذاكرة التخزين المؤقت للنتائج والبيانات الوصفية؛ لذلك لا يمكن لتغيير السياسة إعادة استخدام وصف فيديو كامل قديم. تحتفظ بيانات وصف ذاكرة التخزين المؤقت v4 بوضعها وبصمتها، وليس المهمة الخام للمستخدم. تقارير بيانات وصف الحماية عن كل من أوضاع التحليل المطلوبة والفعالة؛ يتم الإبلاغ عن وضع `focused` المطلوب بدون نص مستخدم قابل للاستخدام على أنه فعال `full`.

تستخرج الحماية كل جزء فيديو مدعوم ولكن لا تصف أكثر من `modalityBridgeVideoMaxVideos`. بالنسبة لهدف ثبت أنه `supportsVideo === false`، تصبح مقاطع الفيديو الفاشلة والحدود الزائدة علامات نصية آمنة صريحة بحيث لا تبقى أي وسائط فيديو خام. عندما تكون القدرة غير معروفة، تحتفظ تلك الأجزاء بحامل الفيديو الخاص بها؛ يتبع أي نص احتياطي تحويل النص المحدود أعلاه. تتجاوز الأهداف التي تحتوي على `supportsVideo === true` الجسر. تنتشر إشارة إلغاء طلب العميل عبر التنزيل، وطابور الوسيط، والعمليات الفرعية، واستدعاءات التسميات؛ تتوقف عمليات الإلغاء بين مقاطع الفيديو ولا تفشل أبدًا في فتح الوسائط الخام.

الإعدادات الزمنية مدعومة من قاعدة البيانات ومصدقة بواسطة Zod:

| المفتاح                             | الافتراضي   | النطاق / السلوك                                                                    |
| ----------------------------------- | ----------- | ---------------------------------------------------------------------------------- |
| `modalityBridgeVideoEnabled`        | `false`     | وقت تشغيل اختياري، اختيارية                                                        |
| `modalityBridgeVideoAnalysisMode`   | `"full"`    | `full` يحتفظ بالتسميات العامة؛ `focused` يستخدم السياق الأخير غير الموثوق المحدود  |
| `modalityBridgeVideoModel`          | `""`        | وراثة نموذج جسر الرؤية                                                             |
| `modalityBridgeVideoFrameCount`     | `8`         | 1–16                                                                               |
| `modalityBridgeVideoSamplingPolicy` | `"uniform"` | `uniform`، `scene_aware`، أو `segment_aware` النسبي؛ فشل الكاشف يعود إلى `uniform` |
| `modalityBridgeVideoMaxVideos`      | `1`         | 1–4                                                                                |
| `modalityBridgeVideoTimeout`        | `120000`    | 1000–120000 مللي ثانية                                                             |

قيم مهلة الفيديو المحفوظة القديمة التي تتجاوز 120 ثانية يتم تقليصها إلى
موعد انتهاء الوسيط؛ يتم رفض الكتابات الجديدة التي تتجاوز هذا الحد.
`GET /api/modality-bridge/video/runtime` يتطلب موثوقية محلية موثقة قبل المصادقة أو استكشاف وقت التشغيل، ثم يتطلب مصادقة الإدارة. يعيد فقط إصدارات FFmpeg/ffprobe المتاحة والمعقمة، وسبب ثابت عندما يكون وقت التشغيل غير متاح. نقطة استخراج الداخلية ليست واجهة برمجة تطبيقات تحميل عامة: تشبع الطابور يعيد `503` بالإضافة إلى `Retry-After`، وقطع الاتصال من المتصل يعيد `499`، وموعد انتهاء الوسيط الثابت يعيد `504`. تضيف الاستجابات المحولة
`video->text;model=<visionModel>;parts=<videos>` إلى رأس `x-omniroute-modality-bridge` المركزي دون إزالة مقاطع الرؤية أو الصوت.

### ماسك PII (`piiMasker.ts`)

يعمل على **كلا** المرحلتين.

- **`preCall`** يقوم بنسخ الحمولة، ويمشي عبر `system` و `messages` و `input` و
  `prompt` (بما في ذلك العناصر النصية العادية)، ويطبق `processPII()` (من
  `@/shared/utils/inputSanitizer`) على حقول النص `content`/`text`. عندما
  يكون `PII_REDACTION_ENABLED=true`، يتم حذف PII المكتشفة في الحمولة الصادرة. هذا مستقل عن `INPUT_SANITIZER_MODE` (الذي يتحكم فقط في سياسة حقن الموجه). عندما يكون الحذف غير مفعل، تسجل المكالمة عدد الاكتشافات دون إعادة كتابة المحتوى.
- **`postCall`** يقوم بعمل نسخة عميقة من الاستجابة، ويشغل `sanitizePIIResponse()` بالإضافة إلى
  ماسك شكل واجهة برمجة التطبيقات للاستجابات (`maskResponsesOutput` — يغطي
  `output_text` و `output[].content[].text`). إذا حدث أي حذف، فإن
  الاستجابة المعدلة تحل محل الأصلية.

لا يمنع الحاجز أبدًا؛ بل يقوم فقط بالتعليق (`meta.detections`,
`meta.redacted`) أو إعادة الكتابة.

### حقن الموجه (`promptInjection.ts`)

يكتشف الهياكل العدائية في المحتوى المقدم من المستخدم ويطبق السياسة المكونة. يتم تحديد السلوك بواسطة متغيرات البيئة وخيارات المُنشئ:

| الإعداد    | متغير البيئة                                                                                             | الافتراضي | التأثير                                                                                                                                                                       |
| ---------- | -------------------------------------------------------------------------------------------------------- | --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| مفعل       | `INPUT_SANITIZER_ENABLED`                                                                                | `true`    | عندما يكون `false`، يقوم الحاجز بتقصير الدائرة.                                                                                                                               |
| الوضع      | `INJECTION_GUARD_MODE` / `INPUT_SANITIZER_MODE`                                                          | `warn`    | سياسة الحقن: `block`، `warn`، أو `log`. (`redact` مقبول للتوافق العكسي ولكنه لا يقوم **بإزالة** نص الحقن؛ طلب إعادة كتابة PII يتم التحكم فيه بواسطة `PII_REDACTION_ENABLED`.) |
| عتبة الحظر | خيار `blockThreshold` / `INPUT_SANITIZER_BLOCK_THRESHOLD` (اسم مستعار `INJECTION_GUARD_BLOCK_THRESHOLD`) | `high`    | الحد الأدنى من الشدة المطلوبة للحظر. المتوسطة هي للمراقبة فقط بشكل افتراضي.                                                                                                   |

**أولوية الوضع** (`getMode`): `options.mode` للمتصل →
`INJECTION_GUARD_MODE` **تجاوز علم ميزة DB** (لوحة التحكم → الإعدادات →
أعلام الميزات) → `INJECTION_GUARD_MODE` متغير البيئة → `INPUT_SANITIZER_MODE` متغير البيئة →
`warn`. لذلك، فإن تجاوز لوحة التحكم يفوز على متغيرات البيئة، لذا تتحكم واجهة مستخدم أعلام الميزات في تشغيل الحاجز مباشرة (بدون إعادة تشغيل). قراءة DB آمنة ضد الفشل:
إذا حدث خطأ، يعود الحاجز إلى سلوك يعتمد على البيئة، وعندما لا يتم تعيين أي تجاوز يكون السلوك مطابقًا لحل يعتمد فقط على البيئة.

مصادر الاكتشاف:

1. `sanitizeRequest()` من `@/shared/utils/inputSanitizer` (مجموعة كاشف مشتركة
   تستخدم في أماكن أخرى في خط الأنابيب).
2. أنماط الحماية المدمجة `DEFAULT_GUARD_PATTERNS` (حاليًا `system_override_inline` و
   `markdown_system_block`، كلاهما بشدة `high`).
3. أنماط `customPatterns` الاختيارية المرسلة عبر خيارات المُنشئ (سلاسل نصية، regex،
   أو سجلات `{ name, pattern, severity }`).

عندما يكون `mode === "block"` **و** يلبي اكتشاف واحد على الأقل عتبة الشدة،
تعود `preCall` بـ `{ block: true, message: "Request rejected:
suspicious content detected" }`. في أوضاع `warn`/`log` يسجل الحاجز ولكن
يسمح بالمكالمة. يتم أيضًا تصدير المساعد المشترك `evaluatePromptInjection()` للمتصلين الذين يحتاجون إلى تقييم الموجهات دون المرور عبر السجل.

**حد المسح (v3.8.20):** يقوم الكاشف بفحص **أول 16 كيلوبايت** من
نص الموجه المدمج — `MAX_INJECTION_SCAN_BYTES = 16 * 1024` (16 384 بايت) في
`src/shared/utils/inputSanitizer.ts`. كل من `detectInjection()` و
`evaluatePromptInjection()` `slice(0, MAX_INJECTION_SCAN_BYTES)` قبل تشغيل
حلقة النمط. تقع توجيهات الحقن بالقرب من أعلى الإدخال، لذا فإن هذا يحد من استخدام وحدة المعالجة المركزية/GC على الحمولة التي تتجاوز مئات الكيلوبايت دون إضعاف الاكتشاف (راجع
#3932، #4041).

### ماسك بيانات الاعتماد (`credentialMasker.ts`)

يعمل على **كلا** المرحلتين، آخر في السلسلة الافتراضية (الأولوية `95`). يحذف
أنماط مفاتيح API / رموز السر المعروفة من الحمولة الصادرة (محتوى الرسالة، وسائط استدعاء الأدوات، نتائج الأدوات) **وأيضًا** استجابة المزود، بحيث لا يتم تسريب بيانات الاعتماد الملصقة في موجه (أو المعادة من قبل نتيجة الأداة) إلى المزود العلوي أو مرة أخرى إلى العميل.

- **الاشتراك فقط**، نفس القاعدة كما في حذف المعلومات الشخصية (قاعدة صارمة #20 المجاورة):
  معطلة ما لم يكن `settings.credentialRedactionEnabled === true` **أو**
  `CREDENTIAL_REDACTION_ENABLED=true`. مع إيقاف تشغيلها، فإن الحاجز هو لا شيء —
  لا يمنع أبداً ولا يعيد الكتابة.
- `redactCredentials()` يتجول في شجرة الحمولة/الاستجابة الكاملة (`walkValue()`,
  آمن من تلوث النموذج، آمن من الدورات عبر `WeakSet`) ويستبدل المطابقات بـ
  عنصر نائب `[REDACTED:<type>]`، مع استنساخ فقط الفروع التي تغيرت فعلياً.
- `CREDENTIAL_PATTERNS` تغطي مفاتيح مزودي LLM (OpenAI، OpenAI-proj،
  Anthropic، Google، Hugging Face، Replicate)، رموز VCS/SaaS (GitHub، Slack،
  Linear، Notion، npm، Postman، Discord)، مفاتيح الدفع (Stripe، Square)، مفاتيح السحابة
  (مفتاح وصول AWS، Twilio، SendGrid، Mailgun)، المفاتيح الخاصة / JWTs،
  سلاسل الاتصال الحاملة للاعتماد (`mongodb://user:pass@...`، إلخ)، ونمط رأس عام
  `Authorization`/`x-api-key`/`api-key`/`apikey`. المفاتيح على شكل رأس (`authorization`، `x-api-key`، `api-key`,
  `apikey`) يتم حذفها هيكلياً (القيمة فقط، مسبوق بمخطط مثل
  `Bearer `/`Basic ` محفوظ) بدلاً من استخدام تعبير نصي عام.
- الحاجز لا يمنع أبداً؛ إنه يعيد الكتابة فقط (`modifiedPayload` /
  `modifiedResponse`) ويعلق (`meta.credentialsRedacted`، `meta.count`).

حماية التراجع: `tests/unit/credential-masker-guardrail.test.ts`.

## العقد الأساسي (`base.ts`)

```typescript
class BaseGuardrail {
  enabled: boolean;
  name: string;
  priority: number;

  constructor(name: string, options?: { enabled?: boolean; priority?: number });

  async preCall(payload: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;

  async postCall(response: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;
}

interface GuardrailResult<TValue = unknown> {
  block?: boolean; // true يقطع السلسلة
  message?: string; // يظهر عند الحظر
  meta?: Record<string, unknown> | null;
  modifiedPayload?: TValue; // يتم إرجاعه بواسطة preCall لإعادة كتابة الطلب
  modifiedResponse?: TValue; // يتم إرجاعه بواسطة postCall لإعادة كتابة الاستجابة
}

interface GuardrailContext {
  apiKeyInfo?: Record<string, unknown> | null;
  disabledGuardrails?: string[] | null;
  endpoint?: string | null;
  headers?: Headers | Record<string, unknown> | null;
  log?: GuardrailLog | Console | null;
  method?: string | null;
  model?: string | null;
  provider?: string | null;
  signal?: AbortSignal;
  sourceFormat?: string | null;
  stream?: boolean;
  targetFormat?: string | null;
}
```

تشير الحواجز إلى "لا تغيير" من خلال إرجاع إما `void` أو `{}` أو
`{ block: false }`. إرجاع `modifiedPayload`/`modifiedResponse` يستبدل
القيمة المتدفقة عبر السلسلة للحواجز السفلية.
`signal?: AbortSignal` يحمل دورة حياة المتصل إلى الحواجز. يعتبر إلغاء الطلب استثناءً متعمدًا للفشل المفتوح: تتوقف جسور الوسائط عن العمل وتنظف دون استعادة الوسائط الخام إلى هدف معروف أنه لا يدعمه.

## السجل (`registry.ts`)

يكشف `guardrailRegistry` الأحادي عن:

- `register(guardrail)` — يضيف (أو يستبدل بالاسم المعياري) حاجزًا و
  يعيد الترتيب حسب `priority` التصاعدي.
- `clear()` / `list()` — مساعدات إدارية.
- `runPreCallHooks(payload, context)` — يكرر الحواجز النشطة، يمرر
  الحمولة عبر `modifiedPayload`، ويتوقف عند أول `block: true`.
- `runPostCallHooks(response, context)` — نفس التدفق على جانب الاستجابة.
- `resetGuardrailsForTests({ registerDefaults })` — يمسح الحالة و
  يعيد تسجيل الإعدادات الافتراضية اختياريًا لعزل الاختبار النظيف.

يعيد كل من المشغلين `{ blocked, payload|response, results, guardrail?, message? }`
حيث `results` هي مصفوفة من سجلات `GuardrailExecutionResult` التي تتضمن
حقول `blocked`, `skipped`, `modified`, `error`, و `meta` لكل حاجز،
مفيدة للتتبع.

### تعطيل الحواجز لكل طلب

يقوم `resolveDisabledGuardrails({ apiKeyInfo, body, headers })` بتجميع قائمة
غير مكررة لأسماء الحواجز التي يجب تخطيها للطلب الحالي. المصادر (جميعها اختيارية، وجميعها مدمجة):

- `apiKeyInfo.disabledGuardrails`
- نص الطلب `disabledGuardrails` (على المستوى الأعلى)
- نص الطلب `metadata.disabledGuardrails`
- الرأس `x-omniroute-disabled-guardrails` (أو القديم
  `x-disabled-guardrails`)

يمكن أن تكون القيم مصفوفات من السلاسل أو سلسلة مفصولة بفاصلة؛ يتم
تطبيع الأسماء إلى صيغة kebab-case بالأحرف الصغيرة (`pii_masker` ← `pii-masker`).
يتم تمرير النتيجة عبر `context.disabledGuardrails` إلى السجل، الذي يتخطى
الحواجز المطابقة (`skipped: true` في `results`).

## ترتيب التنفيذ

لكل طلب يمر عبر `src/sse/handlers/chat.ts` و `open-sse/handlers/chatCore.ts`:

1.  يقوم `resolveDisabledGuardrails(...)` بإنشاء قائمة التخطي من مفتاح API، والنص الأساسي، والرؤوس.
2.  يقوم `guardrailRegistry.runPreCallHooks(body, ctx)` بتشغيل الحواجز الأمنية بترتيب تصاعدي للأولوية:
    - يتم تسجيل الحواجز الأمنية المعطلة على أنها `skipped`.
    - قد يقوم `preCall` لكل حاجز أمني بإعادة كتابة الحمولة عبر `modifiedPayload`.
    - أول `block: true` يقطع السلسلة ويعيد المعالج استجابة رفض الحاجز الأمني.
3.  تتدفق الحمولة (التي قد تكون أعيدت كتابتها) إلى توجيه التحرير والسرد والإرسال الأولي.
4.  بعد تجميع الاستجابة، يقوم `guardrailRegistry.runPostCallHooks(...)` بتشغيل نفس السلسلة على الاستجابة. `block: true` هنا يسقط الاستجابة الأولية.

يتم تسجيل الحواجز الأمنية التي تثير خطأ بـ `error: <message>` ويتم تسجيلها عبر `logger.warn`، لكن السلسلة تستمر — تصميم يسمح بالفشل المفتوح.

## التكوين

متغيرات البيئة التي تقرأها الحواجز الأمنية المدمجة:

| المتغير | يستخدم بواسطة | التأثير |
| `INPUT_SANITIZER_ENABLED` | `prompt-injection` | تعيين `false` لتعطيل الكشف بالكامل. |
| `INPUT_SANITIZER_MODE` | `prompt-injection` | سياسة الحقن: `warn` (تحذير)، `block` (حظر)، أو `log` (تسجيل). القيمة القديمة `redact` لا تعيد كتابة نص الحقن. |
| `INJECTION_GUARD_MODE` | `prompt-injection` | وضع حماية الحقن؛ وهو أيضًا علامة ميزة قاعدة بيانات **تتجاوز** متغيرات البيئة (قاعدة البيانات > البيئة). |
| `INPUT_SANITIZER_BLOCK_THRESHOLD` | `prompt-injection` | الحد الأدنى للخطورة الذي يرفضه `MODE=block`: `high` (مرتفع، افتراضي)، `medium` (متوسط)، أو `low` (منخفض). |
| `INJECTION_GUARD_BLOCK_THRESHOLD` | `prompt-injection` | اسم مستعار قديم لـ `INPUT_SANITIZER_BLOCK_THRESHOLD`. |
| `PII_REDACTION_ENABLED` | `pii-masker` | عندما يكون `true`، يتم تنقيح معلومات التعريف الشخصية (PII) للطلب (بصرف النظر عن وضع الحقن). |
| `PII_RESPONSE_SANITIZATION` / `_MODE` | `pii-masker` (downstream) | يتحكم في سلوك قناع الاستجابة. |

تقرأ الحواجز الأمنية لـ Modality Bridge التكوين في وقت التشغيل من مخزن الإعدادات المدعوم بقاعدة البيانات (`getSettings()`)، وليس من متغيرات البيئة. المفاتيح الأساسية لـ Vision هي `modalityBridgeVisionEnabled`, `modalityBridgeVisionMode`, `modalityBridgeVisionModel`, `modalityBridgeVisionTaskAware`, `modalityBridgeVisionPrompt`, `modalityBridgeVisionTimeout`, `modalityBridgeVisionMaxImages`, `modalityBridgeVisionMaxChars`, `modalityBridgeCacheEnabled`, `modalityBridgeCacheTtlMinutes`, و `modalityBridgeCacheMaxEntries`. يتم قبول المفاتيح القديمة `visionBridge*` فقط كخيار احتياطي للقراءة لمرة واحدة كما هو موثق؛ تستخدم عمليات الكتابة في لوحة التحكم المفاتيح الأساسية. توجد القيم الافتراضية ومحلل الاحتياطي في `src/shared/constants/modalityBridgeDefaults.ts`، مع الاحتفاظ بالثوابت القديمة في `src/shared/constants/visionBridgeDefaults.ts`.

يستخدم الصوت `modalityBridgeAudioEnabled`, `modalityBridgeAudioModel`, `modalityBridgeAudioTimeout`, و `modalityBridgeAudioMaxClips`, بالإضافة إلى إعدادات `modalityBridgeCache*` المشتركة. لا يحتوي الصوت على خيار احتياطي للمفاتيح القديمة لأن هذه المفاتيح تم تقديمها مع مخطط Modality Bridge.

يستخدم الفيديو `modalityBridgeVideoEnabled`, `modalityBridgeVideoAnalysisMode`, `modalityBridgeVideoModel`, `modalityBridgeVideoFrameCount`, `modalityBridgeVideoSamplingPolicy`, `modalityBridgeVideoMaxVideos`, و `modalityBridgeVideoTimeout`, بالإضافة إلى إعدادات `modalityBridgeCache*` المشتركة. يتم تعطيله افتراضيًا لأن FFmpeg/ffprobe هي تبعيات تشغيلية اختيارية، وإضافة تسميات الإطارات تزيد من زمن الاستجابة وتكلفة النموذج.

## حواجز حماية مخصصة

```typescript
import { BaseGuardrail, guardrailRegistry } from "@/lib/guardrails";

class BudgetGuardrail extends BaseGuardrail {
  constructor() {
    super("budget", { priority: 50 });
  }

  async preCall(payload, ctx) {
    if (ctx.apiKeyInfo?.budgetExceeded) {
      return { block: true, message: "Daily budget exceeded" };
    }
    return { block: false };
  }
}

guardrailRegistry.register(new BudgetGuardrail());
```

الخطوات:

1.  أنشئ `src/lib/guardrails/myGuardrail.ts` يوسع `BaseGuardrail`.
2.  نفّذ `preCall` و/أو `postCall`.
3.  سجّل إما وقت الاستيراد (ادفع من `registerDefaultGuardrails`) أو
    استدعِ `guardrailRegistry.register(...)` في وقت التشغيل — يحل السجل محل
    أي حاجز حماية سابق بنفس الاسم المعياري.
4.  أضف اختبارات تحت `tests/unit/` (أمثلة موجودة:
    `tests/unit/guardrails-registry.test.ts`,
    `tests/unit/prompt-injection-guard.test.ts`,
    `tests/unit/guardrails/visionBridge.test.ts`).

## تغطية مسار حماية الحقن والاختبار الأحمر (المرحلة 8 · الكتلة D)

يغطي حارس الحقن (`createInjectionGuard` / `withInjectionGuard`) جميع المسارات
التي تقبل مطالبات المستخدم. وهو يحترم `INJECTION_GUARD_MODE` (الافتراضي `warn` = تسجيل فقط؛
`block` = يعيد HTTP 400 `SECURITY_001`).

| النوع      | المسارات                                                                                                                                             | الوضع الافتراضي |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | --------------- |
| نص (موجود) | `/v1/chat/completions`, `/v1/completions`, `/v1/relay/chat/completions`                                                                              | warn            |
| توليدي     | `/v1/messages`, `/v1/responses`, `/v1/images/generations`, `/v1/images/edits`, `/v1/videos/generations`, `/v1/music/generations`, `/v1/audio/speech` | warn            |
| بيانات     | `/v1/embeddings`, `/v1/rerank`, `/v1/search`, `/v1/moderations`                                                                                      | warn            |

تغطية استخراج النص (`extractMessageContents`) تشمل `messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system`.

**الفريق الأحمر (ليلي، `nightly-llm-security.yml`):** يتحقق promptfoo من أن كل مسار يحظر
مجموعة OWASP-LLM في `INJECTION_GUARD_MODE=block`؛ يقوم garak بتشغيل الفحوصات (يتخطى بدون سر).
يتم تضمين `moderations` من أجل الاتساق — يمكن للمشغلين في وضع الحظر إعفائها عبر
`resolveDisabledGuardrails`.

يحتوي سير العمل الليلي (`.github/workflows/nightly-llm-security.yml`، cron +
التشغيل اليدوي) على وظيفتين:

- **`promptfoo-guard` (حظر)** — يشغل `promptfoo eval -c promptfooconfig.yaml`
  مع `INJECTION_GUARD_MODE=block`. تؤكد كل حالة عدائية (مثل "تجاهل جميع
  التعليمات السابقة..."، اختراقات على غرار DAN) أن الاستجابة تحمل
  `error.code === "SECURITY_001"`، أي أن الحارس رفض الطلب بالفعل.
- **`garak` (استشاري)** — يشغل garak `--probes promptinject,dan,leakreplay`
  مقابل مثيل OmniRoute محلي (`http://localhost:20128/v1`). يتم التحكم فيه بواسطة
  سر مزود (`PROMPTFOO_PROVIDER_KEY`)؛ يتخطى بأمان ويتم إلحاقه بـ
  `|| true`، لذلك يتم الإبلاغ عنه دون فشل CI.

تغطية مساعد الحارس (`createInjectionGuard` / `withInjectionGuard`)
تمتد عبر كل مسار `/v1` يحمل مطالبة؛ يتم سحب نص المطالبة من
`messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system` بواسطة
`extractMessageContents()` في `src/shared/utils/inputSanitizer.ts`.
